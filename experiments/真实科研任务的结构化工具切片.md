# 真实科研任务的结构化工具切片

> 2026-09-26。此记录保留最初的工具设计与无模型验证；后续三类真实数据核查和失败案例见 [结构化 MCP 三类真实数据核查记录](结构化MCP三类真实数据核查记录.md)。

## 为什么做

前两次付费原生 DeepSeek Harness 任务分别核查 TauBench 和 AppWorld 的实验图。两次都是真实研究核查：找原始依据、复算、核对图与图题。Agent 主要调用自由形式的本地命令；命令内部的“哪个输出成为下一步的哪个参数”没有稳定的机器记录，因此严格挖掘得到 0 个跨任务可执行 Motif。不能事后把这些命令改写成已观察到的参数链。

## 现在可怎么做：以 AppWorld 为例

研究问题仍是“原始记录能否复现图表，图题是否受到数据支持”。Agent 自己决定要不要检查重复任务的影响。若决定检查，它可以调用以下**通用只读工具**：

1. `pin_source(coverage_points.csv)` 固定文件字节，得到 `source_id` 和 SHA-256。
2. `inspect_records(source_id)` 得到字段、196 条记录和 `dataset_id`。
3. `aggregate_records(dataset_id, group_by=["task_id"], measures=[计数, 调用差值求和])` 得到 `result_id` 和逐任务统计。实际数据有 92 个 task ID；重复最多的任务出现 22 次，其调用差值合计为 456。
4. 若有新的数据版本，可再固定、检查和统计，并用 `compare_results(旧 result_id, 新 result_id)` 只查看改变的分组。`compare_sources` 可检查两个文件的字节差异。要核查生成的 SVG 是否与原图一致，必须先生成 SVG，再对两个 SVG 调用 `pin_source` 和 `compare_sources`。

前三步不是写死的任务流程；这些工具也可以处理其他 JSON/CSV/TSV 研究记录。工具只做读取和明确指定的计算。Agent 仍须决定研究问题、选择分组与指标，模型或研究者仍须判断图题的科学表述。数字 196、92、22、456 是这份数据上的无模型工具验证结果，不等于 Agent 报告已通过人工审核。

`source_id → dataset_id → result_id` 是参数传递凭据。工具每次消费旧凭据前都会重新核对原文件哈希；文件变化则停止并要求固定新版本。凭据只存于被忽略的 `.local/structured-research/`。工具仅允许读取限定的科研输入目录，并限制单文件、行数、字段、分组和返回量。`run_python` 仍可做开放探索，但任意代码内部的操作不能自动当成 Motif 证据。

## 轨迹如何变得可挖掘

Harness 若实际调用上述工具，其原始 `tool/call` 与 `tool/result` 事件会含不易偶然重复的凭据 ID。离线轨迹适配器只在**先前成功结果**确实返回相同 ID 时，推断“本次参数来自哪次调用的哪个字段”；未见来源、来源歧义、调用失败或插入未批准工具时，不把片段当作有据的连续只读链。工具契约见 `config/structured-research-tool-contracts.json`。三类数据阶段任务现已观察到参数传递，但仍为候选边，**0 个可执行且通过质量门的跨任务 Motif**。

## 下一轮实验顺序

1. 保留真实图表核查题和原始资料，冻结问题、验收项、资料版本与费用上限。给原生 Harness 开放这些通用工具，但不规定调用次数或固定工具顺序。记录工具是否被 Agent 自发选择、为什么仍使用本地命令、模型请求、token、费用、耗时及人工修订。
2. 用至少第三个不同研究内容、同类核查需求的任务收集轨迹。只从训练任务的真实调用与参数流挖局部候选；留出任务不得用于挑选或调参。要同时保留一次可安全复用的资料变化和一次必须打断旧路径的新反证。
3. 候选通过留出任务执行与人工质量门后，才比较原生 Harness、Motif 和普通脚本／缓存。先看合格交付，再比较合格交付的总成本。若工具改善了所有组而 Motif 无额外收益，就如实记录。

本切片只解决本地记录读取、计算与版本比对。Zotero、Obsidian、文献发现等跨应用工具的统一来源凭据与轨迹绑定仍待实现；84 个已暴露工具不等于 84 个已被 Agent 使用。

## 已做验证

- AppWorld 真实 CSV 经直接函数与 MCP 客户端调用，均得到 196 条记录、92 个 task ID、最高重复 22 次及该任务调用差值 456；原始 JSON 的 `per_task_common` 有 200 条。
- 数据文件改动后，旧 `dataset_id` 和 `result_id` 不再可用于统计或版本比对；非法路径和非数值计算报错。
- 本节所述是初始验证。最新结构化工具加入文件清单与分组排名；本次对照后 `npm run test:structure` 为 219 项通过，六个默认连接器正常枚举，本地科研工具 13/13、总数 87。真实 Agent 使用结果和限制见上方后续记录。
