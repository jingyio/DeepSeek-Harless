# 日历内 Motif 跳轮候选：真实轨迹审计与影子回放

本记录只针对 `find-available-slots → validate-slot` 的局部参数链，不把日历排期写成固定 DAG，也不把合成题算作真实科研决定。来源是前轮普通 DeepSeek Flash Agent 在真实 Google Calendar MCP 上的 A/B/C 只读轨迹；原始事件、日历 ID、账本与派生候选保存在 `.local/benchmarks/mcp-app-internal-v2/calendar/availability-v1/`。

| 题 | 查找／校验所在模型步骤 | 实际参数来源 | 可作为后继跳轮见证？ |
| --- | --- | --- | --- |
| A | 同为第 3 步，并行调用 | 候选虽与查找结果一致，但校验并未等待查找结果 | 否 |
| B | 第 2 步／第 3 步 | 校验的 `candidateStart/End` 等于前步 `earliest.start/end`；日历、时区、窗口、时长保持相同 | 是 |
| C | 第 2 步／第 3 步 | 同 B；两次工具结果的 `sourceSha256` 相同 | 是 |

`scripts/audit-calendar-motif-opportunities.py` 核对调用先后、全部六项校验输入、结果有效性及来源哈希；A 被拒绝，B/C 通过。参数或来源哈希变动的单元扰动均被拒绝。对 B/C，`scripts/compile-calendar-motif-candidate.py` 通过原始工具事件生成有记录的 `candidateStart/End` 来源声明，交给已有的 `compile_witnessed_edge_motif` 分别编译；两个输出参数边各有两题的唯一见证，其余四项参数在 B/C 的查找与校验调用中逐值相同。产物状态明确为 `candidate_only_requires_independent_heldout`，不允许在线执行。这里只证明轨迹中存在参数依赖，未验证 D 留出或后续任务效果。

`scripts/replay-calendar-motif-candidate.py` 用原始 Agent 已确定的查找参数，在真实受限日历 MCP 上重新执行 B/C 查找，再依据候选边生成校验参数。两题参数都与原 Agent 的校验调用完全一致，实时校验结果为 `valid=true`、`isEarliest=true`、来源哈希一致，模型请求为 0。首次尝试因 Google free/busy 请求中断而停止；一次新尝试通过，失败未计成成功。此项是**影子回放**，不是在线替代 Agent 的模型轮次。

可跳过的目标若在线成立，是 B/C 第 3 步那次“调用校验工具”的模型判断，账本中该次请求的本机估费分别为 US$0.00058474 与 US$0.00066650。删除该请求的金额不能直接当成净节省：之后模型输出、缓存命中、工具顺序和异常恢复都可能改变。A 没有对应独立轮次，不能套用同一预估。下一步须从独立 D 自然轨迹认证，再在独立 E 同源普通／Motif 两组中实测请求数、完整费用、质量与来源变化后的失效；[写入及付费预览](日历Motif跳轮续测预览_2026-09-29.md)已冻结，尚待确认。简单脚本与直接合并工具依然是必须保留的强基线。

后续 D 留出已通过，E 普通组、认证产物与两题实时影子回放均已完成。E 在线组又做了首次和一次标记重试：首次因 Google 工具错误安全回退，重试确实跳过一次模型判断，但同题总请求仍为 4 次，费用高于普通组。完整数值更新在[续测结果](日历Motif跳轮续测预览_2026-09-29.md)。上段“尚待确认”仅指写作当时的准备状态。
