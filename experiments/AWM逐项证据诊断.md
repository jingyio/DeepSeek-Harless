# AWM 逐项证据流程：事后诊断

> 2026-09-24。本文是在[新资料初次对照](AWM新资料对照结果.md)发现缺口后修改检索/选证据流程，并对**同一份已读 PDF** 再运行一次。属于事后方法开发，不能视为新的盲评，也不能与原始两组宣称公平胜负。原始运行保留在被忽略的 `.local/point-research-runs/20260924T144627Z-be7349/`。

## 方法变化

原多步流程只规划 2–3 个子问题，再从每题选页，七项必答点可能没有独立证据。新流程从调用前固定的[七项清单](AWM工作流记忆必答点.json)出发：每项规划字面检索词；运行时核验文件哈希、页哈希及 750 字符摘录；语义层为每项选择一段；综合结论只能引用分配给本项的证据；最后逐项检查“有引文结论且无明确阻断性缺口”。每步轨迹和原始响应均保存。结构检查**不能**判断引文是否蕴含结论，仍需人工逐项判分。

调用前的预览显示 1 份 PDF、16 页、7 项，最多 3 次模型请求，规划/选证据/综合的输出上限分别为 900/900/1800 token。实际使用 `deepseek-flash`、推理关闭、无模型工具调用，3 次请求累计输入 5,215 token、缓存读取 0、输出 1,198 token。按 2026-09-24 运行时[官方空闲时段单价](https://api-docs.deepseek.com/zh-cn/quick_start/pricing/)估算，API 费用约 ¥0.010007，不含人工与本地处理。程序返回 `incomplete_answer`，6 条保留结论、1 条因跨项引文被拒；未运行自动重试。单就 API token 用量而言，仍高于原始一次调用的普通脚本，且当前没有合格答案，不能计算合格任务的成本优势。

| 预先固定的必答项 | 机器检查 | 人工核对 |
| --- | --- | --- |
| 经验组成 | 有引文 | 直接：p.3 原文说明指令与动作轨迹。 |
| 工作流形式 | 有引文 | 部分：引文证明步骤里有自然语言状态和可执行动作，但未引用工作流整体由描述和步骤序列组成的定义。 |
| 细粒度抽象 | 明确缺口 | 部分：选中 p.3 的占位符段，遗漏同页前面的细粒度子任务段；模型如实标记缺口。 |
| 离线记忆 | 有引文 | 直接：p.4 说明测试前完成诱导，并对每个测试任务使用同一份记忆。 |
| 在线成功准入 | 有引文 | 直接：p.4 的二元成功标签及仅成功轨迹进入诱导均被引用。这是初次流程漏掉的核心条件。 |
| 在线更新 | 无有效引文结论 | 缺失：选中了 p.3 的图示附近段落；模型又引用了分配给离线项的 p.4 段，跨项引用被拒。 |
| 代理使用工作流 | 有引文 | 部分：引文证明加入辅助记忆，未直接证明下一任务的动作如何依据它生成。 |

人工严格判分为 **3/7 直接、3/7 部分、1/7 缺失**；程序自身仅报告 5 项有引文关联、2 项不完整。两种数值衡量的不是同一性质，不能把 `point_links_present` 当质量通过。相对初次流程，在线成功准入项被找到；但单页只选一个 750 字符窗口使相邻段落的两个条件可能分离，选证据提示仅展示每个窗口前 260 字符也掩盖了末尾关键句。

## 已做的无模型修正与下一轮判定

诊断后，选证据提示对每项排名第一的候选同时展示窗口开头和末尾。用**已保存候选**离线重建提示，长度为 11,511 字符（低于 12,000 上限），在线更新候选的“每个测试任务推理后”句已出现在提示里；32 个结构测试通过。该修正尚未发起模型调用，**没有实测回答增益**。接下来应让同一必答项可选来自同一页的多个经核验窗口，确保“细粒度子任务＋占位符”或“任务后更新＋供下一任务使用”这类复合条件同时进入综合；再以新题预先固定方案做公平质量/成本评估，避免继续在 AWM 上调参充当成绩。
