# 日历 Motif 跳轮续测预览（合成开发诊断）

目标是检验普通 Agent 在确定日历、时长与窗口后，运行时能否复用已见过的 `find-available-slots → validate-slot` 参数链，并在结果或来源变化时拒绝旧路径。上一轮真实轨迹中，B/C 的查找结果出现在第 2 个模型步骤、校验在第 3 步；校验输入与查找输入一致，候选开始／结束来自查找结果，来源哈希相同。A 在同一模型步骤并行提出两次调用，不算可跳过的后继。私有逐步审计在 `.local/benchmarks/mcp-app-internal-v2/calendar/availability-v1/motif-opportunity-audit.json`；当前只是 **2 个候选见证，未获独立留出认证**。

下一道独立题 D 将在已有的专用「SSS MCP Test」日历中写入两条标明测试用途的占用：2026-10-15 09:40–10:30、11:20–12:00，均无参与者、邀请与提醒。普通 Agent 的只读请求为：在 Asia/Shanghai 当日 09:00–12:00 或 14:00–16:00 的窗口内，找连续 50 分钟的最早讨论时段并列出来源事件 ID。独立计算预期为 **10:30–11:20**。D 的自然轨迹先作为留出：若未出现同样的先查找、后校验的参数链，则不得认证或在线执行该 Motif。

若 D 认证通过，独立题 E 在 2026-10-16 写入两条占用：09:00–09:30、10:20–11:00。E 请求在 09:00–12:00 或 14:00–16:00 中找连续 55 分钟的最早时段；预期 **11:00–11:55**。E 将以相同提示与来源分别运行普通 Agent 和 Motif Agent，对比最终质量、实际模型请求、缓存计价费用、工具调用及耗时。随后可再写一条 11:10–11:40 的测试占用，旧 E 答案将冲突，新最早时段为 **14:00–14:55**，用于检验来源变化后的局部失效；此增量轮次不算新独立任务。

测试日历写入仅由评测准备脚本执行，Agent 始终只见受限只读桥。精确事件及任务预览见 `node scripts/setup-calendar-motif-fixture.cjs --preview`；D/E 普通 Agent 的冻结提示与工具版本见 `.local/benchmarks/mcp-app-internal-v2/calendar/motif-continuation-v1/agent-{d,e}/`。拟用 DeepSeek Flash，`reasoning_effort="off"`，普通 D/E 每题最多 10 次请求、US$0.50；在线 E 若进入，则单独冻结 Motif 来源、模式和同等预算。模型费用是上限，运行后另按逐请求账本估算真实用量；不把合成题报告成真实科研交付收益。

认证必须来自 B/C 的真实轨迹与 D 的独立自然轨迹，不用手写步骤清单充当 Motif 库。现有通用在线适配器只允许有限的标量参数和已认证只读边；日历时窗是数组，校验还须复用前一步参数，因此需先实现并测试有类型的参数绑定与来源守卫。若扩展无法在不降低安全门槛的前提下通过，就保持候选状态并报告此边界。

## E 同题在线实测结果（追加）

用户继续测试后，已运行在线 E 的首次尝试和一次**明确标记、不覆盖首次记录**的重试。两次均为只读、同一测试日历、DeepSeek Flash、`reasoning_effort="off"`；逐请求账本、完整事件、最终答案及 Motif 审计分别在 `.local/benchmarks/mcp-app-internal-v2/calendar/motif-continuation-v1/agent-e-motif/` 与 `agent-e-motif-retry-1/`。以下 API 金额按成功返回请求的缓存命中／未命中及输出用量估算；首次尝试另有一个 HTTP 502 请求未给出用量，不擅自计作零费用。

| E 运行 | 答案与事件 ID | 成功模型请求 | 实际 Motif 跳轮 | API 估费 | 耗时 |
| --- | --- | ---: | ---: | ---: | ---: |
| 普通 Agent | 正确，11:00–11:55；e1/e2 | 4 | 无 | US$0.00394881 | 14.656 秒 |
| Motif 首次 | 正确，11:00–11:55；e1/e2 | 5，另有 1 次 HTTP 502 | 0 | 至少 US$0.00477886 | 47.589 秒 |
| Motif 标记重试 | 正确，11:00–11:55；e1/e2 | 4 | 1 次，校验结果通过来源哈希及 `valid/isEarliest` 守卫 | US$0.00413401 | 18.751 秒 |

首次 Motif 尝试中，Google 忙闲接口给 `find-available-slots` 返回“结果未精确覆盖请求日历”的错误；守卫拒绝跳轮，普通 Agent 自行重试后完成。这是实际失败成本，不从结果中删除。标记重试中，Motif 真正代替了查找后的一次模型请求并调用 `validate-slot`，随后校验返回相同来源哈希、`valid=true`、`isEarliest=true`。但该次 Agent 在查找前先多做了一轮 `get-freebusy`／`list-events`，普通组则在同一轮调用 `list-events`／`find-available-slots`；两组最终都是 4 次模型请求。重试费用比普通组高 **US$0.00018520（约 4.7%）**，耗时多 **4.095 秒（约 27.9%）**。一次成功跳轮并未转化为整题净节省。

这组数据只支持两个窄结论：认证的结构参数链能在普通 Agent 已选择日历／窗口／时长后安全跳过一次模型判断；当前真实 E 任务没有降低请求总数、API 费用或耗时。它不能证明更广泛任务受益，也不能把首次失败后的重试当作唯一成绩。强基线的直接计算脚本仍能在此类明确排期题上零模型请求、正确完成；因此日历类别不再继续增加同型合成题，应转向其他应用内部任务与更有语义缺口的跨资料任务。
