# SSS 阶段汇报：场景实测、优化机制与创业判断

日期：2026-09-30。**一句话结论：**MotifAgent 内核已在受控任务及两种真实本地应用中，从普通 Agent 轨迹复用带来源校验的工具步骤，确实跳过完整模型请求；但尚未证明它能在课题组自然工作中持续降低**合格交付的总成本**。现阶段适合展示“可工作的机制与明确的适用边界”，不适合宣传通用 Agent 已省钱或可以收费规模化。

## 两个优化开关到底开了没有

| 优化 | 真正做过的实验 | 看到的收益与代价 | 当前默认判断 |
| --- | --- | --- | --- |
| **跳过模型请求**：Motif 按当前工具结果重绑参数，校验来源／版本／唯一性，执行已认证只读步骤，失败交还模型 | **已在线开启**于 Numbers、Keynote、Finder、Gmail、日历及部分真实科研诊断、合成科研决定；逐次审计 `model_request_skipped_verified`，并与普通组的实际总请求数分开计 | Numbers／Keynote 的请求和执行费用下降；Gmail 请求稳定下降但费用受正文长度和缓存影响；Finder 无接管，日历与两项真实增量研究虽有局部接管却无净省费 | 保留，但只对任务匹配、可唯一定位、结果可验证的局部算子默认启用；不能把每次接管等同于整题少一次请求 |
| **压缩模型所见内容**：可恢复的 Gmail HTML 视图、无损 JSON 紧凑化或历史摘要 | Numbers／Keynote／Finder 的**首轮**没有开启压缩；随后在同题四条件复测中开启了保留全部字段的 JSON 紧凑化。Gmail 专题的认证短视图在三题共少送约 **97.6 KB**；日历字段视图仅量到工具字节减少约 57.6%。AIDD 提前摘要和 Distil `context-only` 也单独试过 | 本地应用普通 Agent 单开 JSON 紧凑化，三组估算费用均略升；Gmail 短视图明显省费但阅读质量未独立确认。AIDD 提前摘要回答仍不合格；Distil 修复接线后上游请求 **7→16**、估费约高 **37%**；旧 PDF 轨迹目前认证可压缩 **0 字节** | 不默认开启通用压缩。只对数据较大且完整性可验证的输出考虑局部开启；记录恢复与缓存失效，绝不把少送字节写成省钱 |
| **两者同时开启** | Gmail 真实提醒已比较“原文／短视图 × 普通／Motif”：同一短视图下新三题请求 **9→6**、估算费 **$0.006970→$0.006222**。本地应用同题复测也同时开启：Numbers 三题在压缩条件下普通→Motif **15→6** 请求，严格质量双方 **3/3**，估算费 **$0.005921→$0.004425** | 两种机制可以叠加，但 Numbers 中压缩本身的额外收益只是在 Motif 组约 **2.36%** 的单次样本；Keynote 短 JSON 的费用差夹杂模型自发合批，Finder 0 次跳轮且压缩后费用上升。Gmail 的压缩也帮助普通组，不可全归给 Motif | **尚没有“质量已核验的自然多应用任务”上的完整二因素胜出结果**。目前仅在具体单应用任务中有局部成绩；详见[四条件复测](本地应用工具压缩与Motif四条件复测_2026-09-30.md) |

“API 缓存命中”是模型服务对稳定提示前缀的计价行为，所有正式费用表均尽量按命中／未命中分别算；它不是 SSS 自己的压缩。普通版本化结果缓存也做过同题对照：三个固定统计切片里，缓存与 Motif 都把第二轮工具调用从 3 次降至 1 次，Motif 没有额外调用优势。详情见[压缩对照](Distil_context_only跨应用批注对照_2026-09-27.md)、[邮件视图](Gmail动态搜索锚点Motif试验_2026-09-28.md)、[跨应用视图波动](真实提醒跨应用工具与投影试验_2026-09-29.md)。

## 面向创业，应怎样解释这批结果

**已降低的风险：**我们有能接入真实桌面应用与 MCP 的运行原型，能从正常执行轨迹编译局部算子，在新文件或新邮件上重新定位，拦住已知歧义，并留下逐请求费用与来源回执。这比“提示模型少想几步”更具体。Numbers／Keynote 表明控制点可在实际应用中发挥作用，日历表明确定性计算能直接提高某类任务的正确性。

**尚未降低的风险：**没有课题组同学独立完成的连续真实任务、可靠的人工修订分钟数、付费意愿或部署维护数据；跨论文科研判断常被证据边界和材料错误卡住。API 单题绝对节省很小，单靠卖“每次省几个模型 token／几万分之一美元”不足以构成面向用户的价值主张。训练摊销、连接器故障、权限、隐私与真实支持成本也未算入。当前不宜承诺“所有办公场景自动更便宜”或“科研报告自动正确”。

**建议的创业楔子：**停止横向增加应用，先做一个可交付的**组会材料核验助手**试点：让同学用自己每周已有的 Numbers 数据表与 Keynote 幻灯片，检查数字、公式、正文与备注的一致性，生成带来源和版本的待审问题清单；模型负责定位用户意图和解释差异，明确算术与已认证读取由工具完成。我们只分别验证了两个单应用切片，**尚未验证表格到幻灯片的完整工作流**，所以这是一项产品假设而非已取得的跨应用成绩。它比开放式“帮我做科研决定”更容易给用户看见准确性、节省的核对时间及可审阅性；文献增量判断继续作为较长线研究方向。

**下一次是否继续投入的门槛：**请至少 3 位实际使用者带来真实旧稿及后续更新，先记录他们手工核对耗时和常见错误，再让他们独立试用。对同一批任务比较原来做法、普通 Agent、简单校验／版本缓存和 Motif；盲核对漏检与误报，并计安装、授权、复核、人工修改、失败重试、训练与维护时间。另设一次无关变化应沿用、一次关键证据变化必须停止的增量测试。若基本脚本以更低的完整成本交付同等结果，产品应采用脚本，Motif 只保留它实际解决的跨任务重绑与局部恢复。只有真实用户愿意持续使用，且合格交付时间或成本有稳定改善，再扩充应用和讨论收费模式。
