# 六类 MCP 应用内实测：可以据此做什么决定

日期：2026-09-29。**结论：真实工具已在六类中分别受测；Gmail 读取链和合成日历排期的局部校验链均实证跳过过模型请求，仍不能证明 Motif 降低了“合格科研交付”的总成本。** 日历 E 在线跳轮一次但整题请求未减少，估费和耗时反升；另一次因真实工具错误安全回退。对固定来源取证和固定统计，普通脚本已经很快；新做的文献 Agent 虽给出了正确的主引用方向，却越过证据声称版本正文差异，因此质量门未过。继续扩大同一开发题的调用次数不会解决这些问题。先给语义交付加证据边界，再用不同真实决定做同题普通 Agent／脚本／Motif 对照。

本报告按**文献发现、Zotero、Obsidian、本地 Python／Quarto、Gmail、Google 日历**六类工具，而不是旧合成题里的六种科研决定。所有工具检查访问的是真实 MCP 连接器；Zotero／Obsidian 限此前批准的来源，文献和数据为公开来源，Gmail 为本人已有提醒，日历仅本人忙闲。未发邮件、建会或修改应用资料。AIDD 的文献、Zotero、Obsidian 和数据四项共享同一研究决定，**不能算四个独立留出任务**。

## 文献 Agent 的证据复核

冻结任务要求核对 2023 bioRxiv 预印本 DOI `10.1101/2023.05.17.541222` 与 2025 *Nature Computational Science* DOI `10.1038/s43588-025-00823-8` 是否为同一工作，并明确标出不能仅凭题录确定的正文差异。公开 MCP 的 Crossref 返回 `is-preprint-of`／`has-preprint`，两条记录作者与题名匹配；Europe PMC 找到了期刊全文，但未给出预印本可读全文；OpenAlex 仅提供其摘要和 PDF 链接，Agent 没有读取该 PDF。这支持“同一工作两个出版版本，当前文献卡以期刊版为主引、注明预印本来源”，**不支持声称已经比对两个版本的正文**。

原答案的三处可定位错误：

1. 说“双方各自声明”“双向交叉确认”。实际期刊记录 `has-preprint` 的 `asserted_by=object`，预印本记录 `is-preprint-of` 的 `asserted_by=subject`；两者的断言来源都归到**预印本 DOI**。Crossref [关系文档](https://www.crossref.org/documentation/schema-library/markup-guide-metadata-segments/relationships/)明确说明一端存入 DOI 关系后会自动生成反向显示；其[预印本说明](https://www.production.crossref.org/blog/leaving-the-house-where-preprints-go/)解释 `asserted-by` 用来保留声明来源。两条显示不能当作两家出版方独立背书。
2. 用预印本**摘要**未提 Rosetta、若干基线与稳健性数值，对照期刊版**正文**，命名为“已核对的版本差异（有正文证据）”，并推断期刊版“新增”或结论“改为”。预印本正文未读到，摘要缺省不等于预印本没有；这张差异表应整体降级为**待全文比对**。原答案末尾承认无法取得预印本全文，更说明前面的断言自相矛盾。
3. 说两记录“引用者集合高度交叠”，但轨迹只调用了**预印本一侧**的 `get_citing_works`，没有期刊版引用者集合，不能计算交集。该论据须删除。

人工桌面审计的门槛是：标识和引用建议正确，且不能把未核对的正文差异当成已证实。前两项通过，后一项失败，因此**本次完整文献卡暂判不合格**。这是可复核的证据约束审计，不冒充领域研究者盲评。可交付的保守文献卡应只写：两个 DOI 由 Crossref 一条可追溯到预印本记录的关系相连，题名和作者一致；主引 2025 期刊版，附注 2023 预印本；具体实验、数值、图表或措辞变化待取得预印本全文后逐段核对。

文献试跑使用 DeepSeek Flash、`reasoning_effort="off"`，冻结的 **12 请求／$0.50** 闸门内实际发出 8 次请求；缓存未命中输入 **22,236**、命中输入 **101,632**、输出 **3,306** token。逐请求 API 用量按本机价格表合计 **$0.01124779**，没有与供应商账单核对；失败的 arXiv 查询和最终长答案均已计入轨迹；没有发生模型请求重试。最初任务预览、哈希、批准记录、源码快照、原始事件和账本位于 `.local/benchmarks/mcp-app-internal-v2/literature/`，不进入仓库。

## 已执行的修正与下一次判定门槛

发现关系误读后，`verify_doi_metadata` 新增 `assertion_source_doi` 和关系来源说明，使期刊侧 `object` 与预印本侧 `subject` 都明确落在同一个预印本 DOI；文档和回归测试同步更新。**这是事后工具修正，不能回填为本次 Agent 已看到的证据，也未证明新输出一定会使模型不犯错。** 冻结试跑当时的工具源码已按预览 SHA-256 另存 `.local`，所以原结果可复核。正文差异问题仍需语义层遵守“双方全文未齐，不生成已证实差异”的质量门；不能靠多读一侧正文解决。

下一轮要另选至少两个不同真实研究决定获取自然轨迹并编译／认证 Motif，再封存第三个独立决定做同题留出；同模型、工具范围、提示和来源版本比较普通 Agent、同权限简单脚本或缓存、在线 Motif。先由领域研究者盲评交付与人工修订时间，只在合格者中比较核账费用、模型请求和端到端时间。还需至少一例来源不变可安全沿用、一例新反证或版本变化必须打断旧路径。若简单脚本已能同质完成该类操作，Motif 的主张应收窄到它确实多解决的参数重绑定、失效恢复或跨任务组合。
