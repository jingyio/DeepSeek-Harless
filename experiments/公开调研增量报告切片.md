# 公开调研报告的增量更新：可运行切片与未完成的效果验证

> 2026-09-25。本文记录程序行为和无付费模型测试，**不是报告质量或费用优势结论**。

## 用户任务

课题组同学上周完成一份有来源和引文的调研简报；本周资料库新增、修改或移除文件，需要一份更新草稿和变更记录。软件应保留仍可核对的部分，重写受影响的问题，提醒同学检查新资料是否推翻旧结论。

`research-points.py` 现在接受 `--previous-report-run /path/to/previous/run`。上一版必须来自同一资料目录、有相同问题文本、逐项要求、已核验的引文和结构覆盖记录。运行时重新读取当前资料、生成当前证据目录和逐项选择，然后比较 MotifFrame 中各问题的依赖签名。对可沿用的结论，再逐条核对来源文件哈希、页码、引句和当前问题的证据范围。旧版缺答、有不确定项、问题要求变化、候选变化或引文无法重验时，该问题必须重新综合。

输出 `incremental-plan.json`、给同学看的 `change-log.md`，以及待审阅的 `incremental-preview.md` 或 `answer.md`。沿用的结论标为**待人工复核**；新资料可能提出相反证据，单凭旧引文仍可定位不能证明旧结论继续成立。只要沿用了旧结论，完成的报告状态就是 `incremental_draft`，即使同时重新生成了部分结论，也不等同于报告合格。未经复核的增量草稿不能在下一轮继续沿用结论；如果所有问题都重新综合，则无需批准旧文字。

2026-09-26 增加了多轮交接：研究者实际审完盲评材料后，在 `.local/` 中填写单独的 JSON 评分表，逐项给出引文支持和要求覆盖的 0–2 分、重大错误、审阅分钟数与 `approved`／`rejected`。运行 `scripts/record-research-review.py <上轮目录> --form <评分表路径>` 后，程序只在每项均为 2 分且无重大错误时接受 `approved`，并将判定绑定到上轮问题、结论、引文、来源状态和报告文件的哈希。下一轮只有在这些文件仍与已审版本完全一致时，才允许从 `incremental_draft` 沿用任何结论；`incremental-plan.json` 留下所用评审记录的摘要。评分本身必须由人完成；这个本地哈希记录只能防止**审后改动**，不能认证评审者身份或证明科学判断正确。未填写或不合格时仍停止下一轮沿用。

评分表结构如下；`point_scores` 须列出上轮 `answer-points.json` 的每个 `id`，不能只填示例中的一项：

```json
{"reviewer":"研究者姓名或编号","reviewed_at":"2026-09-26T16:00:00+08:00","verdict":"approved","point_scores":{"示例问题ID":{"support":2,"coverage":2}},"serious_error":false,"review_minutes":15,"notes":"核对了原文与新增反证"}
```

| 检查 | 观察 |

| 来源变化 | 变更记录识别 `web-09.txt` 被修改 |
| 逐项重用 | `coarse`、`fine` 的证据签名及引文仍吻合，2 项进入待审草稿 |

| 无资料变化 | 4 项结论均可生成待审增量草稿，综合模型请求数为 0 |

本机记录分别在被忽略的 `.local/point-research-runs/20260925T022802Z-2128d9/` 和 `.local/point-research-runs/20260925T022802Z-775c10/`。它们是程序机制检查，不能用其“提示字符减少”推断真实 token、总费用或交付质量。

2026-09-26 补充了恢复边界：旧版 `research-repair.py` 现在将修复限定到父运行的**完整 Motif 来源快照**，包括资料目录和全部去重后页面，而非只核对旧报告引用的几页。新增、移除或修改任一资料时，局部修复停止，转交增量更新路径；所有经通用 DSH 语义端口发出的付费请求也须经过本地预算闸门。用先前 AutoTool 公开资料的真实缺答运行做了无模型修复预览，识别出 3 个未覆盖点，规划提示 986 字符；未请求模型。另用独立本地来源测试验证：旧引文不变但新增一份资料时，快照检查会阻断修复。这些结果只验证边界，不是修复后报告的质量成绩。

## 验收缺口

1. **真实内容**：需要先在公开题上由模型生成并经人工评审一份可用简报，再对新增资料运行增量更新；目前保存的父报告是合成夹具。
2. **冲突检查**：当前旧结论虽重验引文，但无法自动判断新资料是否与其冲突。沿用部分必须人工复核；以后可测试有边界的冲突分类器，不能直接用高置信答案覆盖人工门。
3. **效果对照**：同题比较从头重写、简单脚本局部更新、固定 Motif 和进化 Motif。报告质量达标后，再比较真实 API 费用、人工修订时间、端到端时间与失败恢复成本。
4. **任务范围**：当前只处理固定本地资料和逐项问题；资料自动检索、跨任务匹配、代码迁移及组内共享文件发布仍未形成产品闭环。
