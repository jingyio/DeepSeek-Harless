# Motif 证据视图：旧科研轨迹离线试验（2026-09-28）

## 问题与边界

检验旧跨应用科研任务中的 PDF 工具输出，是否已有足够的结构证据，让 SSS 在**最近一轮**向模型呈现较短视图，同时保留原文供恢复。这一轮只回放本机既有 DSH 轨迹，不调用模型，不修改 Zotero、Obsidian 或 PDF。私人原文和逐请求日志仍在 `.local/`；本文件只记录长度与守卫结果。

脚本：`scripts/audit-motif-pdf-evidence.py`。它只使用工具调用先后顺序、已返回的唯一 `match_id`、PDF 版本哈希和精确引文匹配来计数。所谓“引文窗口”是引文前后各 250 个规范化字符的**假设上界**；它不是已经认证的输出视图，更不是可以供开放式科学判断直接使用的摘要。

| 既有独立任务轨迹 | PDF 结果原字节 | 已读批注能精确匹配的 PDF 页 / 所读页 | 唯一定位句柄驱动的读取 | 仅在“已选引文核查”子任务下可考虑省去的页文字字符 |
| --- | ---: | ---: | ---: | ---: |
| 论文影响卡 P1 | 46,409 | 2 / 8 | 0 | 0 |
| Agent serving 批注影响决定 | 87,523 | 2 / 14 | 0 | 0 |
| 批注影响 smoke | 33,656 | 1 / 6 | 1 | 5,456 |
| Boltz-2 AI4S 影响决定 | 54,921 | 2 / 13 | 1 | 3,445 |
| AIDD SAR 决定 | 86,228 | 0 / 14 | 1 | 5,523 |

前三项中的普通批注匹配只证明“这句话出现在该页”；它没有证明本页其他内容与研究决定无关。后三项有一次 `locate_pinned_pdf_quote → read_pinned_pdf_match` 的版本化句柄链，因此存在更明确的**引用核查子步骤**。但其页文字减少数仍只是离线窗口估计，未计元数据、恢复调用、模型使用方式、缓存计价或质量。

## 结果

1. 旧任务的 PDF 输出确实很大，但大多数页没有来自先前批注的准确锚点。这些页用于探索新证据时，不能靠 Motif 擅自裁剪。P1 和 Agent serving 两条轨迹的完整 PDF 页输出，当前均没有可认证的压缩边。
2. 已有的版本化定位句柄可为“核查一条已选引文”提供窄范围切片机会。脚本确认句柄先于读取产生，读取回传相同句柄及 PDF 版本，引文在该页唯一出现；缺一项就不计入。
3. **当前 SSS 在这五条旧轨迹上的已认证 PDF 压缩节省为 0 字节。**现有 `output_projections` 只认证了 Gmail HTML 视图；已认证的跨任务批注 Motif 是 Zotero `pin → read`，没有 PDF 页证据视图。用这几条旧轨迹重新试编译时，PDF 定位与读取之间夹有其他工具调用，且部分任务多次尝试定位，严格挖掘器没有认证出独立留出的 `locate → read_match` Motif。不能把离线匹配数冒充为 Motif 收益。

## 下一项可执行试验

冻结三个**独立研究决定**中的“已选批注原文是否在对应 PDF 页得到准确支持”子步骤：两项供轨迹编译，一项留出。研究者或模型先选择待核查的引文；Motif 只接管 `定位 → 唯一句柄读取 → 核验版本`。仅当编译器从轨迹证实参数流、输出视图可保留引文和必要限定语，并能精确恢复整页时，才开启 SSS 最近一轮 PDF 投影。开放式寻找新证据、没有唯一定位、PDF 抽取异常或版本变化时保留全文。

同题比较普通 Harness、Distil `context-only`、SSS 投影及简单引文定位脚本。统一 `reasoning_effort="off"`、工具范围、提示和预算，记录请求数、缓存命中与未命中输入 token、输出 token、恢复次数、总费用、耗时，并先盲评引用与科研判断。之前的 Distil 对照使用不同思考配置，不能与下一轮直接混比。

本轮验证：`python -m unittest tests.test_motif_pdf_evidence_audit -v`，覆盖未来批注不可回填、句柄/版本不匹配不可计入，2 项通过。
