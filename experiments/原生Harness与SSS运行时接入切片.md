# 原生 DeepSeek Harness 与 SSS 运行时接入切片

> 2026-09-25。此切片是机制接入，不是科研任务的质量或费用成绩。

## 已接通的链条

```text
专用 Harness Agent
  → agent 作用域工具限制及执行守卫
  → SSS MCP 入口
  → 已认证的只读 Motif 库／MotifController
  → hash_source → read_source，或 snapshot_sources → retrieve_point
  → 缺检索术语时返回有签名的 handoff
  → Harness 给出术语，SSS 核验并从同一 Motif 前沿恢复
  → 保存资料版本与证据；来源变化则拒绝旧证据
```

`src/adapters/dsh_sss_guard.mjs` 使用 Harness 的 `agent/created` 扩展点，在专用 Agent 的工具作用域只放行 SSS 的五个工具：资料收集、分段读取、增量刷新、打开逐项检索前沿、提交该前沿的语义术语；同步执行守卫会拒绝其他工具调用。结构执行发生在 `src/mcp/sss_runtime_server.py` 及已有 Motif 内核中，非提示词 Skill。资料目录和两份已认证 Motif 的路径由宿主在启动时固定，模型参数不能改动。一次收集的页证据与状态存于被忽略的 `.local/sss-runtime/<run_id>/evidence.json`；增量刷新沿用旧 Motif 状态，未变来源复用，修改来源重新读取。旧 run 的页读取在来源变化后被阻断。

`open_point` 先由已认证的 `snapshot_sources → retrieve_point` Motif 执行可确定的快照节点，在缺少 `terms` 时暂停，并将主控的重放检查点保存在私有运行目录，返回不暴露底层内容的 `frontier_id`。`resolve_point` 必须带回该 ID、原 handoff 签名和有限术语；SSS 在当前资料上重建主控、重放 Motif 并核对同一交接点后才恢复执行。无效签名、过期资料、损坏检查点或越界来源会停止。宿主插件还记录由 `open_point` 发出的 `frontier_id` 被下一次 `resolve_point` 使用的参数来源旁证；不能靠值相等猜测来源。Harness 决定的术语会由检索工具核对是否在限定来源中得到文本支持，不会自行授权写操作。这里的研究任务接口是场景适配层；可执行图仍来自独立轨迹认证的 Motif，而非手写场景 DAG。

2026-09-26 的参数流补充：`config/sss-runtime-tool-contracts.json` 明确了这五个原生 MCP 工具的只读契约。宿主现在逐字段旁证 `resolve_point` 的运行 ID、前沿 ID、研究点 ID、问题、来源范围与交接签名确实来自之前成功的 SSS 结果；术语仍是 Harness 的语义输入。轨迹适配器会核对原始工具结果与参数，包括完整来源列表的相等关系；缺任何必需旁证、改了列表或伪造字段时，这次调用不能进入有据的连续片段。该片段供分析，不直接等于可重放的 Motif。

2026-09-27 补上通用编译器对列表参数边的支持：仅对契约声明为集合参数的目标允许非空标量列表传递，执行时再次核对；未声明的列表仍不能成为自动绑定。两个训练轨迹和一个留出轨迹组成的稳定工具夹具，已验证列表从真实工具结果字段编译、认证并在新输入上执行。它验证编译机制，不计交付效果。

随后检查发现更根本的区别：旧实现的 `collect_sources` 和 `open_point` 每次生成新 ID，相同资料重放也得不到相同输出，导致外层 Motif 无法跨进程恢复。现已将 SSS 及结构化研究工具的本地句柄改为带本机密钥的内容绑定 ID：相同证据和参数得到同一不易猜测的 ID，来源或问题改变则得到新 ID；旧 ID 仍可读取，但每次使用均经过来源版本检查。密钥与句柄状态留在受保护的 `.local/`。契约解析器要求每个工具显式声明结果是否可稳定重放；不稳定的工具即使只读，也不得被编译为可执行 Motif。SSS 五个工具在当前实现下声明为稳定；该声明由无模型跨运行时重放回归覆盖，仍须在真实 DSH 轨迹和质量评测中验证。

同一链条的跨进程恢复回归暴露了一个检查点问题：单个 Motif 的隐式节点版本在导出后被当成调用者必须显式传回的版本，直接按当前来源快照恢复会误报过期。主控现在会从当前快照重建这组隐式版本；MCP 恢复入口不再把检查点里保存的版本原样冒充“当前版本”。测试覆盖恢复后填入术语完成执行，并确认来源版本变化、同版本下已执行节点的观察结果变化都会拒绝旧前沿。

已完成的 Motif 现在还可以通过主控导出独立的**证据快照**，供宿主保存在受保护的 `.local/`；新进程只在 Motif 库摘要、输入快照版本和当前来源核验都一致时恢复绑定过的成功工具结果。快照限制记录数和大小，拒绝错误结果、重复绑定及内容损坏。它是已执行结果缓存，与可执行 Motif 库和暂停时的语义交接检查点分开；普通 SHA-256 校验只防意外损坏，不防拥有本机写权限者重写快照。

专用 Harness 插件还观察成功的 SSS 工具结果：只有先前由 SSS 返回的 run handle 再作为同一 Agent 后续工具参数出现时，才记录 `callId → run_id 参数来源` 旁证，保存在 `.local/sss-runtime/provenance/`。未知 handle 不产生旁证。该记录只证明这一项参数的宿主来源，尚不能证明检索术语、来源选择或报告内容的参数依赖，也未经过实际付费 Agent 轨迹的编译验收。

保存的证据记录另有整体内容校验。刷新旧 run 前先核对记录，避免损坏的页文本或 Motif 状态被当作可复用证据；这项校验用于发现本地意外损坏，不构成对掌握本机文件写权限者的防篡改安全边界。

## 独立启动与验证

先生成本机补丁（可用 `--source-root` 和 `--motif` 指定已有资料目录和认证产物）：

```sh
.venv312/bin/python scripts/prepare-sss-runtime.py
```

只检查 Harness 合成配置时使用：

```sh
DSH_HOME="$PWD/.local/dsh-sss" node_modules/.bin/dsh --profile web --patch .local/sss-runtime/harness.patch.yml --dump-config
```

若要单独打开 SSS 试验界面，使用单独的 `DSH_HOME` 和端口，按该环境配置模型凭证：

```sh
DSH_HOME="$PWD/.local/dsh-sss" node_modules/.bin/dsh web --patch .local/sss-runtime/harness.patch.yml --port 8767 --no-open
```

这不会修改现有 8765 Harness 的启动补丁或重启其进程。专用 Agent 若真正发起 DeepSeek 模型请求，会产生费用；本轮仅检查了无模型启动与工具后端。来源目录当前支持最多 20 份 PDF、Markdown、文本文件，每份至多 10 MB。

## 本轮验证与剩余边界

- 135 项 Python 测试和 11 项 Node 测试通过。无模型测试覆盖认证 Motif 在新资料上的执行、页读取、路径限制、旧来源失效、无变化复用及修改后重读；还覆盖逐项检索的暂停、跨运行时实例恢复、有效术语、签名不符和来源失效拒绝。Node 测试覆盖工具限制及 run handle 参数来源记录。
- 生成的补丁在隔离的 Harness Home 中成功启动 Web 与 SSS MCP 服务；未创建付费模型会话，未验证模型实际按该工具边界完成研究交付。
- 经真实 MCP stdio 协议调用，服务列出了五个 SSS 工具，`collect_sources → open_point → resolve_point` 返回结构化结果；在本地 `reference/` 得到 4 个候选证据。该调用没有经过付费模型或原生 Agent 的决策循环。
- 对本地 `reference/` 的 3 份真实参考材料进行无模型读取，得到 45 个非空去重页、3 次 Motif 结构执行和 0 次模型请求；立即刷新时 3 份资料均复用，0 次重新读取。这是资料读取链的功能验证，不能外推为报告质量或成本收益。
- 2026-09-26 将上述随机检索前沿接到通用 Motif 重启检查点。用 MGGA 开发题的 4 份真实来源，`collect_sources → open_point → 新运行时 resolve_point` 读取 107 页并返回 4 条候选证据，模型请求为 0；损坏状态、过期来源和参数越界的无模型测试仍会阻断。该验证未经过付费原生 Agent 循环，不计报告效果成绩。
- 新增无模型轨迹契约回归：`collect_sources → open_point → resolve_point` 的模拟原始事件配上宿主旁证后形成连续只读片段；缺前沿 ID 旁证或伪造来源字段会断开。模拟独立轨迹可做编译和留出认证；实际 MCP 入口在跨进程重复调用时返回相同的内容绑定句柄，来源变化时生成新句柄并拒绝旧证据。另用稳定工具夹具检验集合参数边的编译与执行。这些都不是正式效果成绩。
- 用既有三项不同研究决定的**真实 DSH 工具轨迹**产生、且经第三项参数流留出验证的 `pin_source → inspect_records → aggregate_records` 三节点产物，在未参与该产物训练／留出的 DR3 来源目录上做无模型执行：首次实际调用 3 个工具，紧接着同版本同绑定重跑增加 0 次调用，得到 15 条记录的计数。诊断摘要在 `.local/sss-runtime/diagnostics/real-trace-motif-replay-dr3-20260927.json`，含来源与产物哈希；这只证明轨迹迁移、参数流和进程内局部复用能工作，未证明研究结论质量或实际费用优势。该产物仍未通过产品质量与总成本门槛，不会自动注册为正式 Motif。
- 在上述同一份 DR3 资料和三节点产物上，第一进程执行 3 次工具调用后把 3 条绑定证据保存在 `.local/sss-runtime/diagnostics/real-trace-evidence-snapshot-20260927.json`；第二个独立 Python 进程核对当前来源哈希并恢复证据，同参数任务完成且新增工具调用为 0。来源版本不符、快照内容改动及已执行节点观察变化的拒绝路径也有单元回归。这仍是无模型结构收益，未测端到端报告质量或完整费用。
- 目前资料读取和逐项检索两个结构片段由 Motif 内核接管，后者有一次真实的语义 handoff/reentry。原生 Harness 仍负责对话、什么时候开始一个研究点以及后续选证据和写报告；它们尚未处于同一个 SSS 可恢复主控状态机。下一步要把这些语义前沿和有条件写入纳入 SSS 主控，并将 Harness 的实际工具调用及各参数来源经过独立留出任务认证后再入可执行 Motif 库。
- 这条路径不能宣称比原生 Harness 更省 token、费用或人工；须在合格科研任务上同题验证。
