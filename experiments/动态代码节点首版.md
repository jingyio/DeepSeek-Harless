# Motif skill 动态代码节点：可执行首版

## 为什么这样做

模型在正常科研任务中可能发现一个可重复的纯计算变换，例如把来源中的页码标签、条目编号或状态字段转成下一次读取的参数。该变换不需要暴露为新的应用 MCP；MCP 仍负责访问应用。代码先是候选，不能因为在当前任务成功一次就自动接管未来任务。

## 候选到执行

Agent 可把候选 JSON 经标准输入交给 `scripts/propose-motif-code.py`；脚本只做静态语法检查，把带哈希的候选写到忽略版本控制的 `.local/motifs/code-candidates/`，不会运行或安装它。候选包含当前真实轨迹的 `trace_id`，只描述两个只读工具之间的缺口，不预写科研答案：

```json
{"trace_id":"trace-alpha","tools":["pin","read"],"from_tool":"pin","from_field":"raw_id","to_tool":"read","to_param":"doc_id","expression":"upper(strip(x))"}
```

`scripts/compile-dsh-motif-library.py` 的本地任务 manifest 通过 `code_candidate_files` 引用这些候选文件；也接受内联的 `code_candidates` 供开发测试。编译器先按原规则从不同研究决定的工具轨迹认证 Motif，再用至少两条训练任务和一条独立留出任务核查候选：提议轨迹属于训练集、来源字段存在、代码输出逐次等于下一工具实际参数、训练输入与结果不是常量，且该参数没有已认证的直接字段边。失败候选进入 `rejected`；成功候选成为 skill 内的 `code_nodes`，连同来源、目标、程序哈希、任务证据、`code_dag` 一起纳入 `certified_digest` 和 library digest。当前 DSH 轨迹没有专门的代码提议事件；记录文件的 `trace_id` 是提议者声明，尚不能独立证明提议确实发生在该轮执行中。

执行时，Motif 内核从已核验的来源输出取 `x`，在独立 Python 工作进程中解释受限表达式，给下一工具填参。DSH 在线适配器使用同一工作进程执行规则；若输入缺失、程序失败、版本不合或目标工具不可用，回退模型，不计为已验证的请求跳过。审计仅记录节点 ID 和程序哈希，不记录私人输入或输出。

## 代码边界

`src/motif_core/pure_code.py` 只解释无副作用的表达式；没有 `eval`、`exec`、导入、文件、网络、属性访问、循环或任意函数调用。允许有界的字符串规范化、简单数值运算、条件和正则捕获。输入与代码长度受限，工作进程有超时；结果目前必须是一个不超过 500 字符的字符串。代码不是通用 Python 沙箱。

本版支持任意符合契约、且在认证轨迹中相邻的**两个只读工具**之间，一个来源字段到一个必填参数的代码节点。若原任务把计算藏在中间的自由命令里，现有工具序列挖掘不会将两端自动拼起来。多输入、多输出、多节点、跨应用不同版本映射及模型提议事件的自动采集尚未实现，不能据此声称所有科研语义步骤都能转成代码。半结构化选择、科学解释及失败后的 handoff 仍由原 Motif 机制承担。

## 验证边界

无模型测试覆盖了训练／留出任务认证、恶意表达式拒绝、skill 篡改拒绝、Python 内核执行、导出后 JS 校验，以及 DSH 拦截时用代码结果发出工具调用并跳过测试替身的模型请求。尚未在真实付费科研任务中测得质量、实际模型请求数或总成本变化。
