# Distil `context-only`：跨应用批注决定对照（2026-09-27）

## 冻结条件

沿用 `agent-serving-impact-20260927` 的同一科研决定、批准的 PDF／Zotero 四条历史批注／Obsidian 状态、DeepSeek Flash 高推理档、每请求最多 8000 输出 token、只读 MCP 范围。历史批注在任务中作为“模拟新到资料”，不是新发生的真实事件。原生 Harness 是已完成的参照；Distil 固定为本机源码 `e836dc1540dd390823b26582ad137f73072d6871`，`context-only` 关闭输出塑形和 shadow，保留 Distil 的可恢复上下文摘要。私人原文、答案、逐请求账本在 `.local/benchmarks/research-weekly-loop/agent-serving-impact-20260927/` 和 `.local/distil-sss/`，不提交仓库。

两次 Distil 运行共使用预算代理估算约 $0.08392，低于用户批准的 $1 上限。费用依据上游 API 返回的 usage 和预算代理计价，**尚未与 DeepSeek 控制台账单核对**。耗时为端到端单次运行，不能从同题复跑推断统计显著性。

## 故障与修复边界

原版 Distil 把长工具输出变为带 `handle` 的摘要。模型需要细节时，有时在一轮里同时请求 `distil_expand` 和 Zotero／PDF 工具。Distil 的透明恢复循环为保留客户端工具调用，会把这种混合工具批次交回 DSH；DSH 原先没有注册同名恢复工具，返回“unknown tool”。原版答案最终把四条批注和 Obsidian 状态列为无法读取，因此不合格于本任务的信息闭环。

SSS 现增加 [DSH 恢复桥](../src/adapters/dsh_distil_expand_bridge.mjs)，仅在本诊断组加载：以 `distil_expand` 原名读取本次 Distil 私有加密存储，校验 8 位句柄，失败时报错并要求重读已批准来源。Distil 冻结源码未改；纯恢复批次仍由 Distil 自己处理，混合批次由 DSH 接住。无模型回归覆盖一次响应同时调用恢复与文件读取，验证两项结果都进入下一请求。修复组 4 次可见恢复调用成功，工具错误为 0；本机 Distil 信号日志记录 41 次成功句柄恢复、0 次缺失，信号数含内部反复恢复，不能当成 41 次独立模型请求。

修复组答案确实引用了四条 Zotero 批注、Obsidian 当前状态与 PDF 页码，形成待审决定；原生 Harness 也形成完整答案。两份答案尚未完成匿名人工盲评，不能宣称等质或合格。接线修复组是看到原版失败后做的同题诊断，**不是独立留出实验**；其额外工具 schema 与原生 Harness 也不同。

## 对 SSS 的含义

本任务中 Distil 缩短了 Harness 可见上下文，但恢复及其后续轮次增加了上游请求，按缓存命中计价后没有总成本优势。SSS 现有“最近一轮 Motif 字段投影”在这条任务轨迹的离线重放中裁剪了 0 字节：已认证参数链只要求短的 `source_id`，长 PDF／批注字段尚无安全的投影依据。两者都**不能**据此宣称对所有科研任务无用；当前证据只支持本题无收益。下一轮若继续试上下文方案，应先记录需要恢复的字段、把纯结构输出与语义证据分开，再在独立任务上比较合格交付的总费用、人工修订和耗时。

验证：`tests.test_distil_dsh` 六项无模型测试通过，修复组真实 DSH 端到端完成；没有修改 Zotero／Obsidian，也没有触发邮件或日历写入。
