# 应用内普通 Agent 首批实测（2026-09-29）

这轮针对真实应用内的已批准资料，而非跨应用合成资料。用户批准了 Zotero 与 Obsidian 两项只读普通 Agent 试跑；两题沿用已预览的 DeepSeek Flash、`reasoning_effort="off"`、每题最多 12 次请求及 US$0.50 费用闸门。原始提示、批准范围、逐请求账本、事件轨迹和答案只保存在 `.local/benchmarks/mcp-app-internal-v2/{zotero,obsidian}/`。运行前核对批准记录与预览哈希，运行中未写入应用。

| 应用内任务 | 自然调用链 | 模型请求 | MCP 调用／错误 | 未命中／命中输入 token | 输出 token | 端到端时间 | 逐请求用量估算费用 |
| --- | --- | ---: | ---: | ---: | ---: | ---: | ---: |
| Zotero：区分论文条目和 6 条批注的证据、疑问及限制 | 列出 7 个来源 → 逐项固定 → 读取条目和批注 | 4 | 15／0 | 7,104／12,928 | 2,585 | 13.843 s | US$0.00531076 |
| Obsidian：从两段批准笔记提取当前判断、收窄说法、缺证据及下一步 | 列出 2 个角色 → 逐项固定 → 读取批准行段 | 4 | 5／0 | 4,660／10,496 | 1,660 | 10.534 s | US$0.00345298 |

两题共 8 次模型请求、20 次只读 MCP 调用；费用闸门按每次 API 返回的缓存命中／未命中和输出用量累计估算 **US$0.00876374**。这是本地代理的用量计价估算，尚未与供应商账单核对。两题均观察到固定来源返回的 `source_id` 被后续读取使用，分别为 7/7 和 2/2；工具结果的 `isError` 均为 false。仅凭参数值相同不能认证其来源证明，现有自然轨迹尚无宿主提供的参数来源旁证。

随后用现有只读边审计器离线检查模型轮次；不增加模型请求。Zotero 的 `pin→read` 有 7 条安全观察边，Obsidian 的 `pin→批准摘录读取` 有 2 条。两题的第三轮都只执行这些读取，因此各有 **最多 1 个可尝试接管的完整模型轮次**；这只是上界，不能算实际跳过或节费。审计时发现 Obsidian 新增 `pin_scoped_note` 工具的合同漏登记，已补齐合同并加回归测试；补齐前审计错误报告该类为 0。两题仍属于同一 AIDD 决定，不满足跨任务认证，也没有进行 Motif 在线对照。

另用 `scripts/run-app-internal-script-baseline.py` 对**相同批准范围**执行简单脚本取证，仍通过真实 Zotero／Obsidian MCP 并逐次核对来源 ID 与版本：Zotero 15 次工具调用、0.387 秒；Obsidian 5 次、0.436 秒；两者均 0 次模型请求。它只覆盖“列出→固定→读取”的结构部分，**没有生成研究判断，不能拿其零模型费用与普通 Agent 完整交付直接比较**。但它说明这批短链条已有简单脚本实现；后续 Motif 若只接管相同固定链，必须证明跨不同任务的绑定、失效与恢复或合格交付成本优于脚本，而不是仅展示能执行读取。

人工初筛认为，两份答案都覆盖了预览要求的主要问题，且给出来源角色或行号。Zotero 答案把唯一一条带研究者评论的批注与纯标记分开，也说明正文未在授权范围内；但它把带上标引文的短句解释为对既有工作的转述，这一点仍须回正文核对。更关键的是，适配器返回六条批注的附件归属为 `unverified`，因为本次批准范围没有附件到论文的冻结关系。答案正确标注了这个**运行时证据缺口**。试跑后另做了一次本机 Zotero 只读元数据核查：该附件确实指向获批论文；此结果没有提供给试跑中的 Agent，也不能回填其答案或算作本轮工具链完成了归属核验。Obsidian 答案区分当前立场与未完成的对照，下一步提出文献核查；该文献是否存在、该行动是否最佳仍未验证。以上是非盲初筛，**不是交付合格判定**，也没有记录人工修订时间。

为后续任务准备了未批准的附件关系候选：只冻结附件的版本、内容哈希与父论文 ID，不暴露附件正文。用候选 scope 对同一六条批注做无模型只读复验，适配器均返回 `verified_attachment_to_paper`。候选 scope 明确标为 `candidate_for_review`，不会被本轮付费运行入口接受；未来若让模型使用这一新增关系，须另行冻结与批准，原始 Agent 轨迹保持不变。

这批只证明普通 Agent 已在两个真实应用中走通不同的只读工具链，并产生可供后续分析的自然轨迹。它们共用 AIDD 来源簇，属于开发例，不能充当相互独立的训练／留出任务；当前没有同题 Motif 组，不能报告请求、费用或质量增益。下一步先解决 Zotero 附件归属，再从不同真实研究决定获得轨迹和参数来源旁证，编译经独立任务认证的局部 Motif，随后做同题普通 Agent／Motif／简单脚本或缓存对照及盲评。本段记录的是首批 Zotero／Obsidian 完成时的状态；随后文献发现完成了普通 Agent 试跑，Gmail 的配对试验也已汇入[六类总判断](六类MCP应用内实测总判断_2026-09-29.md)。日历仍无真实排期需求。详情见[六门类只读试跑](六门类真实MCP应用内只读试跑_2026-09-28.md)与[首批预览](应用内普通Agent首批付费预览_2026-09-28.md)。

复现入口是 `scripts/run-app-internal-baseline.py`，两题各经 `scripts/run-distil-dsh.py` 的独立费用闸门启动。原始尝试有排他标记，不能覆写或作为同一首次试跑重跑；后续复跑须另建尝试并保留原始账本。
