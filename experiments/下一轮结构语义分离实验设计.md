# 下一轮实验：图执行是否有独立价值

> 2026-09-24。预注册式实施清单；不是当前实验结果。优先使用 `reference/` 三篇论文提出的机制与边界。

## 研究问题

本轮已经证明一个确定性迁移配方可在多处调用点复用，也证明证据筛选能缩短研究任务输入。但**普通 AST 脚本和普通检索脚本可能做到同样的事**。下一轮要检验图运行时额外提供的能力：跨步骤依赖验证、由守卫触发的局部语义调解、失败后的安全恢复，以及跨任务片段复用。若它们不改善每个合格任务的成本或人工负担，就不应把结构图当作产品核心卖点。

## 固定任务集

| 场景 | 任务单位 | 最低样本 | 成功定义 |
| --- | --- | ---: | --- |
| 代码迁移 | 固定提交的公开仓库、目标 Python 版本、变更要求、离线测试命令 | 3 个仓库；每仓库至少 2 类迁移点 | 目标版本可导入；相关离线测试通过；所有变更有来源与差异；原仓库无改动；人工盲评无功能退化 |
| Deep Research | 一个具体问题、固定来源集合与截止日期、需核对的答案点 | 5 个不同问题 | 引文可在原文定位；结论被证据支持；遗漏和错误由盲评记录；报告可复现 |

Requests v2.0.0 可用于迁移规则开发，但不能作为唯一的最终测试仓库；本轮看到的 `Callable` 错误已影响规则设计，应另留未参与开发的仓库作检验。论文三篇可用于研究流程开发，但最终题目应加入未见过的材料。

## 同题对照

每组固定模型、API 价格时段、版本、工具权限、任务文本、预算与测试命令。按同一质量门槛统计完整任务，不只比较单次调用：

1. 原生 DeepSeek Harness Agent：直接接任务和工具，由模型决定每步。
2. 提示词或 Skill：把流程写成指令，但没有运行时证据节点和守卫。
3. 普通脚本：使用相同 AST 变换或检索器、缓存和同一模型调解入口，不引入操作图。
4. 结构—语义运行时：已核验节点与参数流自动推进，缺口只送局部证据给模型，答案经守卫再进入图。

WorkBuddy 免费版只作可用性与现金支出参考：手工完成同题，记录是否完成、交互次数、耗时和可导出的结果。其免费额度与模型/token 用量不透明时，不把 Credits 直接换算成 API 成本。Codex 可作额外产品基线，但须区分订阅成本与 API 调用成本。

## 关键消融

- **关掉证据守卫**：保留同样节点和工具，观察误执行、坏补丁或错误引文是否增加。
- **每步都问模型**：保留相同工具与检索结果，关闭图的自动参数传递，量化重复结构决策的调用成本。
- **只用脚本**：保留相同规则与缓存，检验图对中途失败、歧义、测试回退及跨任务复用的额外作用。
- **扩大上下文**：保持模型和输出规则，比较局部缺口调解与传递完整历史的质量及费用。

不能因为只用脚本在确定性任务上同样高效，就删除该对照；它是判断论文机制是否带来独立收益的必要条件。

## 记录与判定

逐任务保存：固定输入与版本、工具轨迹、结构自动步骤数、语义请求数、回退与人工修正次数、输入/缓存/输出 token、实际 API 账单或按当日官方价格估算、墙钟时间、测试结果、盲评质量。把失败调用和重试计入任务成本；同时报告均值、中位数与失败分布。

每个方案先达到相同质量门槛，再比较每个合格任务的总费用和人工时间。若结构流程只是压缩上下文而不能优于普通脚本，就调整研究问题到图真正有用的多步不确定任务；若图在模糊点停得过于频繁，则优化证据和局部调解，而不是放宽守卫。

## 工程下一步

1. 当前迁移已把“来源与绑定核对 → 输出候选改动”做成逐调用点子图，也已验证失败后从安全候选中选择并重测。下一步将语法与局部测试检查纳入每个调用点，并扩展到混合导入、绑定歧义及更多 API 变化。模型只能选择或建议受约束的变更；所有修改仍需在复制仓库中重新通过语法、差异与测试守卫。
2. Deep Research 先解决已观察到的证据粒度问题：一个必答项可能需要同页两段分别支持不同条件，选页时要展示候选窗口末尾，并允许以经核验的多个窗口支撑同一项；任何跨项引用仍由运行时拒绝。再加入来源选择与网页检索，同时保留出处、时间和引文核验；把“结论是否被引文支持”加入人工盲评。AWM 已用于事后方法开发，不能再次充当新题成绩。
3. 做等工具、等缓存的普通脚本对照，再做原生 Harness/Skill 对照。先完成质量评审，再计算成本差异。
4. 连续收集可追溯的成功与失败轨迹后，按 G-Agent 的片段来源/支持度思想提取 motif；没有足够支持度的片段不得自动执行。
