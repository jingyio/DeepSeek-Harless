# 六类科研决定任务与在线 Motif 跨类型试跑（2026-09-28）

## 任务与边界

新增 `research_decision_portfolio_v2` 三类九题，与已冻结的 v1 三类九题合计**六类、十八项独立决定**。新类型是 Quarto 图卡／附录归档来源核查、复现结项条件、有限资源下的下一实验选择；每类三题，独立的任务文本、来源对象和隐藏评审标准见各版本 `cases/` 和 `fixtures.lock.json`。任务通过隔离的只读 MCP 返回合成 Zotero、Obsidian、WPS、GitHub、Quarto、Gmail、日历及论文摘录对象。它们检验工具参数流与语义交接，**不是实际课题组资料或真实应用连接成绩**。

原型只使用 v1 的 `l_state_update`、`r_label_policy` 两条普通 Harness 轨迹训练，并用 `c_protocol_conflict` 的独立轨迹认证。编译得到四个已认证只读参数边：事件对象 ID→固定来源、固定来源 ID→读取、已读对象第 0／1 条关联 ID→固定来源。在线 Motif 的相似度阈值 0.3、差距阈值 0.1 在 v2 试跑前固定；v2 九题均未用于编译或调阈值。v1 六项对照是在看过普通组答案后选择的，存在选择偏倚；v2 九项按整个新版本全部纳入，作为更有价值的留出结果。

两组都使用 DeepSeek Flash、`reasoning_effort="off"`、同题提示和八个只读 MCP 工具；每次运行最多 15 个模型请求、每题 1 美元费用闸。Motif 组仅在工具结果参数来源、对象版本、工具 schema 和相似度守卫均通过时，在模型请求前合成下一批只读工具调用。科学解释、试验设计和待审文字仍由模型生成。失败的本地 embedding 预检不会进入付费调用；一次本机服务退出导致三项 Motif 预检中止，重启后按已冻结输入原样完成，未产生这些中止尝试的 API 请求。

## 请求与费用账本

| 任务集 | 已配对题数 | 普通请求 | Motif 请求 | 经验证的接管轮次 | 普通估费 | Motif 估费 |
| --- | ---: | ---: | ---: | ---: | ---: | ---: |
| v1 六题 | 6 | 55 | 29 | 30 | $0.024752 | $0.018883 |
| v2 九题 | 9 | 74 | 45 | 50 | $0.034714 | $0.027150 |
| 合计 | 15 | **129** | **74** | **80** | **$0.059466** | **$0.046033** |

合计实际模型请求少 55 次（42.6%），按本机费用闸的逐请求 API usage 和缓存命中计价，估费少约 22.6%。80 个已验证接管轮次**不能直接当成**净减少 80 次：两组后续路线和请求安排不同。累计缓存命中输入 token 从 379,520 到 206,592，未命中输入从 73,671 到 74,711，输出从 29,240 到 18,650；这些数字表明节省主要落在重复的已缓存上下文和输出，费用降幅小于请求降幅。两组逐题运行用时之和分别为 197.2 秒和 143.6 秒，不包含开发、服务启动与人工审阅。估费尚未与 DeepSeek 控制台账单核对，不能称为已核实的实际账单。

v2 按新任务类型拆分：归档来源链 26→16 次请求，复现结项 23→13 次，实验选择 25→16 次。所有九题均至少有一次版本核验后的完整请求接管，在线审计未记到接管结果未验证。原始请求账本、工具轨迹、冻结预览和审计保存在 `.local/benchmarks/research-portfolio-v2/` 与 `.local/benchmarks/research-portfolio-v2-transfer/`，不提交到 Git。

## 质量判断与后续核查

十五题的匿名答案核查已完成，结果与局限见[质量门槛评测](科研决定组合质量门槛评测_2026-09-28.md)。该核查由项目 Agent 完成，尚非独立研究者盲评；下列开发时记录保留为试跑诊断。

上述是**机制与成本的开发试跑**，不是“合格科研交付成本下降”的结论。独立盲评尚未完成，人工修订时间也未记录。已生成 v1 六题与 v2 九题的 A/B 隐名答案包，分别放在 `.local/benchmarks/research-portfolio-blind-v1/` 和 `.local/benchmarks/research-portfolio-blind-v2/`；评审应先按每题 `rubric.json` 的必要点、重大错误和数字核对判断合格，再解封 arm 身份。

开发者非盲检查已经发现具体问题：v1 的 `r_hardware_mix` Motif 答案虽然算出各设备均下降，却没有给出隐藏标准要求的旧等权 60.5% 与新 4:1 加权 70.3%；v2 的 `e_state_vs_retrieval` Motif 答案把两个种子的方向写成“不一致”，与原始行不符；`p_dataset_shift` 有一处对数据口径作用的归因偏强。这些题不能仅因为工具链通过校验而判为科研答案合格。若盲评确认质量下降，须按合格交付成本重新计算；不应先报告 22.6% 为有效产品收益。

曾开发一个穷尽读取所有授权对象的通用脚本作为诊断，但用户指出其开发与维护费用未计，且日常 Agent 并不天然拥有该程序。该脚本初版还把新旧表比较方向反了，诊断结果**不列为主对照**；后续若比较，应单独计入脚本编写、修改、适配新任务的成本。主对照保留普通 DeepSeek Harness 与相同工具下的 Motif。

## 下一道证据门槛

1. 对十五项已配对答案做独立盲评，记录每项是否合格、重大错误与修订分钟数；给出仅合格任务的请求、费用和时间。
2. 为六类任务各找至少一项真实研究者问题和真实来源，只读执行。特别核查论文发现、Zotero 批注、Obsidian 状态、实际表格复算与 Quarto 交付在决策中是否都有用；模拟的邮件或日历不得算真实沟通闭环。
3. 冻结后续任务和模型／工具设置，前瞻记录至少一种无关变更可安全沿用、至少一种新反证或口径变更必须中断的增量轮次；比较独立任务的局部参数边，而非整条预写流程。
