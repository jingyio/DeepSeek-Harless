# AIDD SAR-Diff 真实 MCP 任务试跑诊断

2026-09-28。任务设计见[任务卡](../benchmarks/research_weekly_loop_v1/aidd_sar_baseline_decision.md)。这是 AIDD 已开发项目的同一来源簇；两组各一次独立 DeepSeek Flash 会话，不是跨任务留出或盲评成绩。原始提示、限定来源、事件流、分析脚本、Quarto 草稿和费用代理账本保存在 `.local/benchmarks/research-weekly-loop/aidd-sar-baseline-decision-20260928/`，不提交私人内容。研究者尚未审核交付。

## 同题配置与结果

两组都显式设置 `reasoning_effort="off"`，使用同一任务文本、7 个限定本地／Obsidian 来源、1 个 Zotero 条目、17 个真实公开 CSV，以及相同的文献发现、限定读取和本地分析／Quarto MCP。原生命令与文件工具均禁用，因此这是**MCP 工具条件**，不能代表保留命令工具的自由 Harness 基线。来源字节和 Zotero 条目版本在启动前核验。每组有独立的私有 Python 工作区和 US$2 本机费用闸门；Agent 只读外部应用，没有发送或建会。

| SSS 在线 Motif | 34 | 55 | 61,536 | 1,563,904 | 29,948 | 148.7 秒 | US$0.063782 |

两组所有 API 响应均为 HTTP 200，思考 token 均为 0。费用列是本地代理按逐请求 usage 计算的观测估值，**尚未与 DeepSeek 控制台账单对齐**；它不包括人工修订成本。SSS 插件加载且会话匹配，但 `motif_bypass_attempts=0`、`model_requests_skipped_verified=0`。因此两组请求差 **31 次不能归因于 Motif**；单次会话的工具选择与 PDF 阅读路线不同。普通组 25 次 PDF 引文定位、19 次 Python 运行；SSS 组分别为 4 次和 14 次。两组都生成了可打开的 Quarto HTML 草稿；普通组的第一次渲染失败后重试成功，SSS 组也有一次渲染失败。失败调用及重试已计入。

隔离审计发现普通组用 Python 列目录时看到了评审文件的**文件名**，但没有调用读取该文件的工具，也没有在轨迹中出现评审正文。严格盲评条件仍因此受到污染；本次只作开发诊断。评审文件现移到 `.local/sealed/`，Python 沙箱加入读取拒绝；无模型验证确认封存文件不可读而公开数据仍可读。后续执行包还需用独立工作区预检，防止其他目录名或旧报告进入 Agent 视野。

## 交付质量的初审

两组都正确复算出：这个公开训练 CSV 为 85,998 行；16 个 SAR-Diff 标签文件共 154 行，其中 29 行、28 个不同原始 SMILES 字符串出现在该 CSV。该核对是**单个训练文件上的字面配体交集**。

两组随后都把 `85,998 / 8.6M ≈ 1%` 推成“训练全集的 1% 抽样”，并把所算配体重合比例称为真实污染率的下界。行数比值不能证明抽样关系；文件是否为抽样、分片或不同处理阶段仍需查原始数据说明。普通组进一步用配体字符串重合质疑论文“排除了重合蛋白–配体复合物对”的声明；SSS 组把两个配体在训练行共现称为该声明的直接反例。然而当前 CSV 缺少可核验的靶标／复合物对应关系，**配体重合或配体对共现都不能直接推翻蛋白–配体复合物对排除规则**。SSS 组还将近似标签值解释为“同一 ChEMBL 测量经 BindingDB 传播”，缺少来源链验证。两组自行设定的 1%／5% 决策阈值也未预注册或论证。

这些是影响最终研究决定的证据边界错误，故本轮暂不记为合格交付；仍需研究者审阅其他科学判断。Quarto 成功渲染、工具调用数和字节数不能替代质量门。

## 机制诊断与下一步

本次使用的已认证在线库来自早先不同项目的 Zotero 调用轨迹，只有“固定已批准 Zotero 条目 → 读取同版条目”等窄片段，没有对 17 个 CSV 的复算、PDF 选证据或 Quarto 渲染的已认证 Motif。离线重放本题 SSS 轨迹证明：Zotero 固定结果之后，参数边和当前版本足以形成一个结构候选；但当时的本地 embedding 相似度约为 **0.476**，低于冻结的 **0.8** 门槛，因此在线运行时没有接管。额外的 1 请求与 3 请求有界诊断确认插件的 `llm/stream` 钩子收到真实 DSH 请求；这 4 次诊断请求不计入上表，费用代理观测估值合计约 US$0.003876。它们只定位门槛原因，没有形成新的效果成绩。

本题揭示两个不同缺口：其一，匹配器把一整段长科研意图与“读取 Zotero 元数据”的短描述直接比较，容易漏掉已经可验证的局部参数依赖；阈值应在**其他任务**上校准，不能看到本题后降至 0.45 并称留出成功。其二，交付质量守卫没有阻止“行数恰好 1% → 抽样”和“配体重合 → 复合物对泄漏”这类跨单位推断。下一轮须先修复证据单位和判断交接，再在独立研究决定上检验安全的完整请求跳过。若只在本题降低阈值，最多是开发诊断，不是 Motif 的真实收益。
