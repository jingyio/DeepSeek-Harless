# 缓存感知的结构执行与多 MCP 科研任务

> 2026-09-27 方法修订。这里确定下一轮实验的默认策略与可证伪条件；不把历史试跑当成已证明的 Motif 收益，不启动新的付费模型请求。

## 为什么修改

同题 TauBench 资料核查的普通 DSH 路线用了 317,041 token，其中缓存命中输入 289,920、未命中输入 19,132、输出 7,989；按当时价格估算分别收费约 US$0.000870、US$0.002870、US$0.004793。SSS 路线虽只用 18,971 token，仍未交出合格终稿，简单聚合路线在该题更强。完整账本见本机 `.local/benchmarks/research-weekly-loop/taubench-table-20260927/TOKEN_BREAKDOWN.md`。这说明总 token 减少不是合格交付成本的替代指标，也不能由缓存命中总量反推其中任何片段都不重要。

DeepSeek 只保证对满足其条件的**相同前缀**复用缓存；不能假设删去中间一段后，后面的历史仍以不连续 KV 片段命中。服务端缓存能否命中、命中多少，以实际 API usage 为准。MotifAgent 的核心价值候选因此是**验证过的结构步骤少用整轮模型调用，并在增量事件后正确复用或失效**；短上下文仅是可选择的实现策略和独立对照。

## 正式路径默认策略

1. 同一任务会话保持初始指令、工具 schema 的集合与顺序稳定；来源变化、工具结果和研究决定尽量追加带版本的记录。来源原文、页码与权限保留在可按 ID 找回的工具侧，模型仅在需要证据判断时读取。追加内容本身仍可能花钱，不能预设每轮全命中。
2. Motif 按真实轨迹编译出的参数流和守卫执行读取、版本核验、确定性统计与可恢复节点；只有当一轮的必要语义判断确实已被验证的结构操作覆盖，才跳过该模型请求。来源未变不等于没有新反证。跳过须记录原本的判断点、依赖签名、实际工具结果和错误跳过审计。
3. 有歧义时交出有界的语义问题，附可定位的证据和找回入口。**新建**语义请求可以只带当前候选，但不得把它与在同一 DSH 会话中反复改写旧消息混为一谈；两者对前缀缓存的影响不同。论文含义、冲突、下一步实验与正文仍由模型／人判断。
4. 优先减少失败重试、无用的模型输出和整轮请求。输出变短不能删去必答条件、引文或必要的反证；模板化字段和确定性计算可以由运行时填充，须验证报告质量。`MotifContextManager.build_context_for_llm` 当前只是保留的摘要接口，未作为正式 DSH 会话压缩入口；启用前需经过下述同题门槛。
5. 只有接近实际模型窗口、过长证据确实妨碍判断，或同题试验显示**合格总成本**更低时，才启用摘要、删除旧工具结果或动态换工具集合。需要保存原文句柄、可恢复性和来源签名；一旦找回或守卫失败，停止复用。原生 DSH 的高压力保护可保留；AIDD 的 5% 提前压缩配置只属于独立的对照组，不进入正式默认路径。

## 每项成本取舍怎样判定

同题固定任务快照、事件切点、模型路由、权限、评分和预算；逐**实际请求**记录命中输入 `H`、未命中输入 `M`、输出 `O`，以及模型 ID、工具 schema 版本／顺序、摘要或重试标记。按该次实际价格计算 `C_API = p_hit × H + p_miss × M + p_out × O + 摘要/重试请求费`；加本地计算、人工修订与部署开销，报告端到端时间。费用代理的保守预留和供应商实际扣费另列，不把预留当账单。若跨阶段变更工具集合，还要标出变更点前后命中率与质量。

主比较是每份**达到预登记质量门**的交付成本与研究者时间。不合格路线报告全部耗费和错误，但不进入节省率分母。先并排看普通 DSH、相同工具的静态预选、简单脚本／缓存、`research-workflow + 同一模型` 与 SSS Motif；再以同一结构只改变上下文策略做消融。若 Motif 只降低可见 token、没有少发请求或改善合格成本，就缩小主张；若静态预选或缓存已经同样好，不能把其收益归 Motif。

## 多 MCP 任务从哪里来

继续使用[研究 Idea 演进与证据闭环任务协议](../benchmarks/research_weekly_loop_v1/README.md)和[三题候选册](../benchmarks/research_weekly_loop_v1/task_family_candidates.md)，而非再造一个便于刷工具数的图表核查题。实际研究决定的旧状态留在 Obsidian，文献及批注留在 Zotero，新增论文经文献发现工具定位；相关原始数字由 Python 核查，Quarto 产出可审阅决定材料。只有真实协作者线程和讨论需求存在时才用 Gmail／日历。执行包给范围和目标，不预写检索词、固定工具顺序或未来事件。

| 候选决定 | 当前定位 | 下一步可收集的可复用轨迹 |
| --- | --- | --- |
| Model RSI：内部可更新能力状态的最小反证实验 | 已有真实笔记与一次多 MCP 开发试跑；科研质量未验收 | 圈定旧笔记、条目／批注和相邻论文；得到来源身份→版本→证据读取→有界比较的参数链 |
| AIDD：首个应用和泛化划分 | 已有 scoped MCP 轨迹及 `pin → read` 参数边；仍是一个独立决定，增量事件不算第二题 | 核查已有论文批注与公开原始数据，复算 split／分母，再看真实增量怎样打断旧判断 |
| SSS：下一项区分 Motif 与简单优化的实验 | D-03 方法开发诊断，不计入同类任务的第三题 | 可调试轨迹记录与质量门；不得用本地 Figure 7 核查代替跨应用留出 |
| 第三个独立科研决定 | 尚未选定或冻结 | 从真实研究项目圈定应用来源与决定，编译 Motif 前封存为留出 |

每个任务类型至少需三个**独立**研究决定：两个开发候选片段，第三个在编译前封存；同一 AIDD 的多轮压缩与增量仍只算一题。当前候选册不是三个已冻结、可评分的完整实例。邮件、日历、原始数值、研究者期限和读者缺失时标为局部实例，不伪造完整闭环。私人资料只留 `.local/`；真实发送与建会只执行一次且经研究者审核。

## 下一轮的实际顺序

1. 先用无模型健康检查确认文献发现、Zotero、Obsidian、Python／Quarto 及本题适用的邮件／日历连接；冻结各题的来源 ID／版本／权限和 Agent 可见包、隐藏评审包。健康检查不计 Agent 自主工具轨迹。先复核 AIDD 既有交付质量，再选择与 SSS 方法开发无关的第三个真实决定；未凑齐独立任务前只做开发诊断，不报告跨任务 Motif 增益。
2. 先跑真实来源仍在应用内的普通 DSH，允许它自由选择 MCP、原生命令或停止；记录工具 `可用→暴露→调用→成功→被研究决定使用`。另跑静态相关连接器预选作为工具发现基线。不能把禁止命令的受限 profile 与自由原生 DSH 混报，Python 的 CLI 与 MCP 等价操作需注明。
3. 从两个**不同且合格**的开发任务中审计调用结果怎样成为下一调用参数，只编译能重绑、能验守卫、能安全停止的局部子图；第三题留出执行。新批注／论文版本出现后检验正确沿用和正确打断。
4. 最后比较质量、缓存计价后的每请求费用、输出 token、整轮跳过、人工修订和耗时。提前压缩、步骤级工具动态暴露各自作为独立消融；只有在质量与总成本都过门时进入默认路径。

这里的 MCP 设计解决的是**结构化参数流可观察性和真实应用资料可达性**。它本身不会保证 Agent 选对工具、科学判断正确或 Motif 优于缓存；这些必须由真实轨迹和留出任务证明。
