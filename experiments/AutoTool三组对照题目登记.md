# AutoTool 方法问题：三组对照登记

> 2026-09-24。在本题任何模型调用之前固定。此题材料属于开发阶段已见的 `reference/`，但问题尚未用于优化三组提示；不算未见材料盲评。

## 任务

只依据 `reference/AutoTool.pdf`，回答：**AutoTool 的 Tool Inertia Graph 如何从执行轨迹保存工具顺序与参数流？运行时在什么条件下可跳过 LLM，参数来源按什么顺序尝试；失败或置信度不足时如何回退并更新图？** 每个机制给出 PDF 页码；没有原文依据时标注不确定。

人工核对六点：

1. TIG 的 ToolNode/ParamGraph、ParamEdge、ToolPath 分工，以及从轨迹积累频次/参数流。
2. 近期工具序列、inertia window 与 CIPS 阈值如何筛选下一工具。
3. 参数填充的优先级：依赖边回溯、环境/上下文、历史值等，以原文/算法为准。
4. 只有工具选择与参数填充都成功，才不调用 LLM 直接执行；任何一环失败回退。
5. 执行反馈如何增减序列边权重；失败路径/负频次如何记录（若相应段落有证据）。
6. 与本文结构—语义分离的关系只作推论，须区分 AutoTool 原文结论与我们的设计启发，不能把代码实现未完成的能力说成已有。

## 固定路径和比较边界

- **原生 Harness Agent**：`deepseek-flash`、推理关闭；任务工作目录中仅复制该 PDF，不使用本项目研究脚本；可使用 Harness 自带本地工具，禁网页工具。最多 1,800 输出 token/模型响应；完整工具轨迹、请求、token、时间、失败按原始运行记录。工作目录副本不是操作系统只读沙箱，本地工具可访问其他路径，后续须审计实际工具轨迹。任务若需要人工许可或在有界时间内无法完成，照实记为未完成。
- **普通检索脚本**：同一 PDF，人工词固定为 `Tool Inertia Graph,ToolNode,ParamGraph,ParamEdge,ToolPath,CIPS,inertia window,parameter filling,execution feedback,fallback`，按现有一次综合流程运行，不因结果重排词或证据。
- **多步结构流程**：同一 PDF，现有规划、选页、综合三步，不附事后证据契约。结果须经来源页与短引文校验；人工再核对是否回答六点。
- 同题只运行每组一次；模型/调用上限、输出格式和工具自由度不完全相同，因此此轮是诊断性比较，不能推出严格因果或统计优势。分别报告“合格答案的完整任务成本”、工具请求与人工修正；不把免费订阅额度等同 API 账单。
