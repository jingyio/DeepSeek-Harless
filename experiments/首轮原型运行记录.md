# 首轮结构运行时原型记录

> 2026-09-24。此记录验证可执行边界与保守回退，不用于宣称节省比例或产品质量。

## 已实现

- `src/graph/runtime.py`：操作 DAG、显式依赖、输入证据、守卫、结构事件与类型化语义缺口。节点只有在所需证据已核验时运行；错误或缺口会停下，不转成猜测。
- `src/workflows/migration.py`：Python 3.10 的旧式 `collections.Mapping`、`MutableMapping`、`MutableSet`、`MutableSequence`、`Callable` 迁移。已核验的单项导入、全部为目标 ABC 的同一行导入和属性绑定由结构层批量处理；ABC 与非 ABC 的混合导入及绑定歧义留给语义层。可用 `--include` 指定扫描范围。扫描、解析、生成差异、语法检查、歧义审查均由结构层执行；每个候选改动再通过“来源与绑定核对 → 输出改动”的子图，保存逐点轨迹。验证 motif 在复制的仓库中应用补丁、运行测试，并以测试结果守卫后续步骤。不改用户原仓库。子图目前使用人工制定的规则，尚未自动挖掘 motif。
- `src/workflows/research.py`：针对本地 PDF/文本，执行来源提取、页去重、按给定关键词筛选、来源页码与片段核验；结论综合留给语义层。

## 本机验证

`npm run test:structure`：23 项通过，覆盖未核验证据不得执行、非法依赖拒绝、代码安全导入、多点属性绑定复用、子图拒绝未核验绑定、重名绑定停机、同一行多处改动停机、ABC 与非 ABC 混合导入歧义停机、全部 ABC 的同一行改写、扫描范围排除其他文件、复制仓库测试通过/失败守卫、失败后的候选选择与重测、不相关失败无候选、原生值迁移形态识别及重复执行停机、研究证据核验后进入语义边界、分步研究证据复用与选页编号边界、必需原文锚点进入最终摘录或停机、同一页多段摘录及跨段引文拒绝、必答点无结论引文时停止、检索词落地、逐字引文校验和 PDF 抽取空格缺失。

使用公开仓库 [Robpol86/colorclass v2.2.0](https://github.com/Robpol86/colorclass/tree/v2.2.0) 的固定提交 `c7ed6d78b16160fe88a966da9d464674beb7152d` 做代码样例：预览发现 `colorclass/codes.py` 一处旧导入，生成一处替换，0 处歧义。Python 3.12 下，未修改的源码导入时报 `ImportError`；复制仓库并应用预览补丁后，基本调用成功，安装该旧项目测试所需的 `docopt` 后完整测试为 **139 passed、7 skipped**。随后用 `npm run migration:verify` 完整执行“预览 → 复制 → 应用 → 测试 → 守卫”，同样得到 **139 passed、7 skipped**，原仓库 Git 状态保持干净。这里的隔离是目录复制，不是安全容器。这证明该窄迁移样例有效，但只有一个调用点，不构成重复结构收益证据。Python 官方说明 3.10 移除了 `collections` 中已弃用的 ABC 别名；该项目的相关兼容性问题亦见 [oletools issue #709](https://github.com/decalage2/oletools/issues/709)。

使用公开仓库 [Requests v2.0.0](https://github.com/psf/requests/tree/v2.0.0) 固定提交 `4401620111bee0a7319bf1cb4bd0852f7c854bf6` 做多点样例：原版在 Python 3.12 下因 `MutableMapping` 旧导入无法加载。扩展后的 motif 在 **6 个文件生成 12 个改动**，覆盖 2 个直接导入、6 个显式模块属性引用，以及 4 个模块绑定改动；12 个改动点均留下两节点子图轨迹，0 个歧义。复制仓库中的旧测试按离线可执行范围筛选，得到 **19 passed、65 deselected**；原仓库 Git 状态干净。首次只支持 `Mapping`、`MutableMapping` 的版本通过了导入，但全套测试出现 `collections.Callable` 错误，测试守卫正确停下；据此把 `Callable` 加入同一规则。全套旧测试还依赖联网，且有 `assertEquals` 与 Python 3.12 不兼容，故目前不能宣称整个 Requests v2.0.0 已完成迁移。运行证据在 `.local/migration-verifications/20260924T121835Z-1303ee/`。

测试失败调解样例：固定小型 Python 3.12 任务使用 `from collections import Sequence`。初次自动规则无改动，测试因 `ImportError` 停在 `tests_failed`；结构层识别唯一安全候选，真实 DeepSeek 调用返回 `C1`，结构层仅把该导入改为 `collections.abc` 并在第二份复制仓库中重测，**1 test passed**，原文件保持原样。调用耗时 3.36 秒、输入 751 token、输出 112 token、缓存读取 0 token；未计入测试与复制时间。原始日志在 `.local/migration-mediations/20260924T122516Z-653f61/`。这一样例证明了有界调解的端到端路径，不证明模型选择比程序规则或人工选择更省；通用代码迁移仍未完成。

对 `reference/` 三篇 PDF 的有界问题试跑：结构层提供 12 条带文件名、PDF 页码及来源哈希的已核验证据；专用 DeepSeek Harness SDK 配置禁用模型工具，在 `semantic_synthesis` 缺口发送最多 8 条证据。关闭模型推理后，单次语义调用生成回答。逐字引文校验会剔除与抽取原文不匹配的结论，保留校验后的报告。关键词检索结果仍混入图注、附录和弱相关片段，后续要加证据质量筛选。

同一问题的结构流程与全文模型对照见[首轮同题成本对照](首轮同题成本对照.md)。第一次语义接入曾因输出预算被内部推理耗尽而返回空回答；全文对照第一次因输出截断失败；引文校验器也曾有缩进错误。三种失败均已保留在本机日志并在文档中标注，不计为成功实验。

新增的多步研究流程把规划、逐子问题检索、来源限定、候选页选择、最终综合分开；中间结果保存在证据账本中。与同题普通检索脚本和全文模型的结果见[多步研究同题对照](多步研究同题对照.md)。此题上普通脚本更便宜，图方法的成本增益尚未成立。

第三个公开仓库 Jinja2 2.10.1 的核心包预览得到 5 处差异；另一次预先登记的研究题上，多步流程费用仍高于普通脚本且答案未完整覆盖关键条件。完整结果、事后排除旧测试的说明及六项人工核对见[留出任务结果](留出任务结果.md)。

针对留出题暴露的摘录截断，新增可选的必需证据守卫 motif：来源、页码与原文锚点先核验，模型选页后将必需短语重新定位到最终有界摘录，缺失即停机。复用保存的规划与选页、**不调用模型**进行离线回放，两个事后指定的关键条件都进入综合提示，见 `.local/deep-research-runs/20260924T132119Z-d2e49f/`。再复用同一规划/选页做一次付费综合，G-Agent 准入条件进入答案，但 ATC 正向验证仍缺；该次另耗 1 次请求、1,906 非缓存输入、256 缓存读取、636 输出 token，见 `.local/deep-research-runs/20260924T132236Z-5ce7bd/`。随后新增答案覆盖守卫，对这份已保存答案离线回放，正确标记 `ATC-positive-validation` 为 `missing_claim_quote`，不再把有 4 条结论的回答直接算作完成。这些都是事后诊断，不是新一轮质量/费用对照；契约由已知答案制定，不能作为留出题的预注册设置。

答案覆盖守卫接入 CLI 后再次进行单次付费综合，见 `.local/deep-research-runs/20260924T132534Z-6ad416/`：1 次请求、242 非缓存输入、1,920 缓存读取、671 输出 token；两项**示例契约**锚点均出现在已核验结论引文中，程序状态为 `answered`。但原留出题有六个评议点，示例契约只规定两个；人工检查仍看到 ATC 正向 motif 的成功轨迹来源、G-Agent 的失败轨迹入库以及两者更新时机等细节未充分回答。该状态只证明两项指定引文覆盖，不能当作整题合格。

为覆盖六项评议口径中可直接在原文定位的要点，新增七锚点**事后诊断**契约。结构层能在同一页组合多个不相邻的连续原文片段，并逐段核验模型引文。复用已保存规划与选页的预览记录 `.local/deep-research-runs/20260924T133300Z-5556fe/` 验证七锚点均进入最终提示。随后只做一次综合，见 `.local/deep-research-runs/20260924T133321Z-869bcf/`：1 次请求、2,003 非缓存输入、0 缓存读取、760 输出 token，8 条结论、7/7 锚点有结论引文、0 条自动引文拒绝。人工检查仍发现 G-Agent 闭合性及可执行条件的定义、失败轨迹处理的直接比较不完整；这是诊断结果，不是同题基线公平对照，也不证明完整题目已合格。

第二类代码迁移针对旧版 Jinja2 `native_concat` 的 Python 3.12 单值 `Undefined` 返回错误。固定源码形态及目标测试后，结构层生成一处非文本单值直返的候选改动；前后均在新复制仓库运行同一测试。基线 **1 failed、534 passed、3 skipped、1 deselected**，改动后 **535 passed、3 skipped、1 deselected**，原始 Jinja2 Git 状态干净；0 次模型调用、0 模型 token。报告 `.local/native-value-runs/20260924T134055Z-baf8d3/`，范围与事前修订见[任务登记](Jinja原生值迁移任务登记.md)。这是精确结构配方的有效性证据，但普通脚本执行同一配方也可零模型成本；图的独立收益仍需失败恢复或跨任务复用对照。

复核运行 `.local/native-value-runs/20260924T134403Z-e5440b/` 额外保存复制仓库路径，并在修复后的复制仓库跑完整旧测试：**535 passed、3 skipped、1 failed**。唯一失败是预先排除的 Python 3.12 traceback 格式预期，没有把局部通过误报为全套迁移成功。

为不依赖事后知道原文页码，新增题目义务清单 motif：运行前验证 1–8 个必答项，综合结论必须指向一项并附可回查引文，结尾由结构守卫逐项检查。用 G-Agent 检索、组合、回退与在线记忆题做单次对照，见[事前登记](G-Agent检索复用任务登记.md)和[结果](G-Agent检索复用守卫结果.md)。守卫发现引文无效并剔除 2 条结论，但仍将含多个条件的必答项误判为有覆盖；人工检查两组都未答全，结构流程更贵。因此程序状态已从暗示质量通过的 `question_covered` 改为仅表示关联存在的 `point_links_present`。这一误报及人工清单成本必须在下一轮继续处理。

随后将模型显式承认的逐项不确定也接入守卫；同一项即使有部分结论，只要声明关键条件仍缺，状态为 `incomplete_answer`。用六个原子条件做 [AutoTool 安全边界诊断](AutoTool安全边界守卫结果.md)：3 次请求、5,500 未缓存输入、128 缓存输入、1,150 输出 token；6 项中 3 项因所选摘录截断而缺失，程序与人工均未将本题判为完成。此项来源已见，仅验证缺口检测，不提供节省比例证据。

新增从保存的未完成报告启动的 [局部修复流程](AutoTool局部修复诊断.md)。第一次付费修复仍失败，定位并修正“检索 900 字符、综合再裁为 750 字符”的窗口错位；第二次修复确实把三项相关原文送入提示并生成有原文支持的补答，但旧版不确定守卫把题外细节当成阻断，程序仍返回 `incomplete_answer`。两次修复连同原任务实际累计 7 次模型请求、约 ¥0.01868 API 费用估算。为区分题内缺口与题外说明，协议新增 `blocks_requirement` 标志并通过单元测试，尚需在新真实任务验证；不能把这次事后诊断记为自动完成或有效成本优势。

随后用此前未参与流程开发的 [Agent Workflow Memory 新资料](AWM新资料对照结果.md)验证该协议并与普通检索脚本同题对照。普通脚本 1 次调用、多步流程 3 次调用；两组人工均未答全七项，结构流程更贵。多步综合首次因模型给出 9 条结论超过旧 8 条上限而被拒；放宽清单任务上限至 12 后，对保存的同一响应离线回放，七项中仅经验表示与离线记忆使用两项明确覆盖，其余尤其在线成功准入因证据选错页而缺失。新协议实际收到了 `blocks_requirement` 字段，但完成判定仍需要人工核对；这不是质量或成本胜利。
