# 组会决定链：版本证据守卫与模型请求归因

## 已实施的质量守卫

SSS 在组会决定链的 Harness 交付边界增加了只读版本证据检查。它只使用本次轨迹里成功的 `read_change`、`read_pinned_object` 和完整 `read_dataset_rows` 结果，先核对旧版哈希及两份逐行数据的版本，再按指标契约的分组字段与 `seed` 匹配旧值、新值。终稿明确把某一版本的逐种子序列写成另一版的数值、在行数未变时声称“新增行”，或把不满足严格分层／总体反转的数字称作辛普森悖论时，草稿隔离、不渲染，并允许同一会话最多一次有账本记录的修复请求；修复仍冲突或证据不全则不交付。

这是**窄范围机械核验**：它不保证报告其他数字、因果解释或研究建议正确。它不修改历史实验数据，不把通用脚本误称为 Motif。用户仍需审核科学判断。

无模型回放关闭思考模式的六份旧答稿：`tail_terms` Motif 把 w38 的 `26/25/24` 写成 w39、把 w39 的 `22/21/20` 写成 w38，守卫报告两处冲突；`site_transfer` 普通组使用了不成立的“Simpson 型”标签，也被标记。其余四份没有这几类可机械核验的冲突。六项针对性单元测试和已有组会工具测试通过。一项预算上限 US$1 的旧题 Motif 真实诊断完整结束：6 次实际模型请求、0 推理 token、旧版守卫报告无显式冲突、0 修复请求。该次没有触发修复分支，所以只能证明正常交付路径；修复分支目前由无模型测试覆盖，不能据此声称其线上效果。

这份新答稿虽然把 w38、w39 的逐种子值写对，却又说“新增 tail 行”；两版实际各 12 行，事件只改了 `correct`。它还把分层方向不一致称作“辛普森式分箱反转”，尚无正式的辛普森悖论证据。随后扩展的行数和严格统计标签检查在**离线回放**中都识别了它们。**当时在线放行不等于合格交付**；扩展后的守卫仍需真实端到端验证。私有诊断：`.local/benchmarks/meeting-decision-evidence-guard-20260928/`。真实 API 费仍按 usage 估算，未与控制台核对。

## 为什么两题接管后没有减少请求

关闭思考模式的 v3 轨迹显示，当前认证产物只有 `pin_object.source_id → read_pinned_object.source_id`。它确实替代了工具读取决策，但后续模型仍要选择统计维度和取回研究笔记：

| 任务 | 普通 Harness | Motif | 未被当前 Motif 接管的后续决定 |
| --- | ---: | ---: | --- |
| `site_transfer` | 6 次付费请求 | 6 次付费请求、2 次认证接管 | 选择逐站点／总体统计，迟后固定并读取笔记与批注；还出现一次错误的依赖查询 |
| `tail_terms` | 9 次 | 6 次、2 次认证接管 | 普通组把多次资料读取拆开，Motif 组因此有净请求节省；终稿版本错误使交付不合格 |
| `lot_stability` | 6 次 | 6 次、2 次认证接管 | 普通组把逐行读取与笔记固定合在一轮、把笔记读取和四次聚合合在一轮；Motif 组把这些拆成后续付费决定 |

“认证接管”是局部执行事实；整次任务少发了几次 API 请求必须单独核算。第一、三题的普通 Harness 已能在一轮里合批多个工具，当前单边 Motif 无法省掉它们的后续语义／工具选择轮。

## 下一条可编译的结构机会

三条独立训练／认证轨迹都出现了相同的跨对象参数流：`read_change.experiment_id` 或 `previous_experiment_id` 被后续 `pin_object.object_id` 使用；`find_dependent_claims` 返回的笔记与批注 ID 也被用于后续固定。当前编译器只对不可预测的 `source-*`／`dataset-*` 句柄推断参数来源；上述应用对象 ID 尚无带类型的来源认证。在线执行器还要求一条边两端的版本哈希相等，而“事件版本 → 实验对象版本”本来就不相等。因此不能把这些观察直接改写成已认证 Motif。

下一阶段需要让工具契约声明“来自先前成功结果的应用对象 ID”这一类型，编译器从多条独立轨迹认证精确字段传递，运行时分别核验事件版本与目标对象版本。若同一事件产生当前、上一版两个可就绪分支，只有训练与留出轨迹均证明两支都被执行，且当前任务授权范围覆盖两者，才考虑合批；对象 ID 冲突、版本变化或研究目标变化时回退模型。随后在新的独立研究决定上比较实际请求数与合格交付总成本。
