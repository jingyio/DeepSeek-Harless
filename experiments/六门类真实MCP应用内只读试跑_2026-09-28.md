# 六门类真实 MCP 应用内只读试跑（2026-09-28）

本轮按研究者要求，先测各应用内部实际连接器的常见读取链，不再把隔离夹具中的“邮件／批注／日历对象”算成 Gmail／Zotero／日历工具已测。入口为 `scripts/probe-mcp-internal-readonly.py`，私有结果在 `.local/benchmarks/mcp-internal-readonly-20260928/result.json`。只使用此前任务批准的 Zotero／Obsidian 范围、限定 Gmail 消息、AIDD 公开 CSV，以及公开论文和本人日历忙闲；没有调用付费模型、发送邮件、创建会议或改动应用资料。脚本只输出工具状态和结构检查，不输出私人正文、账号或来源 ID。

**2026-09-29 后续排障**：本机再次调用 OpenAlex 检索返回 HTTP 429，arXiv 搜索仍返回服务不可用。文献 MCP 新增 Crossref 题名／书目搜索工具，按公开接口查询 DOI 候选，再用已有 `verify_doi_metadata` 核对搜索结果中的 DOI；实际只读探测得到 3 个候选并成功完成这条搜索→核对链。新增核对结果还保留预印本与期刊版的 Crossref 关系及断言来源。源代码哈希、时间和工具状态保存在 `.local/benchmarks/mcp-internal-readonly-20260928/literature-recovery-20260929.json`。它是替代题录路线的工具验收，仍未读取论文正文，也没有普通 Agent 或 Motif 的文献发现交付成绩。Crossref 只能覆盖有 DOI 的记录；不能把它当成 arXiv／OpenAlex 全部发现能力的恢复。原下表保留 9 月 28 日的现场结果。

| 门类 | 真实服务中的操作链 | 观察结果 | 对效果实验的含义 |
| --- | --- | --- | --- |
| 文献发现 | arXiv 题名搜索；已知 arXiv 编号读取 | 搜索返回 `status=unavailable`、0 项，但 MCP 调用本身未抛错；已知编号读取返回 `status=ok` | **没有形成搜索→读取链**。必须把服务层失败计入工具故障和回退成本，不能把 MCP `is_error=false` 当作成功。 |
| Zotero | 已批准条目元数据→同一条目的批注 | 条目身份核对通过，返回 6 条批注 | 真实条目和批注读取可用；此轮条目由既有任务范围指定，尚未测试应用内搜索／集合选择或 Motif 跳轮。 |
| Obsidian | 列出已批准笔记角色→通过受限适配器读取 23 行批准摘录 | 来源哈希、笔记路径和行段边界核验通过；适配器底层调用真实 Obsidian MCP | 可读现有笔记的批准片段；没有新笔记事件或判断质量标签，不能测试旧结论应否沿用。 |
| 本地 Python／Quarto | AIDD 公开 CSV 所在目录列举→来源固定→记录结构检查；已有 `.qmd` 预览 | 四步成功；Quarto 只做预览，未执行渲染 | 数据来源参数可传递；本轮没有复算指标、检查数字或生成新交付。 |
| Gmail | 限定查询→从结果得到唯一已批准消息 ID→只读邮件头 | 唯一 ID 与既有授权范围一致，读取成功 | 真正观察到搜索输出决定读取输入；这仍是既有消息的技术复验，不能算新独立邮件任务。 |
| Google 日历 | 列出日历→查询本人主日历次日工作时段忙闲 | 返回了结构完整的忙闲响应 | 真实服务读取可用，但没有具体研究会议、参与者或改期请求；不能评价安排质量或 Motif 收益。 |

原始第一次检查曾把 arXiv 的 `status=unavailable` 误记为成功，因为其 MCP 外层 `is_error=false`。检查器现同时审阅服务返回的业务状态，相关回归测试两项通过；表中是修正后复测结果。这一发现也提示后续所有门类都需核对**工具返回的实际含义**，不能仅数调用成功率。

Obsidian 的最初探索调用直接取回了批准笔记的整篇正文，虽然没有打印、保存或发送给模型，但超出了试跑应暴露的行段。最终脚本改走已有的受限适配器：先验证本地批准文件版本，再经真实 Obsidian MCP 读取并只返回批准的 23 行。最终结果表按修正后复测记录，原始过程作为范围控制缺陷保留。

以上是**真实连接器操作验收**，不是 SSS 方法效果比较。它没有 Agent 自主选择、Motif 编译／匹配、模型请求跳过、盲评或费用差；也没有六门类各三个独立任务。已有 Gmail 真实提醒任务在另一个开发试跑中观察过只读搜索→读取的 Motif 跳轮，见[专门记录](Gmail动态搜索锚点Motif试验_2026-09-28.md)；其质量尚未独立盲评，不能移到本表充作新成绩。此前六类合成科研决定仍与本轮分开报告。

下一道门槛是为每类冻结**真实工作请求和来源范围**，先跑普通 Agent 自然轨迹，再看是否出现可由 Motif 接管的完整模型决策轮。文献类须先让检索恢复或记录替代公开检索路线；Zotero 加集合／检索→条目→批注，Obsidian 加搜索／路径→结构→指定内容，Python／Quarto 加实际复算与审阅输出，Gmail 用新的独立邮件决定，日历等待真实会议／改期需求。每类与同权限普通脚本／缓存比较；先由研究者判交付合格，再看核验跳过、缓存计价费用、人工修订和端到端时间。若应用内操作已经被一个普通确定性函数足够好地完成，就如实缩小 Motif 主张。

后续付费试跑须先冻结各题 Agent 可见包、封存评审包、来源版本及工具顺序，显式 `reasoning_effort="off"`，并给出逐臂模型请求／美元上限与外部模型可见摘录。此轮的无模型检查不沿用之前“合成任务最多 US$12”的预算作为私人资料付费授权。
