# 三个本地应用场景中的 Motif 复用与负例

日期：2026-09-30。状态：三个应用均完成真实本机调用及普通 Agent／Motif 配对；Pages 的写入接口故障另记，不计成绩。

## 结论

这一轮扩展到了三种不同的任务：Numbers 核验费用表格及公式、Keynote 核对幻灯片正文与演讲者备注、Finder 检查交付文件及其配套清单。**前两种任务有实际跳过模型请求，第三种没有。** 所有配对的核心数据答案均正确；输出格式单独计分。测试资料由我们在本机应用中生成，故它们是“真实应用操作上的受控任务”，尚不是自然用户工作负载。

| 应用与任务 | 三题模型请求：普通→Motif | 经工具结果验证的跳轮 | 核心答案：普通／Motif | API 用量计价费用：普通→Motif | 执行降幅 |
| --- | ---: | ---: | --- | ---: | ---: |
| Numbers：账本合计与公式 | 14→6 | 9 | 3/3／3/3 | US$0.00563077→0.00456972 | **18.8%** |
| Keynote：正文与讲稿金额 | 10→7 | 3 | 3/3／3/3 | US$0.00442851→0.00409388 | **7.6%** |
| Finder：报告文件和清单 | 10→10 | 0 | 3/3／3/3 | US$0.00494155→0.00474248 | 4.0% 数值差，无 Motif 节省证据 |

费用依据逐请求 API 返回的缓存未命中、缓存命中和输出 token，按本地费用门的费率计算；尚非供应商账单核对。Finder 没有跳轮，其费用差来自两次普通生成的用量波动，**不能归因于 Motif**。端到端计时单次波动较大，这里不作速度结论。

三题均按冻结顺序配对，DeepSeek Flash、`reasoning_effort="off"`、同题双方相同工具与提示词、每次 US$0.50 预算上限。匹配阈值维持 0.8，没有按结果下调。本地 embedding 的启动、电力与人工开发时间未折算美元。

## Numbers：修复“只看下一步”后重测

先前系统用任务“核验账本”匹配单独的“列出工作表”，相似度约 0.789，低于 0.8，所以只接管后续两步。现在对**已从普通 Agent 轨迹学得并独立认证的剩余整段操作**计算相似度。其余版本、参数来源、工具 schema 和歧义守卫不变；不是把阈值调低，也没有提前写入新工作簿的名称。旧三题记录保留在[首次 Numbers 报告](/Users/apple/Desktop/SSS/experiments/Numbers真实应用Motif费用核验实测_2026-09-30.md)。

新建的 D、E、F 三份 `.numbers` 文件，表名各异，费用来自既有真实实验的匿名 API 用量；公式由 Numbers 原生计算。普通 Agent 自行完成“打开→列工作表→列表格→整表读数值和公式”。Motif 在每题均验证跳过三次中间模型请求，随后交模型核验，三题全部数字正确。普通组 E 自行合并了调用，所以九次跳轮对应的净请求差为八次。数值相同的一对严格 JSON 合格答案是 F：US$0.00182639→0.00149104，下降约 18.4%。全部三题的 JSON-only 合格数为普通 1/3、Motif 2/3；不能将 18.8% 宣称为“三份严格合格交付成本”。

在先前用实际 Numbers 增加第二张表的守卫记录上，使用新匹配代码离线重放并把相似度强制设为 1：找工作表、列表格可继续，**读哪张表时返回空候选**。文件哈希变化与未保存修改的拒绝也已在真实应用副本上验证。多表守卫的新代码重放无付费模型请求，不能替代真实恢复试验。

原始证据：`.local/benchmarks/numbers-live-v1/EVALUATION-LOCK-v2.json`、`evaluation-v2.json`、`guards/v2-matching-guard.json`，以及每题的应用范围、Agent 事件、工具返回、答案和逐请求费用账本。首次报告中说明了原始两份训练、一份独立认证，以及试跑与训练费用。到目前为止，开发与训练投入尚未摊回。

## Keynote：另一种本地应用任务

Keynote 14.4 中实际创建、保存并读取多页 `.key` 文稿。任务要求找到指定标题的幻灯片，比较可见正文里的批准金额与演讲者备注里的来源金额，输出是否一致。训练目标页分别在第 2、3 页；新留出文稿在第 1、3、2 页，并同时包括一致与冲突结论。读页使用当前 Keynote 返回的文稿名与目标页号，交回模型判断。

首轮三份文稿的 Motif **0 次跳轮**，记录未覆盖：连接器没有在找页结果中回传已核实的文稿名；更早两份训练文稿的目标页都碰巧在第 2 页，编译器正确拒绝把常数 2 当参数依赖。补齐文稿名回执，并增加目标在第 3 页的训练轨迹后，从真实普通 Agent 轨迹重新编译，在独立文稿上认证。冻结之后才执行新的 D/E/F 三题。每题验证跳过一次读页前的模型请求，费用合计降低 7.6%；六份答案的**内容和 JSON-only 格式均合格**。D 题虽然验证了一次跳轮，但普通组本来就合并调用，总模型请求同为 3 次；其余两题分别 4→2 和 3→2。

相关三份正式训练／认证的 API 费用约 US$0.00440738，新留出任务平均每题执行省约 US$0.00011154。若这个平均值延续，约需 40 题才能覆盖这三份正式轨迹成本；早期失败排查和开发成本还未算入。这是外推，不是已观察到的回本。该场景节省确凿但幅度较小。

原始证据：`.local/benchmarks/keynote-live-v1/EVALUATION-LOCK-v2.json`、`evaluation-v2.json`、`certified-library.json`、各案例的原生文稿读取、Agent 事件和费用账本。早期零跳轮结果在同目录 `test_{a,b,c}/*-first/`，没有并入新留出成绩。

## Finder：有可学关系，但没有接管

Finder 实际读取实验交付文件夹中的文件名、大小和文件类型。任务检查指定项目的 Markdown 报告是否非空、同名 JSON 清单是否存在。训练轨迹形成“项目→唯一报告→文件信息”的关系，并在另一文件夹认证；测试包含空报告和缺少清单的变化。所有核心答案正确。

当轮任务与“读取文件信息”这一步的相似度约 0.715，低于冻结门槛 0.8；三题 **0 次跳轮**。这是负结果。清单缺失时普通 Agent 根据实际列表判断，没有自动读取不存在的清单。Finder 需要更好的、经其他任务验证的匹配方式，或者承认这里适合由模型继续处理；不能拿两组输出 token 偶然不同声称复用收益。

原始证据：`.local/benchmarks/finder-live-v1/EVALUATION-LOCK.json`、`evaluation.json`、各文件夹范围、Agent 事件、答案和费用账本。

## Pages 探针为何未进入成绩

Pages 14.4 能打开并从运行中的应用读取正文，但在这台机器上，对新建测试文稿执行 AppleScript 保存会长时间不返回，有时留下未保存状态。试验停在建夹具阶段，没有普通 Agent／Motif 配对，**不计为第四个成功或失败的场景**。已有实验副本留在 `.local/benchmarks/pages-live-v1/`，没有接触用户文档。后续若修复该应用接口，应先验证可靠保存、重新冻结任务，再谈费用。

本轮检验了两个正场景和一个负场景，仍只有每题单次模型执行，且资料是自建夹具。它支持较窄结论：**不同本地应用里，若目标能唯一定位、地址在新结果中可验证，并且已学操作与任务相符，Motif 能跳过局部工具决策；同样条件缺一时系统可能不接管。** 是否能在自然任务、复杂多目标资料和计入训练的长期总成本上成立，仍需另外实测。
