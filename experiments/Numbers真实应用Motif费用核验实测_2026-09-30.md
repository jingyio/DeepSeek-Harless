# Numbers 真实应用：费用账本核验中的 Motif 复用

日期：2026-09-30。状态：已完成真实应用与付费模型对照；三份留出工作簿，每组各执行一次。

**找到了一个有效的本地应用实例：普通 Agent 确定工作簿和工作表后，Motif 自动完成找表、读取数值与公式，两步均跳过模型请求，再交回模型核验账本。** 两组在三题上的数字、最大费用项及公式判断全部正确；模型请求合计从 14 次降到 9 次，按 API 返回用量计价的执行费用下降 17.3%。最严格口径下，两边均完全符合输出格式的 B 题省 16.0%。训练投入尚未摊回，不能把执行阶段节省写成当前实验总成本已经下降。

## 1. 真正使用了什么应用

- 本机 Apple Numbers 14.4，实际打开 `.numbers` 文件，调用实际工作表、表格及公式引擎。
- 上游连接器：[Digits](https://github.com/apeabody007/Digits)，固定 commit `52d0dfc704b8eb03a063d5f0df8c1141ddd75ded`。原生处理函数通过 AppleScript 操作运行中的 Numbers，未替换为模拟返回。
- 自建六份实验工作簿，内容取自此前真实模型实验的匿名费用记录，只包含请求编号、usage 计价费用和 HTTP 状态；TOTAL 使用 Numbers 的 `SUM` 公式。
- 两份普通 Agent 轨迹训练，一份独立工作簿验证，三份工作簿留出测试。文件、工作表及表格名称分别变化。

这是**在真实本地应用里，用真实历史费用数据构造的受控核验任务**，不是用户自然产生的日常办公任务，也不是模拟 Numbers API。测试文件内部名字含 `calendar`，仅表示费用数据来自旧日历实验；本轮没有执行日历任务。

任务要求：不修改工作簿，检查数据行数、费用合计、最高费用请求、TOTAL 是否与逐行合计一致、TOTAL 是否由公式生成，最后输出五字段 JSON。正确答案由源费用记录独立复算，并与 Numbers 原生公式读取核对。容差 `1e-8` 美元；行数、标签和布尔值精确匹配。

## 2. 普通 Agent 与 Motif 分别做了什么

普通 Agent 的正式训练、验证轨迹自然出现以下调用：

`打开工作簿 → 列工作表 → 列表格 → 批量读取表格及公式 → 模型给出核验结论`

使用已有 Motif 轨迹编译器，从两份真实普通 Agent 轨迹挖掘并在第三份工作簿认证，得到六个连续子路径算子。没有预写这条 DAG、复制历史答案或给 Motif 测试工作表名称。测试时从当轮工具返回重新绑定名称。

实际接管的是“列表格”和“读表格”两次工具调用。打开文件、列工作表、最终核验仍由模型执行。每组都保留同样的四次真实 MCP 调用，省下的是中间询问模型的往返，而不是不读新数据。

接口保留原生整表批量读取、可选参数及默认值，没有人为拆成逐单元格操作。两边使用同一提示词和同一有序工具集合。为避免混淆同时打开的文件，任务要求在发现目标名称后显式填写适用的 document、sheet、table；这是一项双方共同受到的任务约束，可能影响自然使用时的调用长度。

适配层仅增加文件版本、未保存修改检查，以及“只有一个工作表／表格”时可验证的名称字段；原生结果完整保留。存在多个候选时，字段为空，不能沿用单一目标路径。核心运行时允许编译算子显式绑定原生 API 中的可选参数，但仍拒绝缺少 API 必填参数或参数已从 schema 删除的情况。

## 3. 配置与结果

模型均为 `deepseek-flash`，`reasoning_effort="off"`，每次最多 12 次请求、输出上限 1,500 token、预算 US$0.50。授权沿用用户对持续实验及费用的明确批准。没有裁剪历史或启用上下文压缩。

Motif 匹配使用本地 `Qwen/Qwen3-Embedding-0.6B`，既有相似度阈值 0.8、差值门槛 0.1，未按测试成绩调低。测试顺序事先记录：A 普通→Motif，B Motif→普通，C 普通→Motif。

| 工作簿 | 模型请求：普通→Motif | 数字及公式核验：普通／Motif | 输出格式：普通／Motif | 执行费用 USD：普通→Motif | 降幅 |
| --- | --- | --- | --- | --- | --- |
| A | 5→3 | 通过／通过 | 多余说明／通过 | 0.00196606→0.00162354 | 17.4% |
| B | 5→3 | 通过／通过 | 通过／通过 | 0.00188896→0.00158591 | 16.0% |
| C | 4→3 | 通过／通过 | 多余说明／通过 | 0.00194109→0.00158291 | 18.5% |
| 合计 | **14→9** | **3/3／3/3** | **1/3／3/3** | **0.00579611→0.00479236** | **17.3%** |

普通组 A、C 在正确 JSON 之外额外写了说明；核验程序分别记录内容正确性与格式合格性，不能把格式问题算成数字错误。按“内容和格式都合格”的严格口径，只有 B 构成两组都合格的配对；17.3% 是三份内容都正确的任务的执行费用比较，不是三份严格合格交付成本比较。未对普通组额外调用模型修复格式，因而也没有计入假设的修复费。

Motif 日志每题记录两次执行后验证通过的跳轮，共六次。普通组 C 自行合并了调用，因此相对于普通执行，净请求数少五次，而非六次。

| 合计指标 | 普通 Agent | Motif |
| --- | ---: | ---: |
| 未命中缓存输入 token | 13,168 | 13,351 |
| 命中缓存输入 token | 41,216 | 21,376 |
| 输出 token | 1,332 | 549 |
| 真实 MCP 调用 | 12 | 12 |
| 任务执行耗时（秒） | 21.831 | 13.711 |

费用按逐请求 API 返回用量和本地费用门的计价规则计算，区分缓存命中与未命中；不是供应商账单对账值。请求数已与成功 API 响应条数核对。耗时包含任务运行及在线匹配，不包含先前的应用建表、编译和本地 embedding 服务启动；只有一次观测，不能当成稳定加速比。

## 4. 训练投入与试验过程

最初三份试跑使用 Numbers 默认的相同工作表／表格名，不能充分检验跨文件重新绑定参数。随后在正式测试前改成不同的原生名称，并加入双方相同的显式目标约束，重新收集两份训练和一份验证轨迹。旧试跑全部保留，没有算成独立测试题。

| 投入 | API 用量计价 USD |
| --- | ---: |
| 初始三份试跑 | 0.00556506 |
| 正式两份训练＋一份验证 | 0.00603888 |
| 六次对照执行 | 0.01058847 |
| 本轮全部付费尝试 | **0.02219241** |

三题执行阶段共省 US$0.00100375。若后续保持相同平均节省，需要约 **19 个同等任务**覆盖正式训练与验证费用；连同初始试跑则约 35 个。这是条件外推，不是已完成的摊销实验。人工开发、应用构造及本机计算能耗未折算成美元。

## 5. 变化时是否错误复用

在单独复制的真实工作簿上完成以下检查，原测试文件未变：

1. 修改单元格但不保存：连接器拒绝沿用旧范围。
2. 保存修改后仍使用旧文件哈希：拒绝读取；更新范围版本后读取成功。
3. 在实际 Numbers 中增加第二张表，将真实 MCP 返回送入冻结运行时：即使将语义相似度设为 1，仍因目标不唯一而不提出自动执行候选。

第三项是**真实应用返回上的离线边界回放**，未执行新一轮付费 Agent；因此只证明守卫没有错误接管，不证明模型后续一定能正确恢复。核心与适配器相关测试 22/22 通过。

## 7. 结论边界

当前证据支持：**在单一明确目标的 Numbers 账本核验任务中，从普通 Agent 轨迹学到的局部工具路径，可以重绑定新文件名称，跳过中间模型请求，并降低后续执行费用。** 这已经是一个真实本地应用里的正结果。

三份留出工作簿都是相近的简单账本，数据量小、工作表和表格目标唯一。尚未证明多表选择、复杂公式审计、大表分页或其他应用的收益。本轮按用户当前要求比较普通 Agent 与 Motif，没有运行简单脚本对照，因此不能据此声称优于专用脚本。真正的下一项扩展应保留这一已有效实例，增加自然变化与多目标恢复，不再把单次执行节省扩大成全场景结论。
