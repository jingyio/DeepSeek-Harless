# 单场景聚焦：候选论文摘要初筛（2026-09-29）

## 为什么选它

本轮只检验一种日常科研任务：研究者已有一个明确问题和 4–8 篇候选论文，Agent 读取真实 Zotero 条目与必要的研究状态，选出最值得阅读全文的两篇，说明至少两篇暂缓的理由和仍需核查的缺口。它是有界的语义决定，不能由脚本仅凭标题做完；来源身份、版本和已选条目的摘要读取则有清晰的结构关系。来源继续留在 Zotero／Obsidian，不预先拼成单个输入文件。

已有 SSS 强基线六篇初筛开发题观察到：普通 Harness 9 次模型请求、Motif 7 次，其中 1 次为经核验的 Motif 跳过；费用代理估值 $0.012672→$0.008592。但普通组做了更多外部检索且输出更长，两组答案均超 900 字预设限制，缺研究者盲评，不能把费用差归于 Motif，也不能报告合格成本收益。另一个 AI4S 六篇初筛题虽有跳轮，但把研究对象写错，已作废。由此仅能说**该场景值得重做一次公平测试**。

## 保留的最小机制问题

模型负责确认本次问题、候选集合和读取权限；之后若所有候选摘要都需要比较，Motif 可从历史普通轨迹编译的 `pin_scoped_zotero_source → read_pinned_zotero_item` 参数关系，读取模型已固定且同版本的条目，再把内容交给模型做取舍。来源选择、摘要相关性、是否阅读全文和最终理由仍由模型判断。条目类型错误、版本变化、权限变化或某份摘要读取失败时回退；不能自动延续旧论文排名。

只要求**这一种任务类型**出现可重复、可核验的完整请求跳过；不再把跨六类 MCP 或连续多轮长链设为成功前提。为避免把同一题重跑当泛化，编译/校准与验证仍需不同的具体阅读决定、不同候选集合。即使只跳一轮，也要在合格交付下比较**净费用**，而非只数轮次。

## 下一次试验怎样做

第一阶段的无模型复用核验已完成：旧 Zotero 读取算子在未参与编译的 SSS 六篇初筛自然轨迹中重新绑定 **6/6** 个新来源，逐项版本一致；详情见[复用离线核验](候选论文初筛Motif复用离线核验_2026-09-29.md)。这只证明结构关系可迁移，尚不满足下面的交付质量与净成本门。

1. 先找一项尚未用来调试的真实阅读决定，冻结研究问题、候选 Zotero 集合、Obsidian 状态范围、任务文本和来源版本。保持一个简短但不依赖字数波动的交付格式：两篇优先、至少两篇暂缓、每项一个可定位的摘要依据和一个全文待核问题。不能把旧初筛题换提示词算新验证。
2. 同题运行三路：普通 DeepSeek Agent；同等权限和版本校验的简单批量读取脚本＋同一模型；从历史工具轨迹编译的 Motif＋同一模型。三路使用同一候选集合、稳定工具 schema、`reasoning_effort="off"` 和预算账本；脚本不是“普通 Agent 本来会写脚本”的假设，而是检验 Motif 额外价值的强基线。
3. 盲评者先判两篇优先和暂缓的理由是否和研究问题、摘要证据相称，是否错认论文、把摘要当全文结果、遗漏相反线索或超出已定交付格式。只有合格答案才比较逐请求缓存计价费用、失败重试、人工修订分钟数与端到端耗时。变更/失效探针另做：条目版本变化或候选集合变化时必须重新核验，不沿用旧排名。

## 明确的止损线

若普通 Agent 在新题中把固定与读取自然合并一轮、Motif 没有净省费，或简单批量读取脚本在同等质量和成本下更好，就不把这个场景写成 SSS 的优势。若 Motif 只比普通 Agent 好而不比脚本好，产品上仍可考虑自动复用减少每题手写脚本，但论文中的机制主张必须缩到“从轨迹自动得到可执行读取算子”，不能声称脚本做不到的成本收益。
