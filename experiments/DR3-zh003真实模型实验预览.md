# DR³-Eval zh/003 真实模型实验预览

> 2026-09-25。等待用户对付费调用的确认；本文件不是实验成绩。

## 输入与冻结范围

- 官方题目和资料：`benchmarks/dr3_zh003/manifest.json` 所列固定 revision、原论文与 32k 文本资料库；本机副本在被忽略的 `.local/benchmarks/dr3-zh003/`。
- SSS 补充验收点：`benchmarks/dr3_zh003/answer_points.json` 当前版，`methods` 要绑定两份不同来源。原清单留在 `answer_points.v1.json`。两者均非官方题面。
- 本地手写的 diagnostic plan 与 selection 仅用于结构预览；**真实模型运行不使用它们**，让模型自己规划和选页。

## 实际将执行的路径

1. Motif 来源层核对 16 份文件哈希、恢复未变证据；4 项必答点与来源目录形成规划 handoff。
2. `deepseek-flash` 非思考模式做逐项检索规划，最多 900 输出 token；结构层在原文核对检索词并检索，每项保留最多 4 个候选。比较项不足两份独立来源时停止。
3. 同模型从每项候选中选 1–2 处，最多 900 输出 token；MotifFrame 记录带候选和必答项签名的决定。结构层重验页码、文件哈希和片段。
4. 同模型据已核验片段写逐项结论及未知项，最多 1,800 输出 token；只收录引文可定位且未跨项的结论。比较项在输出中必须真正引用两份不同资料。程序把接受的结论、未知项和证据索引组织成待审阅简报，并执行结构覆盖检查。

最多 **3 次模型请求**，输出上限合计 **3,600 token**；三个提示分别限制在 8,000、14,000、16,000 字符。无自动付费重试；任一步失败都会记录已产生的费用并停止。输入仅为公开 benchmark 文本；模型不可使用文件或网络工具。输出和用量写入被忽略的 `.local/point-research-runs/`。

按 2026-09-25 [DeepSeek 官方 `deepseek-flash` 价格](https://api-docs.deepseek.com/quick_start/pricing/)估算，峰时未缓存输入 $0.30／百万 token、缓存输入 $0.006／百万 token、输出 $1.20／百万 token，空闲时段为峰时的一半。按当前无模型诊断的三个输入约 24,500 字符，预计 API 费低于 **$0.03**；真实选页会改变后两步输入，最终以 API token 用量和实际时段重算，不把估算当成账单上限。

## 验收与限制

先记录请求数、输入／缓存／输出 token、停止位置、引用错误和人工逐项评估；只有简报达到预先定义的质量门槛后，才与简单脚本、DSH 原生 Agent、mu 等计算合格交付成本。此轮产物是**结构化调研简报**，仍需人工审阅，不直接声称完成 DR³-Eval 官方长报告或取得其分数。`zh/003` 已被用于开发，不能充当留出主结论；需要另选未参与调参的公开题。引文可定位与双来源计数都不等于原文蕴含比较结论，机器状态 `point_links_present` 也不是报告合格。

普通脚本对照已用相同的 16 份来源和当前必答清单做无模型预览：固定人工检索词 `3DGS,pose,registration,optimization`，检索 12 处、交给一次综合的引用片段 10 处、输入 8,900 字符、输出上限 1,800 token；运行记录在 `.local/research-simple-baselines/20260925T012154Z-9b4a0a/`。两组现在使用同一份简报渲染与双来源输出覆盖门。脚本的检索词由人事先给出，SSS 的查询规划由模型完成；必须把这部分人工准备和 SSS 的规划调用都计入成本，不能只比较最后一次综合。

原生 DSH Agent 的多来源入口也完成无模型预览：复制 16 份来源共 3,075,821 字节到独立工作目录，提示包含相同问题与必答清单，记录在 `.local/native-baselines/20260925T012928Z-63f3b3/`。后续为 Agent 增加 `--max-model-requests` 和累计已观察输入 token 的事件守卫；回放本机既有的 16 次请求记录时，设置 8 次会在第 9 个 `step/start` 事件前停止，并保留前 8 次用量。SDK 不提供服务端费用硬上限，输入 token 门只能在已发生的请求后检查；正式付费运行仍需单独预算与确认，不能把本地守卫说成绝对账单封顶。

统一人工盲评包可由 `scripts/prepare-research-review.py` 从两条脚本的保存结果生成，包中只有代号、同一格式的简报、逐条来源原文和评分栏，不含方法名或模型用量。评审逐项给出支持与覆盖 0–2 分、记录关键错误和修订分钟数；比较项还需判断两种方法的异同是否准确。协调者另存代号与运行目录的映射，评审完成前不解盲。
