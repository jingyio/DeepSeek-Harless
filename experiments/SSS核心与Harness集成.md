# SSS 核心与 DeepSeek Harness：按三项工作的真实机制修订

> 2026-09-25。用户指出把核心写成手工 JSON skill 编译器是方向错误。该临时实现已撤回。本文件是实施边界与源码检查记录，不是已经完成的能力声明。

## 三项工作的机制关系

| 工作 | 真正的结构来源 | 推理时做什么 | 对 SSS 的作用 |
| --- | --- | --- | --- |
| MotifAgent，主参照 | 从历史工具轨迹挖掘高频连续片段；再生成 motif、连接、参数流、守卫与执行算子，经验证才进入执行库。 | 匹配 motif、在 `MotifFrame` 中按依赖执行并恢复；缺参数、失败、歧义和写入风险才显式交给语义层。 | **运行内核的来源**，不是一个提示词 Skill，也不是先手写几张任务流程图。 |
| G-Agent，局部参考 | 从历史计划建立整计划超边与可复用 tiny edge。 | 先检索计划，未命中才生成；多任务到同一片段时复用或批处理。 | 以后有足够跨任务轨迹和并发负载时，参考计划检索与片段复用。 |
| AutoTool，局部参考 | 轨迹增量构建工具顺序边和参数依赖边，并用执行反馈更新。 | 每步先检查下一个工具和全部参数能否由结构确定；否则交回 LLM。 | 参考候选生成与参数回溯，不能只凭频率授权工具调用。 |

依据：本地 [MotifAgent 设计](/Users/apple/Desktop/ATC-MotifAgent/artifact/MotifAgent-ATC26-Artifact/motif_agent/DESIGN.md)、[MotifExecutor](/Users/apple/Desktop/ATC-MotifAgent/artifact/MotifAgent-ATC26-Artifact/motif_agent/runtime/motif_executor.py)、[离线编译入口](/Users/apple/Desktop/ATC-MotifAgent/artifact/MotifAgent-ATC26-Artifact/motif_agent/offline/build_all.py)、[G-Agent 方法](/Users/apple/Desktop/KDD-G-Agent/HG-Planning/paper_revision.tex) 及 `reference/AutoTool.pdf`。冻结上游保持只读。

MotifAgent 源码中的 `motif_skill_library.json` 是**轨迹和 schema 编译后的可执行算子产物**，包含参数链与守卫；它不等于 Codex Skill，也不等于让模型照着自然语言步骤做事。手工声明 `step A → step B` 可以做调试夹具，但不能作为 SSS 的方法核心。EvoGraph 的“进化”也要作用在可追溯的 motif 候选／执行证据上，不能把修改提示词包装为结构进化。

## 正确的系统边界

```text
DSH／其他 Agent 的入口和模型能力
            │ 用户任务、工具事件／有界语义回答
            ↓
SSS 适配器：工具 schema／调用事件／结果、模型请求、用量
            ↓
SSS Motif 内核
  轨迹采集与编译 → 已验证 motif 库 → 匹配与执行前沿
                           ↓
              参数依赖、证据守卫、状态、恢复
                           ↓
                 结构可继续？ ──是→ 工具执行
                           │否
                           ↓
                  类型化 handoff → DSH 语义调用
                           ↓
                  验证返回值后重新进入内核
```

**控制权在 SSS Motif 内核。** DSH 在当前阶段提供用户入口和生成模型能力，也可以先跑自由 Agent 取得训练／对照轨迹；它不能在 SSS 正式路径里绕过 motif 守卫自由执行后续步骤。以后 Codex、Gemini、Claude 或本地模型替换的是语义端口，不必改结构产物和状态规则。SSS 内核也不能硬编码“论文第几页”“调研报告有几个必答点”作为图方法本体。

## 当前事实与撤回项

- `src/motif_core/` 已从冻结 artifact 复制 `MotifFrame`、证据、依赖求解、handoff 和 motif 挖掘的必要部分，保留 Apache-2.0 和来源 commit。现新增 SSS 适配的轨迹建库、输出目标匹配和 Motif 主控：只读候选通过独立留出任务核对后进入执行库；唯一命中直接运行，多候选以签名范围交给语义端口，缺参数可恢复同一 Motif。它仍不是完整的上游 `MotifExecutor`，当前执行范围限定为已验证只读算子。
- `src/adapters/dsh_client.py` 是从现有调研代码抽出的低层受限 DSH SDK 调用。逐项调研的**规划、证据选择、证据综合**现经 `src/adapters/motif_research_handoff.py` 做类型化 handoff/reentry：调用前核对来源、候选或引文范围与提示签名；返回后验证有界结果及当前证据签名。`verify_source_snapshot` 在模型调用前和重入前再次核对当前磁盘资料，发现新增、删除或修改就停止。三段均支持保存回答的离线重放。已认证的只读 Motif 图由 `src/motif_core/controller.py` 执行；上层 `research-points.py` 仍负责规划、选择、综合的顺序和预算，**完整调研任务尚未由同一个主控状态机接管**。
- 原生 Harness 的独立入口现有一个[接入切片](原生Harness与SSS运行时接入切片.md)：专用插件限制模型可见及可执行的工具，SSS MCP 工具把资料收集、分段读取与增量刷新交给已认证的只读 Motif。隔离 Web 和 MCP 已无模型启动，旧 8765 进程未变。此切片没有接管完整调研顺序，也没有产生原生 Agent 成功交付的效果数据。
- 已迁移冻结的 `motif_miner`，并增加 `src/adapters/dsh_trajectory.py` 将 DSH `tool/call` 与 `tool/result` 按 `callId` 配对。只有显式登记为只读、参数齐全且成功的调用进入连续片段；未知、失败或有写入效果的调用构成边界。跨两条独立轨迹重复的片段仍只标为 `candidate_only`，不能直接执行。现有一条原生 DSH 基线含 18 次 `bash` 调用，全部被隔离；它不能用来证明已有可执行 motif。此检查只读取本机既有事件，未调用模型。
- DSH 轨迹现在可以附带宿主记录的 `callId → 参数来源` 旁证；适配器逐项核对前序工具、声明字段和实际返回值，不接受仅因数值相等而猜出的参数链。`scripts/compile-dsh-motif-library.py` 可离线读取训练／留出事件与旁证，在 `.local` 生成已验证 motif 库；每条轨迹还须附冻结任务和事件哈希绑定的身份锁，库摘要涵盖这些身份锁的审计证据。未提供旁证的自由 Agent 轨迹仍只能贡献候选片段；身份锁也不替代研究者对“是否属于同一科研决定”的语义核查。
- 新的 `src/motif_core/offline/trace_compiler.py` 要求工具客户端显式记录参数来自哪项结构化输出，再用独立任务和留出任务核对；数值相等本身不构成参数流证据。`src/motif_core/read_executor.py` 让通过核对的只读 Motif 持有资料读取的执行控制，缺参数时交接，失败时阻断。真实 PDF 轨迹、5→7 份资料的增量回放和复现命令见[只读 Motif 回放](轨迹编译只读Motif与真实资料回放.md)。随后加入有声明的集合入口参数，接通逐项跨资料检索、精确绑定的检索结果恢复和来源变化失效；DR³-Eval 开发题 16 个候选与旧路径一致，见[跨资料检索切片](跨资料检索Motif与DSH交接切片.md)。训练轨迹来自 SSS 本地工具，不能称作 DSH Agent 自动学习。
- 本地依赖求解器已修正缓存重用顺序：子节点即使有旧结果，也要先重新检查当前前置条件和参数约束；研究资料读取失败会留下不含原文的**实际执行参数签名**供守卫进化审核。失败不会自动改变执行。候选必须经过独立失败重放、成功对照和单独的任务质量复核记录，才能成为精确限定 Motif／算子／参数／输入版本的活跃负向守卫；运行时在缓存或工具调用前检查它。守卫注册表记录激活、版本和回滚；质量复核记录由外部提供，当前代码不能独立证明复核人身份。
- 迁移的只读 Motif 执行器现经 `src/motif_core/controller.py` 管理入库、目标匹配、执行和恢复；`src/adapters/motif_read_semantic.py` 为多 motif 选择与缺槽位各提供受限语义端口。SSS 会核对候选、当前资料与交接签名后才恢复。每个节点可提供自己的证据版本，缓存键同时纳入已验证前驱版本；局部更新只重算受影响节点及其后继。未提供节点版本时按整体输入版本安全失效。现有科研资料读取和逐问题检索已改经主控，`research-points.py` 的总体步骤顺序仍由脚本控制，尚未产生真实成本或质量增益。
- 重复读取支持两种经轨迹验证的边界：来源工具输出**完整标量列表**并全部读取时，结构层直接展开；训练与留出任务均显示有序子集选择时，结构层只给出当前候选列表，语义端口选子集，重入后再次核验候选、顺序和当前来源。运行时不允许自行添加候选。图中顺序边与已验证的参数边分开记录，未宣称并行或开放式子集生成。
- `offline/link_compiler.py` 将观察到的顺序连接与可执行依赖分开：只有两个已认证只读 Motif 的参数来源在两条独立训练轨迹和一条留出轨迹中明确指向前驱输出、实值吻合，且中途没有未知／失败／有副作用的工具，才生成可执行边。中途若有其他已批准的只读工具，它们不会因观察到顺序而被自动执行。主控根据目标、入口参数和这些边构造无环依赖图，逐节点执行、从当前输出传参，在任一节点缺参数时暂停并恢复。可执行图没有预设跳数上限；已用三段链和分支汇合验证。歧义图、环、失效字段与重复工具名仍安全停下。这仍是只读子集，不是完整的写操作及语义前沿。
- 2026-09-26 补上通用只读主控的**进程重启重放检查点**：已认证图的语义缺参、单个 Motif 缺参及多候选 Motif 选择均可保存库签名、入口绑定、来源版本和 handoff 签名，不保存工具输出。新进程须在当前来源上重新匹配、执行已认证的只读算子，只有重新到达同一证据绑定的语义缺口，才允许沿原 handoff 继续；版本变化、参数篡改或中途观测变化会拒绝重入并清空部分状态。缺参 handoff 现在也绑定已完成节点的输出摘要，避免只核对调用参数却忽略工具观测变化。多段图与选择／缺参的无模型重启测试通过。另用 MGGA 同题四份真实来源重放已认证检索 Motif：保存检查点、重新建立主控、核对同一缺槽交接，再用已有诊断计划中的检索词重入，返回 4 条候选证据，模型请求为 0；检查点在忽略的 `.local/distil-sss/`。这只验证恢复机制。该路径会重新读取前驱，尚未把可验证的跨进程缓存复用或顶层规划／选证据／写报告调度纳入主控，因此不代表完整科研任务已经可持续恢复。
- 无模型验证：目前共 135 项 Python 测试与 10 项 Node 测试通过，涵盖跨 Motif 训练／留出认证、执行、缺参数恢复、当前来源字段缺失与篡改拒绝，也覆盖原生 Harness 工具边界和资料增量刷新。保存规划、选择和综合回答的合成调研命令生成 `answer.md`，三段交接凭据均落盘，0 次模型请求；损坏来源在读取处停止并保存失败凭据，同为 0 次模型请求。资料修改或新增会使重入前的快照校验失败。只读 Motif 的新任务回放同样不使用模型，但原有资料读取也是零模型调用，因此没有成本收益结论。失败凭据现可生成精确范围的负向守卫候选并独立重放核对，仍需跨任务质量门后才能启用。对无效模型返回也验证了用量记录不会因校验失败而丢失。
- 早期 `src/graph/runtime.py` 是独立原型，不能称为 MotifAgent 内核。旧研究 MCP 的自由工具循环不符合正式主控链，已从源码中删除。
- 本轮曾写出的 `src/sss_core/skill.py`、通用手写 DAG 和候选路由演示已经删除；其测试成绩不计作 SSS 方法进展。

## 接下来的实施顺序

1. **把写操作纳入 Motif 编译与执行。** 目前通用内核只认证只读算子。下一步从真实写操作轨迹编译效果边界，并要求本地预览、明确确认与执行后核验；不能让模型回答直接授权文件、邮件或日历修改。
2. **完成通用任务主控。** 已移除按连接跳数扩展的路线：只读 Motif 可以组成无环依赖图，支持多段链、分支汇合和中间恢复。下一步把语义前沿、写操作的预览／确认／事后核验、持久化恢复与跨节点证据版本纳入同一状态机；观察到的顺序表本身仍不能授权执行。冻结源码的 `motif_dag_builder.py` 仅写顺序边，不能据此宣称并行收益。
3. **替换研究报告脚本的顶层顺序。** 现有资料读取和逐项检索由 Motif 主控，规划、证据选择与综合的交接仍由 `research-points.py` 排序。需要把这些语义前沿纳入同一可恢复执行状态，再由 DSH／Jev／其他模型作为有界判断端口。
4. **随后验证效果。** 用真实任务比较合格交付、总费用、人工修订和增量复用；付费 DSH 实验先做预算与预览。Laya／Jev 与其他语义端口在同一结构内核下对照。

已在无模型轨迹回放中验证：独立训练／留出轨迹可生成只读 Motif 和参数依赖边，主控能执行无预设跳数的无环图并在中间缺参时恢复；节点版本变化会局部失效。当前仍需完成写操作、持久化图状态与顶层语义前沿集成，再讨论真实任务质量和成本增益。
