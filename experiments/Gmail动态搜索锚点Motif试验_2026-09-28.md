# Gmail 动态搜索锚点 Motif 试验

日期：2026-09-28。任务是逐封分拣研究者真实收到的 Google Scholar 论文提醒，判断是否有与模型内部能力状态／Agent 自我改进相关的论文线索。邮件属于发现入口，不能把其摘要当成论文结论。此试验验证 Gmail `search_emails → read_email` 的局部模型请求跳过，**不代表完整跨应用科研闭环**。

## 实施和约束

- 只开放两项 Gmail MCP：`search_emails(query)` 和 `read_email(messageId)`；每题锁定一条精确查询。桥接只准读取该次搜索返回的唯一 ID。未修改或发送任何邮件。
- 搜索结果是动态的，所以 Motif 的第一个节点只能作**已观察到的锚点**，不由运行时自行重放。桥接仅在结果恰好一封时给出 `selected_message_id`，并保留有序 ID 摘要。Motif 从已见证输出填入读取参数；读取回来的消息 ID 必须与锚点一致。多结果、版本漂移、参数不符或工具失败时不记跳过。
- 从两封不同日期的普通 Harness 轨迹挖掘并编译参数边，以第三封不同邮件作留出认证。认证产物来自 `build_read_motif_library`，不是手写 DAG。之后的邮件不参与编译。冻结的私有查询、邮件原文、轨迹、凭据、模型输出、预算账本和产物均位于 `.local/benchmarks/research-weekly-loop/gmail-alert-motif-20260928/`，不入 Git。
- 两组都使用 DeepSeek Flash、`reasoning_effort="off"`、同一题的完全相同提示、同一两项工具和各自的 US$2 调用门槛。每组各调用一次搜索和读取。普通组由模型在收到搜索结果后填消息 ID；Motif 组由认证参数边接管该轮。读完邮件后的相关性判断仍由模型执行。

## 观察结果

训练两题和留出认证一题，普通组各用 3 次模型请求，且工具链与参数来源均通过轨迹核验。第一个 serving 版本的三封独立邮件结果如下；费用均由逐请求 API usage 和计价估算，**未与 DeepSeek 控制台账单核对**。

| --- | ---: | ---: | ---: | ---: | ---: |
| d | 3 | 2 | 1 | $0.00601312 | $0.00601794 |
| e | 3 | 2 | 1 | $0.00676462 | $0.00686094 |
| f | 3 | 2 | 1 | $0.00672292 | $0.00656634 |

e 的首次 Motif 尝试在**第一个 API 请求**收到 HTTP 402 `Insufficient Balance`，没有 Gmail 调用或答案；余额补充后使用新的 `retry-1` 目录成功运行，失败记录保留。表中的 e 费用和时间只计成功尝试；完整端到端故障成本还应计入失败等待。第一版三题合计费用仅约省 0.28%，且 e 的 Motif 答案把两篇自己也称为弱相关的论文放进“直接相关”候选，不能据此声称质量合格或有实用成本增益。

在看到第一版结果后，另行冻结更窄的**第二版提示**：明确区分直接相关、相邻参考与不相关，并要求简短的阅读决定；新增三封此前未用于编译的提醒，标为探索性 serving 对照。三题都完成，逐题数据为：

| --- | ---: | ---: | ---: | ---: | ---: | ---: | ---: |

第二版三题合计模型请求 **9 → 6**、Gmail 调用 **6 → 6**，估算 API 费用 **$0.01771515 → $0.01728389**（省 $0.00043126，约 **2.43%**），完成尝试的耗时合计 **36.032 → 34.904 秒**。两组在三题中均判“无直接相关论文”；“相邻参考”和优先阅读哪篇有不同选择。已把邮件可见正文和匿名 A/B 答案放在 `.local/benchmarks/research-weekly_loop/gmail-alert-motif-20260928/blind-review-v2/` 供研究者审核；**尚无独立盲评合格判定**。第二版格式是在看到第一版结果后修订的，不能当作预注册确认性证据。

费用归因：被省掉的中间请求本来便宜，通常只有约 80–100 输出 token，且其输入大量命中缓存。Motif 的最终请求少了一部分缓存预热，单次输入未命中 token 可能增加；最终答案的输出长度也会波动。因此请求数稳定减少，并不保证每题费用或耗时都下降。第二版通过缩短、明确语义交付，三题才都出现小幅费用节省，不能把提示格式的收益归于 Motif。

## 可复现入口和界限

- `scripts/run-gmail-alert-motif-trial.py`：按私有 case manifest 做预览、普通组或 Motif 组。所有付费运行都经 `scripts/run-distil-dsh.py` 的明确预算门槛；`--attempt retry-N` 保留失败尝试。
- `scripts/compile-gmail-alert-motif.py`：核验两条训练轨迹与一条留出轨迹的独立任务身份、精确参数来源和认证产物；库与在线 manifest 留在 `.local`。
- `scripts/prepare-gmail-alert-blind-review.py`：生成私有匿名审阅材料，A/B 映射单独保存。
- 自动测试覆盖：不重放动态搜索根节点、唯一结果才能接管、多结果／版本漂移回退、读前拒绝和错误 ID 拒绝。真实只读 MCP 验证了这些访问边界。

这是一条**有效的模型请求跳过实例**，并在独立邮件上重复出现。其额外价值仍受限：一个事先写好的“按唯一搜索结果读取”脚本也能做这段结构步骤，尚未与同等权限和版本检查的脚本基线比较；大规模费用增益、跨应用迁移、人工审阅时间和合格科研决定成本均未证明。下阶段应在真实跨应用任务中看这些编译边能否与其他 Motif 组合，并把新增变化导致的正确打断作为同等重要的指标。
