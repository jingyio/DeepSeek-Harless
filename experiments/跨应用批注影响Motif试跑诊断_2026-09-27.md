# 跨应用批注影响任务：Motif 在线试跑诊断（2026-09-27）

## 任务与证据边界

两项任务均为研究者要判断“历史批注模拟到来后，现有主张是否需要调整”的只读科研决定。资料留在 Zotero、Obsidian 与批准的 PDF；历史批注不是实际新增事件。第一项 Boltz-2 用于普通 Harness 基线及只读参数链留出认证；第二项 agent serving 用同一冻结来源、提示、模型和工具目录比较普通 Harness 与 Motif。私人原文、日志、密钥和逐请求账本只保存在 `.local/`。

已批准的预算上限为 Boltz-2 US$2、serving 两臂各 US$1。所有调用为 DeepSeek Flash，高推理档；serving 每轮最大输出 8000 token。下表费用是预算代理根据 API usage 记录的估算，不是与 DeepSeek 控制台核对的最终账单。

## 机制发现

1. 从 AIDD 与 Flexibility 两项训练轨迹编译出的 `pin_scoped_zotero_source → read_pinned_zotero_annotation/item` 两条只读参数链，在 Boltz-2 留出轨迹中有精确参数边。它只证明来源 ID 可以从已验证工具结果传给下一工具；不证明省请求或答案合格。
2. 原组在线拦截器没有进入正确的 DSH 模型流作用域。修复为全局 `llm/stream` 监听后，实际 DSH 请求进入拦截器。DSH 在用户提示后还附加工作区说明和运行上下文；原来“恰好一条用户消息”的门槛也会错误放行。
3. 一轮出现 5 个独立的 Zotero 只读候选，旧运行时容量为 4 且同分时拒绝整批。改为容量 8，独立来源按稳定顺序分批；新增 5 来源回归测试。来源版本、参数绑定和只读守卫仍需逐项成立。
4. 结构层在真实轨迹中找到 5 个候选，但本地 Qwen3 嵌入模型对中文任务与英文工具描述只给出约 0.59–0.63，相似度门槛 0.80 拒绝它们。门槛降到 0.55 的一次**任务内诊断**使运行时发出 5 次工具调用、逐一验证版本与参数，并跳过 1 次模型请求。不同意图的局部探针出现分数交叠，不能把 0.55 直接当全局校准值。
5. 首次真正跳过后，DeepSeek 思考模式因合成工具调用没有 `reasoning_content` 而拒绝后继请求。合成流现加入明确标注为“SSS 运行时执行”的来源说明，回传协议通过真实 DSH 完成运行；这不是伪造的模型推理。

修复后诊断的第 3 步由 Motif 一次读取 4 条批注及 1 条书目，确实没有发出 DeepSeek 请求；随后模型仍要选择 PDF 页码、核对论文和写决定。普通 Harness 在同一个模型步骤里同时选择了这些 Zotero 读取及 PDF／笔记读取，因此整个任务的模型请求仍为 **7 对 7**，估算费用和时间反而略高。此任务证实了结构接管与安全回退的可执行性，**尚未证实合格交付的总成本增益**。

## 下一轮判定

先盲评两份完成的决定，核对关键数字与来源，再记录人工修订时间。下一项独立任务应从一条来源未预先给定的批注事件开始：读取批注后才得到附件／论文关系，再按该关系寻找原文和旧主张。这样形成真实的数据依赖，观察普通 Harness 是否自然留下完整的纯结构决策轮次。任务需重新冻结来源、提示、预算和判断目标；不可把本次 serving 的阈值调试当作留出成绩。必须同时比较简单脚本／缓存，并在合格质量下计算缓存计价后的总费用。

本轮运行代码的变更包括 DSH 全局拦截、对注入上下文的提示核验、独立只读批处理、DeepSeek 思考模式回传及诊断账本。测试：相关 Node 测试 14 项、Python 研究试跑与投影测试 10 项通过。真实环境只证明一轮结构读取成功；本地嵌入语义门槛尚无跨任务校准，产品默认仍保持 0.80。
