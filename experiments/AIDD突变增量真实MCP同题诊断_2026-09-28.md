## 为什么原 Motif 没延续合成题的收益

此前六类合成科研决定的十五项配对为 129→74 次请求；两组答案同时可用的九题为 77→45 次请求，费用代理下降约 20.5%。它们使用隔离的模拟 MCP、八个通用只读工具和反复出现的“固定对象 → 读取”参数边，证明有局部结构可接管；质量审阅不是独立人工盲评。参见《科研决定组合的质量门槛评测》。

真实任务只批准一个 Zotero `item`，原认证库却包含从相同 pin 后读取 `item` 和 `annotation` 的两个独立候选。原运行时把它们视为竞争后继，故候选前沿始终为空，**没有发起接管**。真实任务还进行了大量 Python 探索、证据解释和写稿：普通组 27 次、原 Motif 组 17 次 `run_python`。普通组 45 次与原 Motif 组 20 次的差异主要反映自由 Agent 走了不同路线，不能归因为 Motif 省了 25 次请求。

第一次修补错误地把“两条边有共同支持轨迹”当作“两个读取对同一个来源都有效”。诊断 2 中运行时对一个 Zotero `item` 同时调用条目和批注读取；条目成功，批注因类型不符失败，整批为 `bypass_result_unverified`。这不是安全跳过。现已撤掉该合批推断，并在后继选择前核验 pin 返回的 `kind`。针对性 20 项测试通过；诊断 3 对 `item` 只调用条目读取，结果与版本均通过，审计记录 **1 次 `model_request_skipped_verified`**。提交为 `7e45b92`；错误合批曾在 `d1936db` 引入，两次诊断的区别必须保留在记录中。

## 整题效果与质量边界

诊断 3 相对普通组多 7 次 API 请求、约 $0.011263 费用代理和 23.1 秒，虽有 1 次局部跳过，**整题没有净成本增益**。诊断 3 的 `run_python` 为 34 次，普通组为 27 次；工具失败 15 次对 7 次。多次失败的具体原因之一是 Agent 固定了 `idea_current`、`idea_open_questions` 这两份本地 Markdown，却反复把返回的 `kind=text` 句柄交给只接受 `kind=note` 的 Obsidian 读取接口；随后又猜不同的行范围和摘录接口。模型路线没有锁定，无法把每一笔增加精确归因于 Motif；这些计数说明局部跳过被后续探索和错误恢复的波动盖过。不能用原 Motif 的较低总请求数反过来宣称成功，因为其经验证的跳过数为零。

四份答案都报告了 65 行、八靶点等权平均 Spearman 约 0.5297，并区分统计复算与模型重跑、文件名零命中与生物学泄漏。诊断 3 自述旧 Obsidian 状态笔记读取失败，因此原主张的复核不完整；全部答案仍需按封存评审卡和原始资料做研究者审核，不应报告“合格交付成本”。

下一次应先固定笔记读取的授权范围与错误语义，再在**新的独立研究决定**上冻结运行时和评审标准。结构层已经能安全接管真实 Zotero 的一个后继节点，但本题的大部分工作是统计探索与科学判断；若这些轮次仍需模型，不能因合成题的比例推断真实科研任务的总体增益。
