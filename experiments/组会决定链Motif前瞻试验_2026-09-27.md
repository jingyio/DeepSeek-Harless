# 组会决定链：首轮前瞻 Motif 对照（2026-09-27）

## 任务与边界

构造四项相互独立的**合成**研究决定：实验表更新后，核对旧研究主张和文献批注，再形成组会待审稿。每题的数据留在 WPS 可打开的 `.xlsx`、模拟 Obsidian/Zotero 对象中，由只读 MCP 提供带版本的访问。`family_shift` 与 `label_audit` 用于发现局部结构；`hardware_latency` 用于独立认证；`novel_queries` 在编译、认证与相似度门槛固定后用于前瞻对照。第四题没有进入 Motif 编译或门槛校准。

这是合成夹具上的付费 API 试验，不是连接真实 WPS、Obsidian 或 Zotero 的现场试用。四题各自只读，使用 DeepSeek Flash 高推理档；第四题普通组与 Motif 组使用相同的任务文本、六项 MCP 工具和来源版本。每组本地费用上限 US$1，最多 15 个 Harness 步骤。私有原始轨迹、提示、回答、预算账本与 Motif 审计在 `.local/benchmarks/meeting-decision-chain-v1/`，不提交 Git。

## 从历史轨迹取得执行片段

两项训练任务的实际工具轨迹共有三条精确、可追踪的参数边，第三题验证了全部三条。在线执行资格又要求后续工具的全部必填参数由已验证输出绑定，且两端都返回可核对的来源版本；只有 `pin_object.source_id → read_pinned_object.source_id` 符合。筛选规则在 `scripts/compile-meeting-witnessed-edges.py`，没有手写第四题专用 DAG。模型仍须决定固定哪个对象、如何分组计算、如何解释结果。

相似度门槛在前三题上固定为 0.30。它只在已有唯一候选、参数关系成立和来源版本许可时参与执行；第四题运行中实际候选分数约 0.61、0.59。这个门槛针对当前小样本偏宽，不能据此宣称跨领域稳定性。

## 第四题结果

| 组别 | 实际付费请求 | 经结果验证的整轮跳过 | 工具调用 | 缓存未命中输入 / 命中输入 / 输出 token | 估算 API 费 | 端到端耗时 |
| --- | ---: | ---: | ---: | ---: | ---: | ---: |
| 普通 Harness | 8 | 0 | 16 | 5,511 / 25,088 / 5,204 | US$0.00805 | 28.65 秒 |
| Motif 在线执行 | 7 | 2 | 17 | 5,456 / 17,280 / 6,293 | US$0.00929 | 34.86 秒 |

Motif 审计显示两次模型请求被已认证的只读工具调用替代，共接管三次 `read_pinned_object`，工具结果和版本均核验通过。**同题最终付费请求只少一次**；运行路径随之改变，不能把审计中的两次跳过直接当作相对基线减少两次。估算费用反而增加约 US$0.00124（约 15.4%），耗时增加 6.21 秒。上述费用按 API usage 与价格计算，未与 DeepSeek 控制台账单核对。

### 费用和时间归因

逐请求使用量与本地账本可复算以下差额；使用实验账本的 Flash 峰时估价：未缓存输入 US$0.30、缓存命中 US$0.006、输出 US$1.20／百万 token。输出包含模型思考 token。

| 计费类别 | 普通组 token／费用 | Motif 组 token／费用 | Motif 相对差额 |
| --- | ---: | ---: | ---: |
| 未缓存输入 | 5,511／US$0.001653 | 5,456／US$0.001637 | −US$0.000017 |
| 缓存命中输入 | 25,088／US$0.000151 | 17,280／US$0.000104 | −US$0.000047 |
| 输出 | 5,204／US$0.006245 | 6,293／US$0.007552 | **+US$0.001307** |
| 合计 | 35,803／US$0.008049 | 29,029／US$0.009292 | **+US$0.001243** |

因此总 token 虽减少 6,774，费用增加仍完全由输出增加解释；输入费用合计反而下降约 US$0.000063。进入最后一轮写稿前，两组分别花费 US$0.003984 与 US$0.003974，几乎相等。最后一次请求分别花费 US$0.004065 与 US$0.005318，差额 US$0.001254；Motif 最后一轮输出 4,128 token（含思考 2,671），普通组 3,184（含思考 1,848）。这不是“Motif 必然需要更多推理”的证据：两个独立模型会话的文字、调用顺序和最终表述已分叉。

时间上，API 请求累计为 25.617 秒对 31.362 秒，相差 5.745 秒，占端到端差额 6.211 秒的约 92.5%；仅最后一次请求就相差 5.229 秒。其余端到端差额约 0.466 秒，包含本地工具、Motif 匹配和 Quarto 渲染，当前记录不能细分。故本次变慢主要是模型请求耗时，而非已观察到的 Motif 本地调度开销。

路径还出现了不同的错误恢复：普通组有 1 次无效的 `pin_object(claim_id)`；Motif 组在真正接管前有 3 次把对象 ID 传给只接受固定来源 ID 的 `read_pinned_object`。这使两组的后续步骤无法逐轮一一相减，也提示工具参数说明需要更明确。但两个独立会话的早期选择不同，现有一次配对不能判定这些错误由 Motif 插件造成。下一次应冻结更清楚的工具 schema，并在多个独立决定上重复对照，而不能只针对第四题补提示后宣称收益。

两份答案均算对了当前整体 162/240 对 174/240、全新查询 72/120 对 66/120、重复查询 90/120 对 108/120，并暂停旧的“改善全新查询”主张；均明确资料是合成的。Motif 答案给出单一的去重审计动作。普通答案一处把“扩大试点但收窄主张”写成所选分支，同时又说“不扩大”，需要改正。两份都能经 Quarto 渲染，但其正文包裹方式还不是直接可交付的一页简报。以上只是按封存规则所作的开发者核对，**尚无独立人工盲评或修订时间**，不能报告合格交付成本的胜负。

## 简单脚本对照与结论

同一题的普通版本脚本可在 0 次模型请求下完成事件读取、来源固定、复算和相关笔记/批注找回，但会明确停在 `semantic_review_required`；它不能独自交付研究决定。若用“脚本取证 + 一次模型判断”作完整强基线，还须另做同题付费试验；不能把当前 0 请求脚本当作已完成的答案来比较。

本轮证明了**真实 API 请求前**可以按历史轨迹认证的参数边，安全执行跨工具只读步骤并跳过整次模型调用。它尚未证明总费用、速度或合格交付成本有增益。主要限制是 Motif 仅覆盖“固定对象 → 读取”，模型仍要选择统计分组和科学解释；还有答稿格式与盲评工作。下一轮应先固定交付格式和更完整的脚本基线，再在新的独立决定上检验跨工具依赖带来的净收益，保留请求、缓存费用与质量三项指标。
