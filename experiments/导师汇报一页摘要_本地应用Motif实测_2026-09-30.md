# 给导师汇报：MotifAgent 在本地应用中的局部复用（阶段结果）

**汇报日期：2026-09-30。** 当前可以汇报一个有边界的结果：从普通 Agent 的实际工具轨迹中学到的 Motif，在新文件上能够核对目标、接续部分操作，并跳过完整的模型请求。我们已在 **Numbers 和 Keynote 两种真实本地应用**中观察到这种效果；Finder 是没有跳过请求的负例。因此，现阶段证明的是机制在特定任务中可运行，**还没有证明自然科研任务的长期总成本下降**。

**方法与可解释性。** 三组任务都调用运行中的 macOS 应用，读取应用实际返回的数据；测试文件和内容由我们控制，未把旧答案预置到新任务。普通组与 Motif 组使用同题、同模型（DeepSeek Flash，`reasoning_effort="off"`）及相同工具。Motif 来自先前普通 Agent 轨迹的编译与独立认证，不是为每道测试题手写固定流程。它只在目标能从当前工具结果中唯一定位、参数关系可核对且任务匹配通过时接续；多表歧义等情况会停下。Numbers 中一次普通执行把工具调用合并，故 9 次被验证的跳过对应净减少 8 次模型请求。Finder 没有达到匹配门槛，保留了普通 Agent 路径。

**费用边界。** 表中是执行阶段的费用，按每次 API 返回的缓存命中／未命中及输出 token 和本地费率计算，尚未与供应商账单核对；每题只跑了一次。训练、认证、失败试探、开发和人工维护尚未摊入。仅按 Keynote 正式训练与认证的 API 费用，以及这三题的平均执行节省外推，大约还需 **40 道相似任务**才能覆盖这部分 API 训练费用；这不是已观察到的回本。资料是自建夹具，尚未测自然用户需求、长期变化、人工修订时间或完整科研报告质量。

**建议汇报口径与下一步。** 可以向导师报告“在两个不同本地应用中，Motif 对新文件重绑定并安全跳过部分模型请求；一个负例界定了匹配条件”，并展示 Keynote 的合格交付与费用账本。此时无需继续横向增加应用数量。下一轮应选择真实同学会反复做的一类任务，前瞻收集多轮独立请求和来源变化，比较普通 Agent、简单脚本／缓存与 Motif 的合格率、总 API 费、训练摊销、人工修订和耗时；同时检查新歧义或反证是否正确中断旧路径。达到这个门槛后，才可主张实际产品价值和长期净节省。

**后续压缩复测（同日追加）。** 上表是未开启工具结果压缩的原始对照。随后在同九题上增加“无损 JSON 紧凑化”开关，完成普通／Motif × 原始／压缩四条件试验。修正代理后的 Numbers 压缩条件下，普通→Motif 为 **15→6 次请求**、严格质量双方 **3/3**、估算执行费 **US$0.005921→0.004425**；但压缩单独加到普通 Agent 时，三个应用的费用均略升。Keynote 的短结果没有可归因的压缩收益，Finder 仍无跳轮。这是已见题目的单次探索复测，不改写上表冻结成绩；详见[四条件报告](本地应用工具压缩与Motif四条件复测_2026-09-30.md)。
