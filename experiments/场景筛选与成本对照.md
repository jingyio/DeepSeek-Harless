# 场景筛选与成本对照：代码迁移、Deep Research

> 2026-09-24。目标从“先做图”改为“在质量达标时降低每个完成任务的实际成本”。本文件供任务筛选和首轮实验使用；市场需求、性能增益与免费版比较都尚未实测。

## 一、为什么调整场景

手头 ATC 稿件《Make Graphs Great Again》在 PDF 第 10 页的消融中，**只把 motif 当提示词**时，AppWorld 平均 token 从 ReAct 的 204k 增至 243k；让运行时执行可验证的 motif 后降至 130k。该稿件还报告：匹配但只完成部分结构步骤时，token 从 206k 降至 154k；结构执行成功的一组从 180k 降至 79k（PDF 第 10 页）。第 11 页指出主要收益来自运行时结构执行，调度和缓存优化是补充。[本地论文]

这支持一个**筛选假设**：有重复的工具顺序或参数依赖、下一步可由运行时核验、遇到语义不确定性时能回退给模型的任务，更可能省调用和 token。多步、长上下文本身不足以保证收益。稿件结果来自其基准任务，不能直接推断代码迁移或 deep research 的增益。

## 二、场景判断

| 场景 | 可复用的步骤 | 仍需模型判断的部分 | 结果能否核验 | 首轮优先级 |
| --- | --- | --- | --- | --- |
| **明确版本/API 的代码迁移** | 扫描依赖和调用点、套用已知变换、分组运行测试、定位相同类型失败 | 意图不明的调用、跨模块语义变化、失败修复 | 强：编译、测试、静态检查与人工 diff 审查 | **第一优先**。重复结构与验收条件最清楚；避免一开始做无边界的“整个旧项目重写”。 |
| **范围明确的 Deep Research** | 查询迭代、抓取、去重、提取证据、核对引文、按模板汇报 | 判断资料可靠性、发现新方向、综合相互冲突的证据 | 中：引文可查，覆盖与综合质量仍需人工评审 | **第二优先**。选择可核查的技术问题，先测工具和上下文步骤是否真有重复。 |
| 单篇论文摘要与归档 | PDF 提取、字段填写、复制文件 | 理解论文并准确概括 | 中：可人工核对 | 仅作环境和文档工作流试跑；重复决策少，不宜当成本方法的主实验。 |

代码迁移的真实需求是合理假设，但“vibe coding 越来越多，所以一定有市场”还需通过课题组真实仓库、外部开发团队访谈与试用来验证。Deep Research 也应先限定题目和输出标准，避免变成无限搜索和主观报告。

## 三、WorkBuddy 免费版是怎样的基线

截至本日，WorkBuddy 官方定价页列出个人**体验版免费**、每月 **500 Credits**，自动任务基础额度 **3 个**（页面另标“限免 99 个”），默认 Auto 模型调度；这些临时权益应以实际账号页面为准。[WorkBuddy 定价] WorkBuddy 也支持配置自有第三方模型 API。[WorkBuddy 模型配置]

因此要区分两种比较：

1. **用户花多少钱：** 在体验版额度内，WorkBuddy 的现金支出为零。付费 DeepSeek API 不可能在这一区间提供更低的现金价格；要比较可完成任务数、质量、额度用尽后的成本和用户是否愿意迁移。
2. **同模型运行效率：** 若当前 WorkBuddy 账号允许配置同一 DeepSeek API，用相同模型分别运行 WorkBuddy 与 Harness，才能较公平地比较执行框架带来的调用数、token 与结果差异。自有 API 调用仍由该 API 计费，不能与免费内置额度混为一谈。

不能把 WorkBuddy Credits 直接换算成 DeepSeek token；记录每个任务前后的 Credits 和实际套餐限制。价格与限免规则可能变化，采购前重新核对。

## 四、SSS 已有一次成本样本

`AutoTool.pdf` 的论文卡片试跑使用 `deepseek-flash`：Harness 会话日志显示 **13 次模型请求**、36,886 个非缓存输入 token、336,512 个缓存读取 token、6,626 个输出 token，合计 380,024 个 token。运行确实完成阅读卡片和归档预览，但抽查发现一处页码错误，已经修正。运行时并未与 WorkBuddy 同题比较。[首次试跑记录]

按 DeepSeek 官方当前 Flash 公布的缓存命中、非命中和输出单价粗算，此用量约为 **0.0105 美元（非高峰）或 0.0210 美元（高峰）**；这是估算，不等于账单，且仅统计会话 `assistant/message` 中可见的用量，未覆盖可能存在的额外标题生成或其他服务成本。[DeepSeek 定价] 这个例子说明“token 总数很大”和“现金费用很高”不是同一个判断：缓存命中占了大部分输入。但 13 次请求完成一篇论文卡片，值得继续分析是否有多余步骤。

可在 SSS 目录运行 `npm run usage:latest` 获取最新会话同口径用量。`reasoningTokens` 已包含在输出 token 中，不要重复相加。

## 五、首轮实验矩阵

| 组别 | 目的 |
| --- | --- |
| A WorkBuddy 体验版 Auto | 现实中的免费产品质量与可用性基线；记录 Credits、额度、耗时、人工修正。 |
| B WorkBuddy + 同一 DeepSeek API（账号允许时） | 尽量隔离模型差异，比较 WorkBuddy 与 Harness 的运行流程。 |
| C DeepSeek Harness 原生流程 | 测没有优化时的实际质量、模型请求数、缓存结构与费用。 |
| D Harness + 简单优化 | 确定性脚本或 codemod、检索与上下文压缩、缓存/去重、简单模型路由；作为真正的成本对照。 |
| E Harness + 可执行图/结构（条件组） | 只在任务轨迹出现可核验重复步骤时实施；必须胜过 D，且不降低质量。 |

先各选 **1 个真实代码迁移任务、1 个范围明确的 Deep Research 问题**做可行性筛选，记录失败。通过后扩成多个任务和重复运行；WorkBuddy 免费额度不足时，不强行跑满对照。

### 代码迁移任务定义

保存仓库快照、旧 API/版本、新 API/版本、迁移指南、可运行测试与成功标准。先限定一种迁移（如接口更名、参数格式或数据结构变化），让多个调用点暴露可重复步骤。完整重写与架构重构另列为高语义难度任务。验收至少包含编译/测试通过、目标调用点覆盖、回归与人工 diff 审查。

### Deep Research 任务定义

明确一个需要多轮检索的技术问题、时间范围、证据来源标准和报告结构。验收包含关键问题覆盖、每条重要结论可追溯到来源、无虚构引用、人工纠错时间；同时记录搜索/抓取/去重/提取/综合各阶段的 token 与调用数。

## 六、决策规则

- **先看质量门槛。** 任务结果不合格时，单纯减少 token 没有产品价值；计算每个合格任务的总成本，包括重试与人工修正。
- 若免费 WorkBuddy 已满足轻量个人需求，承认这一事实；寻找额度外的高频任务、团队协作、可控私有流程或垂直迁移质量等付费理由。
- 若简单脚本或上下文优化已达到同等收益，产品采用简单方案；论文贡献再判断是否需要图结构。
- 只有在结构方法能对重复步骤做可审计的接管，并在多个真实任务上稳定优于简单优化时，才把它作为主方法。
