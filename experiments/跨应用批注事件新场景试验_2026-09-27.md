# 跨应用批注事件：新来源簇试验（2026-09-27）

本轮按照用户纠正，换用《The Flexibility Trap》、四条真实 Zotero 高亮及 Obsidian 中另一条“最小必要结构约束”主张，**没有重用 AIDD 抗体论文或那条高亮**。为试验增量交接，任务把已有高亮模拟为此时向 Agent 释放的新资料；真实批注时间早于当前笔记。因此本轮是历史材料的模拟事件和开发诊断，不是前瞻真实增量，也不能算独立留出效果成绩。论文公开版本见 [arXiv:2601.15165](https://arxiv.org/abs/2601.15165)。

来源预览只开放一篇 19 页 PDF、一段 Obsidian「当前状态」和 Zotero 的论文条目及四条批注；用户确认后才把所需摘录交给 DeepSeek Flash。总预算上限 US$2，只读，无外部写入。原始来源 ID、完整轨迹和答案留在 `.local/benchmarks/research-weekly-loop/independent-annotation-candidate-20260927/`。

Agent 自主调用了四次 `locate_pinned_pdf_quote`，每次都在批准 PDF 中得到唯一匹配页；随后它选择 `read_pinned_pdf_pages` 或公开 arXiv 页读取，**没有调用 `read_pinned_pdf_match`**。严格轨迹审计的安全跨轮目标和可跳过完整模型轮次均为 **0**，实际在线 Motif 跳过请求也为 **0**。不能把上一条 AIDD 开发试验的候选跳过算到这次任务。

工具可用性有实际影响：Agent 两次请求超过批准笔记片段末行、一次从全文第 1 行重试，另两次请求 3 页而接口上限为 2 页。这些错误引出额外恢复轮次。另一方面，四次唯一定位已经给出了可审计的页码和 `match_id`，但 Agent 使用的是另一条读页路径；要评估 Motif，需要从真实轨迹研究这种参数流，而非在提示词里强迫它选择匹配页工具。

## 交付质量门

Agent 的主结论是维持“合理但尚未证明”的原主张，并限制从 dLLM 生成顺序到 Agent 结构执行的外推。这个判断**尚未经领域盲评**。答案中有一处已核实的来源关系错误：它把 Zotero 批注的直接父附件键当成与论文条目冲突；本地元数据表明该附件的 `parentItem` 正是批准的论文条目。原始答案保留不改，私有审阅记录单独指出错误。本轮不据此宣称合格科研交付或成本增益。

下一轮应先消除受限读页／读笔记接口的易错调用，并让工具返回清楚的 Zotero 附件→论文条目关系；再在不同任务上收集自然调用链。若 Agent 继续利用定位返回的页码直接读页，则需要以来源版本、唯一命中和参数来源证明该路径是否可编译；不能事后把它重写为已发生的 `match_id` 路径。与简单预取和确定性脚本的对照仍未完成。
