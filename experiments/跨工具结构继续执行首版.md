# 跨工具结构继续执行：受限首版

本版让在线 DSH 适配器从已认证只读 Motif 的实际工具结果继续执行。它不预写科研任务的工具 DAG，也不把单个任务里的重复调用冒充跨任务认证。

## 执行边界

1. 运行时观察模型或 Motif 已经成功执行的工具调用，保留调用 ID、输入、输出、任务版本和来源版本。允许其他工具调用交错，但最近历史仍限 12 条。
2. 仅对 `motif_skill_library` 已认证并导出的参数边寻找后继。每个必填参数必须来自已观察的认证输出字段，或来自经过结构化任务输入验证的字段。目标工具必须仍在 DSH 当前工具集合，schema 相符、只读，且目标来源版本已在任务批准集合中。
3. 不同起点的后继可以合在**同一次 DSH 工具调用流**，最多 4 项；同一起点有不同后继候选时回退给模型。每项结果单独核验，整批均成功才记一次 `model_request_skipped_verified`。失败后该会话停止自动接管。
4. 某一批结果成为下一层输入时，适配器可再次拦截下一个模型请求，直到出现参数缺口、工具缺失、版本变化、语义歧义或已完成结构片段。科研判断仍由模型或人完成。

结构化任务的 `source_versions` 现允许每个工具列出至多 32 个具体版本，以便同一工具在不同获批来源上复用；每次后继调用仍绑定产生其参数的那个来源版本。首个工具可由模型选择并执行，其随机 `source_id` 无须在任务开始前出现。

## 代码节点与外部工具的边界

Motif 中的参数提取、字段映射、格式校验、版本比对、就绪节点选择和结果合批由运行时代码执行，参数是上一步的已核验输出和任务输入；这些计算不需要伪装成 MCP。当前 `bindNext`、`matchingPrefixes` 和 `proposeReadyBatch` 就承担了这类代码操作。读取 Obsidian/Zotero 的实时内容仍要调用对应应用接口，才能获得该应用返回的版本与错误信息。`read_pinned_approved_note_excerpt` 是一次受限的外部读取：它在服务端用代码把批准行段变为读取参数，没有让模型选择行号。后续若从真实轨迹发现新的纯计算步骤，可把它编译成带输入输出契约和代码版本哈希的本地算子；不能在执行时直接运行模型临时生成的任意代码并将其计为已认证 Motif。

## 与真正并行的区别

同一轮返回多项工具调用，首先减少**层间模型请求**。当前本机 `@deepseek-ai/dsh-mcp-client` 注册的工具没有 `isConcurrencySafe` 声明，DSH 对它们按独占方式执行；本版没有证明这些 MCP 请求会同时在墙钟时间运行。MotifAgent 冻结源码移植的已认证产物仍有顺序边和单节点并行组。本版仅合并**不同已认证片段**中参数已就绪、起点不冲突的后继；同一 Motif 内部的并行组需要从真实轨迹证明两个节点在同一次模型输出中被同时决定，再重新编译、认证并更新运行器，不能只删顺序边。

## 当前科研任务的具体修复与验证

单条 AIDD 批注试验中，模型多次因 Obsidian 行范围参数出错而重试。新增通用只读工具 `read_pinned_approved_note_excerpt`，由任务授权行段确定读取范围，仍检查 scope、来源哈希和版本。无模型连接实测在该任务的两份获批笔记分别返回 23 行和 49 行，与固定来源哈希相符。

JS 协议测试验证了两个不同版本的来源在一次工具流中读取、结果乱序返回时只记一次模型请求跳过、下一层依赖继续执行、同一起点的不同后继回退、版本漂移和失败回退。Python 测试验证了新工具的权限、行范围和 MCP 暴露。**尚未在真实付费科研任务中测得 Motif 的模型请求减少**：当前 `locate → read` 只有同一来源簇的一条轨迹，未满足独立任务认证门槛；普通预取和更好的工具接口也必须作为单独基线比较。
