请系统检查我上传论文中的全部参考文献及正文引用，并生成 PDF 格式的《参考文献检查报告》。

## 一、检查任务

1. 提取完整参考文献表，保留原编号和顺序。
2. 逐条核验文献是否真实存在，并核对：

   * 标题、作者、年份；
   * 会议、期刊或出版社；
   * 卷期、页码或文章号；
   * DOI、arXiv编号及其他唯一标识符。
3. 检查正文引用与参考文献表是否对应，包括：

   * 列而未引；
   * 正文引用无对应条目；
   * 重复条目；
   * 编号重复、跳号或越界；
   * 未解析引用键；
   * [?]、[22?] 等异常引用。
4. 检查预印本、会议版和期刊扩展版的对应关系，避免版本混淆。

## 二、核验方法

对每条文献依次执行：

1. 规范化标题、作者和出版信息；
2. 使用完整标题检索；
3. 使用第一作者与标题关键词交叉检索；
4. 核对 DOI、arXiv 编号或其他唯一标识符；
5. 查找正式出版页面、会议页面或论文首页；
6. 比较当前著录与权威来源；
7. 判断其属于预印本、会议版、期刊版、技术报告或图书；
8. 记录核验来源、信息差异、真实性状态和修复优先级。

报告不展示冗长搜索过程，只保留足以复核结论的来源、关键差异和最终判断。

## 三、来源与版本规则

优先使用原始或权威来源，包括：

* 出版社、期刊和会议官方网站；
* DOI/Crossref；
* ACM Digital Library、IEEE Xplore、Springer、ScienceDirect；
* USENIX、SOSP、EuroSys、ASPLOS、ISCA、MICRO、HPCA、SC、SIGCOMM、SoCC、Middleware等系统会议官方论文集；
* VLDB、SIGMOD、ICDE等数据库会议官方来源；
* NeurIPS、ICML、ICLR、AAAI、IJCAI、ACL、EMNLP、NAACL、KDD、WWW等会议官方来源；
* PMLR、ACL Anthology、OpenReview、DBLP；
* arXiv。

Google Scholar只能用于发现线索，不能作为唯一依据；若其信息与正式出版页面冲突，以正式来源为准。

版本处理遵循以下原则：

1. arXiv论文已有正式会议或期刊版本时，优先核验并建议引用正式版本。
2. 正式版本存在时，不能只以“arXiv编号可解析”作为通过依据。
3. arXiv年份与正式发表年份不同，应采用正式发表年份，并说明两者关系。
4. 正式版与预印本的标题、作者或出版信息不同时，以正式版本为准。
5. 会议版和期刊扩展版并存时，应根据论文实际引用内容判断，不能自动用期刊扩展版替换会议版。
6. 尚无正式版本时，arXiv可以作为主要来源。

## 四、真实性状态

每条文献使用以下状态之一：

* **已确认**：权威来源可确认文献存在，主要信息一致。
* **已确认，但需修正**：文献真实存在，但存在实质性著录错误、版本选择不当或影响识别的信息缺失。
* **存疑**：找到相似记录，但存在无法消除的重要冲突，或缺乏足够权威证据。
* **未找到**：经过标题、作者、标识符和出版来源等多种方式检索后仍无法找到。

真实性状态与修复优先级必须分别判断。“已确认”不代表引用信息完全正确，“已确认但需修正”也不代表文献为虚构。

## 五、修复优先级

对每个问题标注以下优先级之一：

### P0——严重风险，必须立即处理

包括但不限于：

* 未找到或高度疑似虚构、AI幻觉的文献；
* 正文引用指向不存在的参考文献；
* DOI、arXiv编号或标题实际对应另一篇论文；
* 作者、标题和来源组合无法对应任何真实工作；
* 引用错位导致正文事实由错误文献支撑。

此类问题可能影响学术诚信或论文可信度，必须在提交前解决。

### P1——事实性错误，提交前必须修正

包括但不限于：

* 标题、作者、年份、会议、期刊或出版社错误；
* DOI、文章号、卷期或页码指向错误记录；
* 将不同工作错误合并为同一文献；
* 正文引用编号错误、越界、未解析或对应关系错误；
* 把会议论文误写为期刊论文，或把期刊论文误写为会议论文。

此类问题会使读者获得错误的文献信息，或无法准确定位原文。

### P2——版本选择问题，建议提交前修正

包括但不限于：

* 已有正式会议或期刊版本，仍仅引用arXiv预印本；
* 使用预印本年份、标题或作者列表代替正式版本；
* 会议版与期刊扩展版混淆；
* 引用版本与正文实际讨论的内容不一致。

若论文明确讨论预印本独有内容，可保留预印本，但必须说明原因。

### P3——著录完整性问题，按格式要求完善

包括但不限于：

* 缺少页码、文章号、卷期、DOI或出版社信息；
* 会议名称、期刊名称或作者格式不完整；
* 缺少不会造成文献误认的可选字段。

仅当缺失影响唯一识别、违反目标格式或降低可追溯性时，才列为问题。单纯大小写、标点、会议简称或可接受的格式差异，不应列为实质错误。

如一个条目同时存在多个问题，以最高优先级为该条目的总体优先级，并在说明中列出其他问题。

## 六、报告结构

### 1. 检查摘要

集中展示：

* 参考文献总数；
* 已确认、已确认但需修正、存疑和未找到数量；
* P0、P1、P2、P3问题数量；
* 正文引用问题数量；
* 提交前必须处理的编号或位置。

摘要应明确区分“学术诚信风险”“事实性错误”“版本问题”和“著录完整性问题”。

### 2. 提交前修改清单

按 P0 → P1 → P2 → P3 排列：

| 优先级 | 编号或位置 | 问题 | 核验结果 | 建议修改 |
| ------ | ---------- | ---- | -------- | -------- |

P0和P1放在最前，并明确标注“提交前必须修正”；P2标注“建议更新为正式版本”；P3放在最后，不得与幻觉文献或事实错误并列呈现。

如有必要，为P0、P1和P2条目给出可直接替换的规范引用。正常条目和仅有轻微格式问题的条目不重复生成完整引用。

### 3. 正文引用对应检查

简洁汇总：

* 列而未引；
* 正文引用无对应条目；
* 重复条目；
* 编号重复、跳号或越界；
* 未解析引用键或异常引用；
* 容易被误判为引用的代码、数组或公式。

正文引用错误应根据影响程度标注P0或P1；若未发现问题，应明确写明“未发现”。

### 4. 逐条核验结果

按原编号和顺序覆盖全部参考文献：

| 编号 | 文献简写 | 状态 | 优先级 | 核验来源 | 核验说明 |
| ---- | -------- | ---- | ------ | -------- | -------- |

为减轻阅读负担：

* 正常条目标记“—”，核验说明控制在一句话内；
* 问题条目标明P0–P3，并指向修改清单；
* 核验来源写权威平台名称及来源编号；
* 不在逐条表格中堆放长网址；
* 不重复附上完整原参考文献表。

### 5. 核验来源索引

在报告末尾集中列出：

| 来源编号 | 权威平台 | 链接 |
| -------- | -------- | ---- |

每条文献至少对应一个可复核来源。相同性质的来源无需重复堆叠。

### 6. 总结

分别总结：

* 是否存在虚构、未找到或学术诚信风险；
* 是否存在事实性引用错误；
* 是否存在需要更新的正式发表版本；
* 是否存在一般著录完整性问题；
* 正文引用是否完整对应。

最后按P0、P1、P2、P3给出“提交前最低修改清单”。

## 七、输出原则

* 完整覆盖全部参考文献，不得遗漏、合并或重新排序。
* 所有结论必须有可复核依据。
* 不得虚构DOI、页码、作者、会议或出版年份。
* 不评价论文创新性、实验质量或录用概率。
* 正常条目保持简洁，详细解释集中用于P0–P2问题。
* 不得用大量P3问题掩盖更严重的真实性、事实性或版本问题。
* 正文主体突出风险等级和修改建议，完整来源放在报告末尾。
* 报告页数由实际内容决定，不以固定页数为目标。
* 若上传了参考报告，可参考其信息层级和视觉风格；未上传时采用清晰、正式、易读的学术报告版式。
* 生成PDF后逐页检查，确保无乱码、重叠、裁切、表格越界、编号遗漏或统计不一致。

最终只交付检查完成的 PDF 文件。
