# 科研 PPT 设计

把用户提供的材料组织成适合听众与用途的演示稿。论文数、页数和页序由任务决定；不固定为三篇论文、十五页或某一种报告。使用本场景实际提供的 MCP 和 JSON 契约，不自行安装工具或执行外部脚本。本 Skill 是设计指导，不是学得的 Motif；加载它不证明质量或成本改善。

## 先确定听众要作出的判断

- 从任务要求提取用途、听众、总页数、语言、模板和必须保留的内容；页数包含封面与结尾。输入不明时先读取批准材料，不能用猜测填充研究事实。
- 为全稿明确一个中心问题，例如「该方法为何有效」「这些方法在哪些条件下可比较」「新增证据如何改变旧结论」。根据材料选择问题—方法—证据—边界、比较—选择依据、或变更—影响—待验证事项等叙事；这些是可选组织方式，不是固定页序。
- 多文档任务应围绕相同问题组织对照，保留方法、数据、指标、训练规模和评测条件的差异。各自论文中的最高分不能自动排成公平排行榜。
- 内容更新时说明新证据改变了什么、保留了什么、仍缺什么。仅改风格的任务保留原内容，不借设计改写科学结论。

## 每页只承担一个主要信息任务

标题写清本页问题或有来源支持的结论，避免连续使用「背景」「方法」「结果」而没有具体信息。可选 `takeaway` 给出一个短结论（最多 90 字符），帮助听众带走信息；不要与标题、正文逐字重复，也不要把未证实的推断写成肯定结论。

正文保留判断必需的条件与限制。复杂定义、公式推导、完整实验设置和补充解释放入 `notes`；影响结论成立范围的条件仍须在正文出现，不能全部藏在备注中。封面、章节页也要有材料依据，避免为凑页数加入空页、重复总结或大段致谢。

## 根据证据选页面结构

| 信息任务 | JSON 结构 | 设计要点 |
| --- | --- | --- |
| 解释问题或少量结论 | `layout: "content"`，短 `bullets` | 一页最多 4 条，使用并列短句；必要时补 `takeaway`，不要缩字号塞长段落。 |
| 解释机制或先后关系 | `layout: "process"`，`process.steps` | 2–5 步，每步 `label` 最多 28 字符、`detail` 最多 90 字符；`bullets: []`。步骤与连接表达实际关系，不给无顺序的概念强加因果。原生框与连接保持可编辑。 |
| 展示论文架构、定性结果或原图证据 | `layout: "image"`，真实 `image` | 用图注和页码定位完整图件，图片等比放置；正文只解释要看的区域和结论。复杂小字图优先单图页，裁剪不能删除影响解释的图例或条件。 |
| 同一口径的数值结果 | `layout: "chart"`，原生 `chart` | 柱状图比较离散类别，折线图表达真实有序变化；标明单位、方向和条件。无可靠数值就不用图表，不能从趋势猜数字。 |
| 精确数值或多维差异 | `layout: "table"`，原生 `table` | 精选列和行，表头写清单位；正文指出一项值得关注的差异。过密时精选信息或在允许页数内重新分配，完整细节放 notes。 |
| 两个方案的相同维度对照 | `layout: "comparison"`，`comparison.left/right` | 两边用相同维度、相近粒度；页级 `bullets: []`。明确不可比条件与各自适用边界。 |
| 开始或必要的章节切换 | `title` / `section` | 用短句交代主题和研究问题，控制占用页数；短稿可直接进入内容。 |

一个页面只选择一种主体结构，不同时提交 `image`、`table`、`chart`、`comparison` 或 `process`。不要为多样性强行插入无证据的图表；也不要把所有机制、比较和结果都退化为项目符号列表。

## 信息层级与可读性

- 沿用 `academic` / `lab` 的字体、配色、边距和对齐；模型提交内容及支持的结构，确定性渲染器安排几何。不能向 plan 添加未支持的坐标、字体、颜色、动画或母版字段。
- 标题、主体证据、短结论与来源形成清楚层级；强调一个主要证据，不依靠全页加粗或大量颜色制造重点。相同方法与指标在各页使用一致名称和单位。
- 留白用于分组，相关元素靠近；图片不拉伸，复杂图不要与过多正文争夺空间。表格或图件加短解读，不能只放一张读不清的图让听众自行猜测。
- 表达简洁仍需准确：不要把相关性改成因果，把单数据集结果改成普遍结论，把「部分条件下更好」缩成「全面领先」。幻灯片不出现 API、schema、JSON、MCP、layout 等实现术语，除非用户报告主题确实涉及这些概念。

## 科学来源与 JSON 契约

每页必须有至少一条 `sources: [{"source_id": "实际返回的句柄", "page": 1}]`，且内容得到该页或所列页面支持。`notes` 记录图表出处、关键实验条件、推断的依据和局限。图片标识只来自相同来源的真实工具返回；无完整图件不能把素材片段标成整张 Figure。

过程页示意如下；占位句柄必须换成工具实际返回值，步骤必须根据材料改写：

```json
{"title":"本页的机制或关系","layout":"process","bullets":[],"takeaway":"来源支持的短结论","process":{"steps":[{"label":"来源中的第一步","detail":"该步骤的作用与条件"},{"label":"来源中的第二步","detail":"与前一步的真实关系"}]},"sources":[{"source_id":"实际句柄","page":1}],"notes":"步骤依据、必要条件与局限。"}
```

`takeaway` 是可选内容；`process` 只用于过程页。其他页面严格遵循场景提示与工具契约。不要提交示例句柄、示例数值、未读取的来源或不支持的字段。

## 用真实结果修正

生成后完成实际检查与服务器真实渲染。检查分开记录：内容与来源是否准确、叙事是否适合听众、文字与术语是否正确、视觉层级与可读性、PPTX/PDF 内容与页数是否一致。不要自编分数宣称合格。

发现文字溢出或过密，优先删去重复话、缩短句子、把次要细节移至 notes；保留条件、来源与规定页数。图件不可读则调整结构或重新选取准确完整的图，不能补造图中信息。依据返回的具体诊断修正，不把通用错误当成权限故障。

程序检查通过只证明已检查的文件、文字、页数或边界项；元素遮挡、细小图字、科学解释与审美仍需逐页审阅。无法取得预览或完成检查时明确说明，不宣称已视觉验收。交付路径、真实限制和未评审项如实报告。
