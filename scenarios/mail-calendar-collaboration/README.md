# 邮件与日程管理 Agent

Email & Calendar Agent。场景围绕日常信息与事务处理：重要事项提醒、邮件跟进、会议安排、订阅筛选。用户可以提出临时需求，也可在后续配置每日检查。2026-10-10 按用户审阅意见收敛为先展示实际用途，再验证 MGGA 是否降低模型控制成本。

成功先看有没有漏掉重要事项、误用旧截止、催促已解决的邮件或提出冲突安排。即使暂不启用 MGGA，也应值得使用；结构复用和省费需要真实轨迹与对照支持。

## 第一批 Demo

打开[任务审阅册](review/tasks.md)。用户已确认其作为第一阶段 Demo 验收集；确认的是验收设计，尚未完成工具或真实任务验收。第一批含 8 个合成任务版本，优先下面四个核心需求和无需行动对照；不是 8 个独立真实决定。

| 优先级 | 任务 | 用户价值 |
| --- | --- | --- |
| 核心 | B01 DDL 变更 | 识别最新截止，核对日历中的旧提醒，给出变更预览 |
| 核心 | B02 邮件跟进 | 按最新回复判断谁应行动，避免机械催促 |
| 核心 | A02 会议冲突 | 核对双方约束，准备可审阅的协调方案 |
| 核心 | A03 邮件改期、日历未同步 | 找出不一致，准备更新预览 |
| 简单对照 | A01 无冲突 | 正确说明无需额外行动 |
| 自然变化 | D01 DDL 未变、D02 所需回复已收到、D03 会议取消 | 正确结束，不重复建提醒、草拟催促或重新约会 |

同目标环境变体不凑成独立训练/认证样本。真实实例化只采用实际存在的来信、日程与需要，不为工具链增加步骤；Baseline 可批量读取、并行执行或一轮完成。

## 使用边界与评测

论文通知只初筛题录/邮件摘要、身份和版本；深读 PDF、知识库管理、PPT、数据分析和论文生产由其他场景负责。每日检查和新邮件触发尚未接入，本次没有创建后台自动任务。

第一阶段让原生 Harness 在真实来源范围自然完成任务，先评交付质量，再审计实际局部重复和完整控制请求。存在可认证的机会后才编译 Motif，先 shadow、再冻结受限 execute 范围。研究问题是从轨迹学习的结构能否减少控制请求和维护成本，不能把手写场景流程或压力条件冒充自动学习优势。

工具顺序、最低轮数和强制统一输出均不规定；一次语义判断即可完成的任务，不人为拆成多轮。Workflow 对照允许动态分支、模块选择和组合。质量、学习/选择/绑定/恢复费用与人工维护分别记录，见[验证协议](review/protocol.md)和[Workflow 对照](review/workflow-comparison.md)。

`tasks/*.md` 为 Agent 题面；`review/tasks.md` 与 `review/criteria.json` 为人审资料；`review/fixtures.json` 分离初始来源和未来诊断事件；`task-index.json` 与 `review/checksums.json` 为版本索引。它们不是运行时配置或 Motif 库。

当前没有真实 MCP 或 `scenario.json`，不能直接执行；旧邮件/日历连接器位于本地 archive，尚未迁移，缺口和完成标准见[工具就绪情况](tool-readiness.md)。后续复用现有 Harness、Python 离线编译和 TS 在线插件，不另建 Agent 循环。发送邮件/推送、修改日历与事项仍需权限、预览和确认，本包只产出待审方案。
