# 邮件与日程管理 Agent 验证协议

## 当前优先顺序

先完成可用的日常事务 Agent，再评 MGGA 额外收益。第一批是 B01/B02/A02/A03，A01 为无需行动对照，D01/D02/D03 为自然环境变化；C01/C03 后置为组合测试，B03 为可选产品能力，C02 暂缓，R 组仅后续压力诊断。变体和续段不凑独立真实决定。

首批真实 Demo 先验收时间/事项正确、没有遗漏、草稿可审阅、无需行动时能结束，并记录人工修订。随后审计 Native 自然轨迹；只有反复出现的可认证结构确实对应完整控制请求时，才进入省费验证。订阅筛选一轮完成属于产品可用性结果，不人为拆轮或强求贡献 MGGA 收益。

每日检查与临时任务复用能力是后续产品入口规划；当前未接事件源或后台调度。R 的故障注入不混入首批成功率、使用频率或主要省费结果。全部合成结果与真实前瞻分别报告。

## 假设与范围

MGGA 在邮件和日历场景中，可以从不同目标的正常轨迹发现局部结构，让后续目标按运行时信息选择、复用并组合这些结构，而不必命中一条完整历史 Workflow。待验证的是结构如何生成和适应；完成每日汇总不是充分证据。

A/D 组控制用户目标、改变环境；B 组改变目标，观察共享片段；C01/C03 保留完整目标/有依赖路径用于后续组合留出，C02 暂缓；R 组在诊断中释放新的用户指令、回复或权限变化。环境变体和 R 续段不作独立真实决定。

全部当前材料为合成审题样例，尚无真实训练、认证或效果任务。论文仅使用通知/摘要/身份信息；知识管理、全文研究、PPT、数据复算和投稿均不在范围内。前版每日简报可以作为简单辅助任务，不支配本次目标和输出格式。

## 真实资料实例化

研究者先选真实需求、时间切点和允许的邮件标签/线程、日历、事项状态与偏好。先元数据预检并圈定访问范围，随后读取内容；不为凑路径编造真实订阅、来信、承诺或会议。来源留在 Gmail/Calendar，通过授权工具取得新鲜对象 ID、版本和时间，不提前拼成一个命令行即可解完的大文本包。

将 Agent 可见目标/权限/已释放事件与封存评审资料分开。C 组具体资料和评分答案在模型训练、library 编译及 Workflow 人工实现前封存。当前审阅册向研究者公开，不能把它整体加入任何模型上下文。

R 事件不预先加载到模型：来自真实到达时刻/用户改指令的事件按原时间释放；合成故障单列诊断。指定“待审方案已经形成、尚未确认写入”作为故障注入点，只用于恢复诊断，不能人为建立业务工具阶段屏障来制造依赖或请求。未到该注入点则记录未触发。

## 先审计 Native Tool Calling

复用现有原生 Harness、MCP 和工具生命周期，不规定搜索词、逐项调用顺序或最低调用数。允许批量、并行、无需读取即结束和不需要草稿。至少从不同真实决定取得同类参数关系的两项训练见证和一项独立认证，之后再安排独立效果任务。

第一轮统计三件事：

| 观察项 | 记录方法 | 不算证据的情况 |
| --- | --- | --- |
| 实际路径多样性 | 保留输入输出依赖、决定后继的证据/条件、提前结束与恢复；并行合法顺序合并为同类路径 | 仅 task_id/日期不同，或只交换可并行调用次序 |
| 共享局部结构 | 按工具类型、契约和参数来源检查可重新绑定边/连通片段；版本/权限守卫保持 | 同一事项的三个世界、同题复跑、关键词相似或人工步骤列表 |
| 独立模型控制决策 | 按完整上游请求检查哪些响应仅做已能验证的调度/传参 | 该轮还决定论文相关性、收件人、时间偏好、承诺或包含未覆盖工具 |

资料变化却路径不变并非一定失败，但不能用它证明结构动态性。相同目标有无需执行后继的情况时，应允许正确结束；不能为了命中库强行查询、草拟或推送。

## 学习与组合评测

1. 先冻结首批真实来源、质量门、Native 配置，审计实际重复。没有可认证结构时保留有用的产品任务，但不对该任务宣称接管收益，不增加伪复杂性。
2. 以正常训练轨迹和独立认证构建 library；本包中的片段标签和期望条件只是评审假设，绝不直接编译成库。动态搜索采用新鲜已观察结果作锚点，多候选选择和语义信息提取仍由模型负责。
3. 第二批 C01/C03 完整目标/依赖路径必须从训练和认证排除。运行前用实际轨迹签名复核完整路径是否出现；出现过则失去组合留出资格，仍可计其他诊断。C 不因措辞变化成为新任务；C02 不进入当前组合主评测。
4. 每个运行固定库、代码、工具/schema/order、输入时点和预算。先评下一任务再学习新正常轨迹，永久留出不回流训练。Runtime 自己生成的轨迹不能为自身认证。
5. 先 shadow 验证请求前候选与完整结果，明确事后覆盖/潜在机会/实际跳过。按当前最新要求暂停新的自动execute测试，后续接管须另行明确范围与预算；本轮构建未授权新的外部写操作，也未启动执行。

模型可以在本来必要的语义决策中给出选定对象和结构化输入，Runtime 接续确定性片段；为匹配专门增加的 selection 模型请求计入净收益。当前代码尚无通用跨 Motif 组合和分支条件学习，新增能力需要小步实现与回归，不能把任务描述当成果。

## 对照与质量

采用 Native、允许动态分支的 W1、多模块组合的 W2、MGGA shadow 与受限 execute；整链 Replay/简单程序只作辅助对照。具体公平规则见 [Workflow 对照](workflow-comparison.md)。同组间模型、工具能力、schema/order、权限、批量/并行、缓存/增量同步、输出视图和输出限制保持一致，变化则新编号并另做消融。

先盲评结果与待审材料，允许多个合理处理方式：无需行动、草拟澄清、提出时段、暂缓、承诺受限或交还用户。重大错误包括错误 DDL/时区、已完成事项继续催促、改期未核实、冲突时间被承诺、撤回消息内容作为现行指令、权限失效仍执行、实际写入却无确认。

审批停点按一阶段交付验收：只有待审草稿/变更预览时称“已准备”，不称“已发送/已修改/已推送”。确认不能被 learned Motif 跳过，后续真实写入只执行一次，其他对照留在预览以免重复发信。

## 成本和否定条件

逐决策记录用户目标与变化、执行模式、库/工具/来源摘要、绑定、分支来源、选定 Motif、参数依赖与回退；真实模型请求、缓存输入/输出 token、学习/选择/恢复用量、费用估算/账单核对、人工修订与维护时间。为未完成运行保留费用，不清零预算、不只选成功低费重试。

20% 是项目首个净调用目标而非本场景承诺。质量、动态路径/组合正确性、实际调用与维护成本分开报告。若路径多但重复很少、结构对应的整请求很少、必须手工写全图、目标变化后误沿用、净节省被恢复抵消或 W2 同样好且更便宜，则不足以支持自动学习架构的额外价值。

本次只产生审阅包：真实请求 0，外部写入 0。后续服务器运行加载 `.local/remote-env.sh`，沿用真实 DeepSeek API 测试授权与 `reasoning_effort="off"`，预先冻结实际累计预算/请求/输出限制。新任务、事件或重启不重置已有额度；新场景总预算尚未确定，不能挪用旧论文余额冒充新预算。
