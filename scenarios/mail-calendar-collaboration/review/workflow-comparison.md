# 邮件与日程管理 Agent 的 Workflow 对照

先做首批真实 Demo 的交付与 Native 轨迹审计，再启动本对照。C01/C03 是后续组合候选；C02 暂缓。压力诊断单列，不代表产品高频收益。

## 竞争问题

我们研究一个场景中的多种需求，而不是只优化每日简报或会议协调的一条业务链。竞争主张是：从正常轨迹学习的局部结构，能否在新目标和运行时分支中重新绑定、组合，以较少模型调度和人工维护保持合格交付。

不能预设 Workflow 只支持一种业务。条件路由、循环、动态工作分解及 Agent 节点都可用于人工 Workflow。[LangGraph 官方说明](https://docs.langchain.com/oss/python/langgraph/workflows-agents)展示了条件分支、routing 和 orchestrator-worker 等模式。因此，“有多个分支”不是 MGGA 的独有能力，未见组合任务也不保证 Workflow 失败。

## 强对照必须允许什么

| 条件 | 允许能力 | 结构来源 |
| --- | --- | --- |
| Native Tool Calling | 自主计划、批量/并行工具、正常语义判断与恢复 | 无预编译接管 |
| W1 多业务分支 Workflow | DDL、会议、回复、通知多入口，条件分支、循环、版本校验、失败恢复、同一模型的语义节点 | 开发者从训练资料显式实现业务逻辑 |
| W2 模块化 Workflow 加同一模型调度 | 复用邮件检索、线程读取、时间/身份处理、日历核对、待审输出模块；模型按新目标动态选择、排列、组合，不强制全图重放 | 开发者实现模块与接口，调度模型可自由组合 |
| 整条轨迹 Replay | 仅兼容且守卫通过的完整流程；不兼容时回到同一模型 | 完整历史路线；只作辅助消融 |
| MGGA shadow | 原生执行，加请求前局部候选/绑定/守卫分析 | 正常训练轨迹及独立认证产物 |
| MGGA execute 诊断 | 学到的局部结构在正确绑定后执行，语义层决定新目标、歧义和未认证分支 | 同一训练轨迹及独立认证产物 |

W2 是主要强对照。不能故意禁止它组合模块、让它只走线性路径，或让它缺少批量工具和缓存。若 W2 和 MGGA 都体现结构—语义分工，仅证明 MGGA 优于 Native 不足以证明自动学习的额外价值。

本轮不安装新的 Workflow 框架或另建产品 Agent 循环。以上是评测能力合同；真正实现时优先在现有 Harness/工具合同上表达，必要外部框架只作隔离的实验对照，配置与调用全部记录。

## 两种公平测试

### 冻结后面对新组合

各组获得相同 A/B 训练资料和任务族说明、工具/schema/order、来源权限与质量标准；开发者与编译器可看训练轨迹，不看 C 组具体来源、评分答案或执行轨迹。W1/W2 可实现一般路由与通用组合策略，MGGA 可编译与认证局部结构。

在接触第二批 C01/C03 执行资料前冻结 Workflow、library、代码和提示摘要；它们的完整任务轨迹不能用于训练或认证。与训练共享局部操作类型是实验设计，不能把人审列出的组合预写成 MGGA 库。C02 不进入当前组合主评测。

执行时两边的语义模型均可按用户新请求动态决策、调用工具或安全回退；禁止人工热修、通过改变工具集合给单方捷径或把旧答案直接用作结果。给 Workflow 的任务说明与给 MGGA 的说明同样充分，不以“不认识任务名”判失败。

### 同等调整机会后的维护成本

第一轮结果和困难类型揭示后，允许 Workflow 增补模块/分支，也允许 MGGA 吸收正常轨迹、改进编译或修复接口。双方采用事先冻结的相同调整时间上限和模型费用额度，再用另一批未见独立任务评测；调整窗口和新任务必须在实验前登记，当前未指定具体额度。

记录开发者/研究者分钟数、改动文件及模块/条件数量、调试模型请求和费用、认证耗时、重试与回归损坏。MGGA 的手工契约、参数目录、选择协议和新 Runtime 工程同样计成本，不能将 Workflow 编码全计入而忽略我们的工程。

## 必须拆开的机制证据

1. **局部参数复用**：正常训练轨迹证明输入输出边，后续新参数绑定正确并通过结果守卫。
2. **运行时组合**：当前完整有依赖路径未在训练/认证出现，实际由至少两个不同已认证 Motif 连接；记录父产物、接口与绑定证据。一个宽泛通用“执行任意步骤”函数不算学得组合，手写全链也不算。
3. **分支决定来源**：是普通代码规则、人工 Workflow、语义模型还是轨迹学习条件，逐分支记录。模型选择了分支再复用片段，只支持语义调度加结构复用，不支持自动发现分支条件。
4. **真实请求替代**：每次跳过要求完整响应内所有必要动作都已覆盖，实际结果验证通过；shadow 候选和部分覆盖不冒充净下降。

完整新路径在训练出现过，即使换日期、措辞或 task_id，也不能称为组合留出。只有两个独立读取并行、没有新的依赖连接时，单列为并行复用，不称依赖结构的新组合。

## 判断谁更好

先比较任务完成、事项/时间/身份正确性、冲突处理、及时停止与来源追溯。合格后再看含语义调度、学习、绑定、恢复的真实请求/token/费用和人工修订，维护开销另报累计与摊销。不同任务复杂度不强求逐题单调下降。

若 MGGA 在冻结后新组合上与 W2 质量相当、控制请求更少，并在同等调整机会后减少人工维护或学习成本，才支持自动学习局部结构的额外价值。若只优于整链 Replay 或 Native、与 W2 相当，只支持更窄的分工价值；若 W2 同样好且更便宜，必须保留反例并缩小主张。
