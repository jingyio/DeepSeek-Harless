# 科研每日简报场景验证协议草案

## 要检验的主张

同类但内容不同的日常科研决定中，正常 Agent 轨迹能否留下可认证的工具结构与参数关系；随着经验积累，结构层能否在下一任务中复用这些片段，减少模型调度，并在新含义、冲突、权限或版本变化时回到语义判断。

“每天能生成简报”和“工具调用很多”不构成该主张的证据。简单脚本、缓存或一次批量调用已经足够时应如实采用；不能人为拆工具、加阶段屏障或要求逐封阅读来制造轮次。

## 审题资料和真实实例

当前 S01–S03 是三个合成来源簇的初始决定，S04–S06 是它们的增量。用于审查问题是否自然、答案能否检查、语义判断是否有边界；不能计入真实训练或效果样本。研究项目涉及本架构时尤其只能作为自评诊断，不能充当独立科研效果证据。

每题真实实例化需要研究者确认：实际要作的决定；时区与时间切点；限定日历、邮件标签或线程；当前研究目标；已读、已否决与已处理状态；允许摘录的范围。先进行元数据预检、圈定权限，再读取正文。不得为了达到本资料数量而订阅、发邮件、建会或伪造论文。

来源保留在原应用，通过 MCP 返回对象 ID、更新时间或可核验版本、取证时间及必要关联。私人正文、账号标识、版本清单和评审答案放 `.local/`。公共审阅包中的虚构 ID 绝不传给真实 Google 或论文 API。

具体实例运行前生成两份分离材料：Agent 可见题面与已释放来源范围；研究者封存的来源时间线、版本、可接受决定与重大错误。未来变化和隐藏评分表不进入 Agent 上下文。当前审阅册公开供人选题，不能作为模型评测输入。

## 最小实验顺序

1. 研究者审阅三类初始任务，挑选确有真实需求的任务及实际资料。先收集普通 Harness 的自然轨迹，保留失败；若不存在完整结构请求，不强行进入接管实验。
2. 至少两项独立真实决定用于候选学习，一项独立决定用于认证；另保留未参与编译的后续效果任务。建议再准备至少三项效果决定，当前三份合成初始题并未满足这一划分。关联事件、同日续写、同论文复跑和提示改写均不增加独立决定数。
3. 每个下一任务开始前冻结 library、代码、工具 schema/order、输入时点与预算。先评测下一任务，之后仅将允许学习的 baseline/shadow 正常轨迹加入下一版。认证和永久效果留出不得回流训练，execute 生成的轨迹不能为自身提供独立正确性证据。
4. 先以 shadow 验证预测和结果守卫。事后看到模型选了什么再匹配，单列为覆盖分析；只有请求前已具有可验证绑定的候选才算前瞻接管机会。完整响应含未覆盖语义选择、工具或必要文本时，不计整请求机会。
5. 质量与守卫稳定后，在明确冻结的 execute 诊断范围内比较实际调用。不得按某次 shadow 较便宜就替代公平基线，不得为了达到 20% 首个目标而放宽守卫。

建议的候选结构包括标识到对象读取、分页、论文身份与版本整理、来源归并。它们只是轨迹审计问题，不是手写执行 DAG，也不是已经存在的 Motif。批量读取、多结果选择、无须再次读取和同轮并行都应保留为合法路径。

## 对照与质量

| 条件 | 功能与边界 |
| --- | --- |
| 原生 Harness | 自选合法路径，正常模型决策，无结构接管 |
| 简单脚本及缓存加同一模型 | 相同资料、工具与语义任务；固定读取、批量抓取、身份去重和版本缓存由普通程序完成 |
| 学习型 Motif shadow | 同条件原生执行，额外记录请求前预测、覆盖和守卫；实际跳过为零 |
| 学习型 Motif execute 诊断 | 仅已认证、正确绑定的结构片段由 Runtime 执行，语义判断和失败恢复仍用同一模型 |

压缩、增量同步、工具合并及正文视图必须各组相同，或另列独立消融；不能把其收益全归给 Motif。简单程序对照 N01/N02 应可零模型完成，但不能用它们替代需要语义判断的任务。

评审先遮蔽臂别，由研究者检查来源、漏掉的重要事项、错误提醒、推荐理由、版本判断与变化处理。推荐允许多个合格答案和“暂无值得优先读的论文”；没有固定论文数或唯一排名。记录人工修订分钟数，有重大错误即不合格。

## 记录和否定条件

逐轮记录代码/输入/任务/library 摘要、模型、reasoning_effort、实际工具及顺序、预算和输出限制；完整模型请求、shadow 机会、verified bypass、缓存命中与未命中输入、输出 token、失败、学习/绑定/恢复调用、估费、账单核对状态、端到端时间与人工修订。

净请求减少按同条件对照计算，计入模型参与的学习、选择和恢复；另报累计学习开销与摊销。20% 为首个项目目标，不是场景预定结论。不能要求不同难度的每个新任务都严格单调下降。

若自然轨迹中没有可复用的完整请求边界；需要过多人工绑定；变化后错误沿用判断；学习恢复开销抵消节省；或者脚本/缓存达到相同质量且更低总成本，则当前证据不足以支持本架构在该场景的额外价值。保留任务和负面证据，缩小主张或换场景，不增加无用复杂度。

## 权限和预算

本次构建没有真实模型请求或外部写入，新增 API 支出为零。审题不是发送推送的授权。后续模型验收在服务器 `/root/autodl-tmp/jjy` 加载 `.local/remote-env.sh`，沿用真实 API 持续测试授权并在运行前说明实际模型、模式、累计预算、请求和输出上限。不得重置已有论文账本，也不把默认 1 美元当成可无限重开的额度；新场景总额度须在运行前明确并冻结。
