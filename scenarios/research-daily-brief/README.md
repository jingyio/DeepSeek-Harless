# 科研每日简报场景任务审阅

本场景用于筛选能验证结构—语义分离架构的任务。产品交付形式是根据日历、相关邮件和论文订阅生成待审简报；研究问题是重复结构能否从正常轨迹中学习，在新任务上正确绑定和复用，同时保留必要的语义判断与变化后的交接。

当前提供 3 个初始任务、3 个对应变化任务及 2 个简单程序对照。全部人物、项目、论文、邮件和日程均为明确合成的审题资料。它们不是已取得的真实资料，不是历史实验轨迹，不构成独立真实决定或架构效果证据。

## 人工审阅入口

打开 [任务审阅册](review/tasks.md)。每题列出完整题面、关键资料、可接受交付与重大错误，末尾提供可直接填写的选题表。

| 文件 | 用途 |
| --- | --- |
| `tasks/S01.md` 至 `tasks/S06.md` | 分开的 Agent 题面，只含目标、时间、授权范围与交付标准 |
| `review/fixtures.json` | 合成来源正文、标识、时点及变化；仅供审题与后续无模型诊断设计 |
| `review/criteria.json` | 评审标准与允许的多个答案；不得放入 Agent 上下文 |
| `task-index.json` | 审阅包索引与任务亲缘关系，不是 Harness scenario 配置 |
| `review/protocol.md` | 真实实例化、对照、顺序学习与候选淘汰方法 |
| `review/checksums.json` | 当前文件与资料的 SHA-256，可定位本次审阅版本 |

S04/S05/S06 分别更新 S01/S02/S03，是同一决定的增量，不计为三个新独立任务。两个简单程序对照也不计为科研效果样本。

## 执行边界

当前阶段是任务设计与人工审阅，没有恢复旧连接器、实现新 MCP、生成 Motif library 或发起真实 API。没有 `scenario.json`；任务索引和合成来源格式不能直接交给现有场景运行器，也不能把直接读取 JSON 的试跑当成真实跨应用验收。

真实实例化后，邮件和日程保留在原应用，研究目标及阅读状态使用获得授权的原笔记或文献库。各组获得相同工具、schema、顺序、权限和资料时点。通过现有 Harness、轨迹编译器与在线插件接入，不另建 Agent 循环；不向 Agent 规定搜索词、工具顺序、最低调用次数或隐藏的未来事件。

人工先审题、圈定真实来源，再采集 baseline 正常轨迹检查结构机会。shadow 用于检查覆盖和守卫，不声称真实节省；后续 execute 的范围与预算单独冻结。暂不注册定时推送，不发送消息、不修改邮件、日程或私人笔记。

历史参考为 archive 分支的 `experiments/Gmail动态搜索锚点Motif试验_2026-09-28.md`、`experiments/日历Motif跳轮续测预览_2026-09-29.md`。恢复位置见 [归档说明](../../docs/main-cleanup.md)，当前公共接口见 [接口文档](../../docs/interfaces.md)。
