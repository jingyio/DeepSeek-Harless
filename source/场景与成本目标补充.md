# 场景与成本目标补充

> 依据用户 2026-09-24 的后续说明。此文件记录最新优先级；它补充并在冲突处覆盖此前根据导师录音整理的初步方案。

## 用户明确表达的方向

- 优先尝试 **deep research** 与 **代码迁移**：它们可能具有中等推理依赖、某些阶段较强的重复性、多步顺序执行和逐步增长的上下文。
- 代码迁移包括旧版本代码重构、根据新接口更新代码，以及对混乱代码进行整体规整或重写。需求存在是待访谈验证的假设，不能仅凭直觉认定市场规模。
- **首要目标是减少 token 与实际成本，图不是强制实现形式。** 场景和方法必须与 ATC 稿件的消融发现对照，但不能直接把论文数据外推到新场景。
- 对能否超过 WorkBuddy 免费体验版的使用效果与成本有疑虑。应以同题、同标准、真实账户剩余额度和实际账单比较。

## 对实施顺序的影响

论文摘要归档保留为已跑通的办公基础流程，不再当主研究场景。先对代码迁移、范围明确的 deep research 做小样本试验，测可验证的重复步骤、模型调用数、缓存/非缓存 token、质量与人工修正。再决定是否需要图结构、确定性脚本、模型路由或其他方式。

## 2026-09-24 的进一步约束

用户明确授权启动持续研发，并强调效率提升虽然是主要核心，但实现不能背离**结构—语义分离**。应尽可能以 `reference/` 的 ATC 稿件、G-Agent 和 AutoTool 为依据，避免最终只得到一个“省 token 的 Skill”。首轮实现需有运行时拥有的结构状态、证据验证、语义缺口和回退，并记录实际介入位置。

## 2026-09-24 的最新取舍

用户进一步明确：**办公／科研工作流首选，效果第一，机制第二**。MotifAgent 本地论文与 artifact 是最重要的方法参照；G-Agent、AutoTool 是可选的辅助参照，三者无需全部实现。应为后续真实 Jev 试验预留有界决策接口，但不为了使用 Jev 而增加无收益的调用。下一轮优先完成课题组实际可用的“有范围调研 → 证据表 → 可审阅报告 → 增量更新”，以质量、总费用、人工修订和体验决定哪些结构机制值得实现；代码迁移仍是第二条候选线。

用户随后澄清：MotifAgent 不只是论文参考，而是 **MotifAgent on SSS 的运行内核**。不修改原冻结代码；可在 SSS 复制必要模块，删减无用代码后迁移适配。当前没有指定课题组真实任务，因此先选公开 benchmark；公开题目未覆盖归档／增量更新时，自建并冻结机制题。首轮 benchmark 同时覆盖跨论文证据调研与科研资料整理归档。
