# 论文场景的持续学习验收

2026-10-20补充：[Script RSI真实局部闭环](experiments/paper-rsi-live-loop-20261020-v1.md)已验证任务结束自动编译/发布、后继任务精确加载并实际执行。含首次学习失败和开发期间两次兼容重认证；A2→B、最终冻结代码的C→D分别自动交接。三个后继任务各实际接管一次，C另复用五个新学脚本；不是完整论文报告质量或稳定净降本证据。下方2026-10-16等内容保留为历史机制范围，不再代表新实验仍需手动触发每次学习。

## 当前业务试用门槛（2026-10-16 用户更新）

当前先验收 RSI 机制闭环，不以小样本下稳定优于 baseline 的费用或请求数作为开始真实业务测试的前提。此前的 20% 目标保留为后续效果研究目标，不再用它阻塞机制验收或受控业务试用。

验收需要串起同一条可追溯的链：真实正常任务轨迹 → 候选学习与参数流编译 → 留出轨迹结构认证 → 发布有版本的新库 → 下一任务固定新库 → 匹配、当前输入绑定及结果验证。已有历史脚本和操作序列的参数化复用也计入结构语义分离；模型仍负责当前论文的身份核验、冲突和结论，不能从旧结果复制这些判断。

必须验证来源、Schema、代码或授权变化时拒绝接管或回退，失败及 Execute 自生轨迹不能作为独立成功见证；Shadow 不执行跳过。允许离线命令显式触发学习和发布，但须写明操作步骤，不能把它称为 Web 任务结束后的全自动学习。任务开始后冻结的库版本不能受后续发布影响。

机制验收、完整论文任务完成度、跨论文适用率及净费用收益分别记录。通过窄只读链的机制验收可以开始受控业务试用，不能据此宣称完整 315 条文献核验、稳定降本或无人值守自我改进已经完成。

当前机制证据见[2026-10-16 闭环验收](experiments/paper-rsi-loop-mechanism-20261016-v1.md)：先由真实历史正常轨迹重建三条库，再吸收本轮正常 Shadow 轨迹，训练支持从 2 增至 3、保留原留出认证、发布摘要不同的下一版；随后真实 Web 任务采用更新片段并完成验证通过的只读接管。学习/发布仍显式离线触发，生产未切换。

## 历史效果目标

负责人于 2026-10-10 明确要求：不断执行同类任务、不断学习可复用流程，让后续合格任务需要更少模型调用。冻结读取/arXiv 库当时只发现 5/57 个完整请求机会；该数字仅是历史覆盖诊断。

## 学习与执行闭环

`库 v0 → 新任务 T1 → 正常轨迹/缺口/失败 → 编译与认证 → 库 v1 → 新任务 T2 → …`

- 每个任务开始固定库、工具契约和输入版本；任务过程中不偷偷换库。任务完成后，新的正常轨迹才进入下一轮编译。记录父库摘要、新增/修订/失效节点和认证证据，保留回退版本。
- 优先学习多步片段：来源查询、结构解析、归并、校验及可证明的恢复路径。脚本作为执行节点，显式参数、输入输出、版本依赖与副作用边界；模型处理新需求、匹配歧义、来源冲突和未知故障。
- 脚本本身可以跨任务参数化复用。系统的目标是自动发现、编译、选用并维护这些片段，减少人为配置和重复模型控制；不排斥脚本，也不能仅把模型逐步调度改成手写固定工作流就声称自动学习。
- 使用现有离线挖掘/编译、代码节点和失败守卫底座；接入原生轨迹时扩展明确的协议。现有纯代码节点是受限表达式，不代表已经支持任意 Python 脚本或安全执行完整 shell。
- 模型在本来必要的语义决策中同时给出结构化输入，Runtime 连续执行确定性片段；减少额外 selection 文件请求。参数流和并行关系由轨迹与工具契约证明，不以相邻出现替代依赖证据。
- shadow 保留原生执行。若只在看到模型输出后匹配工具，属于事后覆盖分析；预先得到绑定与参数并预测下一请求，才进入后续接管评测。Runtime 自己生成的轨迹不能充当证明它正确的独立正常轨迹。

## 顺序评测

每轮先用当时的库评测下一任务，再吸收允许学习的轨迹；不能先见评测结果、用它编译，然后把同一任务重跑称为留出成功。另保留不用于学习的评测任务，必要时检查旧能力退化。

任务流可为不同论文，或同一论文的真实新增文献/批注/稿件变化。后者报告为增量复用，同一决定续写和同一输入重复会话不算跨论文泛化。首次缺口由模型求解并留下证据，下一批检验是否已能用新库续接；不能只无限增加相同输入的重复次数。

实验记录至少逐轮列出：当时库版本、可用训练数量、新增/修订片段、任务版本、shadow 完整请求机会、真实模型请求、真实 verified bypass、失败/恢复、交付质量、缓存/输出与费用，以及学习编译和人工修订成本。

shadow 和 execute 分开解释：shadow 预测接管机会的增长用于检查编译覆盖；只有 execute 在质量相当的对照中减少实际模型请求，才能声称实现调用下降。两个重要口径：

1. **边界接管率**：verified bypass /（实际模型请求 + verified bypass），用于描述本次执行的局部接管。shadow 的实际接管率为零，另报机会率。
2. **净请求减少率**：（同条件对照的平均实际请求 − 学习组平均实际请求）/ 对照平均实际请求。计入模型参与的编译、选择/绑定、重试与恢复；累计学习开销另报摊销结果。

固定质量门槛，比较随学习批次变化的平均请求和累计成本；不要求每个更难的新任务都严格单调下降。不能靠缩小任务范围、漏掉核验或隐藏学习调用造下降曲线。至少与原生 Harness 及合理脚本/Code Mode 方案对照，脚本方案可使用同样工具和证据。

## 当前状态与最小实施顺序

2026-10-11已补“先读正常轨迹，再自主提工具目标”的入口：`paper-rsi-trace.py`让DeepSeek阅读全部历史bash记录、自主选择输入输出、生成并修复受限JSON程序；独立源反例验收后冻结成动态TypeScript MCP。真实结果、两次失败和学习开销见[实验记录](experiments/paper-rsi-trace-tools-20261011-v3.md)，[公开原程序](../examples/rsi-tools/trace-coverage-v1/README.md)可用于理解。三个开发、12未见源反例与MCP通道通过，但新工具尚未接入正常论文任务和新的Motif/Shadow；不能把学习会话调用当正常任务独立证据。

后续应沿用下述版本闭环：先让新工具参与正常任务，再吸收真实调用/恢复见证并编译；下一任务固定新图做Shadow。工具目标与算法已能由DeepSeek提出，通用执行器、权限和源oracle仍是开发基础设施，未来修改也需保留独立验收。

已接通参数原型的最小版本闭环：`parameter_learning.py` 登记正常轨迹和永久保留的验证会话，调用 `compile_parameter_runs`，发布不可覆盖的 `round-NNNN/library.json`；`latest.json` 指向下一任务的版本。父库、证据和当前库都核对摘要，重复会话、训练/验证重叠、篡改及 execute 自证被拒绝。原固定五条轨迹入口保留，冻结输出不变。

论文入口新增 `--learning-store`、`--learn-after`、`--input-zip`。每次运行保存自己的 `library-snapshot.json`；完成的 baseline/shadow 才能自动成为下一版训练证据，当前任务不换库。新输入须为 `.local/` 下的私有 ZIP；目前准备器仍要求 `main.tex`/`references.bib`，不是通用 TeX 解析器。离线编译不调用模型。

新增 Crossref 只读查询原型从正常 `web_fetch` 轨迹学习查询键、rows/select 及其顺序，模型显式选择目录中的标题，Runtime 核对来源字节、标题身份、请求模板、HTTP 200 和 JSON 结果。空结果只代表查询未命中；搜索候选不代表正式出版或科研判断已经通过。

这条链目前仍是 `parameterized_continuation_probe`，`production_activation=false`。它已支持发布新库，但没有接入完整脚本/解析/归并节点，也没有自动学到任务选择策略。`offline/motif_miner.py`、`offline/library_builder.py`、`offline/dynamic_code_nodes.py`、`offline/failure_evolution.py` 仍是后续接入底座；不能把本次窄原型编译称为完整 RSI 或实际调用下降。

```sh
# 在服务器加载环境；首次先指定训练与独立保留的验证会话。
source .local/remote-env.sh
node scripts/project.mjs python scripts/paper-motif-learn.py \
  --store .local/paper-reference/<学习实验ID> \
  --train-run .local/paper-reference/<原实验>/runs/<正常训练会话> \
  --validation-run .local/paper-reference/<原实验>/runs/<验证会话>
# 默认仅预览。已授权预算内显式加 --call-model 才运行；每次 suffix 唯一。
node scripts/project.mjs python scripts/paper-reference-continuation.py \
  --learning-store .local/paper-reference/<学习实验ID> --learn-after \
  --mode shadow --suffix=-<下一轮> --input-zip .local/<新稿>.zip
```

真实诊断与负面证据见 [顺序学习记录](experiments/paper-rsi-sequential-20261010-v1.md)。历史会话及目前新运行仍是同一论文/阶段，不能作为跨论文学习曲线；协议新增 Crossref 目录/提示后也不能直接与旧基线归因比较费用。累计预算不重置，实付账单未知。

接下来优先完成：①在新稿或新论文上检验新版覆盖；②将模型生成的解析/归并脚本编译为受限参数节点，并减少额外 selection 请求；③质量验收后做真实 execute 与脚本/Code Mode 对照，记录净请求和累计成本。
