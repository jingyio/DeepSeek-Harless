# 多轮附件输入与视觉读取边界

2026-10-18。多轮附件继承、DOCX 跨场景和气泡显示修复继续保留。PDF 上传新增逐页 OCR 与视觉分析，并通过五个场景的真实模型读取验收；没有制作 PPT。测试范围和限制见[实验记录](experiments/pdf-ocr-vision-20261018.md)。

## 已修复的输入行为

- 同一对话追加附件时，新任务同时取得此前原始附件和新附件。首次原生 Chat、后续私有任务、跨场景切换与服务重启使用同一套继承规则。旧上传回执被消费后，从该父会话持久文件卡片取得来源引用。
- 文件引用在任务接收时冻结；复制前检查长度和已有 SHA。相同名称和内容去重；同名不同内容保留两份，旧文件使用 `-previous-<摘要>` 后缀。原始文件和旧任务目录不改写。
- `/paper` 的历史交付筛选接受 DOCX/DOC。普通 Chat 在首个场景切换前生成的 `outputs/code/` 文档，也会先按原任务时间范围保存不可变副本。双栏结果按原来对应侧继承；单路 Chat 的同一结果可供两侧读取。新上传附件不会阻断历史交付继承。
- 原始附件优先。沿用既有场景文件容量；超过原始文件容量时明确失败，不悄悄遗漏比较对象。容量之外的历史派生结果会在任务上下文明确标记未带入，不能声称已读取。
- 网页的普通用户消息和排队 steering 消息都使用展示投影：保留用户正文和附件卡片，隐藏独立或拼接在正文之后的机器提取块。原始日志、模型收到的证据和文件字节不改写。该展示修复来自前序界面提交，本次继续回归验证。

来源仅取自当前账号、同一父对话的持久记录。交付再次核验任务/对照身份、对应侧、不可变索引和字节摘要；分支截断和原有权限边界保留。

## PPT 为什么目前只能读文字

`harless_attachment_text.py::_office` 按演示文稿保存的页序读取每页 DrawingML 文本段落，没有渲染幻灯片，也没有完整解析主题、母版、字体、颜色、对象坐标或图表。它明确返回 `coverage=text_only`、`visual_content_reviewed=false`、`ocr_performed=false`。因此，文字提取成功不代表已经看到了版式。二进制旧 `.ppt` 也不能等同于 `.pptx` 的 OOXML 文字支持。

改进应使用两条相互校验的输入：

1. 在隔离的只读原件副本上，用 Office/LibreOffice 将演示文稿渲染为 PDF，再逐页生成图像，交给有视觉能力的读取链路观察配色、布局、图表和留白。[LibreOffice 官方 PDF 导出参数](https://help.libreoffice.org/latest/en-US/text/shared/guide/pdf_params.html)提供了命令行导出及 Impress 相关选项。
2. 同时提取 OOXML 的主题/母版/布局、对象边界、字体/颜色、备注、表格和图表数据，按原件 SHA 与页号绑定。图像说明实际外观，结构数据支持可编辑重建；缺字体或转换差异必须可见。

这属于待实施的视觉输入管线，本次没有将文字提取冒充视觉解析，也没有宣称更换 PPT 制作 skill 就能补齐输入能力。

## PDF 上传现在如何处理

Chat、PPT、Paper、Data、Files 共用 `geneloop_pdf.py` 与 `sceneAttachmentContext`。PyMuPDF 按页读取原生文字；无文字页及只有少量页眉、主体为大幅扫描图片的页面自动调用本地 Tesseract OCR。混合 PDF 的扫描页不会因其他页有文字而跳过。中英文语言包固定版本和 SHA，原件只读，结果绑定原件 SHA 与页号。

含嵌入图片或矢量绘图的页面会渲染为整页像素，同时提供图注、当前页及相邻页正文和用户问题，交给 Flash 做图文分析。Pro 不接收它不支持的原生图片，而是取得 Flash 的来源绑定分析，最终回复仍使用用户选择的模型。文字提取成功不再被当作图片已经读过；逐页 `visual_content_reviewed` 和覆盖计数只在实际分析成功后设置，失败页面明确标记。

PPT 的版本化 MCP 逐页阅读和 Paper 的 PDF 阅读也使用同一 OCR 读取器。PPT 不重复注入完整原生正文；仍通过固定来源的 MCP 工具读取，OCR 文字和图片分析则随任务提供。Data 的 OCR/图片观察不替代经过核验的原始表格单元格或独立统计证据。

OCR 不是完整视觉理解，也不保证公式、密集小字、扫描表格和数字准确。本次没有增加倾斜纠正、手写识别、OCR 置信度或逐字坐标协议；不能据此声称这些能力已完成。视觉页面最长边为 2400 像素，特别小的图例仍可能看不清；分析必须如实说明。扫描页仍保留像素供视觉模型交叉阅读。

OCR 在本地处理，不额外调用模型；图片分析请求使用同一已激活任务、同一累计预算与账本，按实际 Flash 模型统计费用。取消会中止 OCR 子进程或等待中的视觉请求，已发生的上游费用继续结算。原生网页的首次 PDF Chat 进入现有后台单路任务，先保存用户消息和文件卡片，再处理 PDF；机器提取块继续从用户气泡隐藏。

安装：先按 `requirements.txt` 安装 PyMuPDF，再运行 `python scripts/install-pdf-ocr.py --root <专用目录>`，配置 `GENELOOP_PDF_OCR_ROOT`。成员部署同时设置 `memberSceneDeployment.pdfOcrRoot`；启动时核对专用目录、语言包摘要和只读挂载。缺失 OCR/视觉能力时返回明确的逐页未完成状态，不伪造识别成功。
