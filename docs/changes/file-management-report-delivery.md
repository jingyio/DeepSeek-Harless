## 共享接口及职责

新增 `scenarios/file-management/workflow_delivery.py`，格式 `sss-current-workflow-report-v1`。仅用于六种工作流的 `task_result`：工作流构造时已声明结果报告覆盖所有当前文件。因此完整成员集合属于真实状态的结构事实，由程序从已校验的 MCP 当前状态生成，不再要求模型拼出所有 ID。

`WorkflowScene` 的14工具、`RecoveryScene` 的15工具名称、顺序及参数类型保持原样。`submit_report(summary, file_ids, gaps, report_kind, search_receipt_id=None)` 的 **file_ids语义改变**：作为非权威的兼容提示，建议传 `[]`，其缺失、过期、重复不会决定实际报告成员。最终 `file_ids` 是全部真实当前身份的排序列表；`final_snapshot` 和 `receipts` 从当前状态与已经存在的真实执行/恢复回执生成。模型仍填写 summary/gaps，summary原上限2000字符、真实报告类型task_result、禁止搜索收据的条件保留。

`read_task.task_result_serialization` 和工具说明明确字段职责、长度及验收边界。报告增加 `structural_provenance`，绑定生成版本、输入SHA、当前快照SHA、成员SHA/数量、真实回执SHA、模型字段名，以及兼容提示的SHA/数量/遗漏/未知/重复数量。提示原文继续保存在原始工具调用轨迹中。返回的artifact SHA绑定完整最终报告。

生成器不读取私有oracle、不选择去重代表、不读取额外正文、不制造操作回执、不宣布验收通过。普通 `ReportScene` 的inspection完整检查集合和literal_search真实命中规则保持原实现。FM05的跨计划去重与原始SHA组完整覆盖检查保留；错误代表/路径/字节仍由独立原验收拒绝。

FM38报告发布新增提交前后原任务 `job_guard`，取消、撤权、预算/版本失效时不能提交。恢复任务的原权限、同一账本、步骤/请求计数、修复次数及未知字节保留要求继续适用。

## 版本、认证和实验边界

workflow/recovery执行版本均增加生成器源码SHA；离线认证的工作流依赖闭包也包含该文件。旧库、脚本及证书保持原字节和签名，不能直接改签成新版本。旧服务证书在当前真实SDK/MCP中失配，回到普通Harness；新服务下从全新普通轨迹学习四个受限程序，先冻结候选，再用独立新材料认证。

新 `report_delivery_study.py` 固定6个日常配对条件及两轮机会：H普通Harness、S预写脚本、F自动检索冻结库、R自动检索持续更新。共享种子冻结后F不更新；R只从日常真实成本/失配触发普通探索，最多4份新普通材料/机会、2份独立认证。两轮升级均须在下一独立日常任务实际执行。完成后才生成10个最终条件（8正常、2外部版本负例）并冻结，最终不学习、不延长期限。

报告生成修复由全部四组共享，不能记为RSI专属收益。完整API比较包括所有共同历史建库、过去失败和重建、共同修复诊断、当前服务种子重学，以及R新增探索/认证/排除/修复。检索无模型请求也保留实际执行耗时；用户不要求人工时薪折算，人工开发维护不视为零成本。费用由原HTTP usage与代理价格上限重算，账单实付未知。
