# 历史Motif与复制程序的当前执行适配

2026-10-18，仅本地个人分支，不推送、不合入main。旧经验只提出候选，新原生见证和两次独立实际复用通过，才可进入原`daily-management-real-v3`长期库。原权限、预算、旧版本、失败、轨迹及费用继续保留；当前[真实验证结果](../experiments/management-legacy-adapters-20261018.md)记录通过项、失败及完整费用。

## 转换契约

`management_legacy.py`登记`sss-management-legacy-adapter-v1`，从统一历史目录提取全部旧集合、两阶段、单文件读取、计划及脚本v1/v2。按执行语义与完整目标/规则绑定归并，旧artifact的SHA与原格式作为aliases保留。无需修改原JSON、伪造原证书或读取历史最终任务材料。

- 集合：模型原生`select_files`后，绑定实际`files[].file_id → pin_files → source_ids → read_files → collect_reads`。当前有界批量接口代替旧逐文件foreach，仍完整覆盖选定成员并交回语义判断。
- 两阶段：同一有界集合图，第二次仍须模型重新决定集合，不自动选择正文；适配器每任务最多两次。独立认证要求两段完整实际执行。
- 读取链：允许原生标量`pin_file → read_file`或已声明的等价批量`pin_files → read_files`表示；按实际原生见证选定新图，再做两次独立复用。语义选择保留在模型根，当前数组界限仍有效。
- 计划：保留旧结构的`preview_actions → execute_plan`，执行回执和独立文件效果验收仍必需；不额外把`inspect_plan_result`读取节点当作旧结构的组成部分。旧`authorize_plan`和旧授权令牌不迁入，限6个copy/move/quarantine操作；外部根或风险计划交普通原生确认流程。先前三节点转换的失败证据保留，新两节点转换重新用新材料认证。
- 复制程序：`sss-management-program-v1` / `management_program`，仅解释旧`hash_representatives(min|max)`和1–2段`copy_map`，来源为原始集合、排除空txt集合、SHA代表或实际上一段产物。禁止eval、任意代码及新指令。

管理MCP的`select_files`增加真实导出字段，`collect_reads`声明只读自动续接；两者显式标注原0–32成员限制，未扩大服务实际边界。其它工具与高风险批准流程不改变。实际schema/运行时变化使旧活动证书失效，必须以新证明恢复，旧证据不重签。

当前集合图的批量续接证明限定非空、至多32成员；空集合交普通Harness，不声称自动foreach覆盖任意空分支或循环。

## 脚本匹配和执行

脚本目标、规则正文SHA、规则路径、来源根和目标目录来自原explore记录与完整原生读取副本。v1固定目标前缀改成其对应目录槽；v1无显式顺序的SHA代表保留原min语义。相同程序、相同完整绑定归并，目标/规则的不同变体分别认证。

读取旧来源前先限制在登记档案并拒绝symlink，核验真实outcome的explore角色，不能只信政策内的角色标签。空txt筛选沿用旧扩展名不区分大小写的语义，包括`.TXT`；空md仍可复制。

实际执行从模型的真实`read_task`开始；按当前scope、完整catalog、目标精确摘要、实际目录与规则完整读取核验候选。存在显式`approved_inputs`时原始集合不能扩大到同目录其它文件。规则、目录、版本、权限、目标或身份不匹配回普通Harness，不自行推测新的任务语义。

`management_program.ts`逐步执行原MCP，验证当前SHA/身份、原件不变、目标不存在、预览实际效果、授权执行回执及刷新目录。第二段必须使用实际备份的新身份。已存在目标要求普通流程处理，不自动覆盖；外部根、只读任务不启动复制程序。报告继续由普通模型提交并经过原目标验收，不由脚本编造交付摘要。

原生预取目录或规则调用可验证采用，但不算模型请求跳过。只有确实生成且核验成功的调用才写入跳过审计；原生学习与生成调用仍严格区分。生成记录使用原来源/事件守卫，不能作为新原生决定。

## 独立认证、队列和恢复

图复用现有操作图v2认证；程序使用`sss-management-program-certification-v1`。原生空库运行须体现完整复制指令语义、实际元数据与规则、每个复制阶段的全部选择、真实执行，以及备份后刷新身份。模型原生计划可以按不同批次组织，但阶段覆盖必须完整且不跨越备份/恢复依赖。新副本上的两次实际程序执行必须完整、无deferred、无修复并通过原质量/权限/费用验收。

原生规则读取可以是完整`read_file`或`read_files`中的真实成员，但必须早于复制选择；截断、缺少正文或事后读取均不成立。保留原批量调用与成员索引，不伪造标量原生事件。原生阶段可显式创建输出所需父目录，除此以外的目录或写操作不构成复制程序见证。

原生预览、目录或哈希调用失败会保留为认证拒绝屏障，不删除失败调用，也不让空结果触发未处理异常中断维护队列。

`sss-exact-management-program-delivery-v1`另核验最终文件恰为原件及按程序确定的产物，字节全部对应；补复制正确文件后仍留着错误代表、额外目录层级副本也不合格。认证前冻结的v4谓词补充未选中潜在目标的`missing`约束，程序执行器不读取这些验收答案。原生与两份候选执行均保留精确快照证明。

原生证明、候选锁、每个实际审计SHA和新证书均冻结；没有证书不得入库。模板只冻结参考验收，不给执行器提供期望答案。认证新材料改变源字节；`certification_fixed_sources`仅保留已知语义规则正文，不继承旧批准或外部授权，且必须存在于原输入，仍须产生新源字节。

既有worker先维护当前图，再处理历史适配，共用每轮最多2个迁移请求的上限；原全局池计入探索、认证和失败。相同证据失败不因nonce或重启再次付费。新合格普通原生轨迹可以触发新一轮，冻结其原记录与材料；中断先续原请求/原预留，源码或配置不同则保留并阻止错误恢复。

历史适配认证的目标摘要还绑定离线认证器SHA，区分执行契约兼容与证明器版本。证明器支持新等价API形式时用新版本和新材料认证，旧失败不改为通过；已通过且执行契约未变的经验可继续使用。存在原未完成请求时优先原请求，不能用新版本或新见证绕开原在途预留。尚未送审的预备材料可追加`preflight-superseded.json`，明确0模型请求和归档原因。

失配继续使用原任务、预算和最多2次普通Harness修复；不可因重开程序重置累计。若在效果后重启且自动程序不能验证初始边界，它会交回普通恢复路径，依靠原MCP日志防止重复效果，不宣称程序跨版本无缝续跑。

长期目录新增`adapter_keys`与适配状态；一份旧脚本只有全部目标/规则变体有当前证明时才标记覆盖。活动入口、HTTP动作及原状态字段保持兼容，`active_motifs`仍为当前可执行经验总数，实际类型在注册条目中区分。其它MCP与任意脚本语法未因此接通。
