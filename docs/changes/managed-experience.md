# 长期经验库、兼容检查与自动重认证

2026-10-18，按用户要求仅本地开发，不推送、不合入main。原历史档案、版本、轨迹、失败、费用和预算继续保留。真实验证结果见 `docs/experiments/managed-experience-20261018.md`。

后续已为已知旧集合、两阶段、读取链、计划及闭合复制脚本登记[当前执行适配器](management-legacy-adapters.md)，仍须新契约独立认证。以下“旧IR待适配”描述保留前一版边界；当前目录会为这些项列出`adapter_keys`与待认证/已覆盖状态，未通过项不能执行。

## 一个长期库，两种视图

长期库固定在原 `.local/rsi/daily-management-real-v3`。路径里的v3是兼容历史配置的名称，不随工具、验收或经验代数升级另建日常库。

- `experience/objects`：按原字节SHA去重复制历史政策、证书、封存运行记录和失败记录；同一签名的不同字节序列也分别保留。
- `experience/versions`及`current.json`：`sss-managed-experience-v1`追加版本与原子指针。记录原始位置、摘要、结构、证书、兼容状态、证据与费用索引。
- `experience/jobs`：自动迁移请求、材料升级锁、三阶段独立认证、失败及激活回执。
- `registry/versions`及`current.json`：同一长期库供执行器使用的活动视图。旧版本不修改，任务开始后仍冻结自己的快照。

原实验目录继续作为原始档案。导入目录不授予执行权限，也不把所有历史JSON、版本或脚本都计为可用Motif。旧公开包保持原字节，不作为直接激活凭证。

历史发现只扫描注册表和经验产物位置；不扫描最终任务材料、attempts、私有凭证和生成依赖。原生连续记录按原queue封存摘要核验。完整事件仍在原位置，统一索引绑定原记录和事件摘要，不把导入复制称为重新评审轨迹。

## 兼容、迁移和认证

`experience_library.py`使用当前管理MCP的真实schema构建器免费生成catalog；不调用模型或执行工具。检查工具声明、必填参数、导出边、自动续接边界和运行时闭包。`sss-runtime-and-catalog-compatibility-v2`目标摘要同时绑定完整catalog、执行版本、源码、quality-v4与认证-v2；schema生成缓存还绑定已安装mcp/pydantic版本。仅schema变化也失效，不能只检查源码SHA。

当前工具/源码/quality-v4完全相符、原独立证书有效的历史图可以原样迁入活动视图，不重复付费。曾停用的同一artifact不能借迁入新位置重新激活，须取得新独立证明。结构相同的当前有效版本覆盖多个旧版本，不重复建库。

失效图进入重认证。支持旧管理quality-v3材料升级到v4：保留原目标、原质量谓词、只读标志及允许操作集合的交集；不复制旧批准令牌、效果日志、provider状态或外部根授权。材料与升级策略冻结后，再生成不同新字节做认证，不能通过降低标准使旧候选通过。

每个候选仍须通过当前模型原生见证、两次不同材料上的实际完整复用、交付、权限、版本、费用和原生事件检查，使用原`ExperienceRegistry.entry`准入。失败不激活；成功生成新artifact和追加活动版本，不重签旧对象。

材料选择优先取最新且尚未尝试的合格普通封存轨迹，不按随机session ID排序。有已认证前缀生成的调用时，须逐项核对实际成功调用、参数来源、scope、至少一个原生模型决定以及已验证的跳过审计，才可把它作为新材料线索；新的原生认证仍使用空库、要求模型独立作出相应决定。材料线索不能替代新认证。复制后完整读取根据原文件字节谓词和实际完整readback冻结附加检查，不能把只验证复制的证书称为已验证读取。

旧collection/reentry专用IR、计划/恢复策略和脚本也纳入目录。当前原生management没有对应执行适配器的项标记`adapter_required`；缺独立证明的为`proof_required`。它们不会被改写成未经证明的可执行图。新普通轨迹可为可兼容旧图提供当前材料和见证，但不是对任意旧IR或任意MCP的自动编译承诺。

## 自动调度与恢复

日常真实启动时免费同步目录，有可处理失效项且原配置启用自动学习才启动既有离线worker；`mode=observe`或`auto_worker=false`不启动付费认证。普通任务封存后，既有自动学习worker先维护长期库，再发现新候选。管理场景CLI省略`--rsi-config`也选同一原配置，普通任务仍禁止指定正确候选或registry快照。

每次队列处理最多启动两个自动迁移任务。已知同一运行版本失败后，重复启动不重新收费；只有新的合格普通任务见证或新的目标运行版本才形成新的机会。自建认证材料的nonce不能自行触发无穷重试。已有活动结构不重复认证，缺适配器/材料的明确待处理。

普通任务中的实际失配仍沿用原停用与Harness回退路径。停用旧artifact不会因导入另一份历史副本而免费重新启用；新材料上的新认证产生新artifact后，方可再次激活。目标摘要升级前留下的失败也核验其实际冻结catalog，schema改变不会被旧失败错误永久屏蔽。

每个自动请求冻结来源、目标版本、材料、配置和源码。进程中断后优先继续原请求、enrollment及原预留，不因后来任务到达而换材料重跑。源码、权限或配置变化时旧在途任务保留并阻止错误续跑；不能宣称跨版本无缝恢复。源码恢复到原冻结版本后才可继续原任务。

沿用原系列USD1000、共享学习USD25、每任务USD5/96步与请求/4000输出/2次验收修复，认证和失败计入原全局池。新建目录、换版本、重启和导入不会创建新预算。未知在途费用继续保守保留。

## 入口与接口变化

```sh
npm run management -- experience status
npm run management -- experience sync
npm run management -- experience maintain --call-model
```

前两项免费读状态或导入索引，不启动模型；最后一项是显式维护入口。日常真实启动和任务后的自动维护沿用已有模型授权，不增加确认页面。

`motifs`新增`unified_experience`，原生持续学习状态新增`experience_library`，提供目录代数、数量、结构数、兼容状态、任务和来源问题。原有字段继续保留。导入状态与当前活动数分开，不以historical/managed数量暗示全部可执行。

注册管理工具的四个读取参数新增句柄说明，action的file_ids/source增加互斥说明；参数名、数组1–40边界、源选择、操作权限和高风险确认不放宽。SDK与原生服务使用相同方法签名。此真实schema变化会使旧运行锁失效，用于验证自动重认证，旧公开包不重签。

私有备份原已覆盖整个`.local/rsi`，因此包含新目录、对象、请求和版本链。换电脑冷迁入仍不继承旧任务授权或伪称旧路径证书在新机器有效；支持的经验契约迁移与物理位置恢复是不同边界。
