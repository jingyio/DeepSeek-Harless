# 附件媒体证据与准备阶段（2026-10-19）

## 已定位的机制问题

旧输入入口每轮对全部传入附件重新提取、OCR，并按页串行请求 Flash；完整视觉工作结束后才发送主模型请求。当前用户问题还会进入每页视觉助手，导致相同资料在“你好”等后续轮次再次分析并产生不同的失败覆盖。解析器预处理时生成的“未视觉读取”通用警告在成功分析后仍保留，与逐页覆盖冲突。DOCX、XLSX 原来只读保存的正文或单元格，没有逐页图像输入通路。

## 处理边界

- `sceneAttachmentContext` 只处理调用方明确传入的资料；新旧资料/本轮用户文字的选择由会话上下文层负责。准备进度使用 `onProgress` 的 extracting、rendering、visual 三种事件，不构造助手回答。
- 观察提示只读取绑定来源的当前页像素和文内背景，不接收当前聊天问题。每份文件的视觉工作最多三页并发，逐页记录成功或失败；成功必须返回精确来源 ID、页号、实际看到像素和非空观察。单独 Markdown JSON 围栏可以消除，未见图片/身份错误/非结构化答案仍失败。
- PDF、PPT/PPTX、DOCX/DOC、XLSX 的画面分别绑定原始文件 SHA、页号和渲染像素 SHA。上传视觉模式的 PDF 包括所有页面，避免纯文字排版表格没有图片/绘图对象而漏读。Office 转 PDF 继续使用已有无网络命令沙箱，禁用宏与链接更新；DOCX 和 XLSX 的原生文字/单元格仍保留。渲染图不认证原生字体、编辑效果或动画；表格预览可能重算，不能替代保存的原始单元格值和公式。
- 只读观察缓存位于宿主私有目录，必须在可写 `/work` 之外。键包含原件 SHA、扩展名、解析/渲染/观察代码版本、实际 PyMuPDF/Pillow 版本、Office 二进制/版本资源、字体和 OCR 语言包字节摘要；每次命中仍检查当前已获准原件字节。缓存只复用来源事实，不复用计划、授权或当前任务判断。
- 成功页可跨同一父会话两侧复用；实际失败页保持失败且保留像素。当前产品需要重新上传同一原件才能触发失败页重试；纯文字后续轮不会自动重读旧失败页，本次没有新增可供模型按需读图的工具。OCR/渲染重试只有像素 SHA 完全相同时才能继续复用旧成功观察。两个并发读取合并同源准备；取消等待者不会取消另一个任务的准备工作。
- 缓存的原始像素不会进入主模型文本或用户气泡。主模型取得确切的覆盖计数与失败页码/错误码；错误细分为来源不符、页号不符、未观察到图片、缺少观察、JSON 结构不合格、HTTP 状态等稳定代码，不保存私有图像正文作为诊断。过时的通用“还没有视觉阅读”预处理提示删除，真实 OCR、字体、图像不可读限制保留。

## 验证与限制

确定性诊断覆盖真实合成 PDF 解析、失败页重试及成功页缓存、内容变化拒绝、有限并发、取消、来源身份拒绝、PDF 单页渲染失败隔离、Office 原生文本和逐页画面分离，以及既有费用门限所有权。这里的伪视觉报告仅检查协议，不能作为真实视觉理解和成本收益验收。正式模型多轮测试、服务器 Office 转换器和 OCR 语言包验收由本次集成记录另记。

缓存命中并不证明观察完全准确；低清扫描、密集图例、公式、外链或视频/动画仍可能不可读。不能保证任意文件格式或所有视觉元素都成功。部分失败不会升级为“已读完整文档”，实际缺口是否影响用户问题，由主模型结合任务判断。

同一父会话双栏共享预处理时，真实费用计入首先执行视觉请求的已激活任务。Baseline/Motif 对照须单列公共资料准备费用或明确归属，不将两侧缓存先后差异解释为 Motif 降本。
