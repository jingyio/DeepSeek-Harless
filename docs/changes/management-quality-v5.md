# 文件管理严格交付与读取来源契约 v5

本轮按用户要求只在本地个人分支开发，不推送、不合入 main。真实验收与最终活动库数量另见本轮实验记录；本文件描述实现契约，不把待验证事项写成完成结果。

## 完整交付与写入前检查

`sss-management-quality-v5`、`sss-management-goal-v2` 在操作前冻结完整目标树和原始来源映射。显式文件／移除／不变／读取／目录谓词也生成完整文件与目录集合，避免只验证必需文件而留下多余副本。将错误副本移动到隔离目录仍属于多余文件，不能算完整交付。

`preview_actions` 核验实际目标路径、源字节与原始来源；两个文件字节相同也不能任意交换来源。已知移动目标拒绝改成保留源的复制，保留源的目标拒绝改成移动。未通过预览不产生效果；`submit_report` 和日常验收再次独立核验完整最终树、来源和冻结谓词，不能靠预览检查替代交付检查。

默认任务副本中的低风险操作、原高风险一次性确认、原权限和预算不变。对无法完整解析的目标，仍允许原权限内的普通处理，并明确显示目标待复核。

`read_task.goal_acceptance` 提供范围、状态及检查说明；完整预期树、来源答案和临时路径清单保留在独立检查端，公开返回契约摘要。执行器不读取预期答案来替代实际规则、目录和模型决定。

## 中间读取与原始来源

新增 `management_provenance.py`。以原计划、源路径、逐效果边界及恢复链追溯实际来源，不通过相同 SHA 猜测身份。每次读取保存 `sss-management-read-provenance-v1`：原任务、实际来源句柄、原始路径、观察快照、操作游标、原读取结果和摘要绑定；标量和批量读取一致。

文件后来改名或移动后，离线核验按操作链找到原始冻结字节，并使用读取时的扩展名重放解析。来源还须出现在原始 MCP 结果中。改动证明、错用同字节原件、缺少边界或原件字节改变均拒绝训练。

显式读取谓词可用 `source` 绑定中间路径的原始来源。明确目标例如：

`把 source.txt 复制到 intermediate.txt，完整读取该副本，再重命名为 final.txt，保留原件。完成后核验并提交报告。`

会在开始时冻结中间读取和最终文件范围；临时副本最终不能残留。中断计划须先执行或恢复原剩余边界，再读取内容或创建新计划，防止未完成边界留下无证明读取。

旧读取记录可作明确标记的免费来源重放诊断；不改旧记录、不重签旧证书，也不将旧失败因此认定为新版认证通过。

## 规则失配后的普通学习与恢复

读取规则和目录的生成调用记为 `management_program_probe_verified`，独立于 `operation_model_request_bypassed_verified`。探针逐项绑定真实工具、参数、结果和权限摘要，只允许指定的只读接口，不能伪装执行计划，也不计入脚本复用收益。

规则不匹配时，保留真实检索证据并交回普通 Harness；新原生决定仍可成为后续学习证据。探针本身始终不是模型原生决定，不能用它证明新操作结构。未核验的失败调用继续保留为屏障。

已有计划状态的原任务恢复时，复制程序不从头启动；普通 Harness 使用实际日志、原任务、原权限、原预算完成剩余工作。未参与的程序不生成虚假的失配记录。

## 版本与长期库

原 `daily-management-real-v3` 路径保持。新版运行时、真实 catalog、v5 质量契约重新判兼容；v3/v4 材料迁移只生成新副本，保留原谓词、输入范围、语义规则和权限交集。新字节材料重新计算目标树，原验收检查不放宽。

旧有效项保留历史版本，由当前原生见证和两次独立实际执行重新认证，通过才进入活动视图。探索、拒绝、修复、学习和认证均计入原账本；系列 USD1000、共享学习 USD25、每任务 USD5／96 步与请求／4000 输出／2 修复不重置。

真实前端验证期间还发现启动探针的分派缺口：通用图维护器已拒绝 `management_program`，但免费 `needs_maintenance` 仍把其旧材料当作图任务，连续启动没有实际工作的 worker。启动探针现仅向通用维护器提交 `operation_graph`，程序候选仍通过原 `management_legacy.pending` 的来源、配置及独立认证规则判断。原待新证据、来源失效和未完成记录不删除、不改为通过；空检查没有新增模型调用。回归同时覆盖图任务继续调度、程序队列有可处理项时继续调度及没有工作时不启动。

## 原生前端上传与恢复

浏览器首轮五格式测试发现：原生 PNG 是 `image` prompt part，原 `bindSceneInputs` 仅收文件回执，导致图片未加入任务清单，随后 Provider 因缺少图片转换服务在 0 次上游请求、0 次 MCP 整理操作时失败。已经准备的输入副本、原任务与失败保留。

新增 `managementFileContent`，只对 `management_graph_v3` 生效：原生附件服务先验证整批图片，随后将每张原始图片字节通过当前会话的官方 `fileUploads.uploadStream` 变成文件回执。图片、普通文件共用 8 件来源限制、所有权、同名冲突和路径检查；图片预览的归一化字节不作为文件副本来源。`request.content` 及原内容摘要保持，交付消息与 `bindSceneInputs` 使用实际转换后的回执，验收冻结包括图片的全部文件；其它场景原内容直接返回。无新 HTTP 动作或权限。

中断恢复时，原生历史已有持久化附件引用，原任务已保存输入及操作状态。续跑仅发送原文字和继续指令，不重发可能已经失效的文件回执或原始图片；权限、预算、MCP 版本与恢复状态仍由原守卫核验。

共享 `harless_task_scope.ts` 的变化触发原 PPT 兼容锁检查。旧 `runtime-bindings.json` 与登记摘要保存在本轮私有快照；新兼容说明仅核对非管理分支保持原内容、原参数与原来源校验，原训练证书、库、完整工具 schema 和学习边保持原字节。此项不是新训练或 PPT 质量/费用认证。可选 PPT 原生 schema 复查因本地缺少 `dist/render.js` 未完成，失败保留，不将历史的 schema 复查改写为本轮成功。

## Motif 起点错误的准入修复

真实独立认证发现：普通模型首次 `preview_actions` 参数被拒绝时，运行时只按工具名选择图，并把尚未建立起点的候选永久停用；随后模型修正预览、交付合格，仍无法继续验证该候选。原认证失败、轨迹与费用保留。

`dsh_operation_motif.ts` 现在仅在尚未建立控制器时检查原生 MCP 显式 `isError`（外层或 `value` 层），记录 `operation_root_error_observed`，交回普通 Harness 修正；此时不记录选择、跳过请求或候选失败。名义成功但作用域不符的起点、已经建立起点后的工具失败、权限和版本失配仍按原规则停用与回退。认证门槛保持原生独立见证、两份新材料实际执行、严格交付、零验收修复和完整执行证明；没有重签旧失败。
