# 普通PDF文献工作台：场景变更与GitHub提交说明

## 问题与结果

原先阅读、审阅、增量更新需要多条实验命令，首版工作台又要求用户逐字段核对与批准。按用户最新要求，改为现有Harness阅读→来源核验→模型自动审阅→直接交付比较表、综合分析和Markdown笔记。网页去掉人工勾选/批准，原文依据可展开查看。自动结果保留质量标签与证据缺口，不提升为人工认证。

## 文件与接口范围

- `agent.ts`：TypeScript协调、缓存、账本汇总及本机HTTP。新增`delivered/delivered_with_gaps`，`delivery_policy=automatic_v1`，`human_review_required=false`。来源变化的自动结果当前完整重读，不要求建立Human记录；自动审阅字段的局部复用尚未实现。
- `agent-ui.html`：默认直接显示比较表、综合分析及缺口，证据可展开；取消人工审阅和编辑/批准按钮。API费用启用开关保留。
- `agent-support.py`：来源重放与交付封装，不需要人工审批；自动模型审阅摘要绑定检查保留。缺口不再阻止交付，来源/工具/费用失败仍停止。
- CLI `deliver --job`：针对旧完整结果重新核验后生成新交付任务，允许仅交付工作流版本变化，拒绝来源、解析器或契约漂移。0新模型调用；旧结果/费用保留。不宣称重新做过模型审阅，不把过时模型审阅附给编辑后的稿。
- 历史`approve/revise`及Human/Codex依赖图保留兼容，不作为默认工作流；未新增Model身份的图认证。
- 相关测试覆盖无审批交付、有缺口交付、审阅绑定、来源变化拒绝、失败记账、缓存与本机同源/并发保护。

**此次无需共享接口变化**：共享Runtime、ToolContract、IR、manifest、预算算法、上游Harness、MCP schema和依赖保持不变。此前已授权的共享续接变化见[单独记录](approved-plan-continuation.md)。工作流实现摘要变化使旧结果缓存失效；显式策略重交付例外保留来源/解析器/契约守卫。新增工作台需要Node22.18+、Python及Poppler，当前验证macOS。

## 验证与证据边界

相关9项Python（含11项Node应用检查）通过。`npm test`通过293项Python和44项共享Node；Python应用包装测试内另含11项Node工作台检查。实际三PDF、15字段旧工件重新重放来源后直接交付，0新增模型请求/$0，原工件SHA一致；此前Codex抽查修3字段仍是该结果的来源，不构成新全自动语义质量实验。之前两版57请求/$0.098076408及模型支持错配记录不修改。

## 可用于提交正文

> 新增普通PDF文献工作台，复用既有Harness阅读/审阅和预算接口，直接交付比较表、综合分析与可追溯笔记。取消默认人工勾选与批准，保留自动核验、明确缺口、失败计费及同源并发守卫。相同任务来源重放后复用；自动稿来源变化当前完整重读，逐字段局部复用待开发。旧人工审核图/接口保持兼容，不伪造人工身份。全部结果留在私有.local，不修改原PDF，不改共享Runtime或MCP schema。
>
> 验证包括无审批交付、缺口交付、审阅摘要绑定、缓存重放及来源失效/费用/HTTP并发检查；真实旧工件重交付0新模型请求。自动审阅不能保证科学判断完全正确，当前未证明跨语料质量或完整RSI净收益。
