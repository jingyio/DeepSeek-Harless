## 版本化执行与学习

- 新 IR `sss-operation-flow-v3` 与认证契约 `sss-operation-certification-v3`，仍以 `operation_graph` 条目加入同一经验库。原 v1/v2 图和有界程序保留原解释器与证书版本。
- Python `control_flow.py` 从至少两个独立普通真实任务提取工具路线、参数传递、条件分支和出口。工具只声明 `control_fields` 的有限输出域，不声明下一工具或路径；支持布尔、显式有限枚举和非空句柄/显式null。每个分支及出口分别需要两个独立原生见证，参数值须有跨任务变化；失败调用、未知调用和语义参数构成边界。已认证生成前缀不能给新的分支伪造原生证据。
- TypeScript `control_flow_policy.ts` 按当前工具返回值选择唯一已见证边，参数只取前一步实际导出字段；不执行表达式或学习语义常量。允许自循环与多工具回边，最多16工具状态、64条边、64次调用。重复工具+参数代表未取得进展，执行下一步前停止；未知条件、来源/权限/schema/版本变化或工具失败交回普通 Harness。
- 同一任务最多16个活动原生读取根，各有独立游标和实际调用ID。只有明确声明、同权限域且成功的只读调用可以交错，不改变另一文档的绑定；失败、未知工具或写入仍构成边界。认证按每个根的原始调用序列重放，拒绝不同根重复占用一次调用或遗失未完成根。
- 已认证v1/v2直接参数边或v3边可作为继承前缀，继承只允许实际审计已验证的生成调用；新的条件边仍分别需要两个独立模型决定。候选新增已见证分支时，即使旧flow仍活动，也可以安排新版本独立认证；只有证据变多而结构不变时不重复认证。
- 第一版支持前一步输出到下一工具的标量或有界字符串数组参数；数组投影仍由已有v2图负责，v3不推断任意数据变换、嵌套循环变量、计算表达式或任意控制代码。有限条件的组合可形成多分支；未经观察的条件组合不猜测。
- PDF 分页增加实际 `next_request_id` 的null/非空及 `empty_text` 布尔控制域；覆盖检查可作为参数化续接和独立出口。循环长度来自实际文档的继续句柄，不能将固定页数链改名为循环。已读与解析缓存的区分、源文件和全文覆盖重放保持。

## 跨工具执行与产物证明

- 通用准备请求保留真实 provider、完整catalog、目标schema和原参数的不可变摘要。模型仍选服务、工具和所有语义参数；可学习的续接仅执行该准确请求、读取该准确收据，不自动编造下一个业务调用。
- 第一批独立业务适配为原默认 `workspace-runtime` 的精确文本编辑及新文本产物。管理包装返回 `prepared_certifiable`，执行成功后才带原授权标记；私有服务覆盖、任意代码及其它无独立业务适配的服务不会取得该准入。普通 Harness 仍可在原权限内使用它们，学习记录保留拒绝理由。
- `general_tool_replay.py` 对照原材料重算精确替换/新文本，检查原输入、真实prepare/execute/inspect轨迹、请求及收据、catalog/schema、任务权限、产物字节与无额外输出。认证的是已选择调用的准确执行和产物契约，不把任意科研结论或代码业务语义当作认证通过。
- 原默认隔离代码和能力查询允许作为普通模型决定的语义边界保留，不妨碍同一任务中合格的局部阅读/编辑结构学习。代码仍完全由模型选择，不作为生成的Motif节点；原程序摘要、输入保全和产物摘要独立核验，代码业务语义不自动认证。未登记的外部业务仍需要独立适配。
- 封存交付时收据继续保留真实执行路径，独立回放只通过原 `enrollment.delivery` 映射到对应封存文件，不能把路径不匹配当作交付损坏，也不能任意猜测其它主机路径。同权限但状态不适用的普通调用不会提前选中并停用候选；真正跨权限或已准入后的执行失败仍停止。

## 独立认证、升级与恢复

- 新原生认证材料必须覆盖候选的每个分支/出口；两个新的实际候选执行也分别覆盖全部分支。每次动态路径从原始MCP结果和参数重新计算，不能只统计完成事件。质量、原生根、预算、无修复和无回退要求保持。
- 旧活动经验因源码变化失效后保持原版本，由长期库原维护队列按当前契约重认证；新flow的历史边/控制域及来源不原地重签。新的原生见证、当前独立执行通过才重新激活。相同失败证据不因重启重复计费。
- 循环每一步仍走 Harness 原生工具生命周期与原任务步数/请求预算。进程中断保留原收据和任务状态；未知效果不重放，版本变化阻止直接续跑。此版本不放宽高风险逐计划确认。
