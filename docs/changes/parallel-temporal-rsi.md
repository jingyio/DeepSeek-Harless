# 并行准备与时序验收（本地开发）

本轮在同一长期库、原权限和预算内扩展请求并存与时序检查。实际认证、失败和费用在对应实验记录中列出；不能以功能实现或免费诊断替代真实通过。

## 请求隔离

通用工具的模型语义选择保持在原 Harness。`prepare_tool_call` 只冻结真实 provider、schema、参数、权限、版本及 request digest，不执行工具。准备请求返回 `sss-prepared-request-v1` 请求域。其它已注册 MCP 只允许纯准备交错（stage_only），不能因此自动执行其业务；已有独立适配业务的实际产物使用新目录，原输入不改写。

DAG 新增 `request_lane_contracts`。最多 16 个原生根可以并存；准备、执行、检查必须绑定各自实际 request/receipt，不能串线。效果仍逐个检查后推进，不承诺多个写效果同时执行。未登记业务、失败收据、权限/版本变化、未知效果继续交给普通 Harness；不能从“另一个请求”推断它安全。

Python 学习器按请求域保留参数关系，跳过已声明且实际合法的同域任务中其它请求；TS 在线维护独立控制器。独立认证逐根从原生事件重算完整路径、参数传递与完成记录，禁止两个根重复消费同一调用；整任务存在回退仍不作认证通过。

## 时序契约

目标契约在付费执行前冻结。文件结果检查之外，程序直接核对 Harness 原生模型消息、tool/call 和 tool/result 序号，区别完成依赖、调用顺序和同消息批次。生成调用不能冒充原生同批模型决策。

当前目标版本 `sss-management-goal-v3`、质量版本 `sss-management-quality-v7`、时序版本 `sss-management-temporal-v2`。支持以下冻结表达：

- `时序要求：先完整读取 a.txt，再完整读取 b.txt。` 首个完整 A 结果必须早于首个 B 调用；后续合法复读允许，不能靠后来重读抹去首次违规。PDF/图片用实际完整覆盖事件，不能用预览或打开代替全文。
- `时序要求：在同一条工具调用消息中依次打开 alpha.pdf、beta.pdf 并完整读取 memo.txt。` 首批必要调用必须来自同一实际模型消息、次序正确；memo 完成后才可读取文档正文。
- `时序要求：先打开 alpha.pdf、beta.pdf，再完整读取 memo.txt，最后读取上述文档正文。` 核对完成依赖。
- `时序要求：先在同一条工具调用消息中准备 2 个工具请求，再执行任何工具请求。` 核对准备数量、同消息批次和全部准备先于任何执行；数量支持 2–16。

简单只读时序目标可自动冻结文件验收，无需用户编写模板。未知或部分解析的时序保留待复核状态。显式文件验收项不能免除自然语言时序。原生 `submit_report` 先提交可核对的结果；最终时序结论由宿主完整事件决定，缺失轨迹不能声称目标已完成。SDK、原生 Web 与离线认证沿用同一检查器。

时序前提未完成时，在线 Motif 暂让普通模型决定下一步；不同阶段各自等待，不因之后的工具准备条件阻塞前面的文档循环。时序不满足和效果失败全部保留，原任务权限、费用、重试和恢复机制不重置。

## 保留边界

这不是任意自然语言的形式化证明，不把新服务登记等同于业务可认证，也不把结构续接计数当作净省模型请求或已证明的完整净收益。最终留出材料不用于训练，旧版本、旧失败和旧费用保留。本轮不提交或推送 GitHub。
