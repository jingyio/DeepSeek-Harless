# Script Motif 瓶颈、显式参数复用与真实对照（2026-10-19）

本轮在 `codex/paper-script-evidence` 分支延续上一轮 `7e42588`，使用独立 worktree、本地真实 DeepSeek API。用户要求效果稳定后再决定 PR；不推送、不提 PR、不部署，不修改桌面原工作区、私人原件或生产认证库。本文只把实际请求和交付作为收益依据。

**结论：已修复真实执行协议问题，并在新论文上观察到 2 次参数化网络脚本复用；8 次完整对照仍未实现净降本或质量合格。** 本轮假设是：从历史脚本恢复 argv/文件参数、受控取得当前 HTTP Evidence 并绑定需求前驱，能够减少后续独立论文的代码生成与完整请求。真实结果仅支持跨任务局部脚本复用，未支持端到端收益。

瓶颈分层：

- **挖掘覆盖**：旧提取器只接受 Python stdin/-c，漏掉真实轨迹中保存到 `.py` 并使用 `sys.argv` 的程序；网络脚本全部排除。多数联网工作不在原 5 个本地算子覆盖内。
- **匹配与必要性**：旧 Execute 做了 112 次 embedding、111 次候选排序，却仅执行 4 次；这不支持“embedding 次数越多收益越大”。弱前驱 Bash 描述不能证明当前仍需要重复检查。
- **执行资格**：含历史任务常量、歧义文件绑定、未认证操作及大输出应拒绝，不能为提高命中率降低这些守卫。16 KB 输出限制修复了上一轮 Bash 截断导致回执无效的问题，但不解决任务必要性。
- **完整请求替代**：4 次回执验证只证明对应 provider continuation 没有调用模型，不保证其他重复请求消失。联网查询对象选择、来源冲突和最终结论仍需要语义判断。
- **抵消收益**：上一轮完整任务增加了搜索、脚本调度与报告恢复，且最终报告截断。不能用 4 次 skips、代码复用字符数或 Shadow 候选数当作净收益。

## 本轮机制与证据边界

1. 自动识别保存 Python 文件后执行及后续带参数调用；对源文件、语法、实际成功轨迹保留来源证据。`sys.argv` 标量槽由真实程序产生，当前参数由模型选择，不复用历史 ID 或结果。一般 Bash 管道仍不被悄悄裁剪成可执行算子；末尾 head 的真实参数只作为额外认证观察。
2. 网络生成代码继续在禁止网络、只读输入的 OS 沙箱内运行。遇到 HTTP 读取先交出需求，由可信驱动验证固定 arXiv/Crossref 元数据 GET、大小与超时，再将本次响应及哈希作为 Evidence 重新送入沙箱。没有把生成代码移到宿主任意执行，也没有读取历史 HTTP 输出冒充新证据。
3. 普通缓存通过已有 Bash 的 `geneloop-cache` 显式选择程序、当前路径和参数，允许批量；脚本正文不进入工具 schema。目录通过公开 system prompt 接口挂载。完整 Motif 使用相同目录，并只在已验证的当前选择后尝试学习到的结构后继；保留目标/前驱语义门槛、负目标、输入版本、一次性 grant 与失败回退。
4. 本地 embedding 增加进程内 256 项向量缓存，只缓存固定模型下的文本向量，不缓存任务决定或工具证据。真实 Qwen 诊断首次 0.391 秒、相同文本第二次 0.00163 秒；这是局部诊断，不能作为端到端节省。
5. 统一将本轮三个实验臂的显式输出上限设为 32,768，避免上一轮 8,000 截断成为比较混杂。该配置只在实验 wrapper 内同时传给预算代理和原生准备过程，公共 CLI/产品默认及认证库不改。

网络认证验证的是当前源代码与参数化代码在两组真实历史参数上的等价、不同参数确实改变输出；不是两篇独立任务的领域正确性证明。正式评测使用未参与挖掘的论文。离线学习没有新增模型请求，仍需计入旧训练调用与本轮重放/HTTP/硬件/人工成本。

## 失败记录与验证

- 首次 32,768 被公共 CLI 的 8,000 校验拒绝，零 provider 请求。临时修改 CLI 后启动 Baseline，但公共证书回归明确报代码锁改变；已还原公共文件，用独立 wrapper 传递同一实际上限。三组实际模型/工具/场景配置摘要已核对一致。
- 首次缓存组试图修改不可变请求对象，工具/模型请求前失败，零费用。改用公开 `systemPrompt.variable/section`；真实事件确认目录进入系统消息，未更改原用户提示。
- 原始失败、认证拒绝、调试重放全部保留。没有重锁生产证书，也没有删除失败检查。

- RMSNorm Execute v2 实际选择过 4 算子批次，命令为 `cd /work/... && geneloop-cache ... 2>&1 | head -60`。旧执行器只识别命令开头的缓存标记，误走普通 Bash，报 command not found；模型之后放弃缓存。**这是执行入口失败，不是模型从未选中，也不是 embedding 不相似。**
- v3 接受已校验的工作区 `cd ... &&` 前缀；管道/重定向仍拒绝并返回可操作提示，不静默删掉 head。目录说明回执必须完整；批量回执全部验证后才发布 Evidence，任何一个失败都不产生可用于后继的成功事实。两个 v3 完整对照重新运行，未覆盖 v2 失败。
- 修复前后代码锁不同，分别重放认证。旧库和失败原样保留；没有只更新 manifest 哈希绕过验证。
