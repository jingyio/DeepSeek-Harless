# Negative Motif 字段依赖验证

- 日期：2026-10-19；分支 `codex/paper-negative-dependencies`，基线 `0d732c6`，实现提交见本文件所属 Git commit。仅本地，未推送/PR/部署。
- 状态：字段条件编译、跨版本门控、历史真实工具重放及原生工具诊断通过；未进行新真实模型对照，不能宣称净降本。

## 问题与假设

前轮只比较完整参数与文件 SHA，35 次相关失败中仅 3 次原样重试。这种统计漏掉了修改无关内容、换新版本号、改了相关值但错误仍存在的失败。用户明确要求学习哪些字段与错误有关；工具序列和完整哈希只能作为保守回退，不能代表完整负面模式。

本轮验证：从受信、只读且确属工具必要条件的校验器自动提取字段依赖和失败谓词，结合当前失败及成功对照认证后，能否在无关编辑后继续识别错误，同时放行真实修复、不同范围及未知状态。如果只能识别历史完整版本，或需要逐错误手写字段规则，该假设不成立。

## 实现与边界

- Python `negative_field_compiler.py` 沿 AST 的别名、静态字段键、列表映射及 `len/set` 比较提取顶层直接抛错条件。没有注册论文错误名或字段名。任意黑盒脚本不在此能力范围。
- 显式私有 `--field-profile` 指定已审阅校验函数及真实失败/成功状态；函数文件须匹配历史工具实现锁。函数只读、且是工具必要前置条件仍需开发者确认，不能将源码启发式称为通用因果学习。
- 支持条件须在真实状态上复现原始错误，在成功对照上为 false；自动进行至少两处依赖外字符串编辑，并要求原函数仍给出同一错误。此类干预是局部诊断，不是独立真实任务。复杂嵌套/动态语义条件保留旧策略，不为扩大覆盖降低认证。
- TypeScript `negative_field_runtime.ts` 有界执行数据 IR，无任意代码求值。上限 256 节点、深度 32、单数组 10000、100000 步；当前 JSON 文件上限 2 MB。类型/字段不明时回退。
- 当前实际失败 → notice 进入实际模型请求 → 同工具重试时重新读取同一权威文件并计算谓词。包装中的任务/来源版本、当前目标/schema/输入及非版本参数须一致；提交版本必须等于当前实际 SHA。只改无关内容或改后仍违反条件可以局部阻止；修复、其他工具、语义参数或范围变化均放行。
- 正负库不扩充 LLM 工具表，不修改上游 Harness。仍只维护最近一条当前失败，不自动修复、不全局停止，也不凭历史失败直接禁止新任务。

## 数据与验证设计

训练来自前轮同一条真实 RMSNorm 失败轨迹，以及两条历史结构定稿成功对照，费用已在旧账。字段 profile 绑定原实现 `paper_renderer.py:validate_audit`；有两个真实成功 audit 状态。它们是结构成功对照，未重新做科研事实盲评。

另将失败轨迹的真实工具参数送入原 `PaperOutput` 实现，在新私有输入/输出副本中依序重建草稿，不改历史原件。记录在 `.local/script-negative-fields-20261019-v1/replay.json` 和 `snapshots/`。这是历史工具执行重放，没有 Provider 固定回复，也没有新 LLM 调用；评估仍与训练同轨迹，不能代表独立新任务泛化。

| --- | --- | --- |
| 历史成功 stage 调用重放 | 85/85 草稿 SHA 与原轨迹一致 | 当前状态重建有依据 |

## 成本、质量与结论

本轮新增真实模型请求、输入/输出/推理/cache token、模型费用均为 **0**，因此没有 KV-cache 或完整任务费用对照。CPU、HTTP 认证和开发耗时未完整计量，不能说学习无成本。没有新最终报告，也没有合格交付或人工修订时间结论。累计本地旧账仍为 2835 请求/保守估费 $4.714453692，旧 1 个 pending 保留，V100 未核清；这不是服务商账单。

在这些只读校验器和历史状态条件下，证据支持“依赖字段＋失败谓词＋当前范围”比完整版本相等更能覆盖实际失败；不能支持通用错误因果学习、跨新论文收益或稳定净降本。负面守卫只省掉局部工具主体，并可能避免后续恢复；它本身不跳过已生成该调用的完整模型请求。提示也会增加输入 token。

下一步最有价值的验证：修复草稿的可读/可修复接口，让模型在新独立论文任务中真正修正这些字段，再比较相同交付标准下 Prompt/Enforce 与普通工程基线的所有正常、失败、学习及恢复费用。复杂枚举/脚本错误的字段切片需扩展通用控制依赖分析，而非逐错误补规则。稳定效果后由用户决定是否 PR。
