# GeneLoop 工作区、场景输入与历史 PPT 修复

- 范围：基于 main `4442199`；本轮修复统计摘要、命名工作区、斜杠选择和 PPT 跨部署恢复。复用已有三场景库，不训练新库、不修改上游 Harness。
- 假设：代码检出目录与保存的用户任务目录分离，触发 PPT 的旧路径守卫；场景候选订阅循环、过期异步选择和草稿竞争导致误选与跨对话弹窗。服务器错误及定向回归支持这些根因。

## 修改与数据边界

- 工作区只输入名称，由当前账号 output 下的 principal 哈希和随机 ID 分配目录。请求 ID 幂等，同名冲突按账号判断；禁用公开服务器目录浏览和任意路径注册，保留已登记工作区兼容性。
- 斜杠候选按当前前缀匹配；设置读取不再反复发布未变候选。点击、空格和 Enter 共用场景选择；手打 `/ppt 内容`、`/data中文` 在发送时解析，旧会话切场景保留草稿并转入新会话。异步结果受会话和草稿版本约束。
- `{{estimate}}` 是未绑定的数据证据占位符，不是 LaTeX 编译错误。双栏展示只采用本轮 `build_evidence` 成功收据、精确来源/SHA/计划一致的统计值；未知或歧义标记未绑定。代码示例、模型原文和轨迹保持原样。显示结果变化时，仅对应旧评分失效。
- PPT 显式 Web 模式将私有范围从代码目录收紧到服务端批准的当前 job 目录。TS/Python 同时验证，单独环境变量不能扩大 CLI 范围。旧检查点只允许四个已审计实现的精确版本迁移，其他来源、权限、代码和产物守卫继续生效；迁移前保留完整原始备份与审计。原 Motif library/certification 不变，只更新运行兼容代码锁。
