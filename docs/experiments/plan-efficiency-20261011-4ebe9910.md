## 问题、协议与范围

已知问题是页尾外的请求长度全额计入预算、重复/重叠读取、缺少汇总决策依据。假设：完整保留模型选择的位置集合的确定性归一化可以消除虚高预算与重复内容；基于原生事件的日志能定位哪些模型决策值得后续优化。若范围发生变化、错误复用旧源、权限混用或漏掉失败费用则否定工程实现。

输入为testpdf的MetaRSI、UnifiedPlayers和Paper2Agent三篇已知实验论文，问题为“这三篇论文的方法、实验证据和限制，对构建高效科研 Agent 有什么启示？”。它们不是留出新语料。普通解析缓存沿用profile v3；更新的是阅读执行/契约/工作流版本，不改原PDF或解析偏移规则。

开始前私有目录 `.local/literature-notes/plan-efficiency-20261011-4ebe9910` 保存 `protocol.json`，记录来源、全部场景代码SHA、Flash/off/无压缩、100美元总技术上限、免费诊断与一次真实开发任务。预算不是预计支出，API由用户授权。首次任务失败后保存 `targeted-repair-protocol.json`，限定3个缺口的新语义补证据，保留原费用，不重跑整份任务。日志时间戳适配从ISO兼容到原生毫秒数字，修正原来无法计算的工具耗时；不改变工具或科研处理语义。

## 决策日志得到的新证据

首次真实阅读5项批量计划中没有重叠：两项请求16785/25500字符分别实际覆盖13642/22625字符。页尾长度修正准确，但本任务没有观察到重叠合并节省模型往返。新增上下文缓存不是模型响应缓存；模型再次要求同一内容仍可能消耗输入Token。

两个全量阅读都猜过一次错误quote_id，原工具拒绝后模型修正。另一次续修只读取3个claim packet，随后说“需要周围原文，接下来读取”，但没有实际补读工具调用便结束。系统保留3缺口，未伪造交付；后续独立补读实际完成。程序仍不能保证模型每轮都会执行其承诺，也不能保证两轮自动复核总能消除缺口。

日志按真实callId对应结果，失败与ledger保留；首次、补证据、误触发任务的诊断分别有71/25/96条记录，原生4/2/4个run。派生诊断可查，但Motif学习必须回到原事件、当前工具契约和独立认证。未表达的选择理由未知，不推测其动机。

## 质量与结论边界

最终稿由真实模型、实际原文和自动支持复核产生，原文凭证重放/程序数字检查通过；没有人工审批。三篇原PDF内容SHA保持原值，同配置缓存证据完全一致。0程序缺口、24引文不证明中文论断全部得到充分支持、论文实验真实或新语料泛化。没有专家盲评，也没有冻结同一交付质量后与旧实现做随机对照。

现在可以支持“确定性计划归一化保留所选原文、版本/权限拒绝仍工作；完整决策和失败费用能回溯；Agent能自动交付且同配置核源复用”。不能支持新Motif收益、稳定净降本、无需模型选择窗口、完整自动自我改进。

下一步优先用原生轨迹验证引用ID选择和未提交便结束的完成性问题；机械规则由程序承担，科研证据取舍继续由模型负责。只有发现具有机器可核验前置条件、确实替代模型推进且优于合理脚本的重复路径后，才重新训练/认证有条件Motif。共享变化与回退见 [提交说明](../changes/literature-plan-efficiency.md)。未commit/push/PR。
