# 论文 Motif 未形成稳定费用收益的审计（2026-10-15）

**问题与范围。** 核对旧论文轨迹是否仍有复用价值，以及当前 Web 论文场景为何没有可复现的净费用下降。本记录只读分析已有真实 DeepSeek 账本、Motif 审计和代码；没有启动新模型任务。原始事件、输入与账本保存在 V100 隔离工作区 `.local/web/runs/`，本地仅在忽略的 `.local/paper-cost-audit-20261015/` 留下分析副本，均不进入 Git。费用为项目预算代理按已返回用量和配置价格估算，尚未与实付账单核对。

**先分清实验。** [旧三轮 Shadow](paper-rsi-overnight-20261011-v3.md) 在同一篇私有论文的变体上得到最佳 37/114（32.5%）严格整请求匹配，但没有执行跳过；九个图是局部候选，均未认证执行。旧 160/55/20 请求的 [PDF 工具采用实验](paper-legacy-reuse-audit-20261014.md)从已有 `audit.json` 开始，20 请求组附加当前报告与冻结排版工具的绑定说明，节省来自模型采用确定性工具，不是 Motif 自动接管。两张表不能相加。

**当前可执行覆盖。** `scripts/compile-paper-composite-runtime.py` 从两份历史库只编译并认证两条任务内 `pin → read` 只读边：上传源码读取与引用读取。旧九图中的 `read_pinned_citation_records`、元数据/查询恢复、`triage` 写后检查等未变成当前任务级 Execute 图。它们涉及动态对象选择、外部来源/版本、写入后的状态或不同工具合同；保留为候选，不可只改路径和摘要就准许跳过。当前 19 工具中的报告暂存、定稿和 PDF 导出是模型调用的有守卫工具，不是认证 Motif。

`c522c40e` 的 Execute 审计有两次真实工具结果验证，接管的是 `read_pinned_paper_sources` 与 `read_pinned_paper_citations`；其余 23 次模型请求仍需支付。该次比 Origin 少 16 请求，但审计只能把两次直接归因于 Motif，其余是模型阅读/工具路径变化。前一次完整任务的 Execute 则因 12 次工具错误比 Origin 多 20 请求，表明单轮请求差不是稳定净收益。旧报告来自预上传 JSON，新生成报告的 `8c31b5bd` 又是 **Origin**，所以该次的零跳过不能解释为库匹配失败。

**费用的实际落点。** `8c31b5bd` 的 11 次真实请求共 85,755 输入 token：77,056 为服务商提示缓存命中（89.9%），8,699 未命中；输出 4,157 token。按本项目预算代理价格拆分，命中输入约 $0.000462、未命中输入约 $0.002610、输出约 $0.004988。服务商提示缓存已经在工作，但它与“由轨迹编译的 Motif”是两套机制；命中输入仍收费，而输出及新输入是本次主要费用。`c522c40e` Shadow 的两次候选对应账本第 3、5 次请求，其当次代理估费分别仅 $0.000247020 与 $0.000244836，合计约占 Shadow 总估费 1.6%。这是若只移除那两次请求的静态账面机会，不是端到端节省估计；真实 Execute 可能改变后继请求。

**局部复用的限制。** 新生成报告的 Origin 事件中，第 3 个模型步骤一次发出 `read_pinned_paper_sources` 和两次 `read_pinned_document`；现有认证库仅覆盖其中一条读取。即使 Execute 接管这条边，也不能从 Origin 轨迹推断整次请求和其余读取都能消失。源码/引用语义判断、报告内容生成、外部证据确认、写入与 PDF 交付仍需模型或明确的确定性工具。当前工具失败、来源版本变化与未认证写入会形成 Runtime 屏障，这是必要的回退，不应通过放宽守卫换命中率。

**下一步最小验证。** 先离线按旧九图逐项核对当前工具 Schema、参数来源、权限、独立轨迹证据和 Shadow 命中请求的估费，优先处理安全且高成本的有界读取；只对过关的图重新编译/认证。随后用同一份独立论文、相同提示/工具/输出上限，运行 Origin、Shadow、Execute，并统一检查报告内容、PDF 和人工修订；记录全部失败、请求、缓存命中/未命中、输出与实付账单。单次新库 Origin 或不同提示的历史 160→20，均不能代替这一验收。
