本次只把已有本地文件管理能力接入 main 的 `/file 文件管理`；另外三个场景、共享原生任务宿主及 Paper/PPT 证书不改。开发基线 `a1c0fa25e8305d69ea7d8b9ed93ec820874657c8`，分支 `codex/geneloop-file-rsi`。用户审阅 PR 后合并，不自动部署。

## 配置与证据

macOS、现有项目 Python 3.12 与 Node 环境、仓库固定 DeepSeek Harness 依赖；真实模型 `deepseek-flash`，推理 off、不压缩。使用新建的合成 TXT 材料经原生前端上传，检查的是集成机制，不是私人办公资料的前瞻业务盲评。各任务在模型调用前冻结目标/来源，未使用历史最终留出集学习。旧版本、失败、原轨迹和恢复数据均保存。

权限沿用任务副本内低风险默认执行、高风险逐计划确认；本轮在原1000美元/共享学习25美元内预留5美元集成封套，任务最多96步/请求、4000输出token、2次验收修复与2次服务商重试。所有普通、学习、原生与实际认证都经原平台计费，不直连绕过。重启使用显式累计 checkpoint，并携带前两轮的247请求与USD0.14932251，原授权和既有未知预留不清零。

私有有效源码快照、冻结材料/验收、浏览器截图、原始 SDK 与 native events、逐 HTTP 账本位于隔离 worktree 的 `.local/integration-checks`、`.local/web`；原本地 `.local/geneloop-file-integration-20261019` 保存迁移/累计费用回执。原始日志与资料不发布。

## 观察结果

- 原生斜杠菜单与另外三个场景并列 `/file 文件管理`，共用编辑、工作区、上传、预览和下载；执行和 RSI 自动开启，不提供额外开关。
- 实际复制→完整读取中间副本→重命名通过，无多余副本，原件字节保持。前端下载与实际输入 SHA 相同。
- 在首次复制已生效后中断，再点击原生恢复按钮，沿用同一 FileJob、来源、权限和预算，累计请求3→11，复制仅一次、重命名仅一次，最终通过。冷重启保留会话、文件、经验库和累计费用。
- 源码更新时旧策略失效，普通 Harness 完成新7/8文件任务；新普通轨迹自动发现集合图并进行独立原生认证和两次实际复用认证。后续普通任务自动选中当前策略，8/8全文覆盖、无文件变更、0次验收修复、5次模型请求、3次有事件证据的模型请求跳过，估费USD0.008654628。未使用 profile_id 指定正确模板。
- `file-v3` 公开3项重新认证策略：单文件 pin/read 与集合图的两个版本。`file-v1/v2` 保留追溯；各账号安装后继续使用独立私有库。新账号隔离、停用不被安装过程重新激活及篡改拒绝均为免费检查。策略数量不等于不同工作流总数。
- 高风险覆盖显示原生“允许一次”，确认前所有原文件未变，确认后只修改指定原文件，保留内置恢复日志。模型另建了备份副本，因此该任务**未通过预先冻结的无额外文件检查**，只证明权限桥接通过，不算严格质量通过。目标仍标记 review_required，未伪称语义完整验收。

## 失败与修复

首轮原生事件投影缺少 surface 标记，1次请求后失败，文件操作前停止；补上 File 专用事件投影与真实 Session 回归。另一轮操作正确但旧验收根路径拒绝新的账号副本目录，同时导致2项原生认证失败；修复为仅允许该账号的受信任副本根，并测试其他账号根被拒绝。旧失败不追改。旧种子在运行源码变化后被免费版本检查拒绝，保留旧版本并独立重认证；没有仅更换源码哈希重签。

高风险桥接另有免费拒绝、批准后中断重试、恢复方向隔离和下载路径/符号链接/摘要检查。未真实执行永久删除或工作区外写操作。所有三项公共种子有独立、无修复且用量完整的当前证据，不含原任务授权。
