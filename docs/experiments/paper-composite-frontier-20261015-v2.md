## 原因与最小修改

在完成的 v8 Execute 事件中，模型穿插调用 `pin_document`／`read_pinned_document`。这两个工具虽在论文 MCP 中标记只读，v8 manifest 未登记它们；Shared RSI 因而把成功结果视为屏障，清除前面的源码和引文 pin。v8 Shadow 的候选 2 次、完整 Execute 尝试 0 次；同库两个独立短任务各有 1 次真实验证跳过，证明不是库缺失。新库现把 `list_inputs`、`pin_document`、`read_pinned_document` 作为**只观察、不自动执行**的只读合同。成功的无关读取可以穿插；失败、未列出的工具、版本变化及 PDF 写入仍阻断。场景提示明确要求先 pin 后读取返回的真实句柄。实现只改库编译配置和场景提示，Shared RSI 代码没有改。

v9 全任务的另一个失败原因是文件容量契约不一致：`references.bib` 123,611 字节，上传允许至 256 KiB，但 `read_pinned_document` 把全部文本算作单页并拒绝超过 100,000 字符。模型对该文件、错误页码和未签发句柄反复重试。v10 把文本按固定 80,000 字符分页，保留同句柄与版本检查；场景提示要求按返回的 `page_count` 读取，避免重复提交失败参数。对该真实文件的无模型调用得到两页，80,000 与 43,597 字符。该修复不扩大文件总量或读取权限。
