# 对照并行、历史恢复与即时评分

- 日期：2026-10-15；类型：合成软件测试及浏览器验收，不是科研质量或普遍降本评估。
- 分支：`codex/comparison-responsive-parallel`，基于 `722b181`；未修改上游 Harness。

## 问题与修改

历史消息保存了对照创建时的 queued 快照。组件每次挂载先显示旧值，等读取完成才恢复终态，因此页面跳转会错误显示等待并阻塞输入。现在当前页面内缓存已确认快照；没有确认状态时显示“正在加载此轮结果”，不把未知状态当排队。普通历史读取不会重跑任务。

两侧原来被对照循环和单 active task 两次串行限制。现在仅同一对照中的 DeepSeek 两侧可以并行，各侧 Session、工具范围、模型请求核验、预算路由和文件目录独立；其他轮次仍排队。旧 GLM 适配器没有明确 Session 请求头，保留串行以防串账。没有新增 Agent 循环。

评分立即显示选择，使用按比较 ID 共享的队列串行提交，快速点击保留最后意图，站内切换继续保存。服务端独立短锁校验版本并持久化，不等待原生通知。网络失败先读取确认，失权、离开页面或结果版本变化会停队列并清理状态；成功队列释放，错误状态有界保留。

运行快照按 250ms 合并写盘，SSE 仍实时广播，终态和评分同步持久化。审查发现异常退出前未落盘的 revision 会倒退，新增同步持久化的 `snapshot_epoch`，前端按 epoch、revision 排序，拒绝旧实例迟到数据。完整终态保存交付核验标记，常规读取不再重复查询预算，旧记录仍执行必要恢复。
