- 日期：2026-10-19；独立分支 `codex/negative-cause-learning`，基线 `2acb445`，实现提交见本文件 Git 历史。未推送、PR 或部署。

## 问题、机制和边界

用户要求从“识别重复 ID”推进到自动学习不同错误的原因。前轮仅支持顶层直接抛错，漏掉循环内枚举检查及控制依赖；仅验证无关编辑也不足以证明修改候选原因能解除错误。

本轮假设：复用同一个通用编译器，沿受信校验器的数据和控制依赖构建条件，并通过原函数验证双向干预，可以覆盖不同结构错误。若必须逐错误注册字段/修复规则，或只知道哪些字段变化而不知道失败条件是否仍成立，则不支持该假设。

实现集中在 `negative_field_compiler.py`、`negative_field_runtime.ts`，复用既有 CLI、存储、代码锁及原生 `tools.guard`：

- 静态解包/别名、有限 tuple 循环展开、动态列表循环、嵌套 if/else、布尔短路、字面量 schema、类型、成员资格和集合关系生成带作用域变量的 IR。同一错误的多个分支合并；条件开关及跨记录依赖均保留。不注册具体错误名或论文字段。
- profile 一次指定整个只读校验器；编译器自行遍历不同错误。schema 常量须来自该文件字面量并与当前全局值一致。函数必须经开发者审阅，确为工具必要前置条件；不导入模型任意脚本。
- v2 认证要求：失败见证、实际校验成功的对照、依赖外干预，以及修复/重新引入的双向干预。优先对照值，行数不匹配时尝试通用数据扰动，由谓词和原函数共同筛选，用有界 delta debugging 缩小改动。只操作内存副本，没有自动修稿。
- 修复要求原目标错误消失，重新引入要求原错复现；另存剩余错误及是否整个校验通过。一次失败可有多个同时成立的原因，不能将首先抛出的错误当作唯一原因。
- Runtime 有界解释，不求值任意代码；错误码与双向摘要绑定。继续当前失败→真实请求提示→重算条件→局部门控，来源/目标/schema/身份/参数及当前 SHA 守卫不放宽。未知/超限回退，其他工具与真实修复可继续。

这是**源码辅助的结构错误原因候选＋局部反事实验证**，不是通用黑盒因果发现。捕获异常、提前返回、复杂/不透明调用、Python 数字类型身份及科研判断仍不支持；静态提取也不等于可发布或可自动接管。

## 真实历史状态与对照

沿用此前一条真实 RMSNorm 失败轨迹和两条结构定稿成功轨迹；不重复计旧模型费用、不改原件。此前 85 次完整草稿版本重放是前轮证据，本轮没有重新执行它们。

字段原因认证仅使用两个失败快照，每个错误取首次状态；剩余 25 个状态留出，并实际调用当前 `validate_audit` 核对首个错误及完整文件哈希。**工具错误标签、失败资格/schema 学习仍使用全轨迹**；该切分仅检验字段原因条件，且同一任务内状态相关，不是独立任务盲测。成功对照是两条不同历史任务的实际 audit，当前原函数成功、两条谓词均 false；科研事实质量未重新盲评。

| 验证 | 结果 | 证据界限 |
| --- | --- | --- |
| 原论文校验器静态提取 | 11 个候选错误条件 | 不是 11 条已认证规则 |
| 实际轨迹支持的字段规则 | 2 类：重复来源 ID、非法 status/priority | 原 5 类负面规则中 2 类升级，其他保持原策略 |
| 留出状态：枚举错误 | 8/8 原错误复现、对应谓词 true | 同轨迹状态留出 |
| 留出状态：重复 ID | 17/17 原错误复现、对应谓词 true | 不等于 17 次 LLM 跳过 |
| 留出状态追加 notes | 25/25 对应谓词保持 true | 无关编辑局部诊断 |
| 历史成功状态 | 2/2 当前校验成功，两谓词均 false | 非新任务交付 |
| 同时成立的原因 | 7/25 同时满足两种失败条件 | 首个错误分类不能代表所有问题 |
| 通用非论文诊断 | 7 个错误标签认证并跨 Python/TS 通过 | 合成诊断，不作为真实泛化率 |

七个通用诊断涵盖枚举、受开关约束的容器/元素类型、跨集合关联、集合上限、必需字段、标量类型及分支内数值范围。字段和错误名不同于论文例子，生产代码无专用分支。各案例同时检查未知状态回退、无关变化保留门控及修复放行；原生 ToolRuntime 继续验证工具主体被阻止而其他工具可用。

真实双向原因证据：

- 枚举错误自动定位到第 28 条记录的 priority；从成功对照替换后整个结构校验通过，反向引入后原错复现。此处是历史具体位置，不作为新任务固定索引规则。
- 重复 ID 自动缩小到一处 ID 改动，目标错误消失，但暴露出枚举错误，因此 `whole_validator_passed:false`。在成功状态中引入重复后复现原错。通用扰动值只用于诊断，没有写回用户资料，不能当科研修订建议。

## 成本、失败与结论

本轮新增模型请求、输入/输出/推理/cache token、模型费用为 0，按用户当前顺序推迟付费恢复/费用实验。不能报告调用下降或 KV-cache 改善。累计旧本地仍为 2835 请求/保守估费 $4.714453692，旧 1 pending 与 V100 未核清费用保留，非账单实付。

单独重认证计量：重复 ID 调原函数 23 次（其中干预 11 次），约 0.044 秒；枚举调 22 次（其中干预 10 次），约 0.050 秒。仅为一次本地认证测量，不包含开发、历史采集、全量回归及正面脚本沙箱/HTTP 认证，不能将学习总成本记作零。

保留的失败：初始按跨论文行号移植无法修复重复 ID，加入受原校验器验证的通用数据扰动；缺字段诊断暴露 dict.keys 集合语义差异，修正 Python/TS 后通过；首个 CLI 库因未注册模块的源码定位失败而保守保留旧策略，修复后新库两类认证通过。初始失败库、局部测试失败和所有旧结果不改写。

目前支持不同结构错误复用同一学习/认证机制，超出只识别重复 ID；但真实错误认证仍仅两类，7 类诊断不是新任务泛化证据。三个原校验器错误（控制字符、计数类型、编号类型）仍无完整支持；不透明 Bash/Python、动态状态、外部依赖失败及语义/科研错误未解决。

下一步先用不同校验器和独立资料检查原因迁移/误拦截，再按用户顺序比较 Prompt/Enforce 的恢复成功率、必要语义判断及最终交付。把错误残留、学习、提示、模型重试和所有失败成本一起计入，不能用局部工具拒绝替代净收益。效果稳定后由用户决定 PR。
