# V17 服务器连续对话改页验收

## 问题、假设与范围

用户要求在服务器实现“生成后继续对话、只修改指定页”，暂不提交或推送。实验 ID 在开始前确定为 `research-ppt-v17-conversation-20261014`。本轮复用已生成的两份 Attention Is All You Need 15页稿件，不重跑论文生成。

验证假设：现有 Harness SDK/MCP 可以在保存的同job生成计划上进行两次连续自然语言修订；独立程序保证父稿版本、非目标页与原稿保持，真实渲染通过后再更新当前稿。提问不改稿、重复请求不重付费、服务重启后可继续。任何未通过实际交付而被展示为完成、未经要求改动其他页、费用丢失或重启重复调用都否定验收。

这是服务器真实前瞻接口验收，非独立同内容降本实验。两份原稿第4页内容不同：普通稿是掩码流程，优化稿是完整原文架构图；不能仅凭本轮差额认证同质量成本下降。

## 实现与有效配置

- 发布基线 `82e137682b32b30e650615a374404de8aec03a3b`，本次改动未提交、未推送。服务器检查树不是该发布commit的权威Git记录，以私有部署包SHA和每条反馈源码快照定位。
- TypeScript `ts/web-tasks.ts` 保存长期任务/对话/版本/预算、按组恢复历史，接入 `message`；`ts/feedback-runner.ts` 调用既有 `scripts/run-scenario.py`，没有新建模型循环。
- `ts/feedback-mcp.ts` 代理原MCP，限制当前deck/SHA、明示目标页、批准来源和本轮新验证回执。既有后端检查非目标页OOXML、notes、媒体、表/图、关系及共享样式，原稿保持；新版需真实PDF/PNG验收。
- `web_feedback_bridge.py` 仅读取同job checkpoint、实际验收与完整账本。费用读取先于交付收集，交付失败不丢模型成本。
- 网页 `/ppt` 继续同任务对话；同源 Harness 鉴权。每条消息 `task_id/message/request_id/expected_version`，重复ID幂等、旧版本拒绝。
- 模型 `deepseek-flash`，思考off、压缩off；每条消息两路合计$0.50、每路$0.25/24步/4000输出。工具表面固定为 `read_deck_plan/read_source/read_page/inspect_deck/revise_deck/validate_deck/deliver_deck`。普通组原子步骤，优化组原job的固定 `host_delivery`。
- RSI候选生成关闭，verified skip为0；每条反馈不生成新工具。改页是既有确定性脚本和接口的可靠复用，不称新增RSI收益。
- Ubuntu18.04、Node22.23.2、Python3.12.15、LibreOffice7.6.7.2，沿服务器原隔离环境/字体。依赖版本见安装锁与原trial环境快照。

## 失败与处理

1. 原结果收集对Harness运行目录误用“必须是文件”的守卫：普通组已有合格副本却未显示；修正为目录/私有runs范围/manifest提示与scenario哈希校验，不放宽其他文件守卫。
2. 原图页的三要点加长证据说明挤占完整原图，被后端正确拒绝；代理此前隐藏具体报告，模型无法局部修复。现在保留有界错误报告，模型只精简本页bullets/evidence_notes，保留原图、sources和notes后通过。未删溢出门槛、未模拟渲染。
3. 首次费用虽已付但结果accounting为null；用原manifest/提示/完整ledger独立核验补回状态，另存 `attempt-01-accounting-reconciliation.json`，旧raw result和失败状态未追改成成功。
4. 失败/纯回答不占实际稿件版本号；每组按成功修订递增。最终双方均为原稿+两次修改，共3个可下载版本。
