## 问题和任务边界

此前 Web 将真实论文简化为平铺的部分源码，无法读取原 ZIP 的嵌套目录和完整书目；旧 Motif 预测的 pin/read 调用也与当前批量证据工具不一致。因此先验证一个明确的局部结构步骤：模型从当前任务的 `collect_current_local_citation_evidence` 返回的 `source_id`，继续调用 `read_pinned_bibliography_first_page`。若真实模型不重复该调用，或 Shadow 在当前任务来源上预测错误，这个局部库便不可用。

## 原始完整题面的反例与成本瓶颈

又以仓库原题面 `scenarios/paper-submission/reference-audit.prompt.md`、相同原 ZIP、PDF 输出授权做真实 Web 复测，不能把局部前 12 条的完成当成全任务。首次 `full-shadow-01` 在提交时因任务绑定把多行长题面直接截到 1000 字符，违反在线 Runtime 的单行且不超过 500 字符的结构标签约束，因而 `motif_library_invalid`，按普通 Harness 继续。它产生 27 次请求、28 次工具调用、2 次工具错误、12,061 输出 token、估费 $0.04106646 和 8 页 PDF，但报告只覆盖 **40/315** 条；质量未通过。14 次 `stage_current_audit` 写草稿请求输出 10,314 token，占当轮总输出的 85.5%，对应账本估费约 $0.018554；这才是长任务可复用脚本最值得处理的输出瓶颈。此轮为失败流程成本，不是 Shadow 效果。

绑定修复只把 Motif 的信息性任务标签规范化为单行 500 字符以内，完整模型题面仍原样保留；Node 长题面协议测试通过，私有 Runtime 按新代码锁重编为 `composite-v4`。有效的 `full-shadow-02` 已加载库：20 次请求、18 次工具调用、0 工具错误、1 个严格整工具请求候选、0 跳过、10,221 输出 token、估费 $0.024053304。候选对应本轮模型第 3 次请求，唯一工具调用及 `source_id` 与任务锚点一致，另有流程旁白；该请求输出 100 token、估费 $0.00365748。它生成 7 页 PDF，但仅覆盖 **35/315** 条，因此同样未达到完整题面的交付标准。两次报告覆盖不同，20 对 27 次请求或费用差额绝不能归因于 RSI；Shadow 没有跳过模型。外部真实性、版本和逐页视觉质量仍未评审。

这说明有两段性质不同的复用机会：已认证的书目来源句柄后继能理论替代一次小输出的模型请求；报告草稿的固定字段、编号、引用键和来源摘要应从已核验的任务数据由确定性脚本生成，让模型只提供需权威检索的判断和差异。后者尚未实现，不能把未核验条目伪装为“已确认”或为凑满 315 条自动填充真实性状态。

本实验私有目录现存 13 条有完整用量的真实任务摘要，合计 93 次请求、$0.156406716 保守代理估费，包含上述旧配置、错误句柄、未命中、两次完整题面和重复运行；另一次启动前因密钥未加载失败，没有模型请求。该累计数不能作为单一方案的对照分母，也未与服务商账单核对。
