# 已有三场景 Motif 库与原生双路聊天联调

## 问题与范围

复用已经存在的 PPT、论文、数据报告库，让同一用户请求和同字节附件进入两个独立、持久的 DSH 子会话，分别交付并收集 1–5 分。验证用户隔离、多轮、重启、幂等、评分与成品下载。当前目标是功能可运行；未做科研事实、视觉质量盲评或成本优越性研究。

公共产物位于 `motif-libraries/`，原 SHA256 与模式见各 `entry.json`。本次接入没有重新训练。PPT 原库、manifest、训练认证保留原字节，当前兼容锁另放 `runtime-bindings.json`；数据原 V3 库有 10 个回执续接；论文原库只允许 Shadow，不能以候选次数冒充跳过请求。文献库不在三场景验收内。前期曾走过重新生成库的错误路径，其私有结果不用于产品；相关真实调用仍计入累计费用。

- 代码基点：main `669d9bcb9976b53f7fa61474dfd8721dab52308c`；初始分支 `codex/paired-scenario-comparison`。PR #17 首次上线为 `1ee0bf4504f6d42798b1c76df3e87eb622717b14`；PR #18 追加修复后的最终生产代码为 main `2f4c8d22f633058f00a4871bc120a9bc7969acaf`。

- 模型实际 `deepseek-flash`、推理 off、输出 cap 1000；每侧新任务请求 cap 24。两侧同请求、附件字节、选项、工具集合、模型；每账号依次运行两侧，账号间并发。
- 合成上传资料：一页 PDF、参考条目 JSON、12 行 CSV 与研究说明 JSON。模型真实执行统计、图表、报告工具，没有预写答案替代模型。
- 数据依赖见 `scenarios/data_analysis/requirements-report.txt`；PPT 渲染器、字体、PDF 安装由私有管理员配置提供，只读挂载到成员环境；安装链接应指向规范化真实目录。
- 私有有效配置、来源摘要、逐步日志、统计和结果位于服务器本轮隔离检出的 `.local/paired-stage`、任务账本、诊断目录。凭证和原始日志不进 Git。缓存命中/未命中与输出 token 保存在账本 `response_usage`；提供方实付和人工修订时间未核对、未计量。
- 免费复现：`npm test`、`npm run smoke`；PPT 实际 MCP/渲染诊断为 `scripts/check-ppt-runtime.mjs <私有诊断job.json>`。真实验收使用私有合成账号及上传、发送，模拟 Provider 不算模型端到端证据。

## main 上线后复验与追加修复

PR #17 已合并到 main `1ee0bf4504f6d42798b1c76df3e87eb622717b14`，四项 Windows/Linux CI 成功。服务器保持 owner 33102 / gateway 33101，原三个账号、Home、文件和历史保留；公网登录、账号信息、工作区就绪、主页面均返回 200。

生产临时双账号验收中，PPT Baseline/Motif 首轮分别 4/3 请求，Motif 1 次已验证跳过；论文 Baseline/Shadow 各 4 请求。均真实交付，工具错误 0，三轮、评分、下载哈希和跨账号拒绝通过。

数据报告的另一条负例：Baseline 17 请求交付成功，Motif 24 请求、6 次已验证跳过，最终模型总结触达 cap。追溯发现回退字体 `STSong-Light` 丢失系统表格标签 `R²` 中的上标，严格文本检查因此失败，模型反复修订后删去可选指标，实际在 step 31 成功交付 PDF，但 step 32 总结失败使界面隐藏交付物。初次修复将系统指标标签改为 `R-squared`，当时用强制该回退字体的正例与旧标签缺字负例验证，未放宽质量检查；后续通用字体修复将 `R²` 改为应完整保留的正例，真正缺字负例仍保留。

同时修复失败任务的已验证成品展示：依赖本任务时间边界内的真实 `deliver_report` 调用和成功回执、当前文件 SHA；不能借先前/后续轮的交付记录恢复。失败状态、预算用量与评分禁用保持，冷读取不启动模型。终态文件读取允许使用落盘统计，不依赖在线预算统计接口；暂时读取异常允许后续再试。

只改系统标签后的下一次负例证明正文中的 `R²` 仍会缺字，两侧均触达 24 请求 cap，未获得交付回执。因此进一步复用服务器已有 matplotlib 的 DejaVuSans，对 STSong 不完整的科学字符做嵌入字体回退，标题、正文、图注、来源、表格共用安全转义入口；原文不改写，审计不放宽。引擎版本升至 v2.3 失效旧失败布局缓存，`missing_text` 块 ID 返回模型。服务器 36 项文档/工作流回归通过，涵盖三样式、R²/下标/希腊/±/负号和真正缺字仍拒绝。此前完整回归更新为 861 Python / 449 Node 通过、3 Docker 条件跳过。

## 预算与结论

用户明确批准把共享累计 cap 从 250 次/$0.23 扩至 1000 次/$1，保留累计用量。切换时沿用 **248 次、代理估费 $0.105100122**；最终验收观测为累计 **424 次、代理账本 $0.204334710**，包含先前失败和修复复验，原预算进程继续存活。checkpoint 在上游调用前落盘，重启不清零，未知使用保留预约费用。后续测试和同学使用均计入总额；代理估费不等于提供方实付。

在受检账号和合成资料下，三场景双路、修订、多轮、重启、评分和隔离得到功能证据。PR #18 的最终数据复验成功，但先前 Baseline/Motif 失败、人工精简与追加修复成本仍属于完整记录。PPT/数据的跳过只针对原库有守卫的机械续接；论文是 Shadow。不能据单次成功对照宣称净降本。未做大规模并发压测、真实科研质量盲评、长期隧道可靠性验收，未证明文献有可上线的已有训练库。
