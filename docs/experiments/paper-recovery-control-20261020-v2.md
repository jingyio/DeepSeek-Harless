# 论文恢复：从参数复用到显式当前操作接管

实验ID：`paper-recovery-control-20261020-v2`。基于`aff4d86`，沿用PR94与已有Baseline。类型是同一真实论文、两种历史完整报告的局部恢复，不是独立论文或完整任务对照。按用户最新要求依次分析代码、Breakdown、归因、修改、实测；未改变生产服务或公共默认库。

## 代码与费用归因

先审计上一轮005/006/007的完整请求。007两次短协议被组合命令拒绝后，模型改走普通原生工具，生成8401输出Token，占该运行输出约72%、费用约45%。006连续四种组合命令都被拒绝；成功之后还查找Bash未挂载的文档服务目录。不能把这些都称作语义推理或Motif自身计算开销。

第一项改动仅改善编译诊断与交付边界：合法静态JSON可在拒绝回执中得到保留全部原计划的`retry_command`，原命令整体不执行；组合写入不推断计划，不放宽parser。当前候选直接附可提交的独立命令。成功交接说明文档服务文件不在Bash目录，并由Runtime核验真实文件。

实测001使用短协议、无成功后读取，但仍9请求。002用了三次短协议导出，却发生67请求：27个生成本地脚本的请求约$0.047487（53.5%），10个搜索内部模型请求约$0.018513（20.8%）；另有读取、联网调度和总结。这些类别按完整请求的可见动作归因，含请求中的语义判断，不能解释为全可省费用。002有12次工具错误，最后保留结构却修改了逐条记录，未作科研盲评，不能当作无损成功样本。由此排除“仅修好短协议就能解决恢复成本”的假设。

代码中`ready()`原来只能执行模型先选择的`frame`。即使已有当前完整目标，也不会在首次请求前执行。因此增加明确的**当前执行义务**，不是继续降低匹配阈值：runner显式`--resume-current-operation`表示当前任务已经选择恢复该操作，写入Bash不可写的任务状态；Runtime核验当前task/grant、完整参数SHA、来源文件、已认证契约与Schema后，直接执行一次。失败立即交回语义修订，不自动重试、不生成科研修改；成功核验文件并交回最终总结。未显式选择、证据不足、撤权/变更时回退。这是执行接线，不能计为新挖出的Motif或自动理解任意自然语言目标。

## 回归与集成
