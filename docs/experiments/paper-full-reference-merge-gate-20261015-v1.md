## 两条优化线的当前状态与合并条件

1. **脚本复用**：现行 `collect_current_local_citation_evidence` 已把本地 pin/检查/BibTeX 读取合为一次有来源守卫的模型工具；旧排版脚本已作为受报告 SHA 和任务输出授权约束的 PDF 工具。它们说明能力已接线，但没有同题、同范围、同质量门槛的节省对照。下一步应从真实多次正常轨迹中选取重复的纯结构程序，先用独立输入验证，再让模型在原完整任务里调用，记录因此少生成的脚本/报告 token、额外学习费、失败和恢复费。不能预先把全部 `stage_current_audit` 输出算作节省。
2. **Runtime 整请求接管**：只对请求前预测、来源/权限/Schema 均有效、下一模型响应的工具集合与参数完全一致且没有不可丢弃文本的请求，计 Shadow 理论机会；逐请求列出实际缓存命中/未命中/输出 token 和代理估费。未认证的旧图不能自动升为 Execute；执行守卫与真实后继费用仍另行验证。

正式合并门槛是：原完整题面或经用户明确接受的等价范围，在相同输入、工具、模型及可核查质量要求下交付；脚本复用有正向 token/费用证据；冻结 Motif 在后续 Shadow 任务中有至少一个严格完整请求机会且其账本 token/费用为正，并报告全部失败、训练摊销与实付未知。Shadow 机会只支持理论节省，不能写成实际少付费。当前 Web 仅支持 16 份平铺论文附件，任务 API 每文件 256 KiB；引用取证一次最多 64 个活动键，且没有对完整书目逐项权威检索的能力。原 34 文件嵌套 ZIP 与约 314 条完整列表尚不能按原题面直接由现行 Web 完成，必须先解决输入、范围、外部证据和报告批量输出，再做付费对照。

私有源文件、完整事件和逐请求账本保存在 V100 `.local/imports/paper-baseline-sync-20261014/`、`.local/paper-source-links-runner-v1/` 与隔离检出的 `.local/web/runs/`，不进 Git。当前分支只修正文案，使场景在用户明确要求全量真实性核验而工具范围不足时报告未完成，不把部分报告冒充完整验收；没有因此宣称优化收益。
