# GeneLoop 原生 PPT 技能对照

## 范围与实验约束

用户要求由 GeneLoop 自己分别使用原技能和 ppt-master 制作同一论文 PPT；测试者只安装/配置、提交、收集和只读评审，不参与内容、版式、公式、修订或制作提示反馈。先前独立 SDK 与人工参与修订的 PPT 全部排除，详见[先导实验更正](scene-skill-effect-20261017-v1.md)。

本实验测试实际 GeneLoop 网关、独立 QA 账号、原生二进制附件上传、`session/selectModel` 和 `session/prompt` 的 `/ppt` 场景。不是独立 SDK 运行器或手工编写的模型循环。生产源代码、用户数据、默认配置未修改。实验在回环地址的隔离网关执行，仍使用原预算代理与累计账本。

任务是《Attention Is All You Need》v7 的严格 10 页中文研究生组会 PPT，16:9 白底学术风，包含封面/结尾、至少两处原图表、来源页码、可编辑文本与核心机制/表格、讲者备注、PPTX/PDF/逐页预览。相同题面明确将设计选择委托给 GeneLoop。用户不需要补充设计确认。输入 SHA256 为 `bdfaa68d8984f0dc02beaca527b76f207d99b666d31d1da728ee0728182df697`。

所有模型调用真实执行 `deepseek-v4-pro`、`reasoning_effort=off`。两组均关闭 Motif、采用普通单路场景执行，以隔离制作技能影响。请求数、单任务/累计费用、输出限制均为 null。代码基线 `5a27208ec9e4051eedb7ecae6a297246a6c9a1f7`，Node 22.23.3、DSH 0.1.5-rc.3，服务器 Python 3.10.21。普通 Bash、后台任务和网页工具沿用应用；均预装相同完整 ppt-master 6.6.0、LibreOffice 7.6 与字体资源，原版仅按原技能工作。

## 接入诊断与有效比较的区别

最初保留原 PPT MCP 制作工具，只替换场景技能指令并安装完整目录。两次模型都读取了 ppt-master 入口和工作流，但随后仍调用原 `render_deck`/`repair_pending_plan`。第一次还尝试把应用附件宿主路径当成 Bash 沙箱路径。此组只能证明“注入技能文本并不等于切换完整制作流程”，**不属于 ppt-master 完整导出器的效果样本**。所有失败和费用保留。

随后在新的隔离网关和账号中，候选场景只暴露公共 Bash/任务/网页工具，用完整 ppt-master 自带流程执行来源转换、设计、页面制作和导出。旧 PPT MCP 工具不再对该候选任务可用，明确输入位于沙箱只读 `inputs/`。没有改动模型、论文、题面或技能文件，没有给模型评审反馈。此比较包含技能配套流程与导出器变化，不能归因成“仅一段提示词”的收益。

原版两次独立运行均保留：第一次只完成阅读与计划，未交付文件，虽应用状态 completed 仍判任务未完成；第二次成功交付。原版结果不挑选为稳定成功率证明。完整候选仅一次独立运行，已交付，不能据此推断稳定成功率。混合入口第二次的停止请求到达前任务已经 completed，按实际完成与全部费用记录，不伪称取消节省了调用。

## 只读核验方法

原始成品先冻结 SHA256；检查 PPTX 页数、画幅、备注、原生形状/表格/Office Math；使用本地 Microsoft PowerPoint 只读打开导出 PDF/PNG，逐页查看。该导出仅供同平台视觉比较，不算 GeneLoop 自行完成的 PDF 交付。原应用/技能生成的 PDF 单独保留。导出后再次核对原 PPTX SHA256，禁止修改原稿。

科学内容对照原论文正文及表格原页，不以文本提取或结构检查冒充事实核验。没有盲评和多题样本，不据单篇论文宣称普遍更优。工具错误计数来自应用，另注意 Bash 非零退出未必计入该字段。

原版第二次已核验：10 页、16:9、10 份备注、106 个可编辑形状、3 张原生表格、2 张图片、0 个原生公式。PPTX SHA256 `674a81ff8504f8c5b9c57167f964588ee5e6bb67a203912bfac990399e425ce0`。白底模板规整，机制主要依赖原图、公式为普通文本。第 5 页把 FFN 写成“逐位置参数不同”，与论文 §3.3 的跨位置共享参数相反；第 8 页把 Table 3(B) 的 `d_k=32` 标成 `h=32`，并混入 60M 参数，属于不同消融变量的混淆。原稿保留这些问题，没有修订。

## 完整 ppt-master 结果与判断

实际轨迹包含读取技能、attribution_guard、来源转换、项目初始化、设计规范/执行锁、逐页 SVG、自检修订、讲者备注、最终导出和 LibreOffice 渲染。13016 个原技能文件逐一比对未修改；没有测试者编写页面或反馈修订意见。模型多次使用 `cd`，违反技能路径纪律，因此不能宣称所有技能协议逐条合规。应用的工具错误字段不统计所有 Bash 内部校验失败，不能把它的 0 解读为“一次通过”。

候选交付 10 页、16:9、10 份备注、PPTX、真实 PDF 和 10 张 PNG。OOXML 检查为 275 个可编辑形状、3 张图片、3 个原生 Office Math、0 张原生表格；表格是可编辑文本/形状组合。PPTX SHA256 `d1ea7a212acaf7630d5418971a092a68b2bce04eccd7aa1cd3797bd1c35d9792`。两份 PPTX 在 PowerPoint 只读渲染前后哈希一致。

视觉观察：候选封面、分区和强调层次更丰富，公式原生可编辑，信息组织比原模板灵活；但不是全面升级。逐页查看发现：

- 第 4、5 页互换了缩放点积注意力和多头注意力原图，与各页标题及图注相反。
- 第 6 页的位置编码原生公式超出左侧区域，左端裁切、右端进入插图区；“低频小维度 / 高频大维度”标签也与编码公式的频率关系相反。
- 第 8 页训练代价列多行错配：GNMT+RL 写 9.6e18（原文 EN-DE 为 2.3e19），ConvS2S 写 2.0e19（原文 9.6e18），Transformer base 写 2.3e19（原文 3.3e18）。big 行在 FLOPs 列填训练天数/硬件，量纲不一致。原论文 Table 2 第 8 页直接核验，不接受模型“逐条核对”的自评代替事实。
- 第 9 页声称 `h=16` 也使质量下降，但原表 (A) 的 h=16 为 25.8，与 base 相同；更高 h=32 才是 25.4。把扩大层数普遍写成更好也过度概括。

原版与候选均未通过可直接用于科研汇报的事实门槛。**本题支持候选在部分视觉表达/公式编辑性上改善，不支持整体效果更好或替换线上默认。** 原稿全部保留，不给制作模型反馈，不手工修稿，不以修后版本作为原始效果。LibreOffice 对原生 Office Math 的渲染差异另外保留，同平台 PowerPoint 上仍能看到上述公式溢出，不能归因成只有 LibreOffice 的问题。
