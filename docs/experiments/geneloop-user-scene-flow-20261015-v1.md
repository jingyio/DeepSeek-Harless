## 范围与配置

基于 main `8325cb5`，分支 `codex/user-scene-workspace-flow`。修复内部 preset 展示、目录 hover、UUID 空会话标题、工作区选择归属、场景选择视觉延迟及无附件消息被拒绝。复用既有三场景库，不重新训练，不修改上游 Harness。

## 真实模型进展与负例

初始实现对无附件输入隐藏文件工具，两账号三场景各两轮在有界恢复后通过（新增 32 次请求含失败）；用户随后明确要求文字和附件使用同一场景执行流程，因此该实现已被替换，不能用初始矩阵冒充最终代码验收。最终实现保留工具及普通 Baseline / Motif 模式，由模型判断是否调用；新双账号三场景各两轮矩阵全部通过，24次真实请求，第二轮记住各自主题、跨账号404。有效配置逐任务核对完整工具集合。记录为 `unified-flow-*`。

该矩阵发现 PPT 运行兼容性记录尚未覆盖本轮 scope 代码，因此其右侧明确回退 Baseline。审阅空来源只读约束、保留原来源版本与权限后更新两份运行绑定，原训练证书与库不变。实际附件随后暴露多行/超过500字符的内部 intent 不满足现有标量契约；只规范化结构元数据，完整 DSH 请求与 job 原文不改，并增加真实运行时解析回归。该失败保留，不能算已优化。

最终实际工具验收：数据账号从直接上传开始，接着纯聊天、再上传新批次，3轮两侧全部完成，`inspect_study` 每文件轮1次、工具错误0，右侧 Execute 无回退。PPT 在原有对话中完成读取、聊天、再上传新批次3轮；两个读取轮左侧各3请求/2工具、右侧各2请求/2工具/1次已验证跳过，工具错误0、无回退。旧结果评分保留、历史子会话不可直接发送、异账号404。PPT无附件在有效认证库下额外两侧完成：右侧保留 Execute 选择，因无来源明确不复用，正常模型回复，0工具错误。没有把无附件问答包装成优化收益。

累计本轮新增86次（包含初版、失败及恢复），447→533；保守预约估值从 $0.291552966 到 $0.350628846，不等于账单实付。官方余额最后查询 CNY55.17、可调用；账号可能还有其他调用，余额差不能直接归因于本实验。

冷重启后的旧结果、下载 SHA/attachment 头、评分持久化及跨账号读取/下载/评分拒绝通过：并发 8、48 请求、约 0.311 秒（服务器回环小样本，0 模型）。

已观察到 HTTP 503（服务商繁忙）及长时间无响应；取消后显式只重试失败侧，保留成功输出和全部累计支出，不重置预算。取消完成到执行器退出有一个窗口，验收脚本对 `comparison_busy` 做有界等待；一次等待未结束，保留失败后重启独立测试后端恢复，生产未受影响。最后统一流程的24次矩阵无需重试，不能据此保证外部服务始终可用。
