# 对话加载与场景后续聊显示修复

## 原因与行为

原加载器被追加到历史记录的普通文档流，且只用未命中的 data-composer-seat 选择器隐藏输入。因此历史用户气泡和输入会在未准备好时露出，加载环缩小为36px但内部图标仍高48px，发生溢出。加载边界现在拥有独立布局和绝对定位遮罩，用显式 data-loading 隐藏该会话的全部原生内容；图标尺寸固定在44px环内，准备完成后才显示历史和输入，不遮住侧栏。

普通 Chat 使用原生 TurnStatus，而场景及其后续普通聊天在保留上下文的单栏子任务路径中又绘制 GeneLooping。前者来自提交乐观态，后者来自结果轮询；两者的字体、颜色和位置分别定义，交接时切换。现在仅原生聊天底部拥有 GeneLooping，展示状态合并本地提交、原生执行、最新轮子任务与权威结果缓存；结束、取消、失败立即退出。旧轮和其他会话不能让新一轮显示忙碌。每侧的实际阅读/搜索/工具活动仍按原记录展示。

附件兼容投影只包裹 user 类型，没有包裹原生队列接纳后的 steering 类型；因此同一用户消息在两种原生投影间会有不同显示。另补充合并文本块的兼容，保留真实用户前缀和附件卡片，原始历史与模型输入不改写，无附件的用户手写JSON不隐藏。

## 验证

本机相关18项初始测试通过；扩大加载、提交状态、双路显示、品牌与样式覆盖后78项通过。新增验证覆盖合并消息、user/steering原生插槽、输入/历史加载边界、首次发送到子任务完成的同一底部状态、旧场景不污染后续Chat。其余跨平台CI和真实网页验收以关联PR与私有验收回执为准。

本次仅修改前端展示，不改变模型、工具、文件批准、任务历史、收费额度和Motif证书。私有回滚脚本与网页截图保存在 `.local/attachment-projection-20261018/`。三个场景的独立benchmark材料准备继续保留为后续工作。
