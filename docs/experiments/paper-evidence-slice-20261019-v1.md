## 当前结论与验收口径

**已观察到真实执行控制转移**：一次模型选择之后，Runtime 在 9.077 秒内连续执行 24 次原生工具调用，24 个不同调用 ID 均有结果；该区间 provider 账本记录和带 usage 的 assistant 消息均为 0。达到 `probe_limit` 后回传证据并交回模型。不能把这直接记成“净省 24 次请求”，因为未观察到反事实模型原本会调用多少次。

**已观察到当前产物参数复用**：Execute004 的一次 120 字节选择绑定 26,157 字节真实参数并成功导出；Execute005 的两次 120 字节选择分别绑定 24,989 字节参数并成功导出。第二次是重复导出，说明成功产物复用和任务终止仍有缺口。

**诊断策略的有效性未建立**：24 步没有定位最小原因。历史轨迹只支持 `sections/*/paragraphs` 数组缩减，逐个缩短非故障段落仍会得到相同失败。这里学到的是可重放的诊断动作，不是错误因果关系。本轮未新增独立论文全任务评测，也未完成科研结论盲评。

按用户最新要求，后续配置和环境固定时复用已有 Baseline，不重复付费重跑；优先核对 Motif 当前轨迹中的匹配、绑定、控制接管、回执与停止。费用高低保留为观察，不单独证明机制有效或无效。若未来要主张稳定净降本，再单独设计配对效果实验。本轮三次 Baseline 均保留；后两次涉及导出器实现/隔离入口变化，不能删除其费用。

## 问题、实现及边界

1. **恢复真实调用前输入**。`reuse_snapshot.py` 从已采集边界摘要恢复调用前的文件版本到全新私有沙箱，校验路径、大小和摘要；不再只依赖任务结束时可能已覆盖的文件。真实原生参数/结果还可另存为数据包，用于不同输入认证，明确标注它不是原始调用前文件。最多 256 文件、单文件 1 MB、总计 8 MB；拒绝符号链接和覆盖已有恢复目录。
2. **挖掘脚本内部与诊断片段**。复用已有 AST 切片编译器；修复真实 `python3 << 'EOF'`（无 `-`、有空格）被漏掉的问题。未引用 heredoc 中含 shell 展开内容仍拒绝。从至少两个真实任务的原生失败/子集试验中学习工具、schema、失败签名、数组轴与成功见证；不按具体论文或错误名写路线。只学习保留 JSON 类型、顺序和重数的删除子序列。历史其他字段可能同时变化，因此不能据此宣称因果或单调性。
3. **Runtime 连续推进**。模型一次选择当前失败参数与认证诊断契约后，TS 控制器按实际结果继续有界缩减、互补试验和嵌套数组试验；不同错误、schema 不兼容、来源/版本变化或达到上限即停止。继续使用原生工具生命周期、唯一 nonce、当前参数、schema、来源与权限守卫；`probeTools` 默认空，只有私有配置显式授权的工具允许探测。没有新增 LLM 可见工具，未调 embedding。
4. **减少无效提示与重复正文**。动态候选通知写入工具结果，保持系统前缀稳定；过滤不兼容 JSON、已经试过的参数，避免每个探测单独追加修复提示。当前工具已提供可校验的字段定位时，直接展示该证据，不再建议盲目缩减。
5. **隔离修复实际导出故障**。真实失败草稿中两处 `ğ` 被输出为 NUL，其余验收通过。已有字体回退只覆盖 CID，配置 TTF 缺字时未回退；旧工具又丢掉了内部 `missing_text` 定位。新增 `evidence_report.py` 与显式 `--report-evidence` 私有入口复用冻结实现，在隔离模块中补字体回退，并返回当前字段 JSON pointer 与文本 SHA256。它是人工完成的服务修复，不是 Motif 自动学会的原因。原 `session_report.py` / `document_engine.py` 已恢复，生产默认和历史证书未改。新变体标注 `production_certified:false`。

原始同稿无模型重放已恢复完整六页，两处字符保留、NUL 为 0；六页已人工查看，无明显裁切/重叠，原稿密集表格样式未美化。真实隔离变体执行也成功导出。以后出现 `page_constraint_satisfied` 失败仍应单独处理，不能归入字体故障。
