# 论文操作实例 Breakdown：到底读什么、写什么、能否复用

实验 ID：`paper-operation-breakdown-20261019-v1`。分支 `codex/paper-operation-breakdown`，基于 `0b9990f`。延续[费用 Breakdown](paper-takeover-breakdown-20261019-v1.md)，本轮把抽象类别展开为实际调用，并做无模型的跨真实输入脚本检查；不改 Runtime、原始轨迹、生产或认证库，不推送/PR。

先纠正上一版分类的歧义：**“模型正在生成脚本”不等于“脚本在写文件”。** 模型可以花钱生成一段只读命令；也可能把数千字当次科研判断放进 `.py` 文件，这时钱主要花在生成数据/文字。下面分开标明。

费用均是**生成该调用的完整模型请求估费**，包括输入与输出，不是文件 I/O 费用。读回的长文本还会进入后续模型输入，不能把该请求费用当成这次读取的全部因果费用，也不能假设缓存命令就能省下全部金额。

## 1. 只是在读文件，也可能产生较高模型费用

P#4 的完整命令如下（原文件名保留，未含原文内容）：

```sh
cd /work/unz && wc -c paper.tex neurips_2019.bib paper.bbl paper.out && echo "=== BIB ===" && cat neurips_2019.bib
```

这不是创造新算法，更没有修改论文。该请求 $0.00419482 中，未命中输入费 $0.003954，占约94.3%；输出只有97 token。**昂贵的是再次进入模型决策并携带上下文，不是 `cat` 本身。**

命令可以换文件参数执行，但后续真实性判断仍需要当前 Bib 信息。Runtime 提前读取能省掉一次选择/生成请求的机会，不等于可以不把必要证据交给模型。目前组合 shell 命令也不在单 Python 调用挖掘范围。

## 2. 一个真实的“能复用，但输入范围没接好”的例子

P#6 原始只读脚本的关键结构：

```python
tex = open('paper.tex').read()
body = '\n'.join(l.split('%')[0] if not l.strip().startswith('%') else ''
                 for l in tex.split('\n'))
cits = re.findall(r'\\cite[a-zA-Z]*\*?(?:\[[^\]]*\])*\{([^}]*)\}', body)
```

同一份原始脚本只把 `paper.tex` 参数化，在现有只读沙箱内运行，未补写新提取算法：

| 真实输入与绑定方式 | 同脚本提取的唯一键 | 当前工程已有静态检查得到的全文键 | 结果 |
| --- | ---: | ---: | --- |
| 原 RMSNorm 单文件论文 | 37 | 37 | 覆盖一致 |
| 另一项历史真实多文件论文，仅绑定 `main.tex` | 0 | 34 | 全文覆盖失败，反例保留 |
| 同一多文件论文，按已有来源依赖清单对10个文件逐一绑定，再合并 | 34 | 34 | 覆盖一致，无额外键 |

这证明的是：**单文件读取算子可以跨任务使用；只有主文件的输入绑定，不能满足“整篇论文”的目标。** 现有来源检查已能给出 active_files，局部诊断循环复用相同算子即可，不需要模型给每个文件重新写脚本。

这不是新在线接管或完整论文验收：共12次无模型沙箱执行，未发布新库。对照使用仓库现有来源解析器，仍受其支持的字面 include/cite 范围限制，不保证任意 LaTeX 宏展开。当前 Runtime 的后缀/单文件契约及相同输入片段机制，尚未表达这种完整依赖集合与批量合并。

P#7 则有另一种问题：它读了 Bib 和 bbl，却把上一条请求得到的37个引用键写进源码常量。原结构节选，值已省略：

```python
keys = re.findall(r'@\w+\s*\{\s*([^,\s]+)\s*,', bib)
cited = set("""<本次论文的37个固定引用键>""".split())
print("in bib not cited:", [k for k in keys if k not in cited])
```

这份代码**不能原样跨论文复用**。应该复用集合对照操作，把 `cited` 绑定到当前 TeX 提取结果；不能仅换 Bib 文件就宣称已参数化。

## 3. 联网取证：通用请求代码可复用，事实与查询对象要更新

    r = json.load(urllib.request.urlopen(url, timeout=40))
    items = r["message"]["items"]
    # 把所需元数据放入 out
json.dump(out, open("ev/crossref.json", "w"), indent=1, ensure_ascii=False)

工具效果是**读远端资料，写本地证据缓存**，并非撰写核验结论。HTTP/解析/保存逻辑可复用；当前查询标题、作者、目标 ID 要从当前 Evidence 或模型的必要选择获得，还要读取新证据。返回的第一条候选不等于已确认引用身份。

N#16 已实际调用了从另一项真实论文任务中学习的 `script_b901cbad4705e29456acf0d8`。真实命令结构如下，当前19个参数值已省略：

```sh
geneloop-cache '{"calls":[{"id":"script_b901cbad4705e29456acf0d8","paths":[],"argv":["<当前arXiv ID>","..."]}]}'
```

原执行回执已验证、获取新元数据，证明跨任务代码复用发生；它不缓存旧事实。但该次仍需模型输出247 token选择参数，不能计作整请求跳过。下一步要检查哪些 ID 能由当前证据绑定，哪些确实需要语义选择。

## 4. 写 `.py` 文件，可能主要是在写本篇论文的结论

B#86 创建的 `data.py` 原结构如下；条目值脱敏省略，不能把模型当时输出的判断视为已证实事实：

```python
REFS = [
    # num, short, key, status, priority, sources, note
    (1, "<文献简写>", "<引用键>", "已确认", "P3", "S01·S02", "<本篇核验说明>"),
    # 其余当前条目
]
```

此请求 $0.00587786 中，输出费 $0.00512760，占约87.2%。虽然保存为 Python，主要输出物是**37条当次论文的结构化结果**。标题、原引用键和已收集来源可从 Evidence 搬运；“是否对应同一工作、是否改正式版本、为何判该优先级”不能复制历史任务的答案。

因此，缓存一个 `save_report_rows(rows)` 写文件函数并不会省掉全部4273 token。要进一步省费，应让模型只填写未确定的判断字段，已知条目身份/来源由 Runtime 绑定；这是参数化结构复用，尚需在线验证。

同一任务内，若这些判断已经存在且依赖的来源版本未变，也可以引用当前结构化状态，不必重复输出；新增反证或来源变化仍要失效/重审。这与把上一篇论文的结论搬到下一篇不同。

## 5. 一笔高成本的写程序请求：确实存在可复用排版代码，但原文件不是干净算子

B#88 创建约2.5万字符的 `build_report.py`，并试导入；**这一条还没有导出最终 PDF**。原通用部分节选：

```python
import json, fitz
class Doc:
    def new_page(self):
        self.page = self.doc.new_page(width=PW, height=PH)
        self.y = M_T
    def ensure(self, h):
        if self.y + h > PH - M_B:
            self.new_page()
            return True
        return False
```

它还有字体、换行、表格、页眉页脚及分页代码，也混入本篇来源清单、报告文字、固定路径和平台字体。$0.01254492 中输出费 $0.01197240，占约95.4%。这部分不能笼统称为“读证据”或“语义推理”：其中确实有大量重新生成排版程序的工作。

**排版函数有跨任务复用价值，但该大文件原样不能作为通用 Motif。** 需分离当前 report_data、字体/布局资产和获准输出路径，再认证。当前 Script Motif 编译器的只读 import/写入边界不接纳这类 `fitz` 写 PDF 程序；不能为扩大覆盖直接解除限制。

B#97 又写了新版 `build2.py`，复用部分旧类、增加表格/分页代码并尝试输出 PDF。$0.00721462 的调用实际以 `TypeError: can't multiply sequence by non-int of type 'float'` 失败，失败费用保留。复用排版框架能避免反复写代码的机会，并不证明缓存这份有错程序就会成功。

## 6. 写报告最明显的重复：已有内容被反复作为工具参数生成

P#149 先读取 `refs_final.json`，拼接表格与当前科研解释，写出 `sections.json`。P#153/P#154/P#160 又让模型把完整 `sections` 作为 `export_review_report` 的内联参数输出，使用的导出程序本来就是同一个已有工具。

```json
{
  "title": "<本次标题>",
  "source_versions": {"<当前来源文件>": "<SHA256>"},
  "sections": [
    {"heading": "<章节>", "paragraphs": ["<当次完整正文>", "..."]}
  ]
}
```

这段展示真实参数结构，值已脱敏，不是新的工具接口。

- P#153：31段完整内容，$0.01218269，回执 `exported:false`，`failed_checks:["page_constraint_satisfied"]`。页数错误并不属于先前17个带 `validation_error` 的字段失败统计。
- P#154：改成30段，再次完整生成，$0.00951528，导出5页。
- P#160：仍输出全部30段，$0.00981200，其中**29段与P#154字节相同**。章节序列化内容的字符相似度约99.7%；改过的那一段仍可能包含必要语义修改，不称整次请求完全无用。

这两次成功导出合计输出14209 token、估费约 $0.019327；不是纯排版计算费，而是模型重新提交了正文。段落相同/字符相似度不换算成精确 token 节省。

**可复用的是同任务当前报告及版本、29段未改内容的传输和导出操作；不能把这29段移植到下一篇论文。** 跨任务可学习的结构是“已保存报告 → 根据模型的局部修改更新 → 验证版本 → 导出”，让模型只输出必要 patch。当前导出参数只接受完整正文，Script frontier 也没有接管这段流程，因此已有脚本/工具没有阻止重复输出。

这给出了比“先统一整个报告接口”更窄的候选改进：绑定现有结构化报告，以当前内容版本承载未变部分，仅语义修改交给模型。原报告质量仍未合格，不能以缓存为由保留错误结论；本轮只定位机会，没有实现或宣称净收益。
