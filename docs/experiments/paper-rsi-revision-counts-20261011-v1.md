## 现在接入了什么

组合后的生成工具名为 `triage_revision_audit`。模型只传当前 `input_id`；MCP 找回当前报告、任务开始报告及本任务目录，验证报告、来源、代码、生成程序和Session版本，然后执行受限纯程序。句柄来自当前读/写结果，不复用另一任务的ID。

| 能力 | 来源与编译方法 | 验收范围 |
|---|---|---|
| 目录配对、缺失、多余、ID差异 | 原有 RSI 生成的 coverage 程序，继承原源脚本重放证据 | 原认证范围不扩大 |
| 前后对象数、初始重复key种类数、新增/移除唯一key数 | v3生成程序中五个表达式原样提取 | 27个新构造的同论文计数例通过 |
| 当前重复key种类数 | 将正确的初始重复表达式输入 before_report 绑定到 after_report | 同27例通过；不是新写计数公式 |
| 已有非arxiv_id字段、报告顶层字段是否保留 | v6候选中两个输出及完整变量绑定原样提取 | 14开发例、21原学习未见派生例通过 |
| 具体哪些当前对象违反字段保留 | 导出原程序已经计算的 mismatched 变量为 changed_existing_records | 重放原14＋21例，不重算为新独立样本 |

组合等价诊断36例通过；原v3的30个失败留出例现在只作历史诊断，不重新包装为独立认证。完整程序失败不意味着所有局部表达式都必须丢弃，但每个保留部分要明确来源、输入依赖和独立验收范围。

例如前后key分别为 `a,a,b` 和 `b,c,c`，对象数都是3，初始/当前重复key种类数都是1，新增唯一key是c、移除唯一key是a。工具把这些数一次返回，模型不必再口算。另一个例子：只修改允许的arxiv_id时字段检查通过；把已有source_urls的顺序或内容改掉，返回false及违规当前对象，模型对照初始同key条目修复。

公开可读程序与合成诊断在[计数样例](../../examples/rsi-tools/revision-counts-v1/README.md)和[字段保留样例](../../examples/rsi-tools/revision-fields-v1/README.md)。没有私人论文、请求或Session见证，不能作为冻结执行库加载。

算法表达式来自模型；表达式选取、输入重绑定、组合器、通用宏展开、解释器、独立验收和权限守卫仍由工程提供。这一轮是轨迹驱动的工具生成与局部代码复用，尚非任意bash自动转为可靠MCP，也尚非RSI自己生成全部基础设施。闭合schema外的字段会拒绝输入，不是静默忽略后宣称通过。

## 正常轨迹怎样变成 Motif

两条新正常任务由模型自由选择读、检查、写和修复顺序，不由手写DAG驱动。Python编译器随后从真实调用中提取两个局部候选：

- read_task_state → triage_revision_audit：只有1个训练Session支持，不能作为本轮严格接管机会。
- write_report → triage_revision_audit：有2个训练Session支持；新input_id由当前成功写入结果绑定，具备本轮Shadow匹配资格。

工具本身一次执行覆盖计数和字段检查；Motif学习的是“何时调用这个工具，以及参数来自哪个当前结果”。TypeScript在下一模型响应之前记录预测，真实Harness仍照常请求模型和执行工具。只有整请求的工具、参数、实际结果、顺序、当前版本都匹配，而且没有额外文字或未覆盖调用，才计严格整请求机会。

典型五请求链是：模型读状态 → 模型检查 → 模型修订写入 → 模型检查新状态 → 模型总结。当前冻结库只覆盖第四次。读取后检查只有一个Session支持，仍交模型；修订判断和最终解释也保留。七请求失败链进行了两次写入和两次检查，因此有2次匹配，但报告仍可能不合格。
