# 多对话请求失败与并行调度修复

## 问题与复现

成员在多个对话运行时发送普通聊天，网页显示 `gateway/internal`。旧实现仅准许一个账号同时运行一个任务，同一 DeepSeek 对照两侧例外；普通聊天的第二次 submit 抛出 TaskError，原生 Gateway 只识别 RemoteError，最终被公网投影为笼统的失败提示。预览已经建档，故失败请求还可能留下 awaiting_confirmation 草稿。

只读取报障账号的任务标识、状态和时间：一个任务在 2026-10-20 06:02:22–06:26:09 UTC 运行，另一个对话在 06:08:43 留下未提交草稿，符合该路径。未读取其提示词、附件或回复；缺少浏览器请求日志，不能断言每一张同类 toast 都只有这个原因。

确定性测试通过安装的原生 HTTP carrier 和 TypertGatewayService 投影真实错误，旧实现返回 `gateway/internal: Another task is running; wait or cancel it`。服务器旧运行代码 d2291646 的独立真实测试也在第一个任务 running 时复现第二个请求 gateway/internal；仅操作新建合成 Session，测试结束取消自己的未提交草稿。

## 修改

- 按用户追加要求，明确 Session 请求头的正式 DeepSeek 通道不设账号级任务并行数量上限。不同账号、不同对话、普通聊天与独立场景对照均可并行；同轮 Baseline/Motif 继续并行。准入短锁保留幂等建档，同一公开对话的新请求仍互斥。
- 每条 Session→turn 路由、工具范围、模型授权、预算激活/结算和取消均独立。旧无 Session 请求头适配器不能猜测费用归属，仍保持互斥；当前正式 DeepSeek 不走这条旧通道。
- Host.prepare 在锁内失去 readiness 时返回 deferred，由现有调度重试；不把资源竞争误报为场景失败。
- 已知准入错误转为原生 RemoteError，公网保留可操作错误码；新增私有错误元数据记录，不记录输入、附件或凭证。旧拒绝留下且未启动的 native 草稿可被新的发送正常替代，运行中的任务不变。
- 初始独立候选 paper-web-v17 / ppt-master-v12 只兼容重导出现有认证 IR。同期 main 已发布同名后继版本，合并时完整保留 main 的证书；合并后的并行及输出容量修复使用新的 paper-web-v18 / ppt-master-v13，保留 main v17/v12。均无新训练，不把兼容认证当成效果升级；初始候选的独立私有检出及 Git 父提交仍保留。
