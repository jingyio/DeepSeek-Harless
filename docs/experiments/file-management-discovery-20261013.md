# 普通文件管理跨流程探索与统一学习

## 问题与实验类型

验证普通 Harness 能否完成不同文件管理任务，并从共同轨迹中发现有参数来源依据的共享结构。真实三篇 PDF 与生成文件混合，属于开发机制实验，不是实际办公用户的前瞻评测。

## 已冻结方案

十二类任务包括盘点检查、建索引、属性检索、内容检索、规则分类、内容分类、重命名、精确去重、冲突处理、转换、增量更新、归档恢复。24探索任务、12独立认证任务、24留出任务。五个材料变体；探索用a/b、认证用c、评测用d/e，各自任务副本、Session和日志。真实PDF分别进入前三组；留出PDF是生成材料。模板相似性是本轮泛化限制。

当前只运行普通 Harness baseline，模型为 deepseek-flash，reasoning_effort=off，压缩关闭，十二个工具固定集合/顺序，最大48模型步、4000输出。1000美元是跨实验的累计上限，单任务保护5美元，未知费用阻止后续付费运行。

## 配置、证据和验收

每个 attempt 保存工具 schema、题面/输入摘要、源码快照、模型与预算、Python/Node/SDK/MCP/Pillow和系统版本、Git提交。原始工具事件及费用账本继续保存在共享 `.local/runs/`，场景 attempt 链接该运行，避免复制后重复计费。

内容由工具解析，Word/Excel从OOXML读取；PDF仅前两物理页和最多6000字符，范围与截断明确保留；图片仅属性/转换，不做OCR。损坏文件显式返回unreadable，不能把它当作材料不存在。

任务结果检查实际目录快照、内容摘要、操作记录、当前输入与实际原生提交收据。索引检查读取和覆盖，内容检索/分类检查生成材料的已知正负项，转换检查产物内容/可解析性，归档恢复检查原目录复原。真实论文的科学理解未验收。

## 学习与界限

完整轨迹用于观察操作实例、时间顺序、参数流、状态与模型请求。观测次序不是自动执行条件，状态转移计数也不是条件正确性证明。

从正常完成且通过验收的探索任务汇集参数边，至少两个独立任务支持，再由未参与发现的认证任务验证。编译和manifest导出复用现有只读机制。操作计划和写入不标记为只读，不通过更名绕过协议。写操作、任意条件分支与数组控制暂为候选。

## 统一学习结果

- 36张完整观测执行图，包括失败任务：762次工具调用节点，其中118次为索引、执行、恢复和报告等派生写操作。图标注实际结果、参数来源与原生模型决策；时间顺序不授予执行权限。
- 18种连续序列候选，47类观测状态转移；参数流候选1种。
- 20个通过任务可用于训练，11个通过独立任务可用于认证。认证产物的实际支持来自18个任务、跨10类任务的117条 `pin_file.source_id → read_file.source_id` 传递。
- 编译得到1个只读局部Motif；一个未参与发现的任务完成参数流认证，合格任务的213份读取结果全部重放核对。当前三篇原始PDF SHA与准备时一致。
- library和manifest保存私有learned目录，权威Node `validateOnlineManifest` 通过。manifest摘要 `fb127150f2a4e8f787d226a770728ac9e096db19473ec8c093eb19d8603ba98b`。
- 一次离线收集失败来自工具参数不是合法JSON。修复后保存原始参数并继续生成图，0新增API请求；两次学习尝试分别记录。原始事件未修改。

当前支持“跨流程确实存在并可认证的局部参数结构”。没有运行在线Motif、同任务效率对照或第二轮学习，不能宣布降本、完整RSI或任意图学习已经成立。分支、遍历和写操作候选需后续接口与验证。
