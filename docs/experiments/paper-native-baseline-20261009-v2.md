## 结果、失败与恢复

- 原生重测 53 次 HTTP 200，超过 24 次；bash×73、read×3、read_image×3、todo_write×2。生成主稿及独立辅助文档 PDF，编译显式关闭 shell escape，执行字体、引用与日志检查、chktex、页面渲染及部分视觉查看。最终构造报告时发生 `finish_reason=max-tokens`，尚无报告文件；保留原记录，不冒充成功。
- 加入“审阅既有证据、分段写入长报告”的交付提示，在同一预算内恢复。首次零请求预检因把免费文件上传混入模型账本计数而拒绝；修正分类后继续，失败证据在私有 `delivery-preflight-failed.log`。
- 交付修复 32 次 HTTP 200，bash×42、read_image×5、write×1、todo_write×2，`finish_reason=completed`。产出 `work/artifacts/report.md`：372 行、22,083 字节。这是有额外提示/恢复的交付，不能称完全无人干预的一次原生成功。
- 主稿 14 页；对主稿执行了字体嵌入、引用、重复标签、溢出和浮动体诊断。原生及交付阶段共实际查看 7 个独立页图（3+5 次查看，有重叠），没有全篇视觉验收。未核验文献真实性、会议合规或科研数据正确性。
- 报告关联的产物路径均存在。Codex 对 source 和四个 build 目录中各 34 个来自 ZIP 的文件逐项比较，均未改动；原 ZIP 未改。
- 证据复核发现报告有表格行列误读、chktex 输出行数与警告条数混淆、编译命令记录偏差，以及对 PDF 差异与视觉检查性质的过强表述。原始报告保留，私有 `codex-audit.md` 单独列明问题，不改写原生质量记录来美化结果。
- native read_image 共 8 次 `/v1/files` 上传页面图到 DeepSeek 视觉 API，账本单独记录；不是投稿/公开发布，但原报告“未上传”的说法不准确。

85 份新模型请求快照的工具 schema 集合及顺序一致，摘要 `0e4ce701e493768e606a1647bf4252b0270120f4c6b953932c35aa070b720d8e`。旧结果、第一次截断、交付修复分别保存有效配置。属于同一决定的重测与续写，不算独立训练/评测任务。
