# 论文统一复用与脚本内部挖掘：真实实验 20261019-v1

本轮已实现并在真实恢复任务触发当前产物引用与原生工具执行，但**没有达到稳定、合格的完整任务净降本目标**。完整 Execute2 账面费用较 Baseline 低11.2%，新增产物复用却未触发，报告存在质量问题，不能归因或认定同质量收益。最后恢复对照输出下降49.5%，请求和总费用仍增加。所有失败迭代纳入费用，不挑最低一次。

## 问题与实际实现

用户指出真实轨迹主要是大段 Bash/Python，而非天然工具序列。此次把候选单位扩展为“脚本内部的输入—变换—输出依赖片段”，而非直接把整个调用序列当 Motif。

1. Python `script_dataflow_compiler.py` 从后续使用的顶层变量向前切片，保留读取、循环、变换与所需导入；与原始前缀在不同真实输入上沙箱比对。原始科研文字、固定路径和作用域不明代码不自动入库。旧整程序挖掘继续保留。
2. 原生工具参数流编译器只学习 schema 合法的真实成功调用，至少两个任务见证；输出→下步参数的无歧义相等关系作为候选边，不能授权当前执行。训练剔除自身合成调用和明确软失败。
3. TypeScript Runtime 统一引用本任务 JSON/旧调用参数/工具结果，支持局部 patch、当前完整输入清单和顺序计划；模型选择必要操作/缺失语义，Runtime 绑定与执行，失败即停。保留原生 schema、来源 SHA、权限守卫，不新增可见工具。
4. 原生工具边界采集受限文本版本，为后续重建中间输入提供数据；新采集器拒绝与边界不符的最终文件。旧轨迹标记为最终工作区重放，不能冒充边界快照。
5. 自动学习 worker 发布脚本库+原生契约库的不可变轮次及 owner 指针；当前测试未证明多轮在线性能持续改善。

示意（机制例子，不是端到端成果）：历史 Python 一次调用中先读 `rows.json`、遍历状态形成表格，再拼入当次科研判断并写报告。编译器尝试抽出“rows→table”这一段，输入改为当前 JSON，正文判断留给模型。对于当前报告29/30段未变的情况，复用旧参数并只修改一段；不能将这些判断跨论文缓存。

## 质量与失败保留

- 未做独立盲评，不能给任何臂“同质量合格”结论。完整Baseline清单计数矛盾（P2称8列9，P3称6列7）；Execute2把65个键出现次数称作65处引用命令，真实为58命令/65出现，且将引用key年份直接当文献年份错误。
- 普通Cache有一份8页脚本PDF在工作区code/report.pdf，但可下载导出目录只有2页摘要。runner只统计outputs下PDF，不代表工作区无其他PDF；交付版本与范围一致性仍需核验。
- 三个恢复Execute产生10、21、21份同名PDF（大多诊断样本），最终最大成稿均6页。最后回答给出最终PDF完整SHA `bdc400d097df5be36b0db8e0fee67dbba3c28caf450770763b71400c475958a3`，比仅文件名明确，但诊断样本仍混入交付列表。
- PDF完成文字提取、抽样首尾页渲染与部分页面目视检查；不是全部页面视觉验收。科研判断没有重新盲评，恢复任务只检查既有结论保留/导出流程，不能认证历史结论。
- 恢复Execute1实际尝试命令替换形式，初始拦截器未识别，落入Shell；已支持固定cd前缀/受限计划文件，禁止执行shell替换并给出修复提示。Execute2计划被选中，但Node stderr警告导致JSON回执误判；已修复成唯一nonce回执核验，失败/重复回执继续拒绝。这两个真实失败及额外费用全部保留。
- 初次采集遇到历史非法JSON参数，已跳过并记录；Shell非零文本退出码不再充当成功。新增边界检查中Python局部import遮蔽问题已修复并有回归。早期测试缺字体/tmp符号链接环境失败，以及一次认证输出目录缺失，日志全部保留，不冒充产品缺陷或删除证据。
