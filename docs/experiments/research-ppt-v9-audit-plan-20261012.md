## 结论与可证伪主张

当前是可运行的科研 PPT pilot。文本型 PDF/PPTX 输入、可编辑生成、两种风格、原生表/条线图/流程、真实预览、来源 notes、显式页修订、同 job 版本绑定重启恢复已存在。截图里的全部目标并未完整达到：科学事实和图件完整性仍不稳定，复杂外部 PPT、任意母版、结构化公式/表格/引文和跨版本增量更新不足。

最值得推进的是“带条件及依赖守卫的结构执行”，但公共核心已有 DAG、参数绑定、缓存、认证、handoff/reentry 与失败守卫，不能重写一套引擎。差距主要在 PPT 场景的证据粒度、条件表达/认证，以及公共 TypeScript 在线子集的接入。

V9 的主要假设：在显式授权的局部修订任务中，已认证的条件结构与语义不变的机械修复，可以减少模型承担的状态读取、下一步选择和排版重试；在科学/视觉质量合格后，其完整成本低于普通 Harness，并至少在适用性或维护方面优于普通手写规则。

否定条件：不能通过独立认证；新任务未实际使用；只有工具批量执行没有整次模型决策减少；合格率下降；人工修订增加；或相比 B1 普通脚本/缓存无额外净收益。出现这些情况，保留工程改进，缩小或放弃 RSI 收益主张。

### 实际入口与关键部署缺口

旧默认入口：cli.prepare/run → scenario_for:67 → scenario.json 的 server.py → 内存型 PPTService。它没有自动接入新 checkpoint 和四个 TS 工具。

可靠交付入口：node dist/mcp-adapter.js → 固定 delivery_server.create_server:24 → CheckpointPPTService；TS DeliveryAdapter 提供 render_delivery、revise_delivery、pin_deck_pages、read_pinned_deck_pages。render/revise 是普通有限脚本；pin/read 才可能通过正常轨迹学习进入只读 Motif。

同 job checkpoint schema 2 已有源文件/构建产物/job/权限/来源/证书守卫、原子保存、旧实例写入拒绝；坏 PDF/PNG 只撤销对应 validation。TS 选页 pin 仍仅本进程有效，重启应重新明确 pin。新旧入口并存需要统一公开启动方式，不宜重新造 Agent 循环。

### 高价值产品拓展

优先扩展：可审阅的科学证据包（数值/条件/图件/来源）、真实反馈和差异页预览、完整论文图与引用展示、既有 PPT notes/对象理解、可靠模板与新机器安装。随后才是外部 PPT 局部对象编辑、公式/误差条等科研图、母版导入、听众/时长规划、附录和问答证据页。产品拓展本身通常是工程或语义能力，不自动成为 RSI 创新。

## B / Graph、Code、Runtime 与认证审计

### 当前调用链和已有机制

正常 Harness 工具事件 → dsh_trajectory / task identity 冻结 → Python offline 的 witnessed-edge/sequence 编译与留出认证 → library → online manifest → dsh_online_motif.mjs 的 tools/result 观察与 llm/stream 拦截 → online_skill_runtime.proposeReadyBatch/bindNext → Harness 真正派发工具 → 结果/参数/版本复核 → model_request_skipped_verified。

公共 Python 核心已有多步参数 DAG、precondition/acquisition 区分、集合/类型绑定、已认证 Motif links、每节点证据缓存、依赖版本失效、handoff/reentry、失败负守卫与 checkpoint。参见 controller.py 的 execute_graph_goal、resume_selection/resume_slots、证据快照；offline/trace_compiler.py、link_compiler.py、failure_evolution.py。它们的存在不等于 PPT 当前在线全部使用。

权威产品在线目标是 TypeScript；当前 .mjs 子集由插件加载，只允许受认证的只读延续，写动作/失败/版本变化为 barrier；有限历史、schema 核对、实际参数流、重复执行抑制和 batch 结果复核已实现。当前 offeredSchemaMatches 主要核 required 与属性存在，不等于完整 type/enum/additionalProperties 校验；新 predicate/Artifact 协议必须补完整运行时校验并绑定 schema 摘要。纯代码参数节点仍可能启动 Python pure_code.py，基础插件无 Python 目标尚未达成。

PPT 三类已观察结构均是短参数边：来源 pin→read、生成目录 pin→read、指定页 pin→read。均 code_nodes=[]。V6 模型生成的 TS 工具在 MCP 内执行，不是在线 Graph 的 code node；不能把“生成工具成功”和“Graph/Code 联合 RSI 成功”混为一件事。

生成工具宿主有纯 JSON/schema、AST 白名单、代码与输出大小、超时、工具版本绑定，不具备任意文件/网络权限。它是有界防御，不宣称形式化安全沙箱。不能为让失败候选通过而放宽 oracle 或由候选重写自己的认证器。

### 候选结构：每项回答十个问题

先从完整正常事件与ledger建立机会表：记录LLM实际选择的tool/参数、依赖字段、前后状态、对应请求费用、是否有语义选择及失败恢复。程序发现重复结构及自然错误，模型依据至少两个独立决定提出predicate/程序和abstain边界；开发端只给固定安全算子、协议与独立oracle，不给预制DAG答案。认证再用未参与提案的新材料和状态变更反例实际执行。科学选择或无依赖证据的路径不进入候选。没有真实重复机会就停止，不靠手工注入工具调用凑学习轨迹。

#### S1：版本与状态感知的只读续执行（优先的 Graph RSI）

1. 原模型决策：恢复后反复询问有哪些成品、是否还有有效计划/证据，选择下一次状态/页读取和复制句柄；相关页的科学选择仍由模型。
2. 输入/输出/依赖：明确用户任务和页号、当前 artifact 状态/源及稿件 SHA、认证 manifest → 必需只读节点与版本绑定 evidence；依赖 job、权限、schema、代码、来源。
3. 确定性规则：已有 list_restorable_decks、pin/read、缓存、版本拒绝可用；按显式状态和无歧义参数选择读取有确定性基础。
4. 适用判定：同 job、显式操作范围、唯一后继、guard 已认证；“历史经常这样走”不能独自授权。
5. Runtime：复用现有前缀/绑定/结果核验；有限 predicate 只读取真实输出字段；每步检查依赖并记录选中/拒绝原因，禁止任意条件代码。
6. 回退：多候选、找不到显式范围、来源/权限/schema 变化、新反证、需研究判断或工具失败，交 LLM；不在 read-only 图中私自生成/改稿。
7. 是否整请求：只有 llm/stream 实际被认证调用流替代且结果核验成功才计；缓存命中和一个 batch 的工具个数另计。未知能否净减少，需新任务验证。
8. 超过脚本/Code Mode 的增量：从正常轨迹及反例学习条件/参数边并独立认证、状态变化时选择性弃权；相同手写状态机为 B1，Code Mode 用相同受限算子单列。若只重演固定脚本，不称 RSI 创新。
9. 净收益：依赖校验、状态/源读取、认证和误触发恢复可能超过省下的一次调用；先测候选覆盖率、额外 payload 与每机会净费用，收益未知。
10. 最小修改：场景新增 typed artifact 状态/依赖投影；Python 离线 condition certification；共享 schema/manifest exporter；TypeScript 在线 predicate adapter。公共核心需团队协调，保留旧 IR 回归，默认 feature flag 关闭。

#### S2：语义内容不变的布局修复程序（优先的 Code RSI）

1. 原模型决策：收到 text/table/chart overflow 后重新选择字号、列宽、媒体区域及合法布局；缩写或删改科学内容不是机械步骤。
2. 输入/输出/依赖：冻结 Slide IR、元素/字形测量、错误枚举、模板约束 → 候选几何策略或 abstain；绑定 renderer/font/schema/content SHA。
3. 确定性规则：已有 buildLayout、LayoutFailure、默认策略回退和7字段策略；新机会是按不同页面特征条件化修复，不再只用统一全稿策略。
4. 适用判定：保持标题、正文、表格/图数据、来源、notes、图片证据不变，字号不低于可读阈值，最多一次机械尝试；否则不适用。
5. Runtime：实际编译模型生成 TS 纯函数，用独立几何/内容验证和真实 PDF/PNG 预览；审美和科学盲评另计。只改变已允许布局字段，成功后继续原 MCP 交付，保留前后内容哈希。当前策略是全稿级，指定页修复须新增按页 override/patch schema 并接非目标页与共享样式保持核验，不能直接修改全局策略影响其他页。
6. 回退：需要删句、改结论、拆科学关系、改变数据/引用/图裁边、未知错误或仍溢出时回 LLM；证书/版本失效不能借默认布局绕过。
7. 是否整请求：内部修复使原工具直接成功，可能避免原来一次“错误→LLM修布局”请求；这不是原有 verified read-bypass 事件，要独立记 repair 与匹配反事实对照，不能把每次修复都自动当省一请求。
8. 创新增量：模型从真实失败轨迹提条件程序，在独立页型/来源认证，学习何时修复/弃权；人工约束求解或静态 repair 是 B1，API包装没有创新。
9. 净收益：旧 V8 有5次连续 overflow 机会，但新任务不一定出现；真实渲染与认证很贵。只有普通规则仍有实测缺口且候选改善新任务时才推进。
10. 最小修改：ts/render.ts、ts/layout-policy.ts、layout_learning.py、generated_tools.py 的有限新输出协议，以及 service.py/revision.py 的按页 gated repair 与保持审计；不允许任意 TS 改写内容或 renderer。

#### S3：内容寻址的解析/图件中间结果缓存（必要 B1 工程）

1. 原模型决策：重复请求原文/图件目录、判断是否需要重新解析；真正重复解析发生在后端，不全由 LLM 决策。
2. 输入/输出/依赖：来源 SHA、解析器/字体/几何协议版本和页号 → 完整页文本/候选/数据摘要；新 job 重新授权并产生新句柄。
3. 确定性规则：已有同 job handles、checkpoint 和 validation 缓存；缺跨 job CAS。V6 read_generated_catalog 每次仍 catalog_input 全文解析和逐页 geometry。
4. 适用判定：内容与解析协议完全一致，权限有效；证据缓存不能继承旧 read/写权限、科学结论或旧句柄。
5. Runtime：读取 blob→哈希/schema核验→当前 job 重新绑定，geometry/目录一次计算；新源或依赖变化精确 cache miss，旧稿不强行恢复。
6. 回退：缓存损坏/协议变化重新执行确定性解析；无法定位图件、OCR/科学理解需要模型，不因缓存有数据而跳过。
7. 是否整请求：缓存本身通常只省 CPU/时间；减少重复模型读取须另有 S1 已认证决策或显式 API，不计 CAS hit 为模型旁路。
8. 创新增量：CAS 本身没有 RSI 创新；仅学习带反例的复用边界/选择性核验，并优于人工规则时才有研究增量。
9. 净收益：解析/目录页越多越可能省工具时间；哈希、存储和版本维护有成本；云 token 可能不变甚至因目录多而升。先测工具时间和 payload。
10. 最小修改：documents.py、figure_catalog.py、service.py 与新增私有 artifact_cache.py，输入许可和 schema 锁；不改公共图引擎。

#### S4：证据化 Slide IR 与数值/条件一致性校验（质量前提）

1. 原模型决策：反复抄数、补来源、检查轴单位/实验条件；科学解释、不同协议是否可比仍是语义性。
2. 输入/输出/依赖：原文 span/表行列/panel、源 SHA、method/metric/value/unit/condition 和用户审核 → typed evidence 引用及确定性缺口报告；不要从模型答案反向制造证据。
3. 确定性规则：已有 plan/request_plan/layout manifest 与 sources；新增证据 sidecar 可检查 value/标签/条件字段保持、引用定位及可见渲染。
4. 适用判定：闭合的直接数值或精确转录；模糊图读数、解释性概括、冲突结论及跨实验比较明确 unknown。
5. Runtime：受版本锁 schema校验、核原页/quote/value/条件、计划→OOXML→PDF 保留；报告 pass/fail/unknown，原始证据可找回；字面命中不是支持性证明。
6. 回退：找不到可核引用、单位换算未获允许、科学矛盾/因果解释/统计推断回 LLM和人评。
7. 是否整请求：纯格式/条件保持检查可以不调用模型；仅提供新报告不能证明减少请求，需 S1 调度或 S2 容量修复闭环。
8. 创新增量：IR/schema/数值检查是普通工程；模型从错误轨迹提参数化闭合校验组合并独立认证、自动学习适用边界，才可能是 Code RSI。
9. 净收益：原文补读和独立审查费用可能增加，但减少科学错误/人工修改可有产品价值；不能只以 token 下降判价值。先记录人评分钟。
10. 最小修改：新 evidence.py/JSON schema、service.py、ts/render.ts、ts/delivery-adapter.ts、validation.py；先 sidecar，不默添未被 Runtime 支持的字段。

#### S5：基于依赖的差异修订和局部失效（分阶段）

1. 原模型决策：某页或某来源变动后决定重读/重算哪些结构步骤；受影响科学结论/相关页仍需语义判断。
2. 输入/输出/依赖：已确认的页/字段 patch，page→asset/evidence/theme/renderer依赖 → dirty节点集合和保持审计；来源改变的新科研判断不复用。
3. 确定性规则：已有 merge/非目标保持、controller 的 node cache/依赖、坏preview局部撤validation；PPT revise 仍全稿render，全源变化全job拒绝。
4. 适用判定：改变集合明确、局部关系完整且全局主题/字体/比例未变；缺依赖证据就保守全重验。
5. Runtime：先普通工程建立dirty闭包和page manifest；复用无变化素材/解析，保持共享对象/notes/图表；第一版保留全稿LO终验，不能宣称已省全渲染。
6. 回退：共享style/主题变化、外部PPT无完整IR、源变更影响研究结论、依赖冲突或保持检查失败，停止结构复用/语义交接。
7. 是否整请求：增量build通常省工具时间，未必省请求；学得的dirty判定/必需读取调度通过S1可减少状态决策，必须分开统计。
8. 创新增量：依赖DAG和dirty-bit是普通工程；真正研究对象是从轨迹学到最小充分依赖、遇反证可靠局部失效，并超越人工完整依赖规则的泛化/维护优势。
9. 净收益：6页稿可能不抵消依赖审计成本，重复多页修订较有机会；跨job迁移复杂，V9不先做通用迁移。
10. 最小修改：revision.py、service.py、recovery.py、TS delivery adapter，加page/dependency sidecar；公共controller规则只协调后复用，不能两套长期分叉。

#### S6：search→read 等稳定依赖（留作扩展）

1. 原模型决策：从检索结果选择要读的科研材料是语义；用户已明确选择的唯一 ID 的句柄读取是结构。
2. 输入/输出/依赖：真实检索结果及明确选择/范围、源版本 → 只读证据；不是预先复制成能靠脚本解完的目录。
3. 确定性规则：仓库已有检索/对象读取的参考机制和首发库，不是 PPT 新发现；当前本场景没有论文 search 工具。
4. 适用判定：唯一已授权后继和实际ID provenance；多结果相关性不由频率/embedding相似度单独授权。
5. Runtime：复用现有 read-only edge/link、来源版本和参数绑定；真实场景新 schema、正常训练、独立认证后再使用。
6. 回退：要选文献、判可信度/冲突、执行外部写、权限变化或不唯一时交模型。
7. 是否整请求：闭合已选ID→read可真实少一次；“一次读多个结果”本身不证明跳过语义决策。
8. 创新增量：普通检索复合工具不是创新；带语义边界证据的条件挖掘/弃权才可能有增量，先检查已有库能否直接满足。
9. 净收益：额外检索/embedding和全结果payload可能更贵；PPT首版只接收PDF/PPTX，此项当前不值得抢占V9。
10. 最小修改：将来独立MCP检索配置/工具契约，复用离线编译，不新增搜索Agent或修改上游。

### 暂停的方向与原因

不再无目标地生成“通用科学证据摘录工具”。V7 9候选、V8 6候选全部未晋级，失败发生在JSON/AST、非重叠匹配和Unicode上下文规则；隐藏BERT未打开，不能说跨论文认证失败。继续同样任务只改提示没有新解决机制。

若恢复此研究，先把Unicode/codepoint、索引、非重叠匹配等做成经过测试的普通typed primitives，固定字面摘录与语义支持的边界，再让模型提组合/适用条件。此工程参考程序可以作为B1，不能冒称模型生成候选。禁止候选生成自己的oracle或训练时查看留出。

也不把 render→inspect→validate→deliver 封装重复称新 Motif；已有 build_delivery 和 TS 有限交付已做到。不得把同一任务续写算新独立训练决定，或把代码编译/功能成功当费用收益。

## C / 三个研究方向及排序

| 排序 / 方向 | 创新假设与相对现有增量 | 适用、收益、失败与可证伪条件 | 复杂度 / 最小成本 / 价值 |
| --- | --- | --- | --- |
| 1 条件及依赖感知的结构决策蒸馏（S1/S5） | 从正常轨迹与失败反例学适用predicate、参数流、最小依赖，在线核验后替代LLM状态/下一步决策；超过现有短pin/read与全job失效 | 重复修订/恢复/源版本变化的只读准备；可能少读取/调度并正确局部失效。若相同手写规则更好、条件不泛化或误用旧证据，则不支持创新收益 | 中；先一个条件两分支而非全图框架；少量新任务可测；最贴Graph/Code/Runtime边界 |
| 2 保持语义证据的条件化程序合成（S2） | 从真实排版失败学参数化修复/弃权程序；独立验证内容及可见约束，新页型实际启用；超过现有统一7字段策略 | 不改变内容的几何修复。可避免错误后的模型请求；退化成手调模板、科学内容被删或不比人工约束求解好则否定 | 中；一个纯函数和已有宿主/renderer，最多3候选；有实际V8痛点但收益待测 |
| 3 质量约束的全生命周期净收益准入 | 功能认证之后，按触发/失败恢复/人评成本学习何时启用或弃权，计学习和维护摊销；超过当前“功能证书即可加载” | 重复任务部署；抑制负收益结构和过度读取。若selector与固定阈值等价、资格质量下降或净收益无优势，则只是普通成本工程 | 中高；先固定成本规则B1，再小型校准；需更多前瞻任务才可发表泛化/统计结论 |

工程：CAS、schema、图件完整性、可靠入口、轴标签、Unicode、dirty闭包。Harness优化：有限读续执行、稳定schema/提示前缀、状态核验、错误分类。RSI研究：从真实轨迹发现并合成结构/条件，冻结独立认证，新任务自主调用，质量与成本证据支持晋级。三层分别归因。

以上是相对本仓现有机制的贡献假设，不是已经完成的科研成果或文献新颖性结论。形成论文前还须系统比较工具学习、workflow synthesis、incremental computation和选择性执行等已有研究；不能声称全球首次。

## V9 最小真实验证协议

### 质量优先，先小后大

Gate 0：只修P0，用真实PDF/PPTX/LibreOffice服务器回归，保留历史失败反例。必须识别截图不全、数值错归、漏实验条件、计划丢字/单位展示和重排页序风险；不能通过放松检查变绿。机械可判问题先验证，科学支持人工核。

Gate 1：两个不同正常训练决定，独立的一套认证材料和反例；最多3候选、最多一次隐藏认证。优先S1一个条件读续执行；S2只有B1普通修复仍存在真实缺口时加入。新条件必须覆盖两个分支、缺状态/冲突参数/权限变化/隐含依赖变更的拒绝边界，并与独立全量执行对照；只有一条留出参数边不能认证条件图。留出失败后不看答案修同证书，任何新研究须另立ID。

Gate 2（V9-alpha）：先做2个未参与训练/认证的新材料局部修订任务×4组=8个完整决定，各单次，不立即跑大矩阵。使用相同来源与预先审阅的冻结计划，在每组独立新 job 合法 pin/read、以实际句柄重新绑定 plan 并构建等价初始稿及状态；这是当前仅支持自生成 request_plan 的可行准备方式，不能直接用外部 PPT 调 revise，也不能跨 job 拷贝/重签 checkpoint。冻结实际来源、计划内容与各初稿 SHA，核等价内容而不强求 ZIP 时间戳一致。用户指定页面和反馈，执行证据获取→修改→重启核验→完整交付→盲评。初始稿生产/审阅成本对各组等额记录，初稿构建时间与工具费用也入账；组间不复用 validation、权限或已生成答案。此阶段只声称“真实增量修订任务端到端”，不能称从论文生成全流程降本。

建议两任务一张复合图与实验条件较多，一张高密度表/图；每份6–8页、修改1–2指定页。不是强制诱发失败的假任务。前两训练须确有独立结构机会，否则停止并报告“候选覆盖不足”，不注入预定工具调用来制造Motif。

Gate 3（V9-beta，条件触发）：alpha质量合格且B3相对B1有候选增益，才扩2个新PDF任务的生成+反馈全链四组，其中一个三论文15页，另一任务按实际需求确定论文数/页数，不固定三篇/十五页。已有PPT的会议风格转换单列产品回归，并用直接代码转换作为强B1；不要求现入口尚不支持的外部稿内容局部patch，不把无适用条件的B3强行套上。alpha/beta/产品回归不混成同一数据集。

若alpha失败，先停研究升级、分析质量/净成本；保留P0/B1工程，不继续产生工具凑成功。任务和对照冻结后不按结果换题。

### 对照组与公平性

| 组 | 定义 | 隔离的因素 |
| --- | --- | --- |
| B0 原始Harness | 当前原生Agent循环和公共P0服务，保留原来已有合法缓存/守卫；无结构拦截与新RSI | 基础语义调度，不假装原系统没有缓存 |
| B1 普通脚本/缓存/规则 | 人工写最佳有限调度/机械修复，使用与B3相同底层算子和证据协议，无轨迹学习 | 最强简单工程替代；不能故意弱化 |
| B2 现有Graph/Motif | 同公共服务，新缓存设置与B1/B3一致，仅现有短读取认证结构，不加新条件RSI | 旧机制相对新条件机制 |
| B3 新RSI | 同底层primitive、缓存、工具；只改变由训练提炼、独立认证的新条件/程序与晋级策略 | 从轨迹学习而非人工固定的增量 |

### 质量门槛与成本定义

每个任务预先建立人工核准的来源证据表和需求清单，评审不知道组别。至少一位领域研究者盲评，重大错误/争议由第二位复核。LLM辅助审查只用于发现问题，不能替代独立人评。

硬门槛：0重大科学错误；主要数值的method/metric/value/unit/condition和来源全部正确且实际可见；必要图/panel与图注完整；指定修改完成；非目标内容保持；页数、原生可编辑对象、真实PPTX/PDF/PNG及SHA检查全部通过。视觉按预定可读/层级/密度/图完整性评分，最低4/5且无阻断问题。不能只检查页数、文字数或来源字符串。

记录原始完成率、首次质量合格率、允许修订后的合格率；不合格稿按统一反馈、最多一次修订轮次继续，全部成本累计。依然不合格计失败，不仅展示成功稿。人工分钟实测，未知不能当0；同一评审者/规则跨组一致，不给RSI稿额外提示。

每运行保存：任务/源/代码/题面/schema/prompt哈希与顺序、library/证书digest和实际开启值、逐决策输入输出、工具时间、模型请求、缓存命中/未命中输入、输出/思考token、所有失败重试与恢复、模型账单/代理估费（分列）、准备到可用交付的wall time、人工修改分钟、程序生成/训练/认证/维护时间和费用。

统计分别给出：每任务逐组配对结果；所有分配任务全部尝试成本/合格件数；失败件与其投入；学习/认证固定投入及摊销。费用模型写为 C总=C固定发现训练认证+Σ(C正常+C重试+C恢复+C修订+C人工)+C维护+C服务器，各项互斥。若 ledger 运行费已含重试/恢复/修订，则直接用完整 ledger 总额，不再加同一费用。人工/服务器若没有统一折算价，先原单位报告，不编美元合计；N合格=0 时合格单位成本未定义，不能写0。

仅当质量门槛和合格率可比较、按所有分配任务的全部尝试费用计算的B1−B3合格单位运行成本差为正，才算盈亏平衡n*=ceil(增量学习/认证/维护投入÷每合格任务净节省)。不能只取成功run均费，也不能把固定学习费用计入分母后又加一次分子。对n=1/5/10/20/50报告敏感性；差≤0则当前无可摊销盈亏平衡。小样本先给观察范围，不给伪精确长期预测。
