# 论文恢复：失败采集、当前条件认证与真实接入

本轮补通了此前未进入 Negative Motif 的报告失败协议。真实恢复中累计观察到 13 次规则激活和已发送提示、6 次局部早停。**这证明链路生效，不证明稳定净降本，也不等于跳过 6 次模型请求。** 三次运行全部保留，其中一次流超时、一次成功报告改写了逐条记录，不能作为无损降本结果。

## 问题与依据

基于 main `4b7a215`（PR94 已合并），独立分支 `codex/paper-negative-recovery`，未修改原脏工作区、生产服务或公共认证库。旧采集器只识别 `validation_error`，实际导出返回 `failed_checks`；旧库的字段规则针对草稿 ID/枚举，没有当前完整报告的结构条件。此前六次恢复未加载该负面库，不能将它们解释为规则已编译但匹配失败。

本轮假设：统一失败协议，并将可信当前目标与真实失败回执绑定，可以识别“参数内容变了，但错误条件还成立”的重试。否定收益假设的证据包括：提示/早停后仍大量生成脚本、交付失败或信息被改写、总费用增加。本轮已观察到这些限制。

## 已完成的机制与边界

1. Python/TypeScript 共用一致的失败判定：接纳多项 `failed_checks` 和旧 `validation_error`；缺少失败码不当作成功。只有明确成功标志且无矛盾/错误才参与成功对照，不透明异常不生成原因规则。
2. 显式选择并锁定已审阅的纯校验器 `evidence_report.py:structure_issues`。编译器将历史实际回执与通用形状谓词对照，要求至少两次不同实际失败调用、实际成功对照、修复后条件消失、重新引入后复现、两个无关文本改动不消除条件。原生代码锁和事件摘要保持不变。
3. 运行时条件取自**当前**受保护完整目标，不在库中保存某篇论文的段数、标题或文本。校验 task、来源、grant、schema、scope 和实际参数回执后才激活。参数变动后仍重新检查必要条件；修复有效或证据/用户要求变化则放行或交回模型。
4. 提示以追加的插件消息交付，只有进入实际上游请求才允许后续早停，虚拟 Runtime 步骤不冒充已提示。局部阻断保留其他工具和语义修订；`model_requests_skipped: 0`。
5. 分开保存“实际失败候选”和“当前批准完整目标”，避免恢复入口将已裁剪候选误当作完整范围。新增 `--recovery-goal-scope`，其原始字节必须与历史失败回执的 scope 摘要相同。
6. 增加当前值字段引用：模型可以选择 `patches[].from`，Runtime 复制完整当前字段并验证两端依赖。已认证结构错误可提供该候选，但模型仍决定是否恢复；复制会替换该字段内已有修改，不能自动代替语义判断。

这是**已审阅结构校验原语的条件认证**，不是任意错误原因的自动发现。数字形状的跨语言歧义、缺少见证或校验器不一致均拒绝认证。页数错误只生成提示，未学出是哪段文字/字体导致超页，也未使用页数观测冒充根因。
