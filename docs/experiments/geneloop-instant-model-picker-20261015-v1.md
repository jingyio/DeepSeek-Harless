# 网页输入栏与模型切换验收

- 实验 ID：`geneloop-instant-model-picker-20261015-v1`；代码基于 `4f54a13`，分支 `codex/instant-model-picker`。这是界面交互与真实链路检查，不评价科研质量或 Motif 成本收益。
- 问题：模型及推理选择等到 RPC 返回才更新，用户感觉卡顿；网页暴露五个不需要的通用命令与权限选择器。目标是选择立即反馈，实际发送仍使用正确模型。
- 实现：公开 slot 包装原生组件，保留编辑器、附件、键盘和菜单；公开 menu store 过滤五个指定命令，模型 directory 用每会话串行队列投影最新选择。发送与选择共用队列，失败保留草稿，旧响应不覆盖新选择。场景按钮在草稿开头插入/替换 chip，正文与附件保留。

## 检查与边界

- 确定性检查：延迟 RPC 时先更新 current 并保持可点击；连续模型/推理写入串行，旧投影不能覆盖最后选择；发送等待选项、后续选择不能越过发送；拒绝回退并阻止待发消息误用旧模型；会话隔离、导航复用、取消、卸载；菜单键盘高亮与场景/附件来源保留；场景前缀插入保留附件。
- 浏览器检查：输入 `/` 和指令按钮均只显示场景候选；权限选择器不存在；已有文字时选择 `/data` 保留正文；Pro/Flash、On/Off 即时更改，刷新后 Off 保持；控制台无错误。截图 `.local/instant-model-picker.png`。
- Linux 完整测试：Python 759 通过/193 跳过，Node 704 通过/3 跳过，之后新增的场景插入回归单独通过。第一次 Linux 检查误用了系统旧 Node，修正 PATH 后完整通过。本机 Python 5 个符号链接权限失败；Node 13 个失败涉及符号链接权限和本机 Python 环境，不修改安全检查来绕过。最终 CI 结果在发布时补记。
- 真实测试只覆盖两次简短 Chat 发送；网络错误与连续快速点击由确定性延迟/拒绝检查覆盖，不宣称所有网络条件下性能已验证。Pro On 继续受现有预算约束，隐藏权限菜单不扩大服务端权限。
