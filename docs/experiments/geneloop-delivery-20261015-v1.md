# GeneLoop 双栏结果与下载修复（2026-10-15）

## 问题与范围

用户反馈双栏回答显示原始 Markdown、服务器绝对路径无法下载，以及偶发 `Failed to fetch`。本次复用 Harness 的公开 Markdown 组件和现有账号网关，完善成品交付、网络恢复和 GeneLoop 品牌；不改上游 Harness，不重新训练 Motif，不重置账号、工作区、历史、评分或累计预算。

## 实现与证据边界

- 双栏使用与原生对话相同的 `MarkdownText`。经白名单确认的文件引用映射为本账号下载；未知本机路径不导航。移除两栏内部固定高度滚动，窄容器改为纵向排列。
- 下载使用同源认证，验证 HTTP 状态、内容类型、长度及 SHA-256 后触发浏览器下载；错误页不能保存为伪 PDF。按钮显示下载中、已交给浏览器、可重试的错误。
- 数据报告及其图表必须沿成功交付回执、报告、草稿、证据包和图表包验证版本、计划与字节。旧任务恢复还要求本任务时间范围内的真实 `deliver_report` 事件。缺成品明确显示“回复完成，尚无通过交付校验的报告”，不把回复结束当成文件交付。
- 终态历史可零模型恢复漏收的合格成品；结果变化使旧评分失效。更早测试版本误收的未交付草稿从公开索引排除，原始文件与失败证据保留。
- GET 网络错误保留回答并退避恢复；认证失效停止请求并提供登录入口。评分或重试响应不确定时仅 GET 核对，不自动重发有副作用请求。完成的轮次不持续轮询。
- 登录、注册、账户页、侧边栏、标题和新预设采用用户提供的 GeneLoop 图标。JPEG 原件保留，通过 CSS 显示标志；实际模型名称、协议和历史内容不做品牌替换。

- `geneloop-download-acceptance.json`：截图对应历史数据任务、另一完整数据任务、PPT 和论文共 **23 个文件**，下载 200、attachment 头、实际 SHA 全通过；另一账号读取比较、评分及下载均 404。截图任务 Baseline 恢复 7 个合格文件，Motif 当时未通过布局/交付校验，正确为 0 个，不能伪造修复后的 PDF。
- `geneloop-multiuser-acceptance.json` 的零模型部分：两个账号、三场景历史结果读取、文件 SHA、评分持久化、跨账号读取/评分/下载拒绝通过。
- 浏览器实际点击 PPT PDF 和数据报告 PDF，收到下载事件且本地字节 SHA 与服务端冻结文件一致。原生粗体、行内代码、列表及成品卡片正确渲染；GeneLoop 登录与聊天品牌已目视检查。截图保存在私有本地验证目录。
- 旧预发布诊断父会话曾写入 Harness 不认识的自定义事件，冷恢复仍拒绝该旧日志；保留负例，不重写历史伪装通过。正式主线自此前修复起使用标准 `user/message` 元数据，本次不改上游恢复机制。

## 真实模型失败与费用

按持续授权使用真实 DeepSeek Flash、`reasoning_effort=off`，仅要求短标记，不使用文件工具。原计划两个账号各三轮、每轮两侧，初始新增请求上限 12；首次失败后只允许一次有界恢复，本轮最多 20，仍受累计 **1000 次 / 1 美元** 限制。

首次论文 Baseline 正常返回；论文 Motif 收到供应商 HTTP 503 `Service is too busy`，守卫取消未完成侧。等待后唯一一次恢复再次收到 503，因此停止，没有第三次重试。成功侧没有重复执行，子会话 ID 保持。

本轮共新增 **4 次请求**，累计由 424 到 **428**；预算代理保守预约累计 **0.220798302 美元**（包含失败请求未知用量的保留额，不等于真实账单）。失败与恢复分别保存在上述报告及 `geneloop-multiuser-recovery-acceptance.json`。
