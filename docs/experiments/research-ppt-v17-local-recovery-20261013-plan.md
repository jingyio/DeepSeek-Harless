# V17：失败草稿的局部恢复

状态：开发与验证中，尚无效果结论。实验 ID 为 `research-ppt-v17-local-recovery-20261013`。

## 问题与最小修复

V16发布重测中宿主组14次提交整稿、13次工具失败，输出89,400 token，高于普通组30,157；当时没有生成新工具。这次只修错误恢复：双方公开准确的计划契约，错误指出页/字段；宿主保留失败计划，模型通过显式局部修改修复，不再重复输出整稿。来源、权限、实现版本、实际渲染及科研事实要求保持。此机制是普通工程优化，不称新RSI。

失败草稿不能自动删页、删条件或改数字。局部修改必须由模型明确指定；来源说明重绑、非目标内容保持、陈旧版本、跨进程并发与重复无变化执行均须独立检查。异常停止不能被当作成功，失败原稿和历史费用不能回填。

## 验证与对照

先在服务器执行有意义的安全回归和真实MCP/渲染诊断，日志统一保存，不用固定模型回复替代真实模型验收。本机只编辑和接收核验副本。

然后只执行一对真实完整生成：沿用75页匿名来源last-ai，来源SHA256为`9fde92cba4d50a38a42570c25b89fe116312f746659e560290d344ead91f7a9b`，要求15页中文科研汇报、至少3幅不同完整原图、准确notes/来源、可编辑PPTX与实际PDF/PNG。两组独立规划，不传计划。

- B0：普通DSH原子步骤，禁止宿主恢复工具。
- B1：同DSH与契约，宿主固定交付链及失败草稿局部恢复。
- 两组相同工具schema/顺序、共享提示前缀、来源、模型、模板lab、质量门槛；执行方式差异由宿主冻结。契约改善同时提供给双方，不以只丰富优化组schema制造优势。记录与V16不同的新schema与源码哈希。
- 沿现有公共prepare_trial/run_trial串行执行；DeepSeek关闭思考与压缩，解析缓存关闭，无候选或active，无新工具生成。
- 两路总模型预算上限$1，每路$0.50，最多40请求、每次8000输出；不中途重建任务绕预算，不扩论文批次。

保存源码及构建版本、系统/Node/Python/SDK、任务/来源/提示/schema/顺序/权限、有效配置、逐工具/决策、失败草稿版本和改动、账本及实际回执。记录请求、输入cache-hit/miss与输出token、估费/账单未知、失败/恢复/端到端时间。人工修订未知就写未知，AI评审不冒充人评。
