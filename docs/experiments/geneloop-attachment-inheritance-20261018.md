# 多轮附件继承修复诊断

实验 ID：`geneloop-attachment-inheritance-20261018`。合成输入、无模型诊断，不代表模型比较质量或 PPT 制作效果。

## 问题与实现

追加附件原来同时被两层条件排除：对照接收层只在无新附件时保存历史来源，任务准备层也只在无新附件时继承。现在每次新建执行范围时冻结同一父对话的原件引用并合并当前附件；原生持久文件卡片支持消费后的回执，跨轮与重启仍可读取。同名不同字节保留旧版本别名。

历史交付的 Paper 白名单遗漏 DOCX，普通 Chat 首次切场景前的代码交付也未进入对照历史。现在接受 DOCX/DOC，原生代码交付经过原任务时间窗口及不可变快照，双栏按对应侧核验。新附件也可与历史交付同时使用。原始文件优先，不能为了容量静默漏掉比较原件。

网页排队消息的独立/拼接提取块展示投影已由前序 PR #75 修复；本次验证普通 user、steering、正文保留、文件卡片保留及原始模型证据不变。

## 验证与反例

- Node 针对性回归共 114 项各自通过，包括四场景三轮追加、重启后切场景、同名版本、消费后的回执、双栏及原生 DOCX、携带新附件、篡改拒绝、容量明确失败、原生图像、分支截断和展示投影。
- 服务器完整 Python：1056 通过、2 跳过；完整 Node：828 通过、3 跳过。使用独立验证目录及项目隔离运行环境，未向生产会话发送模型任务。
- `npm run smoke` 与 `npm run motif:check` 均通过；工具连通、失效拒绝和离线跳过诊断不调用外部付费模型。
- 本地全量 Python 因未安装 MCP 无法收集；服务器首次全量两个历史文献 MCP 用例因子进程缺 Poppler 动态库路径失败。采用项目既有 test-bin 包装器后完整 Python 通过。
- 服务器一次完整 Node 暴露合成 DOCX 标记的时间窗口不稳定，20 次单独复测未复现。夹具现在显式把标记文件 mtime 设在模拟任务窗口内；未放宽产品文件时间/版本检查。直接运行 Node 时还需沿用 `scripts/project.mjs` 的 `SSS_PURE_CODE_PYTHON`，遗漏会导致旧纯代码节点测试回退；恢复相同环境后完整 Node 通过。失败日志保留，不当作产品能力或效果证据。

私有脚本、日志和原始诊断在本机及服务器独立验证目录 `.local/attachment-inheritance-20261018/`。原始文件格式矩阵保留在前次 `.local/web-file-input-audit-20261018/`。公共文件不包含原始文档、账号凭证或运行日志。
