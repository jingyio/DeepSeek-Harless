# V10：以可用 PPT 和实际成本为验收的工程改进计划

状态：2026-10-12，已实施、完成两组真实明确编辑对照及三稿最终交付；补全科学条件后的图件过小已按页修复。本轮采用普通工程优化，未生成/启用新 RSI 候选。最终结果另记 `research-ppt-v10-product-20261012.md`，本计划保留原假设与验收设计。V9 代码、费用和失败记录不追改。本计划取代“先扩展条件 Graph、再看产品收益”的下一轮优先级，不取代既有安全检查。

## 目标与当前依据

交付用户愿意使用、能自行修改的 PPT Agent。每项改进至少证明一项实际收益：在内容正确、可编辑且渲染正常的前提下，PPT 更清晰好看，或同一任务的模型请求/token/费用减少且质量不退化。机械测试通过、生成候选或增加工具数均不单独算收益。

V9 已修复字体、内容保持和局部修订等可靠性问题，但没有新的 RSI 净收益；最终辅助审阅仍发现内容错归、表头断词和图件过小。两次明确标题修订用了 8/9 次请求，它们是历史机会依据，不是 V10 对照基线。完整依据见 [V9 记录](research-ppt-v9-quality-20261012.md)。

## 优先交付

| 顺序 | 用户能得到什么 | 最小改动与现有入口 | 验收 |
| --- | --- | --- | --- |
| P0 成品改善 | 机制、结果、原图页清晰可读，保留完整条件和匹配对照 | 先修现有 PiSSA/LoftQ 稿的已知错误；改 `ts/render.ts` 的按页布局、表格列宽和大图策略，复用 `skills/research-design/`，不另建生成引擎 | 同内容的新旧逐页预览；原图/条件/数值不丢失；可编辑及真实渲染通过；由用户判断是否明显改善 |
| P1 明确编辑直达 | 对保留完整计划的本项目稿，用户提供页号、字段和新值时直接修改并验收 | 复用 `DeliveryAdapter.reviseDelivery`，补最短直接操作入口和版本核验，不重复 pin/read 或启动 Agent 循环；任意外部 PPT 的对象编辑另行开发 | 明确操作路径模型请求数和 token 均为 0；只改指定页；重启、过期版本和无权限反例通过；与同任务正常 Harness 路径比较 |
| P2 从失败学习修复 | Agent 在实际使用后学会解决重复的排版问题，后续同类任务少重试或更好看 | 复用 `layout_learning.py`、`ts/layout-policy.ts` 及现有渲染诊断；必要时小幅扩为按页策略。模型提出有界修复，程序校验，后续新稿验证后才启用 | 新稿优于手写规则：少一次模型修复请求，或在同预算下改善真实可读性；事实、来源、字数要求、非目标页保持；失败自动恢复原策略 |

P0/P1 属于普通工程优化，应直接使用，即使不属于 RSI 也有产品价值。P2 才是本轮 RSI 闭环：真实失败/反馈 → 模型提炼可复用修复 → 独立程序检查与新任务试用 → 保留有效策略 → 复用/失效回退。不能把现有全局参数认证当成审美改善，也不把人工样板冒充自动学习。

不以图结构复杂度作为晋级目标，不继续为恒定状态强造两分支，不先扩大候选工具或付费矩阵。如果少量真实失败没有形成有用规则，就保留普通工程收益，停止该学习尝试并记录原因。

## 最小验证与成本

1. 先对现有两份稿做内容修订和视觉样板，保存原稿、修订计划、PPTX/PDF/PNG 与逐页前后图。这个步骤不需要重新跑整套付费生成。内容修订和纯布局改动分开标明，不能以内容更换解释为渲染器单独收益。
2. 对同一稿、同一明确标题编辑分别执行正常 Harness 与直接入口。正常路径沿用同一模型、工具顺序、提示、预算和版本；直接入口取消的模型调用是该组实际差异。比较完整交付及恢复成本，不拿旧 V9 次数作为新对照。
3. 若有真实可重复排版失败，只提出一个修复候选，在一份未用于提炼的新稿上与手写规则比较。不同组共享 P0 的渲染器及质量检查；无有效增益则停止，不扩大实验。

所有新运行使用新 ID，保留来源/配置/代码哈希、实际模型请求、命中/未命中输入 token、输出 token、代理估费、重试和恢复、耗时；修复提炼费用单列并计入累计费用。账单、用户修改时间和视觉评价缺失时写未知。计算复用次数带来的累计节省与一次学习投入，不只报成功旁路的局部收益。

目标是明确编辑零模型请求、视觉样板得到用户认可，以及学得修复在新稿取得至少一项上述改善；它们均为待验证目标。若只改善视觉而费用略增，必须明示增量成本，由用户判断价值；若只降成本，必须保证内容与可读性不退化。

真实模型任务在服务器串行运行、思考/压缩关闭并留日志；既有不限总预算授权持续，每阶段保留 $0.75/40 步/8000 输出防失控限制，不重复询问。公共实现仍限定科研 PPT 场景及已有公开入口，不修改上游 Harness，不覆盖本机旧检出。提交前告知、中文 commit、不 PR。
