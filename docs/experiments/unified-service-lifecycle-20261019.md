# 2026-10-19 统一服务生命周期入口

## 范围

此前管理员令牌故障来自一次自定义发布脚本跳过旧启动函数中的认证同步。本次将已准备好的 owner/gateway 启动、身份检查、重启和回退移入版本控制中的 `scripts/geneloop_service.py`，由 `npm run service -- ACTION` 调用。AGENTS、README 和账号部署文档共同指定该入口，禁止为单个修复另写启动/kill 流程；配置准备、证书编译与场景验证仍由已有入口负责。

## 行为

- 私有 version=1 计划明确两个进程的 argv/cwd/env、gateway config、持久输出及管理目录。启动只使用显式配方，不执行 shell；状态/回执不输出凭证。
- 核对启动时间、argv/cwd 和启动环境，拒绝未知监听者、PID 复用和配置原地改写。互斥锁阻止并发启动；重复 start 复用健康进程。
- owner 启动后强制完成 launch token → 内部 cookie → 认证首页 200，再同步私有令牌并启动网关；新日志按次隔离。
- 重启前检查所有成员及 owner 的任务、对照与分支，活动或未知状态拒绝；不改任务状态，不强杀、不重启预算服务。不是零停机部署，仍须安排维护窗口，避免接收新任务的竞争。
- 保留冻结启动计划与配置，失败时复用同一启动路径恢复上一份计划；支持显式 rollback。外部库、preset、源码和依赖必须保留原版本，入口不能恢复被外部删除/修改的资源。
- 可选私有 runtime pointer 合并更新进程信息，保留累计预算及其他回执；数据/预算端口迁移拒绝并要求单独审查。

## 验证记录

定向无模型检查覆盖真实本地 HTTP 认证、启动/重复启动、重启令牌轮换、手工及失败回退、活动任务/对照拒绝、外来端口、PID 代际变化、配置改写、互斥锁及持久内容/预算字段保留。Linux 隔离环境使用诊断 HTTP 服务，不是生产用户或模型任务，不声称场景质量/成本提升。Windows 跳过 Linux 进程检查，不宣称支持 Windows 正式托管。

全套检查、生产接管和发布状态见本次 PR 及私有 `unified-lifecycle-validation-20261019` 回执。原网页服务的代码版本与数据不因安装管理入口自动替换；生产验证先接管既有健康进程，再重复 start/check，避免为验证中断用户任务。
