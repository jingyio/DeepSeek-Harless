# V14：减少模板生成的恢复与重复输出

- 实验 ID：`research-ppt-v14-recovery-20261013`；2026-10-13。
- 范围：先修复一次只返回一个容量错误、单槽修订重发正文/讲稿、确定性依赖错误留到付费阶段三个问题。不修改上游 Harness 或放宽验收，不覆盖 V13 原产物。
- 授权：用户要求继续，既有不限总 DeepSeek 预算授权延续。本轮先一个新论文任务的三组先导，单组上限 $1.50 / 40 步 / 5000 输出 token，串行；只有机械链路及部署守卫通过才执行。出现同一确定性阻塞不反复付费重跑。

## 假设与最小实现

1. 公共绑定器一次返回所有文字槽容量问题，MCP 同时返回物理行联合容量；不自动删改科学信息。
2. 已核验来源/版本的容量失败可保存私有草稿。`patch_page` 用草稿 SHA、当前页 SHA 和计划版本合并明确修改，保留未给出的文字、图、来源及长讲稿，再完整核验。陈旧草稿、来源变化、权限/模板变化拒绝。失败草稿不算已交付页。
3. 全库零模型预检真实 compiler/渲染、字体/图标/链接依赖；公式探针保持原文。通过仅证明诊断文本机械可用，不能证明任何公式/实际内容都可用。
4. 先继承 V13 模型生成的只读 batch 程序，维持首次 save 后且无任何 write/revise/patch 的原范围；新增 schema 必须有新部署证明。恢复结构先从失败证据诊断，不无目标生成候选。

## 对照及划分

- 旧 V13 失败轨迹只用于工程诊断与纯程序来源，不追改旧证书。新增独立论文用于部署认证；评测论文与旧训练/留出论文不同。
- B0：更新后的普通 Harness/MCP 链，模型自行选择下一步；全量容量、草稿、局部 patch、模板预检为共同工程底座。
- B1：同底座，加手写确定性批读选择器；与 RSI 的触发范围、独立守卫、回执验证一致。
- B3：同底座，由原模型生成并认证的程序选择；新部署摘要、实际 Harness 八工具装配、独立任务状态认证通过后 opt-in。
- 三组任务、原论文/图件字节、页数、模板集合、提示、工具顺序、模型及思考/压缩 off、预算/上限相同。只更换是否及怎样选择结构执行；源码、有效配置和新 run ID 冻结。先少量任务，不按中途结果调提示、模板或候选。
- V13 与 V14 配置不同，历史成本不可直接当公平降本基线。零模型重放可量化传输字节/失败反馈覆盖，不能冒称真实模型 token 节省。

## 验收与指标

- 公共协议回归、真实 stdio MCP 的越权/陈旧草稿/来源/模板变更/非目标页与讲稿保持；全部在服务器执行，日志 `test-logs/<ID>/`。
- 科学内容、数值及条件逐项核对；实际 PPTX/notes 可编辑、真实 PDF/PNG 与文字/字形/图件完整性验收。全部页辅助视觉检查，独立盲评及人工时间缺失仍明确记录。
