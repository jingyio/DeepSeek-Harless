## 更新完整性与质量反例

新增/替换分别精确保留15个旧字段、处理对应5个字段；同名替换读到G-Agent新PDF，旧AutoTool来源句柄未发布。删除后15个剩余字段与父稿逐字一致，被删条目及其引文均不在交付中；默认全局复核实际读取整份当前表，未仅依据变化字段。所有成功组源重放通过，原三篇及两参考PDF字节保持不变。源重放不判断语义支持。

新增增量更慢且调用更多：读取29请求、字段修复7、全局综合3。它读了14个窗口并做6次检索，无提交错误；不是32步失败的隐藏重试。普通全量组批量读窗与证据选择行为不同，所以“少做15字段”没有自动转化为少调用。它又留下evaluation/findings两个缺口，不能将费用更低判为同质量收益。

开发来源核对另存第二协议`add-quality-counterexamples.json`与`replacement-quality-counterexamples.json`，均未修改模型稿：新增增量limitations仍有未被所选片段覆盖的历史数据质量条件；综合从特定论文成功转换74/100的限制扩大为“多数论文缺少代码”；新增全量evaluation列出所选片段没有的基准名；替换增量evaluation也存在基准名/评分条件超出两条选中片段的问题，并缺少findings。完整专家盲评、实验复现和全字段独立审阅未完成。相同缺口数不能证明两稿质量等价。
