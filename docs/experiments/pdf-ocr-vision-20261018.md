# PDF 自动 OCR 与论文图像读取验收

## 问题与实现

此前上传只读整份 PDF 的文字层，混合文档中的扫描页可能遗漏，论文图像也没有进入模型。新流程逐页读取；扫描页在本地 OCR，含嵌入图像或矢量绘图的页面渲染后由 Flash 结合图注、正文及用户任务分析。Pro 仍负责其被选中的最终回复。所有场景使用同一处理入口，不添加 Agent 循环。

OCR 基于固定 PyMuPDF 1.26.7 及固定中英文语言包。服务器测试发现合并语言设置对中文有明显英文偏置，改为先使用包含拉丁字母的中文模型，无 CJK 字符的扫描转录再使用英文模型。转录、公式和数值仍可能出错，没有虚构置信度、完整字符坐标或倾斜纠正能力。

## 合成来源与真实调用

三页合成 PDF：第一页有原生文字与柱形图，Alpha=17、Beta=43 只在图片像素内；第二页是中英文扫描，校验码 314159、样本量 2718；第三页含朝右的青绿色矢量箭头。已渲染检查夹具外观。测试要求同时识别像素、OCR 和原生文字来源；不制作 PPT、不编辑原件、不生成报告文件。

代码冻结读取验收 `4fe683b`；后续兼容修正增加新版 PyMuPDF 导入、账号视觉路由及准备阶段取消回归，未修改这份验收的模型答案。服务器 Linux / Python 3.10，Harness 0.1.5-rc.3，SDK 0.1.5rc1；推理 Off；应用预算、请求数及输出上限均 null，保留任务账本。原始提示、有效配置、图像、答案和账本位于私有 `.local/pdf-ocr-vision-20261018/` 及关联 Web run，未提交原始日志。

| 场景 | 最终模型 | 图片请求 | 全部请求 | 代理峰值估费 USD | 用时秒 |
|---|---|---:|---:|---:|---:|
| Chat | Pro | 3 | 4 | 0.00670929 | 18.580 |
| PPT | Pro | 3 | 4 | 0.00531752 | 16.925 |
| Paper | Pro | 3 | 4 | 0.00487840 | 17.632 |
| Data | Flash | 3 | 4 | 0.00244412 | 22.112 |

这是初轮结果：五场景均识别出 17、43、314159、2718，但人工逐字复核发现视觉助手在本页没有其他页图片时也回答整份任务，产生跨页缺失描述。Data 最终拒答箭头方向；初版仅检查非空 HTTP 成功就标记已读，不能算全部视觉验收通过。共 20 次真实请求，其中 15 次辅助图片请求均返回 HTTP 200；代理峰值估费 **$0.02243549**。失败与费用保留，不能把 HTTP 成功当语义成功。

修正要求每页只返回绑定 `source_id`、页号、`image_observed`、观察与不可读项的 JSON；未见图片、身份不符或无有效观察均不设置已读标记。相邻正文只作为解释背景，不要求视觉助手跨页回答最终问题。正式验收需重跑同一五场景并逐项核对箭头。

费用为代理估算而非提供商账单，CPU 和人工未计价；没有重置正式服务累计账本。独立开发入口的提交耗时包含解析和图片准备，不能用其提交耗时声称正式网页的即时反馈已验收；正式网页另有后台提交与取消测试。

## 修正后的五场景复测

同一三页来源、同一任务和模型配置重跑，实际实现冻结 `8977224`，有效工具/库版本随任务保存。五场景最终答案均读出两组值、校验码、样本量以及箭头朝向/颜色；人工逐字复核通过。15 份 JSON 观察均与原件来源 ID、当前页号一致，均明确观察到当前页图片；没有把别页未传图片当成本页失败。

## 回归与限制

回归覆盖原生页不重复 OCR、混合页、真实中英文扫描、矢量图、加密和损坏 PDF、逐页失败覆盖、图片/图注/相邻正文绑定、模型与费用归属、未授权或跨账号请求、取消、附件气泡隐藏和多轮版本继承。首次 PDF Chat 使用现有后台单路任务；测试以阻塞的视觉服务确认先返回接收成功，取消后不会再提交主模型请求。准备阶段取消绕过耗时的接收队列，避免取消被自己的 OCR/视觉等待阻塞。

`ppt-master-v5` / `paper-web-v10` 只从原两项训练、一项独立留出证据兼容重编代码锁；结构、工具 schema 和科学范围不变，无新采集、无编译模型调用、不提升质量或费用主张。旧库保留。

本次证明的是合成 PDF 的输入连通与来源/费用保护，不能推广为复杂真实论文图表的全面准确率。最长边 2400 像素的整页渲染可能看不清密集图例；OCR 可误读汉字、公式或数字。Data 的观察文本不替代原始表格单元格验证。暂未实现 PPTX 样式/母版的视觉输入解析。
