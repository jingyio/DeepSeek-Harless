# 历史分页修复与五用户多场景压力测试

## 已复现问题与修复

上轮自己的旧成员测试对话打开后退回首页。本轮通过同账号公开原生 API 确认 session/list 包含该记录、未进最近删除，空对话分页正常，目标 session/page 返回 gateway/internal。目标历史只有 11 条事件，排除大历史和压缩尾损坏。

原生分页使用 `request.address.sessionId`，公开输出适配器却只读取旧的 `request.sessionId`。旧比较消息没有普通任务记录时，原文恢复函数又让两个缺失 ID 相等，再解引用不存在的任务。修复正确的 session/subagent 地址解析、拒绝缺失地址的原文查找、显式检查任务存在。分页权限和原始 journal 不改。

并发审查还发现 File 按整个 workspace 拒绝其他对话，实际文件副本也按 workspace 共享；简单去掉闸门会污染文件。新任务副本稳定绑定 workspace+session，同对话保持幂等及互斥，不同对话独立。普通后续输入恢复 Chat；File 准备/启动窗口取消保护保留。短元数据写锁最多等 30 秒，学习 worker 仍单独互斥，模型运行不持此锁；种子安装进入原子元数据发布区。成员私有状态显式放入已持久绑定的 policy.output。

## 验证计划与边界

实验 ID `five-user-stress-20261020`。`scripts/check-five-user-stress.py` 默认只预览；显式 execute 才使用现有网关内部 API 生成 5 个邀请码，经真实注册创建 5 个新成员。每人独立 Chat/Paper/PPT/Data 对话，三轮附件标记、问候、回忆交替；另做小型真实报告、统计与 3 页 PPT 交付，PPT 由 GeneLoop 自主制作。私有 File 驱动另测同工作区多对话及普通续聊。只使用合成素材，不读其他成员正文。密码、邀请码、cookie、原始回答、输入/输出哈希与日志只留私有实验目录。

模型 Flash/Off；平台费用/请求/输出额度保持 null，API wire 最大容量保持 393216，沿用共享账本。既有 File 四种图形需用新运行代码真实重认证后才能发布新库；该独立兼容诊断保持既有明确实验封套，不代表平台额度。Paper/PPT 通过确定性再导出证明在线 IR/证据不变，仅更新两处经审查的分页源码锁，不宣称新训练或效果升级。旧库全部保留。

实际压力结果、费用、失败清单、逐项修复复验和部署/PR 状态在运行完成后补录；计划不能当作通过结果。目标是验证并发与合成交付契约，不是无限物理吞吐、科学结论或演示设计质量的保证。

## 发布前实测

服务器定向 Node 34 项、Python 50 项通过。File v8 四种结构均取得新的真实原生见证和两项独立实际使用，70 请求、代理估费 USD0.041094445，全部 usage 完整；不是账单实付。首次诊断路径落在项目私有根外被拒绝、模型调用为零；随后漏继承已有服务启动环境导致原生认证任务以 MISSING_CREDENTIAL 中断、请求为零，补齐原批准环境后续跑原 enrollment/预约，未清零重建。原失败和恢复日志均保留。

统一服务入口额外纳入 File SDK 活跃/未知状态与损坏状态保护，避免普通任务空闲但 File 仍运行时发布。该保护不限制不同对话任务的正常并行。
