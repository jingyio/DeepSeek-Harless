# 自动报告状态与 Negative Motif 集成验收

本轮完成旧结构规则在当前校验器上的重新认证，并将负面库接回自动报告状态实验。三次负面结构恢复均为 **2 次真实模型请求**；两次不预置恢复 scope 的自动采集恢复为 6/5 次请求。五次均保留预期内容、校验实际文件和版本，成功后无工具调用。**这是历史失败的局部机制验收，不是新的完整论文成本对照，也没有证明自由生成总结始终准确。**

## 问题、假设与范围

前轮当前状态接入改动了报告工具和负面 Runtime，实现锁使旧 Negative 库不能加载。不能把旧库换上当前哈希后沿用旧认证。假设是：只对当前已审阅的纯必要条件重新做双向认证，并保留真实旧见证及版本，可以恢复负面引导与类型化修订，同时保留实现、当前失败、用户意图及交付守卫。

否定条件包括：旧 prompt-only 规则获得早停权限；没有当前实际失败或未实际发送提示就阻断；恢复改动未选字段、丢失段落、来源失效仍交付；成功后重复导出。模型总结失实另行记录，不能以参数正确掩盖。

用户明确不重跑 Baseline。本轮从已有失败轨迹进行局部验证，未发起新完整任务、未改检索配置，也未扩场景。最新 `origin/main` 为 PR95 合并提交 `8b4fdc5`；实现位于独立分支 `codex/paper-live-recovery-state`，真实运行绑定当时源码快照，不影响生产。

## 实现与认证边界

- `learn-negative-motifs.py --recertify-current-constraints` 为显式离线入口，要求指定当前受信 `--constraint-validator`，不与字段 profile 混用。默认入口仍拒绝工具实现改变，已独立复核原拒绝。
- 新库只保留当前纯校验器通过失败/成功见证、修复、重新引入及无关编辑认证的条件规则。不迁移旧工具的执行认证，也不迁移未认证的 prompt-only 规则。保存旧事件、源码快照及旧实现摘要；当前实现和 Runtime 仍按新字节锁定。编译/再认证 API 请求为 0，离线计算和开发时间未计量。
- 本轮重新认证 `evidence_report.py:structure_issues`，保留 `recovery_structure_preserved`；页数规则未通过原因认证而被丢弃。这不是自动发现任意黑盒错误，也不是证明新工具渲染或科研结论正确。
- 自动捕获目标额外核对当前用户消息摘要、当前工具及参数 Schema。新用户要求不能通过再次返回旧失败而重新激活旧约束。
- 成功交接继续绑定实际文件、来源、导出配置和本轮参数差异；提示总结聚焦文件链接、修改路径和必要限制。此提示不构成自然语言事实校验器。
