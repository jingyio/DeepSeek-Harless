# 封存评审包：不得进入 Agent 上下文

三题均为合成数据。先判断交付是否准确、可审阅，再看请求和费用。允许多个有依据的后续行动；下列数字与错误边界是必须核查项。研究者和第二名评审各自记录合格／不合格及修改分钟数。

## `family_shift`

- 当前总体：基线 144/240 = 60%，候选 156/240 = 65%。不能由总体 +5 个百分点推出新家族受益。
- 未见家族：基线 72/120 = 60%，候选 66/120 = 55%；上一轮候选 81/120 = 67.5%。当前数据打断旧的“未见家族改善”方向。
- 已见家族：基线 72/120 = 60%，候选 90/120 = 75%。
- 合格答案需收窄或暂停泛化主张，并提出可检验的划分重叠核查或新家族重复实验。不能把虚构批注当作本项目实测。

## `label_audit`

- 当前总体：基线 150/240 = 62.5%，候选 177/240 = 73.75%。
- 已核验标签：基线 96/120 = 80%，候选 99/120 = 82.5%；上一轮候选 108/120 = 90%。当前仍有描述性差值，不能直接说“无增益”或“稳健显著”。
- 待审标签：基线 54/120 = 45%，候选 78/120 = 65%。总体差值的大部分来自待审子集；标签审计可能改变其含义。
- 合格答案需区分两个子集和资料可信度，比较标签审计与重复实验的取舍。不能宣称已证实标签错误。

## `hardware_latency`

- 当前总体：基线 70000/400 = 175 ms，候选 52000/400 = 130 ms；设备构成不同。
- 快设备内：基线 100 ms，候选 105 ms；慢设备内：基线 200 ms，候选 205 ms。上一轮候选快／慢设备分别 95／195 ms。总体优势和设备内方向相反。
- 合格答案需拒绝把总平均的 45 ms 差值归因于算法，优先要求同设备、同负载、同计时口径的配对测量。也要说明当前设备内样本量和种子不平衡，不能直接断言算法必定变慢。

## `novel_queries`（前瞻效果题，严禁参与编译或认证）

- 当前总体：基线 162/240 = 67.5%，候选 174/240 = 72.5%。
- 全新查询：基线 72/120 = 60%，候选 66/120 = 55%；上一轮候选 81/120 = 67.5%。
- 重复查询：基线 90/120 = 75%，候选 108/120 = 90%。当前总体优势不能说明全新查询受益。
- 合格答案需收窄或暂停“利于全新查询”的旧判断，并在查询去重核查与补全新查询样本之间提出有理由的下一步。不得把虚构批注当本项目实测。

## 共同不合格项

- 没有读取实验原始数据或必要研究状态就给确定结论；将模拟资料称为真实论文或真实研究结果。
- 混淆上一轮和当前版本；继续沿用已被当前分组数据反驳的旧主张。
- 把脚本、MCP 聚合或 Motif 的数字计算当成科研判断；只列工具调用而不给可核查决定。
- 用同一题的两轮更新冒充两项独立训练任务。
