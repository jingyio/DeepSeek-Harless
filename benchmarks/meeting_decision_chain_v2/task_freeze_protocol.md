# 下一批独立组会决定：冻结任务要求

本文件先冻结**研究问题与验收标准**。现已根据此协议生成三套独立的合成表格与应用对象，生成器为 `build_fixtures.py`，逐文件哈希见 `fixtures.lock.json`；它们尚未形成经过盲评的效果 benchmark。三题与 v3 的外站迁移、低频术语、测量批次是不同研究决定。当前在线 Motif 已由 `family_shift`、`label_audit` 的轨迹编译、在 `hardware_latency` 轨迹上验证，阈值沿用此前冻结值；以下三题不得参与这批 Motif 的训练或阈值选择。

## 共同输入与交付

每题给 Agent 一条明确的更新事件及研究者问题。原始结果保留在可由 WPS 打开的实验表，已有判断留在 Obsidian 笔记，相关方法提醒留在 Zotero 批注；模型可通过相同的只读 MCP 接口发现、固定版本、读取、分层复算，必要时用 Python 复核，并以 Quarto 渲染一页待审组会决定。任务不得把对象 ID、正确分组、答案数字和后续工具顺序全部塞进提示。Agent 应自行决定核查哪些分层、何时参考批注及旧主张。

每题至少包含一个不改变主张依赖的后续资料变动，及一个会改变关键证据或口径的变动。两者都属于同一决定的增量轮次，不算额外独立任务。版本不符、字段含义变化、对象 ID 歧义或结论与证据冲突时，运行时必须停止复用并交回模型或人工。

## 三个已冻结的具体任务

| 任务 | 研究者要做的决定 | 必需证据与真实语义缺口 | 可复用的结构机会 |
| --- | --- | --- | --- |
| **Model RSI 跨任务能力状态** | 新一批未见任务结果到来后，是否继续声称“内部能力状态改善跨任务迁移”，本周该补哪类验证？ | 实验表含方法、任务族、种子和正确数；Zotero 批注提醒训练任务与留出任务须分开；Obsidian 存旧主张。总体均值是否掩盖特定留出任务退化，由模型判断证据含义。 | 更新事件定位当前／上一版实验；逐版固定、读数、按任务族复算；找回依赖该实验的旧主张。 |
| **AIDD 突变外推** | 新一轮突变结果后，旧的“样本效率提升”主张能否用于未见突变类型，下一轮应补数据还是改评价口径？ | 实验表含训练预算、突变类别、重复、有效预测数；批注限定“同分布提升不能直接外推”，笔记有当前主张。预算和分母可机械复算，是否构成外推证据需判断。 | 同一组版本绑定与分层统计结构，但参数重新绑定到独立的对象、指标和类别。 |
| **科研 Agent 工具迁移可靠性** | 工具 schema 更新后，能否继续沿用“跨工具链成功率稳定”的旧判断，本周先修接口还是补任务样本？ | 实验表含工具链类型、schema 版本、任务种子、成功数和失败原因；批注提醒区分工具错误与模型决策错误；笔记记录旧结论。故障归因和优先级不能由计数自动推出。 | 事件→对象→版本→结果→旧主张的参数关系重复，但工具 schema 变化必须打断旧执行路径。 |

## 数据冻结与对照

1. 每题由不同来源文件组成独立输入；没有复制 v3 的原数值，仅改题名或替换词汇。生成器固定指标定义、样本分层、版本差异和预先登记的反证点；合成数值及构造规则公开于生成器，但 Agent 的工具权限不能读取生成器或答案。真实个人资料只能留 `.local/`。
2. 在运行前保存题目、工具 schema、来源文件哈希、许可与预算；同时冻结人工评分表。评分先检查来源版本、算术、反证、旧主张处理和本周动作，再看费用。待审报告要能被研究者理解和纠正。
3. 普通 Harness、当前 Motif、具同等版本检查的脚本／缓存用同题同工具同模型配置对照。分别记录认证接管数、**实际付费请求差**、缓存命中／未命中及输出 token、账单或估算费用、修复调用和人工修订分钟数。关闭思考模式保持一致。
4. 三题都先作为**新任务**完成一次，再做各自的无关变动与反证变动。若 Motif 只在这些特制题上省钱，而日常科研决定无法合格交付，不扩张效果主张。
