# 首批同类任务：从研究现状到下一步可反证行动

> 2026-09-27 状态修订。F1-01、F1-02 是两个不同科研决定；原 F1-03 是 SSS 自身方法开发题，只保留作诊断，**不充当第三个独立科研任务或留出题**。目前还没有三个冻结、完整、可评分的同类实例。私人来源 ID、资料正文及未来事件只进 `.local/`。

## F1-01：Model RSI 的最小反证实验

**研究决定**：模型主干之外的可更新内部能力状态是否值得做最小原型？第一项实验怎样把未来任务能力变化与外部记忆／检索、长上下文和重复题目记忆区分开？允许选择先不实现，转而补一个关键反证。

**已见真实材料**：研究者数周思考记录、Obsidian 当前状态和开放问题；文献发现服务的公开题录预检。这些预检结果不是 Agent 的检索成绩，也没有证明论文内容。已有的 Model RSI 预检记录在私有 `.local/benchmarks/research-weekly-loop/model-rsi-preflight/`。

**自然工具机会**：arXiv/OpenAlex 找互补与反证论文；Zotero 查已有条目／批注及版本；Obsidian 恢复承诺、否决和概念边界；有真实原始实验记录时用 Python 比较泛化与记忆基线；Quarto 形成可审阅的一页决定；真实协作者澄清与讨论存在时才用 Gmail／日历。

**冻结缺口**：研究者尚未指定专用 Zotero 范围、当前期限与读者、可复算实验数据、真实沟通、对外摘录权限和后续事件。因此目前只能做局部文献与研究决定试点，不能按完整多 MCP 任务评分。

## F1-02：AIDD 首个可检验应用与泛化划分

**研究决定**：对“局部界面状态变化改善亲和力变化预测”这个 idea，第一个可反证任务应选蛋白–配体还是抗体–抗原？哪个划分能避免相似结构或同源信息泄漏？若强基线已做等价的状态更新，是否应先收窄新颖性主张？

**已见真实材料**：用户 `research-workflow` 的公开 Idea State、开放问题、否决和决定记录；本机 AIDD Zotero 集合已有批注；Obsidian 中已有项目索引和研究状态。首轮付费 Agent 决定材料已形成待审核基线；随后取得 PBCNet2.0 作者公开突变预测、补充表与训练索引，65 对记录的宏平均 Spearman 已机械复算。参见[局部任务卡](pilot_task.md)、[执行包](execution_packet.md)与[公开数据预检](../../experiments/AIDD-PBCNet公开数据复算与泄漏审计边界.md)。

**自然工具机会**：文献发现检索近邻和负面结果；Zotero 核对人类批注与论文原文；Obsidian 恢复既有判断；结构化科研 MCP／Python 复算已确认的公开预测与训练索引，并检查泄漏审计需要的字段；Quarto 出组会决定材料；只有真实合作者线程／讨论需要才进入 Gmail／日历。

**冻结缺口**：PBCNet2.0 的公开数值与真实后续资料事件已到位，见[增量事件 01](aidd_incremental_event_01.md)；但训练索引缺蛋白序列、口袋残基和沉积年份，尚无可验证的训练／测试生物学对应。完整科研办公实例仍缺真实合作者邮件、讨论对象、研究者当前期限和明确交付读者；首轮决定材料尚待研究者与领域审核，不能把连接器测试中读到的批注当成已完成科研判断。该增量事件属于 F1-02 的同一任务，不算跨任务 Motif 支持。

## D-03：SSS 下一项能区分 Motif 与简单优化的实验（开发诊断）

**研究决定**：下一项真实科研办公任务应怎样区分 Motif 可执行局部结构的收益，与普通脚本、缓存、窄上下文或单次强模型的收益？应优先补哪个证据或消融，什么结果会让我们缩小机制主张？

**已见真实材料**：SSS 的方法与评测设计、原生 DSH Figure 7 窄题诊断轨迹、Obsidian 关于结构—语义分离的研究笔记，以及 Motif Agent Zotero 集合中已有的相关论文批注和若干本地实验数据线索。Figure 7 轨迹只是 D-03 的既有诊断证据，不能算新的独立科研任务。

**自然工具机会**：文献发现核对相邻系统方法；Zotero 比较已批注论文与实际实现；Obsidian 恢复旧主张和否决条件；Python 对已确认的原始运行与 DSH 用量做同口径统计；Quarto 形成下一轮实验决策；真实共同作者邮件或组会时间存在时才用 Gmail／日历。

**用途与限制**：该题直接参与 SSS 方法开发，只能调试轨迹、工具契约和质量门，不能作跨项目留出效果成绩。还须指定当前未决定的实验问题、原始而非派生的数据范围、交付读者与时间、对外摘录权限和实际后续事件；缺这些条件时也不是完整多 MCP 实例。

从研究者确实正在推进、且与 SSS 方法开发不同的项目中选取。冻结前只登记候选项目的研究问题、期限、读者及相关应用的**元数据范围**；确认 Zotero 文献／批注、Obsidian 人工研究状态、公开新论文与至少一个可核查的数据或方法比较确实共同影响同一决定。没有真实邮件、会议或后续事件时标记为局部实例，不编造它们。该题在 Motif 编译前封存，不能从 F1-01、F1-02 或 D-03 的旧轨迹改写出一份“留出题”。

## 三例入选与 Motif 挖掘门

1. 对每题确认研究者目前确有此决定及期限，圈定可读来源；只读冻结 ID、版本、哈希和权限。若其中一题已过期，就从真实候选池替换，不能把旧题硬当活跃研究决定。
2. 每题单独构造 Agent 可见包和隐藏评审包；至少记录一次原生 DSH 自主工具轨迹。不同任务可以用不同论文和数据，但保持模型、预算策略、工具能力与质量门可比较。
3. 候选 Motif 必须来自**至少两个独立实例**中实际出现、参数可重新绑定的工具／证据依赖子图；第三题留出验证，随后轮换留出。跨三个题型都只看到“写报告”或“读取文件”不足以支持新机制。
4. 只有至少三题都确有后续真实事件，才能称此任务类型验证了局部增量与有界惯性。初始交付可先单独评测；邮件、日历、数值数据缺失的题按局部实例记录。若三题最终都缺同一连接器，不能据此声称该连接器已经被多任务盘活。
5. 质量先行：研究者与领域评审先判科学决定是否合格，再比较原生 DSH、简单缓存／脚本、`research-workflow + 同一模型` 和 Motif 的工具机会、模型请求、实际费用、人工修订与端到端时间。开发题得到的 Motif 需在后来的独立项目／研究者上复验。

Figure 7 数值／图柱核对是另一种“研究产物证据审计”任务的第一个开发实例。要将该类型纳入 Motif 挖掘，也必须另找至少两个不同研究决定和更独立的来源；不能把 Figure 7 的阶段 A、阶段 B 和 Pro 审核凑成三题。
