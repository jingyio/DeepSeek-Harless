# 真实试点候选：局部界面状态能否成为可检验的 AIDD 研究问题

> 未冻结、未运行。问题来自用户 [research-workflow](https://github.com/jingyio/research-workflow/tree/55bbec71f888b3573ec295a0256bde05daf665a9) 公开的 `research/idea/current.md` 与 `open_questions.md`，不是 SSS 虚构的论文或实验结果。由研究者确认其仍是近期要推进的课题后，才可计入真实试用。私人 seed、个人批注和 Zotero／Obsidian 内容不复制到此仓库。

## 需要研究者作出的决定

当前设想是：把局部修改或突变后的分子相互作用／结合界面表示为显式计算对象，并用其变化预测结合亲和力变化。近期需要决定：**选择哪个首个真实任务和泛化设置，界面“状态变化”与已有方法有什么可检验的区别，以及下一步应继续查文献还是启动最小反证实验？**

这不是请 Agent 直接设计一个新模型。可以得出“现有强方法已经做了类似更新”“数据不足以识别动态更新收益”“局部假设在目标体系下不成立”“先做静态界面基线”等结论。研究者需在运行前明确真正要决策的期限和可接受输出。

## 相互依赖的主张与路线

| 主张／问题 | 可能改变它的证据 | 影响的下游行动 |
| --- | --- | --- |
| 显式界面状态／更新是否区别于现有强方法 | 最近邻、表征与机制论文；代码实现；不同术语下的相同做法 | 新颖性表述、需要复现的 baseline、是否继续发明新结构 |
| 哪个应用场景最能检验“局部变化” | 蛋白–配体、抗体–抗原等任务的科学过程、结构变化、标签条件 | 任务定义、数据集选择、领域专家复核 |
| 泛化分割和标签能否测到真收益 | 数据来源、同源性、结构相似性、随机划分与 OOD 结果、负面结果 | 评价协议、是否先做泄漏审计和简单基线 |
| 局部更新假设在诱导契合与远程效应下是否站得住 | 生物物理／结构证据以及失败案例 | 适用范围、边界条件、可能的否定结论 |

这些不是四个独立摘要。比如发现数据泄漏，会同时影响“哪个应用最合适”和“某论文是否证明界面状态有效”；发现已有强方法明确维护同类 pair state，会同时改变新颖性、基线和最小实验。Agent 要构造跨主张依赖，不能把每个路线互不相干地写完。

## 分阶段真实事件

**阶段 A：恢复与调查。** 从公开 Idea State、否决记录和研究者允许的 Zotero／Obsidian 范围恢复现状。按当前最重要的不确定性动态选择互补路线，读取真实论文和已有批注，产出论文卡、证据与矛盾账本、待核实项，以及“继续文献调查／先做代码或数据实验”的决定。若资料不足，必须说明缺口，不能为了填满卡片而推断实验结果。

**阶段 B：人的批注进入。** 研究者在 Zotero 对实际读过的论文新增或修订一条有决策意义的批注，或在 Obsidian 修改问题范围。事件在阶段 A 完成后才释放。Agent 需要判断批注是原文证据、研究者解释还是待验证猜测；定位它触及的主张、旧卡片、阅读队列与报告段落。无关内容应复用，涉及科学含义的旧判断要重审。

**阶段 C：合作者澄清与外部证据进入。** 若研究者确实需要确认数据集划分、模型实现或实验条件，Agent 先读取研究者圈定的 Gmail 往来，提出具体待澄清问题并准备有来源依据的邮件草稿；研究者逐封确认后才发送。收到真实回复，以及真实到来的新论文、修订稿、负面结果或数据集审计后，Agent 要处理版本和重复、检验与已有结果是否可比、寻找反证，并决定是否需要新路线、数值复算或最小实验。回复中的个人说法与公开论文证据分开记录。若没有真实后续事件，该增量部分暂不评分；可用有时间戳的真实历史资料做单独标记的回放。

**阶段 D：交接。** 研究者复核 Idea Delta、主张—证据关系和下一步建议。确认后才更新 Obsidian／research-workflow 的状态文件，保存 Quarto 组会简报；如需要与合作者讨论，读取 Google 日历忙闲并提出真实可用的会议时间，研究者确认后再建会。重点是能否让研究者继续推进 idea，而不是创建了多少日历事件。

## 所需交付与可观察的机制

- 中文决策简报：当前问题、路线取舍、证据支持和反例、不能比较的结果、推荐行动及明确的停止条件。
- 逐条来源定位的证据表：论文陈述、实际结果、Zotero 批注、Agent 推断分别标记；矛盾要保留。
- 可审阅的 Idea State 差异：哪些承诺保持、收窄、撤回或重开，为什么；拒绝无证据复活旧方向。
- 批注／新证据进入后的依赖变更表：复用、重验、失效、重新搜索、转实验分别列出原因。只有验证输入、依赖和旧证据后才能记录“跳过模型”；新科学证据的语义冲突不能按文件哈希跳过。
- 实际人工修订、模型调用／费用、耗时、下一周是否采纳或执行。没有合格输出，不报告“省了多少”。

## 冻结前须由研究者补齐

1. 本周真实要决定的具体问题、读者、期限、若无 Agent 的现有做法。
2. 允许读取的 Zotero 条目／集合、批注、Obsidian 笔记、Gmail 线程和日历范围，以及可发给外部模型的摘录范围；明确实际需要联系谁、澄清什么，不为测试虚构邮件。
3. 阶段 A 初始资料的快照、版本与哈希；后续真实事件的发生时间和封存方式。
4. 各组相同模型与预算、写入权限、报告位置，以及两名有领域知识的评审。
