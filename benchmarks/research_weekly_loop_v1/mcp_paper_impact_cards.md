# MCP 核心轻量任务族：一篇论文如何改变当前研究判断

2026-09-27。此任务族检验结构执行能否在日常、多应用的小任务中**跳过完整模型请求**，目前只是待验证假设。它比“设计一个领域的最小反证实验”窄：每次只处理一篇已指定论文和一条现有研究主张，不要求开放式规划、全领域检索、邮件、日历或原始数据复算。任务仍须对研究者有用，不能为工具计数制造调用。

## 用户交给 Agent 的真实问题

> 这篇论文及我在 Zotero 的批注，是否改变 Obsidian 当前记录的一条研究判断？给我一张可审阅的论文影响卡：论文实际证据、我的批注、与旧判断的关系、接下来读／做／暂缓什么，并标出不确定处。

一张卡只对应一篇论文、一个明确的问题和一个截止版本。研究者可指定论文 Zotero 条目与 Obsidian 笔记；如果新论文尚未进 Zotero，文献发现 MCP 可定位公开版本，但“没有 Zotero 批注”须如实注明。文献发现不是每张卡的强制调用。Quarto 输出一页 HTML 草稿，原始来源留在 Zotero 和 Obsidian；本轮不写回笔记库。

## 自然的工具依赖

| 需要的信息或动作 | 工具机会 | 只有下列结果才算贡献 |
| --- | --- | --- |
| 论文身份与版本 | Zotero 条目；必要时文献发现 MCP | 防止把近似标题、预印本和修订版混成同一证据 |
| 人的阅读解释 | Zotero 批注 MCP | 区分论文原文与研究者的判断、疑问、反证标记 |
| 旧主张与否决 | Obsidian MCP | 明确卡片针对哪条当前判断，而非泛泛摘要 |
| 实际证据 | 公开全文限页读取或获准的 Zotero 附件读取 | 引用论文实际方法／结果与页码；只看题录时不得做正文结论 |
| 可审阅交付 | Quarto MCP／CLI | 生成带来源位置、缺口和下一步的一页草稿 |

Agent 自行决定阅读顺序、补哪页证据及何时停下来。模型处理的核心缺口是：**论文结果是否真的支持或反驳那条研究主张，以及批注是事实还是人的解释**。来源身份、版本校验、参数传递和未变节点重用是结构层可尝试接管的工作；Quarto 渲染可由独立确定性工具完成，当前 Motif 控制器还未接管它。若模型判断仍必要，就调用模型；不能把“相同 DOI”或“笔记没改”直接解释为科学结论没变。

## 无模型选择的真实边界

**第一次做影响卡一般需要模型处理科学含义，但不一定需要模型选择每个工具。** 当前只读 Motif 控制器的 `execute_goal` 接口要求宿主给出目标输出、当前版本和起始绑定；这是**目前实现的边界**，不是结构方法的理论上限。AutoTool（本地 PDF 第 5 页）用近期工具序列的历史频率与当前语义相似度提出下一工具候选，再从先前工具输出、环境状态和启发式中尝试补齐参数；高置信且参数齐全时可省掉该步 LLM。SSS 可以借用这种**候选提出**方式，但科研来源的相似度／历史频率本身不应授权执行或维持旧科学判断。

任务入口也可以是明确的结构化输入，例如 `paper=zotero:ABCD1234; claim=obsidian:idea-note#claim-02`。固定格式可用受约束的正则提取标识；JSON 加 schema 更易处理嵌套和版本。解析结果随后必须在当前授权范围里解析成真实对象，核对类型、版本与权限，并形成起始绑定。解析到 `ABCD1234` 不等于证明它是这项任务中正确的论文。若输入仅是开放自然语言，或解析后同时命中多篇论文／多条主张，可以用轻量语义匹配提出候选，再让校准的阈值与结构守卫决定是否执行；不确定则交给大模型或人。

在已认证的局部 Motif 内，工具序列来自真实轨迹编译的参数依赖；运行时先以任务给定或匹配出的 `role` 固定来源版本，再把工具返回的 `source_id` 绑定到后续读取工具的 `source_id` 参数。契约默认的页／行范围可确定使用；非默认页码若来自当前版本的目录／章节定位结果，也可以作为有据参数传递。若页码、论文对象或批注—主张关系只有模糊猜测，且没有通过校准与守卫，就必须停止并交给模型或人。当前控制器只接管只读节点，**尚不能无模型地生成影响判断或执行 Quarto 写入**。

工具选择可分两层：**提出候选**可以用近期调用链、Motif 描述与当前任务文本的相似度；**执行授权**还要通过候选唯一性／校准置信度、当前工具 schema、全部必需参数的来源、作用范围、来源版本、失败与写入守卫。小型 embedding 或 Choice 模型若参与匹配，也要单独计入调用和费用；目标是减少昂贵的开放推理请求，而不是声称没有任何模型参与。当前代码已有有界候选建议入口，但尚未把它接入真实 DSH 科研任务的逐步调度，也没有本任务族的阈值校准。

首先检验跳过整轮模型请求的场合是**同一张卡的真实增量复查**：事件或用户操作明确给出条目与主张，旧卡记录了来源和判断依赖；运行时校验这些输入、读取变化并找出受影响节点。若所有语义依赖未变，仅有可机械更新的元数据或渲染变化，才可能沿用已审核判断并跳过语义请求。新批注、新论文证据或主张改动会重新打开语义判断。即使这条路径成功，也须与版本缓存和普通脚本比较；否则只是缓存收益。

## 三个具体候选与当前就绪度

| 候选 | 一篇论文与一条判断 | 现有工具来源 | 状态 |
| --- | --- | --- | --- |
| P1：AIDD 抗体路线 | 已圈定的抗体路线 Zotero 论文及六条批注；核对它是否改变当前应用路线／新颖性判断 | 已批准的 AIDD Zotero 条目、批注，Obsidian 当前状态与开放问题，已圈定 PDF | 可做**只读开发试跑**；仍需研究者审核卡片是否有用 |
| P2：AIDD 配体路线 | 已圈定的配体路线 Zotero 论文；核对它是否改变同一 idea 的另一个应用路线判断 | 已批准的 AIDD Zotero 条目、Obsidian 状态与已圈定 PDF | 无已圈定批注，记为“无批注”子型；与 P1 共用项目状态，**不算跨项目留出** |
| P3：Model RSI / Metis | 论文的内部记忆结果是否改变“可更新能力状态”的一条现有主张 | 已批准的 Model RSI Obsidian 状态、week7 PDF，文献发现可定位公开论文 | 目前没有已批准的 Model RSI Zotero 条目／批注；只能先做缺 Zotero 的**局部试跑**，不能声称完整 MCP 覆盖 |

这三项是**具体任务候选**，不是三个已冻结的独立评测实例。P1、P2 共享 AIDD 来源簇；P3 缺 Zotero 范围。正式的跨任务挖掘仍需第三个不同项目的论文与项目状态，且至少两项任务有真实的 Zotero 批注。缺口不能通过把同一决定续写三次或伪造批注补齐。

## 最小实验与跳过模型的判据

1. 先在 P1 做一次普通 DeepSeek Harness 自主只读执行，保留所有合法工具，记录每轮的工具调用、参数来源、模型请求和卡片质量。不要提示它按预写的工具顺序走。随后 P2/P3 可作不同范围的诊断，但不得混成独立留出成绩。
2. 找**真实发生**的后续变化：Zotero 批注修改、论文版本更新或研究者修改对应主张。另记录无关元数据变化或未变来源。没有真实变化时只测初始卡片，合成变化只作守卫回归。
3. 从至少两个独立任务的实际轨迹编译局部算子；运行时在新任务或下一轮只执行来源、参数和权限均可核验的节点。若本次变化只触及元数据，允许复用已核验正文及不变主张的卡片部分；新批注或论文结果影响科学含义时必须重新交给模型。
4. 对照普通 Harness、同一工具下的简单缓存／预取／脚本与 Motif。**主指标是官方逐请求日志中少了多少完整模型请求，同时卡片仍合格**；另报未命中／命中输入与输出 token、费用、耗时、人工修订、错误沿用和回退。只减少 MCP 调用或只缩短提示词不算目标收益。

开发试跑可以证明连接器与轨迹能否支持这种任务，不能单凭 P1–P3 宣称跨项目 Motif 泛化或实际省钱。若简单缓存达到相同质量与成本，应把该机制定位为工程缓存，而非 Motif 特有收益。
