# 真实轻量试点：多轮 Agent 的缓存基线怎么选

状态：2026-09-28 开发性任务；两篇真实 Zotero 论文、对应 PDF 与一段真实 Obsidian 研究状态。私有来源范围、哈希、模型提示和运行轨迹留在 `.local/benchmarks/research-weekly-loop/serving-cache-baseline-decision-20260928/`。

研究者要决定下一轮 SSS 多步骤科研 Agent 实验的基线：普通 DeepSeek Harness 加现有缓存是否足够，还是应先实现一项 KV 缓存／请求调度优化。Continuum 与 SGLang 的实测对象、工作负载和指标必须与 SSS 的“跳过模型决策请求”分开描述。交付一页中文待审材料，明确最小对照、观测量与改变建议的条件。

这是实际研究设计决定，不预设应采纳任一论文的方法。Agent 可自由选择两篇论文和笔记的读取顺序；来源只通过批准范围内的只读 MCP 暴露。两组提示、来源版本、工具和模型固定，`reasoning_effort="off"`，每组费用上限 US$2。此题不含真实新批注、实验结果或协作事件，因此只评价初始决定，不声称验证增量恢复或完整科研闭环。

机制预注册：已认证的 Zotero 固定来源→读取同版条目可在唯一后继且所有参数由前一步结果填充时接管；PDF 页码选择、论文是否适用 SSS、基线取舍都必须交给模型。记录实际接管、净模型请求、缓存计价费用和待审材料的证据准确性。若 Motif 只改变调查路线而无经验证接管，或答案出现对象/指标混淆，记为开发失败。与旧 MotifAgent/MGGA 项目共享研究背景，因此不得当作独立跨项目留出成绩。
